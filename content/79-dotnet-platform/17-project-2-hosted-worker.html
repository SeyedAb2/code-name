پروژهٔ ۲ — Worker میزبان‌شده و قابل‌عیب‌یابی

Project 2 — a hosted, diagnosable worker

یک job دوره‌ای روی سیستم توسعه درست کار می‌کند؛ اما وقتی Ctrl+C می‌زنند، معلوم نیست کار جاری تمام شده، لغو شده یا نیمه‌کاره رها شده. مأموریت تو ساخت Worker Service کوچکی است که چرخهٔ شروع/توقفش روشن باشد، تنظیماتش هنگام startup اعتبارسنجی شود و تیم بتواند مصرف و رخدادهایش را با شواهد بررسی کند.

A periodic job works locally, but after Ctrl+C nobody knows whether the current work completed, was cancelled, or was abandoned. Build a small Worker Service with explicit startup/shutdown behaviour, startup-validated configuration, and inspectable resource and event evidence.

مأموریت: هر چرخه را قابل‌مشاهده و قابل‌توقف کنMission: make each cycle observable and stoppable

Worker هر چند ثانیه یک واحد کار ساختگی و محدود انجام می‌دهد، نتیجه را با structured log ثبت می‌کند و cancellation میزبان را تا I/O و delay پایین می‌برد. یک مسیر failure کنترل‌شده هم داشته باش تا exception، retry policy محدود و توقف قابل‌آزمایش باشند. هدف ساخت صف توزیع‌شده نیست.

The worker performs a bounded synthetic unit of work at a configurable interval, records structured events, and propagates host cancellation through delay and I/O. Add a controlled failure path so exception handling, bounded retry, and shutdown can be tested. This is not a distributed-queue project.

مرز تضمین: jobها در این پروژه در حافظه‌اند و با process از بین می‌روند؛ پس restart تضمین نمی‌کند job نیمه‌کاره از همان نقطه ادامه یابد. README باید همین محدودیت را بگوید. از stress، loop بدون delay و host-wide resource pressure استفاده نکن.

Guarantee boundary: jobs are in memory and disappear with the process; restart does not guarantee resuming a partially completed job. State this in the README. Do not use stress workloads, busy loops, or host-wide resource pressure.

محدودهٔ فنی پروژهTechnical scope

  • Generic Host و BackgroundService؛ graceful shutdown با CancellationToken.
  • Generic Host and BackgroundService; graceful shutdown through CancellationToken.
  • تنظیمات interval، مدت کار و تعداد retry محدود؛ مقادیر هنگام startup validate شوند.
  • Configurable interval, work duration and bounded retries; validate at startup.
  • هر رخداد log دارای job id، attempt، elapsed و نتیجه باشد؛ secret یا payload حساس log نشود.
  • Each log event includes job id, attempt, elapsed time and outcome; never log secrets or sensitive payloads.
  • یک component کار مستقل از Host داشته باش تا unit test آن سریع باشد.
  • Keep work logic independent from the Host so it can be unit-tested quickly.
  • در cancellation، retry تازه شروع نشود؛ shutdown و timeout مستند باشند.
  • Do not start a new retry after cancellation; document shutdown and timeout behaviour.
  • diagnostic با dotnet-counters روی workload آرام و محدود انجام شود؛ dump فقط در محیط آزمایش و بدون دادهٔ واقعی.
  • Use dotnet-counters with a bounded workload; collect dumps only in a lab without real data.

راهنماهای مرحله‌ایStaged hints

راهنما ۱ — cancellation را تا پایین پاس بدهHint 1 — propagate cancellation

توکن را فقط به while شرط نده؛ delay و APIهای async پایین‌دست هم باید همان token را بگیرند.

Do not use the token only in the loop condition; pass it to delay and downstream async APIs too.

راهنما ۲ — retry محدود و قابل‌لغوHint 2 — bounded, cancellable retry

بین attemptها delay با token بگذار، سقف تلاش تعیین کن و cancellation را به failure عادی تبدیل نکن.

Use cancellable delay between attempts, set a maximum, and do not treat cancellation as an ordinary failure.

راهنما ۳ — counters سؤال محدود می‌خواهدHint 3 — counters need a narrow question

اول بگو CPU، allocation یا exception rate را می‌سنجی؛ بازهٔ کوتاه و PID تأییدشده انتخاب کن.

Choose whether you are measuring CPU, allocation, or exception rate; use a short window and verified PID.

طرح مرجع و مرز آنReference design and its boundary

  1. Host فقط composition و logging configuration را می‌سازد؛ worker منطق orchestration را نگه می‌دارد.
  2. The Host composes services and logging; the worker owns orchestration.
  3. یک سرویس job مستقل، کار محدود و deterministic را اجرا می‌کند و cancellation را می‌پذیرد.
  4. A separate job service performs bounded deterministic work and accepts cancellation.
  5. Options در startup validate می‌شود؛ singleton worker هرگز scoped dependency را captive نمی‌کند.
  6. Options validate at startup; the singleton worker never captures a scoped dependency.
  7. retry فقط برای failureهای قابل‌تکرار، با سقف و delay؛ cancellation retry نمی‌شود.
  8. Retry only eligible failures, with a bound and delay; cancellation is not retried.
  9. logها job ID/attempt/elapsed/outcome دارند؛ payload حساس ندارند.
  10. Logs include job ID/attempt/elapsed/outcome and no sensitive payload.

این طرح صف durable، exactly-once delivery یا resume بعد از crash را تضمین نمی‌کند. برای آن‌ها state پایدار و قرارداد پیام لازم است؛ پروژهٔ بعدی دربارهٔ تحویل release است، نه ساخت broker.

This design does not guarantee durable queues, exactly-once delivery, or resume after a crash. Those need persistent state and message contracts; the next project focuses on release delivery, not building a broker.
