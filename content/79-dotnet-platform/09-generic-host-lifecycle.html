Generic Host و عمر برنامه

Generic Host and application lifetime

کاربر Ctrl+C می‌زند و پنجره بسته می‌شود؛ اما worker هنوز وسط نوشتن گزارش است. آیا برنامه فرصت توقف تمیز گرفت؟ اگر عمر process را فقط «تا وقتی Main تمام نشده» ببینیم، worker، log و اتصال‌ها بی‌صاحب می‌مانند. Generic Host این منابع را زیر یک چرخهٔ start/stop هماهنگ می‌کند.

A user presses Ctrl+C and the window closes while a worker is writing a report. Did the app get a chance to stop cleanly? If process lifetime means only “until Main returns,” workers, logs, and connections are left unmanaged. Generic Host coordinates these resources through one start/stop lifecycle.

فصل ۸پیش‌نیازprerequisite

process زنده است، ولی کار نیمه‌تمام می‌ماندThe process lives, but work is left incomplete

یک worker هر دقیقه گزارشی می‌سازد. هنگام توقف، گاهی فایل ناقص می‌ماند؛ گاهی آخرین log ثبت نمی‌شود. developer می‌گوید «سیستم‌عامل process را می‌بندد، پس کاری از ما برنمی‌آید». اما host معمولاً برای shutdown graceful سیگنال می‌فرستد و به برنامه فرصت می‌دهد کار را جمع کند—تا یک مهلت مشخص.

A worker writes a report every minute. During shutdown, the file is sometimes incomplete and the final log is sometimes missing. A developer says “the OS closes the process, so nothing can be done.” But the host normally signals graceful shutdown and gives the app time to finish—within a deadline.

Generic Host مجموعه‌ای از منابع برنامه را گرد هم می‌آورد: DI، configuration، logging، hosted serviceها و مدیریت عمر. الگوی builder امروزی برای برنامه‌های جدید Host.CreateApplicationBuilder است؛ WebApplication در ASP.NET هم روی همین خانوادهٔ hosting بنا شده. در این فصل host را از ASP pipeline جدا نگه می‌داریم: host عمر process را مدیریت می‌کند، pipeline عمر درخواست HTTP را.

Generic Host brings application resources together: DI, configuration, logging, hosted services, and lifetime management. Host.CreateApplicationBuilder is the current builder pattern for new generic apps; ASP.NET WebApplication uses the same hosting family. Keep host lifetime separate from the ASP pipeline: the host manages process lifetime, while the pipeline handles HTTP request lifetime.

ساختن host و نگه‌داشتن processBuild the host and keep the process alive

Host.CreateApplicationBuilder تنظیمات پیش‌فرض، logging و DI را آماده می‌کند. Build container و host نهایی را می‌سازد. Run اجرا را آغاز می‌کند و تا shutdown منتظر می‌ماند؛ StartAsync شروع می‌کند و برمی‌گردد، پس caller خودش باید منتظر توقف بماند و host را dispose کند. برای console worker ساده RunAsync معمولاً چرخهٔ کامل را واضح نگه می‌دارد.

Host.CreateApplicationBuilder prepares default configuration, logging, and DI. Build creates the final host. Run starts and waits for shutdown; StartAsync starts and returns, so the caller must wait for stop and dispose the host. RunAsync usually keeps the full lifecycle clear for a simple console worker.

چرخهٔ worker کوچک
var builder = Host.CreateApplicationBuilder(args);
builder.Services.AddHostedService<HeartbeatWorker>();
using var host = builder.Build();
await host.RunAsync();

اگر برنامه با همین کد فوراً خارج شد، ثبت hosted service یا روش اجرای host را بررسی کن. تعریف یک کلاس BackgroundService کافی نیست؛ باید به services اضافه شود. اگر StartAsync را تنها صدا بزنی و Main تمام شود، process هم ممکن است پایان یابد.

If the app exits immediately, inspect hosted-service registration and host execution. Defining a BackgroundService class is not enough; it must be registered. If you call StartAsync alone and Main completes, the process may end too.

کار طولانی باید cancellation را ببیندLong-running work must observe cancellation

BackgroundService یک IHostedService است که task طولانی‌عمر را نمایندگی می‌کند. ExecuteAsync باید token توقف host را به delay و عملیات async قابل لغو بدهد. حلقه‌ای که token را نادیده می‌گیرد ممکن است تا پایان مهلت shutdown زنده بماند و بعد process متوقف شود، حتی اگر نوشتن نیمه‌کاره بماند.

BackgroundService is an IHostedService representing long-running work. ExecuteAsync should pass the host’s stopping token to cancellable delays and operations. A loop that ignores the token can outlive the shutdown window; the process may then stop with a partial write.

worker که توقف را رعایت می‌کند
public sealed class HeartbeatWorker(ILogger<HeartbeatWorker> log)
    : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            log.LogInformation("Heartbeat at {Time}", DateTimeOffset.UtcNow);
            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}

هنگام توقف، Task.Delay با cancellation تمام می‌شود و host سرویس را جمع می‌کند. اگر cancellation طبیعی است، آن را مثل خرابی غیرمنتظره گزارش نکن. برای عملیات فایل یا شبکه نیز token را تا API پایین‌دست عبور بده؛ tokenی که فقط در شرط حلقه چک می‌شود ممکن است وسط I/O کمکی نکند.

On shutdown, the delay observes cancellation and the host can stop the service. Do not report expected cancellation as an unexpected fault. Pass the token through to file or network APIs too; checking it only in the loop condition may not interrupt in-flight I/O.

مهلت shutdown، قول بی‌نهایت نیستShutdown timeout is not an unlimited promise

host برای توقف به سرویس‌ها فرصت می‌دهد، اما timeout دارد. مقدار پیش‌فرض امروزی Generic Host در مستندات .NET برابر ۳۰ ثانیه است و قابل تنظیم؛ محیط container یا orchestrator هم ممکن است مهلت کوتاه‌تری داشته باشد. اگر کار طولانی‌تر است، آن را بی‌انتها نگه ندار: کار را checkpoint کن، زمان را اندازه بگیر و سیاست توقف را با میزبان هماهنگ کن.

The host gives services a chance to stop, but within a timeout. Current .NET documentation describes a 30-second default Generic Host shutdown timeout, configurable by the app; a container or orchestrator may impose a shorter window. If work takes longer, do not wait indefinitely: checkpoint, measure, and align stop behaviour with the outer host.

graceful یعنی فرصت، نه تضمینGraceful means opportunity, not guarantee

فرایند ممکن است با kill سخت، crash یا قطع برق متوقف شود. دادهٔ مهم باید مستقل از shutdown امن شود؛ اگر worker یک کار را وسط نوشتن رها کند، persistence و idempotency لازم می‌شوند.

A process can be force-killed, crash, or lose power. Important data must be safe independently of shutdown; if a worker can stop mid-write, persistence and idempotency matter.

چه زمانی host شروع یا متوقف می‌شود؟When is the host starting or stopping?

IHostApplicationLifetime tokenهای ApplicationStarted، ApplicationStopping و ApplicationStopped را در اختیار می‌گذارد. از آن‌ها برای واکنش محدود و مشخص استفاده کن: مثلاً وقتی توقف اعلام شد، ورودی جدید را نپذیر و وضعیت را log کن. این eventها محل اجرای کار طولانی و مسدودکننده نیستند؛ توقف واقعی hosted serviceها از چرخهٔ StopAsync می‌آید.

IHostApplicationLifetime exposes ApplicationStarted, ApplicationStopping, and ApplicationStopped tokens. Use them for bounded reactions: for example, stop accepting new work and log when shutdown begins. These events are not a place for long blocking cleanup; hosted services participate through StopAsync.

ثبت رویداد توقف
public sealed class StopObserver(IHostApplicationLifetime lifetime,
    ILogger<StopObserver> log) : IHostedService
{
    public Task StartAsync(CancellationToken token)
    {
        lifetime.ApplicationStopping.Register(
            () => log.LogInformation("Host is stopping"));
        return Task.CompletedTask;
    }

    public Task StopAsync(CancellationToken token) => Task.CompletedTask;
}

این فقط نشانهٔ شروع توقف را log می‌کند؛ callback باید کوتاه بماند. اگر نیاز داری کار asynchronous یا زمان‌بر را متوقف کنی، token را در BackgroundService مصرف کن یا StopAsync را با مهلت مشخص پیاده کن.

This only logs that stopping began; the callback must remain short. For asynchronous or longer cleanup, observe the BackgroundService token or implement StopAsync within the supplied deadline.

Host lifetime با request lifetime فرق داردHost lifetime differs from request lifetime

در ASP.NET Core یک host می‌تواند هزاران request را در طول عمر خود بپذیرد. پایان یک request نباید host را خاموش کند؛ توقف host هم باید جلوی پذیرش کار جدید را بگیرد و serviceها را هماهنگ متوقف کند. request-scoped dependency عمر کوتاهی دارد و hosted worker معمولاً singleton است؛ worker برای استفاده از سرویس scoped باید scope بسازد، نه اینکه آن سرویس را در constructor بگیرد و تا ابد نگه دارد.

An ASP.NET Core host can serve thousands of requests during its lifetime. Ending one request must not stop the host; host shutdown should stop new work and coordinate services. A request-scoped dependency is short-lived while a hosted worker is usually singleton; the worker should create a scope when it needs a scoped service, not capture one forever in its constructor.

طول عمر DI در فصل بعدی همین دوره به‌طور کامل بررسی می‌شود. فعلاً قانون ساده را نگه دار: host طولانی‌عمر است؛ request و dependencyهای scoped عمر مشخص دارند؛ برای اتصال این دو مرز باید scope را آگاهانه بسازی و آزاد کنی.

The next chapter examines DI lifetimes in detail. For now, keep this rule: the host is long-lived; requests and scoped dependencies have bounded lifetimes; bridging them requires an intentional scope that is disposed.

آزمایشگاه: توقف را واقعاً ببینLab: observe shutdown for real

یک Worker Service موقت بساز و یک کار تکراری سبک در آن ثبت کن. هدف benchmark نیست؛ می‌خواهیم ببینیم Ctrl+C چه زمانی token را لغو می‌کند و کدام log آخر ثبت می‌شود.

Create a disposable Worker Service and register a lightweight repeated task. This is not a benchmark; observe when Ctrl+C cancels the token and which final log is written.

  1. worker را ثبت کن و RunAsync را صدا بزن؛ log شروع و heartbeat را مشاهده کن.Register the worker and call RunAsync; observe startup and heartbeat logs.
  2. به Task.Delay token توقف را بده و یک log در finally قرار بده.Pass the stopping token to Task.Delay and place a final log in finally.
  3. Ctrl+C بزن؛ ترتیب ApplicationStopping، cancellation و آخرین log را ثبت کن.Press Ctrl+C and record ApplicationStopping, cancellation, and final-log order.
  4. در نسخهٔ disposable token را از delay حذف کن و آزمایش را تکرار کن؛ اثر را ببین و بلافاصله کد سالم را برگردان.In the disposable version, remove cancellation from the delay and repeat; observe the effect and restore correct code immediately.
  5. یک cleanup کوتاه به StopAsync اضافه کن و مطمئن شو در مهلت تمام می‌شود.Add a short cleanup in StopAsync and verify it completes within the shutdown window.

گزارش: زمان دریافت signal، token observed، آخرین کار کامل‌شده، cleanup و exit code. اگر مهلت محیط از cleanup کوتاه‌تر است، mismatch را بنویس؛ timeout را پنهان نکن.

Report signal time, token observation, last completed work, cleanup, and exit code. If the environment deadline is shorter than cleanup, document the mismatch instead of hiding it.

برنامهٔ پایدار، توقف را هم طراحی می‌کندA reliable app designs its shutdown too

Generic Host منابع و lifetime را هماهنگ می‌کند. Run process را زنده نگه می‌دارد؛ hosted service کار طولانی‌عمر انجام می‌دهد؛ stopping token به آن فرصت می‌دهد به توقف واکنش نشان دهد. اما این فرصت timeout دارد و در kill سخت اصلاً تضمین نمی‌شود.

Generic Host coordinates resources and lifetime. Run keeps the process alive; hosted services perform long-running work; a stopping token gives them a chance to react. That opportunity is bounded and is not guaranteed under forceful termination.

برای worker، cancellation را به I/O پایین‌دست برسان و cleanup را کوتاه و قابل‌اندازه‌گیری نگه دار. برای دادهٔ مهم، shutdown را به‌جای persistence نگذار. اگر ASP.NET میزبان requestهاست، عمر host را از عمر request جدا کن و برای dependency scoped scope مناسب بساز.

Pass cancellation into downstream I/O and keep cleanup bounded and measurable. Do not treat shutdown as a substitute for persistence. In ASP.NET, separate host lifetime from request lifetime and create proper scopes for scoped dependencies.
