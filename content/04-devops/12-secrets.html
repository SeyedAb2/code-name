مدیریت secret

Secret management

یه رمز آزمایشی commit شده. بعداً حذفش کردیم و دوباره push زدیم. خیال‌مون راحته؟ نه. هم‌تیمی هنوز می‌تونه بره توی history و همون مقدار رو پیدا کنه. secret چیزی نیست که فقط «یه جا قایمش کنیم»؛ از لحظهٔ ساخت تا تحویل، مصرف، چرخش و لغوش یه مسیر کامل داره.

A secret has a lifecycle: create, deliver, consume, rotate, revoke, and audit.

۱۸تمرینexercises

از فایل حذف شد؛ چرا هنوز پیداست؟Deleted from the file—why is it still visible?

رمز آزمایشی commit شد، بعد حذف و push شد؛ هم‌تیمی اون رو در Git history پیدا می‌کنه. حذف از درخت فعلی، commit قبلی رو پاک نمی‌کنه. فقط مقدار ساختگی می‌آزماییم؛ اگه اطلاعات دسترسی واقعی لو رفت، اول revoke/rotate کن. history rewrite پاک‌شدن clone، fork، artifact یا لاگ رو تضمین نمی‌کنه.

A test password was committed, then deleted and pushed; a teammate finds it in Git history. Removing it from the current tree does not erase the old commit. We use only fake values; if a real credential leaks, revoke/rotate it first. A history rewrite cannot guarantee removal from clones, forks, artifacts, or logs.

منبع مجاز تحویل می‌ده، runtime مصرف می‌کنه، rotation اعتبار رو تغییر می‌ده؛ Git بیرون مسیر می‌مونه.

An authorised source delivers, runtime consumes, and rotation changes validity; Git stays outside the path.

تنظیمات رو از secret جدا کنیمSeparate configuration from secrets

آدرس سرویس و سطح لاگ معمولاً تنظیمات هستن؛ password، token و private key راز‌اند. محیط variable راحت هست ولی ممکن هست در process inspection، crash dump و debug دیده بشه؛ env به‌تنهایی vault نیست. فایل mountشده می‌تونه دسترسی رو محدود کنه، اما permission و لاگ همچنان مهم‌اند. Compose secrets رو زیر /run/secrets/ به سرویس مجاز می‌ده؛ در local Compose فرض نکن فایل روی دیسک رمز هست.

Service addresses and log levels are usually configuration; passwords, tokens, and private keys are secrets. Environment variables are convenient but may appear in process inspection, crash dumps, and debugging; env alone is not a vault. A mounted file can narrow access, but permissions and logs still matter. Compose exposes secrets under /run/secrets/ to authorised services; do not assume local files are encrypted at rest.

یک مقدار ساختگی رو از Git history پیدا کنFind a fake value in Git history

فقط پوشهٔ تازه و دورریختنی بساز. مقدار واقعی نیست. پیش‌بینی کن بعد از حذف فایل diff چه می‌گه.

Use a fresh disposable directory only. The value is fake. Predict what the diff shows after removal.

مقدار در commit قبلی می‌مونه. مقدار واقعی رو افشاشده فرض کن و revoke کن؛ history remediation بعدی cloneها رو خودبه‌خود پاک نمی‌کنه. از این پس .env رو ignore کن و فقط placeholder بی‌خطر رو در .env.example بگذار.

The value remains in an earlier commit. Treat a real value as compromised and revoke it; history remediation does not clean clones automatically. Ignore .env and keep only harmless placeholders in .env.example.

app مقدار رو از /run/secrets/payment_token بخونه و فقط «secret loaded» چاپ کنه. _FILE قراردادی هست که بعضی imageها پشتیبانی می‌کنن، نه قابلیت خودکار هر app. فایل رو بیرون Git و با permission محدود بساز. git وضعیت، docker compose تنظیمات و لاگ رو بررسی کن؛ مقدار نباید چاپ بشه. این آزمایش encryption at rest رو ثابت نمی‌کنه.

Have the app read /run/secrets/payment_token and print only “secret loaded.” _FILE is a convention supported by some images, not an automatic feature in every app. Keep the file outside Git with restrictive permissions. Check git status, docker compose config, and logs; the value must not appear. This does not prove encryption at rest.

CI، Vault و ابزارهای KubernetesCI, Vault, and Kubernetes tools

CI secret store مقدار رو در سطح repository/محیط نگه می‌داره؛ workflow فقط با نیاز و مجوز کم بگیره. untrusted fork نباید secret production ببینه. auto-mask تضمین نیست؛ مقدار رو به image، artifact یا command line نریز.

A CI secret store keeps values at repository/environment scope; workflows receive them only when needed and authorised. Untrusted forks must not see production secrets. Auto-masking is not a guarantee; never put values in images, artifacts, or command lines.

در Vault، workload authenticate می‌شه، سیاست مسیر رو محدود می‌کنه و secrets engine مقدار رو می‌خونه، می‌سازه یا encrypt می‌کنه. Dynamic credentialها ممکن هست lease داشته باشن و renew/replacement بخواهند؛ KV مقدار ذخیره‌شده هست، نه لزوماً dynamic. اگه app rotation رو reload نکنه، تغییر در Vault کافی نیست.

In Vault, a workload authenticates, a policy limits paths, and a secrets engine reads, generates, or encrypts values. Dynamic credentials may have leases requiring renewal/replacement; KV stores a value and is not automatically dynamic. If the app cannot reload rotation, changing Vault alone is insufficient.

SOPS با KMS یا age فایل رو رمز می‌کنه تا ciphertext در Git باشه و decrypt key بیرون repo بمونه. Sealed Secrets و External Secrets گزینه‌های Kubernetesاند؛ controller ciphertext مقصددار رو باز می‌کنه یا provider خارجی رو sync می‌کنه. Secret runtime و RBAC حذف نمی‌شن؛ namespace و کلید controller همچنان مرز اعتمادند.

SOPS encrypts files with KMS or age so ciphertext can be versioned while decryption keys stay outside Git. Sealed Secrets and External Secrets are Kubernetes options; a controller unseals scoped ciphertext or syncs an external provider. Runtime secrets and RBAC remain; namespaces and controller keys are still trust boundaries.

Rotation تمام هست وقتی مقدار جدید در app کار می‌کنه و قبلی دیگر معتبر نیست. اگه overlap ممکن هست، هر دو رو کوتاه‌مدت بپذیر، مصرف نسخهٔ جدید رو verify و بعد قبلی رو revoke کن. Audit مسیر دسترسی رو ثبت کنه، نه خود مقدار رو.

Rotation is complete when the new value works in the app and the old one no longer does. If overlap is possible, accept both briefly, verify use of the new value, then revoke the old. Audit access paths, never the value.
