پروژهٔ ۱ — اولین خط لولهٔ CI

Project 1 — your first CI pipeline

این پروژه قرار نیست با حافظهٔ آدم‌ها کار کنه. هر push باید خودش بره توی یه محیط تمیز، dependencyها رو نصب کنه، lint و test رو اجرا کنه و آخرش یه جواب روشن بده: این commit از بررسی‌هایی که تعریف کردیم رد شده یا نه؟

Nobody should have to remember to run tests manually; every push should produce a clear signal.

۶۰دقیقهminutes
۵ایستگاهcheckpoints

مأموریت: علامت سبز باید معنی داشته باشهMission: green must mean something

یک API کوچک روی لپ‌تاپ شما کار می‌کنه. هم‌تیمی‌تان تغییر رو push می‌کنه، اما معلوم نیست تست اجرا شده یا نه. GitHub Actions رو طوری تنظیم کن که هر push باید بره توی یه محیط تمیز، dependencyهای قفل‌شده رو نصب کنه، lint و test رو اجرا کنه و اگه چیزی شکست، از توی لاگ بشه فهمید کجا و چرا.

A small API works on your laptop. A teammate pushes a change, but nobody knows whether tests ran. Configure GitHub Actions so every push installs locked dependencies in a clean environment, runs lint and tests, and exposes useful failure logs.

از پروژهٔ Node موجود استفاده کن؛ اگه نداری اپ کوچکی بساز که npm ci، npm run lint و npm test داشته باشه. هر سه رو محلی اجرا و lockfile رو commit کن. CI جای درست‌کردن برنامه نیست؛ همون بررسی‌ها رو در محیط تازه تکرار می‌کنه.

Use an existing Node project, or create a small app with npm ci, npm run lint, and npm test. Run them locally and commit the lockfile. CI does not fix the application; it repeats those checks in a fresh environment.

علامت سبز فقط وقتی مفید هست که همون commit و همون بررسی‌های موردنظر اجرا شده باشه.

A green status is useful only when the intended checks ran against the intended commit.

مرزهای پروژهProject boundaries

توکن یا فایل محلی رو commit نکن. نسخهٔ Node رو مشخص نگه دار و به lockfile تکیه کن. تست رو با continue-on-خطا یا شرطی که همیشه موفق هست بی‌اثر نکن. GitHub-hosted runner ماشین پاکی هست؛ چیزی که فقط روی لپ‌تاپ نصب هست آنجا نیست. نسخهٔ actionها و runner تغییر می‌کنه؛ نسخهٔ پشتیبانی‌شده رو از مخزن رسمی بررسی کن.

Do not commit tokens or local-only files. Pin Node and rely on the lockfile. Do not neutralize tests with continue-on-error or an always-successful condition. A hosted runner is clean; laptop-only tools are absent. Action and runner versions change, so verify supported releases in their official repositories.

پنج ایستگاه تا سبز قابل‌اعتمادFive checkpoints to trustworthy green

۱ — اجرای تمیز

در checkout تازه npm ci، lint و test رو اجرا کن. مدرک: خروجی‌ها و commit شامل package manifest و lockfile. اگه نصب شکست خورد، اختلاف lockfile و manifest رو بررسی کن.

In a clean checkout run npm ci, lint, and tests. Evidence: outputs and a commit with manifest and lockfile. If install fails, inspect manifest/lockfile consistency.

معیار پذیرش

هیچ وابستگی‌ای به ابزار global یا فایل untracked وجود ندارد؛ هر دستور محلی موفق است.

۲ — ساخت workflow

در .github/workflows/ci.yml روی push و pull request اجرا کن؛ checkout، نصب Node مشخص، npm ci، lint و test. لاگ job برای دیباگ کافیه؛ گزارش جدا رو فقط اگه پروژه تولید می‌کنه upload کن و مدت نگه‌داری محدود بگذار.

Create .github/workflows/ci.yml for push and pull requests; check out, set a Node version, then run npm ci, lint, and tests. Job logs are enough for debugging; upload a report only if generated and keep retention bounded.

راهنمای ساختار
name: CI
on: [push, pull_request]
jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm test

این اسکلت نمونه هست؛ نسخهٔ فعلی action و Node سازگار با برنامه‌ات رو از منابع رسمی انتخاب کن.

This is a structural example; select currently supported action and Node versions for your app.

۳ — سبز را ثابت کن

تغییر سالم push بده. ثابت کن trigger اجرا شده، SHA درست هست و لاگ نصب، lint و test سبز هست. اگه مجاز بودن، وضعیت check رو برای merge اجباری کن.

Push a known-good change. Prove the trigger ran for the right SHA and install, lint, and test logs passed. Require the check for merging if policy permits.

پاسخ

Run URL و SHA به‌همراه سه step موفق؛ badge به‌تنهایی ثابت نمی‌کند شاخه/commit درست بررسی شده.

۴ — شکست عمدی

یک assertion رو وارونه و push کن. run باید قرمز بشه و اسم تست/خطا رو در لاگ نشون بده. اگه سبز ماند، working directory، script واقعی و پنهان‌نشدن خطا رو بررسی کن؛ بعد کد خراب رو اصلاح و run تازه بگیر.

Invert one assertion and push. The run must fail and identify the test in logs. If green, inspect working directory, real test scripts, and swallowed errors; fix the code and run again.

ترمیم

run قرمز را نگه دار؛ برای SHA آزمایشی مدرک لازم است. پس از اصلاح، run سبز تازه بگیر.

۵ — خطای lint و handoff

یک خطای lint کنترل‌شده بساز، شکست رو ببین، اصلاح کن و موفقیت هر دو SHA رو ثبت کن. README بنویس که triggerها، check اجباری و محل لاگ رو معرفی کنه.

Introduce a controlled lint error, observe failure, fix it, and record both SHAs. Document triggers, required checks, and log location in README.

تعریف پایان

یک شکست قابل‌توضیح و یک اجرای سبز تازه؛ نه صرفاً PR ادغام‌شده.

راه‌حل مرجع و بازبینیReference solution and review

نمونهٔ workflow
name: CI
on:
  push:
  pull_request:
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm test

نسخهٔ actionها رو با مخزن رسمی و سیاست تیم بسنج. run مربوط به SHA رو باز کن؛ شکست تست و lint رو ثبت کن، تغییر عمدی رو بردار و run سبز تازه بگیر. نگه‌داری لاگ تابع سیاست مخزن هست؛ گزارش اضافی رو فقط اگه نیاز ذخیره کن.

Check action releases against official repositories and team policy. Open the run for the exact SHA; record failing test and lint runs, remove deliberate faults, and capture a fresh green run. Log retention follows repository policy; store extra reports only when useful.

pipeline سالم تضمین نمی‌کنه برنامه بی‌باگ هست؛ ثابت می‌کنه بررسی‌های تعریف‌شده روی این commit اجرا شدن. قدم بعد انتقال همون artifact به staging با تأیید مشخص هست.

A healthy pipeline does not prove the application is bug-free; it proves defined checks ran on this commit. Next, move the same artifact to staging behind an explicit approval.
