VPN چیست: مدل تونل

What a VPN is: the tunnel model

تفاوت بنیادی با پروکسی، در لایهٔ شبکه.

The fundamental difference from a proxy is the network layer.

۱۸تمرینexercises

برنامهٔ تازه‌ای نصب نکردی، ولی مسیر همه‌چیز عوض شدNo new app setting, yet the route changed

با proxy معمولاً برنامه یا سیستم می‌دانست یک درخواست مشخص را به کدام واسطه بدهد. VPN می‌تواند در سطح IP interface و route اضافه کند: kernel برای مقصدهای انتخاب‌شده packet را از مسیر tunnel می‌فرستد. بنابراین برنامه لازم نیست برای هر اتصال جداگانه proxy-aware باشد؛ اما این به معنی عبور خودکار «همهٔ ترافیک» نیست. route تعیین می‌کند کدام packet وارد tunnel شود.

With a proxy, an application or operating system typically knows which intermediary should receive a selected request. A VPN can add an IP interface and routes: the kernel sends packets for selected destinations through the tunnel. Applications need not be individually proxy-aware—but that does not mean all traffic automatically uses the tunnel. Routes decide which packets enter.

آدرس بیرونی مقصد tunnel با مقصد packet داخلی فرق دارد؛ تونل خودش هم باید از route قابل‌دسترسی استفاده کند.

The tunnel’s outer destination differs from the inner packet destination; the tunnel endpoint itself still needs a reachable route.

مدل دقیق به VPN بستگی دارد. در tunnel شبکه‌ای رمزگذار، packet داخلی به‌عنوان payload در packet بیرونی منتقل می‌شود؛ gateway سمت مقابل آن را decrypt و route می‌کند. TUN مجازی معمولاً IP packet می‌بیند، TAP Ethernet frame. روی Linux هر دو device می‌توانند packet/frame را میان kernel و برنامهٔ userspace جابه‌جا کنند؛ نیاز دسترسی و پیکربندی route جداست. Linux kernel: TUN/TAP

The exact model depends on the VPN. A network tunnel can carry an inner packet inside an outer packet; the peer decrypts and routes it. A TUN device works with IP packets; TAP with Ethernet frames. On Linux, both can pass packets/frames between kernel and userspace software, while permissions and routes remain separate concerns.

Proxy و VPN: هر دو route می‌دهند، اما در لایهٔ متفاوتProxy and VPN both redirect traffic, but at different layers

HTTP proxy می‌فهمد HTTP request, URL و header چیست. SOCKS5 مقصد socket را می‌گیرد و byte stream را relay می‌کند، ولی همچنان برنامه آن را انتخاب می‌کند. VPN شبکه‌ای به OS route/interface می‌دهد و می‌تواند packetهای چند برنامه را بگیرد. VPN الزاماً app traffic را می‌خواند؟ نه؛ encryption/VPN software معمولاً packetها را tunnel می‌کند، نه اینکه همهٔ protocolهای برنامه را parse کند.

An HTTP proxy understands HTTP requests, URLs, and headers. SOCKS5 accepts a socket destination and relays a byte stream, but the application still selects it. A network VPN installs or uses OS routes and an interface to carry packets from many applications. Does a VPN necessarily read app content? No: tunnel software typically transports packets rather than parsing each application protocol.

Route تصمیم می‌گیرد؛ «اتصال VPN» کافی نیستThe route decides; “VPN connected” is not enough

routeها با prefix مقصد سنجیده می‌شوند؛ معمولاً longest prefix match از route کم‌اختصاصی‌تر جلوتر است. split tunnel می‌تواند فقط شبکهٔ سازمان را به VPN بفرستد و اینترنت عمومی را مستقیم نگه دارد. full tunnel معمولاً default routeهای IPv4/IPv6 را از gateway VPN می‌گذراند. تنظیم فقط IPv4 می‌تواند IPv6 را بیرون tunnel باقی بگذارد. هر سیستم‌عامل/کلاینت ممکن است route policy و kill switch متفاوتی پیاده کند.

Routes are matched by destination prefix; the longest matching prefix generally beats a less-specific route. A split tunnel sends selected private networks through the VPN while public Internet traffic remains direct. A full tunnel typically sends IPv4/IPv6 default routes through the VPN gateway. Configuring only IPv4 may leave IPv6 outside the tunnel. Client and OS implementations can differ in route policy and kill-switch behavior.

در Linux، بدون تغییر هیچ route، ببین kernel برای یک آدرس نمونه چه تصمیمی می‌گیرد: ip route get 198.51.100.7. این بازهٔ TEST-NET-2 برای مستندات است؛ درخواست شبکه‌ای نمی‌فرستد، فقط lookup می‌کند. در خروجی دنبال dev و via بگرد. این تصمیم فعلی میزبان را ثابت می‌کند؛ نه وضعیت peer VPN یا رسیدن packet به اینترنت را.

On Linux, inspect the kernel’s current decision without changing routes: ip route get 198.51.100.7. That address belongs to documentation-only TEST-NET-2; the command performs a route lookup, not a network request. Read the dev and via fields. This proves the host’s current lookup decision—not VPN peer health or end-to-end reachability.

ip -6 route

خروجی واقعی به سیستم تو وابسته است. اگر Linux نداری، معادل route table را فقط مشاهده کن (Windows: `route print` یا `Get-NetRoute`). پیش از هر command تغییردهنده، مسیر فعلی و راه برگشت را ذخیره کن؛ این فصل route اضافه/حذف نمی‌کند.

Actual output depends on your host. On Windows, observe the equivalent with `route print` or `Get-NetRoute`. Before any route-changing command, preserve the existing route and rollback path; this chapter deliberately adds and removes no routes.

Full tunnel یا split tunnel؟Full tunnel or split tunnel?

این یک انتخاب عملیاتی است، نه درجه‌بندی امنیت. full tunnel مسیر بیشتری را از gateway عبور می‌دهد و خروجی عمومی ممکن است IP gateway باشد؛ ولی اگر DNS، IPv6 یا برنامه‌ای از policy مستثنا شود، leak هنوز ممکن است. split tunnel دسترسی به شبکهٔ مشخص را می‌دهد و بقیه را مستقیم می‌فرستد؛ routeها و DNS suffixها باید دقیق باشند. VPN provider نیز می‌تواند مقصدها و metadata خروجی را ببیند.

This is an operational choice, not a security score. Full tunnel sends more traffic through the gateway and may expose the gateway’s public egress IP—but DNS, IPv6, or excluded applications can still bypass policy. Split tunnel sends selected networks through the VPN and the rest directly; routes and DNS suffixes must be precise. The VPN provider may still observe destinations and egress metadata.

kill switch هم تضمین ذاتی VPN نیست؛ بعضی clientها firewall rule می‌سازند تا هنگام قطع tunnel، ترافیک انتخابی بیرون نرود. از app خودت بررسی کن دقیقاً چه route/firewall rule ایجاد می‌کند و IPv4/IPv6 را جدا بیازما. نام feature به‌تنهایی مدرک نیست.

A kill switch is not inherent to every VPN. Some clients add firewall rules to prevent selected traffic from escaping when the tunnel drops. Check what your client actually installs and test IPv4 and IPv6 separately. A feature label is not evidence.

TUN و TAP را در حد انتخاب interface بشناسKnow TUN and TAP as interface choices

TUN با IP packet کار می‌کند و برای خیلی از tunnelهای routed انتخاب طبیعی است. TAP با Ethernet frame کار می‌کند و برای bridge/L2 نیازهای خاص کاربرد دارد؛ broadcast، bridge و DHCP را هم وارد طراحی می‌کند. TAP «بهتر» یا «کامل‌تر» نیست؛ اگر فقط شبکهٔ IP می‌خواهی، انتقال Ethernet شاید سربار و پیچیدگی اضافه باشد. جزئیات driver در OS فرق دارد.

TUN works with IP packets and is a natural choice for many routed tunnels. TAP works with Ethernet frames and serves specific bridging/L2 needs, bringing broadcast, bridging, and DHCP concerns. TAP is not “better” or “more complete”; carrying Ethernet may add overhead and complexity when you only need IP routing. Driver behavior varies by OS.

خرابی عمدیِ مفهومی: endpoint را داخل تونل فرستادیDeliberate conceptual failure: you routed the endpoint into its own tunnel

VPN client برای نگه‌داشتن tunnel باید به public endpoint خودش packet بیرونی بفرستد. اگر route جدید باعث شود همین endpoint هم از داخل تونل route شود، بسته باید برای عبور از tunnel به همان tunnel برسد؛ recursion یا disconnect محتمل است. معمولاً client برای endpoint route استثنایی/host route نگه می‌دارد یا policy routing می‌سازد. این جزئیات implementation-specific است.

A VPN client must send outer packets to its public endpoint to keep the tunnel alive. If a new route also sends that endpoint through the tunnel, packets need the tunnel to reach the tunnel; recursion or disconnect can follow. Clients often preserve an endpoint exception/host route or use policy routing. The implementation is client-specific.

قبل از fix، route lookup برای endpoint واقعی را روی یک VM آزمایشی بررسی کن؛ دستور read-only ip route get VPN_ENDPOINT نشان می‌دهد خروجی از کدام `dev` می‌رود. اگر interface همان tunnel باشد، فرضیهٔ recursion قوت می‌گیرد؛ اما routing rules، mark و tables هم ممکن است تصمیم را عوض کنند—فقط `ip route` اصلی کافی نیست. در این فصل config را روی host روزمره خراب نکن و route جدید نزن.

Before fixing anything, inspect the route lookup for the real endpoint on a disposable VM. The read-only command ip route get VPN_ENDPOINT reveals the selected device. If it is the tunnel itself, recursion is plausible; policy rules, marks, and tables can also change the decision, so the main route table alone may be insufficient. Do not break your daily host or add routes in this chapter.

DNS خرابی جداگانه‌ای است: اگر endpoint hostname resolve نمی‌شود، ممکن است پیش از route lookup شکست بخوری؛ اگر route درست ولی DNS leak داری، tunnel برقرار است اما resolver از مسیر موردنظر نرفته. ترتیب را حفظ کن: DNS endpoint، route endpoint، handshake tunnel، route مقصد داخلی، DNS اپ. فصل DNS داخل tunnel این آخرین مرز را باز می‌کند.

DNS failure is a separate branch: if the endpoint hostname cannot resolve, failure may precede route lookup. If the route is correct but DNS leaks, the tunnel can be up while the resolver bypasses policy. Keep the sequence clear: endpoint DNS, endpoint route, tunnel handshake, inner destination route, application DNS. A later chapter handles DNS inside the tunnel.

مدرک را چهار بخش کن: route انتخابی؛ endpoint بیرونی؛ DNS resolver؛ و مقصد نهایی. این‌ها مستقل‌اند. اگر فقط interface up می‌بینی، هنوز ثابت نکرده‌ای packet به peer رسیده، DNS درست است یا برنامه به سرویس وصل شده.

Record four separate facts: selected route, outer endpoint, DNS resolver, and final destination. They are independent. An up interface alone proves neither peer reachability, correct DNS, nor application connectivity.

یک interface جدید، یک مرز اعتماد جدیدA new interface is a new trust boundary

proxy به برنامه کمک می‌کند یک اتصال منتخب را از واسطه بگیرد؛ VPN شبکه‌ای route را عوض می‌کند تا packetهای مطابق policy از tunnel رد شوند. TUN packetهای IP می‌بیند، TAP frameهای Ethernet. full/split tunnel، IPv6، DNS و route endpoint هر کدام مسیر جدا دارند. دیدن interface یا پیام «connected» فقط یک شاهد است، نه اثبات کل مسیر.

A proxy lets an application send selected connections through an intermediary; a network VPN changes routes so policy-selected packets enter a tunnel. TUN handles IP packets and TAP Ethernet frames. Full/split routing, IPv6, DNS, and the endpoint route are separate paths. An interface or “connected” message is evidence, not proof of the whole path.
