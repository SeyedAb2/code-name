# CodeNames — Proxy & VPN Editorial Report

این نسخه با فصل اول Git به‌عنوان مرجع صدا و ریتم بازنویسی شده.

## چیزی که عمداً تغییر کرد

- فارسی از لحن مستنداتی به لحن کلاس تبدیل شد: «می‌شود» → «می‌شه»، «می‌تواند» → «می‌تونه»، «اگر» → «اگه»، «را» → «رو» و شکل‌های مشابه.
- شروع هر ۱۷ فصل دوباره طراحی شد تا فصل با یک موقعیت، سؤال یا درد واقعی باز شود؛ نه با تعریف.
- اصطلاح‌های انگلیسی غیرفنی و تزئینی تا جای ممکن فارسی شدند. اصطلاح‌های واقعی شبکه مثل proxy، client، server، route، packet، TLS، handshake، peer، tunnel و interface حفظ شدند.
- فصل‌های عیب‌یابی مثل routing، DNS، performance و monitoring با منطق «شاهد جمع کن، بعد نتیجه بگیر» جلو می‌روند.
- سه پروژهٔ آخر به شکل مأموریت مهندسی حفظ شدند: هدف، مرز آزمایشگاه، شواهد، معیار پذیرش و تحویل.

## چیزی که عمداً تغییر نکرد

- متن انگلیسی.
- محتوای command/output داخل `<pre>`.
- ساختار کلی HTML و شناسه‌ها.
- معنی فنی سناریوها، مرزهای ایمنی و آزمایشگاه‌های محلی.

## شخصیت روایی فصل‌ها

01. Proxy — مسیر را دنبال کن، اسم را حفظ نکن.
02. HTTP proxy — دو مکالمهٔ HTTP و CONNECT را روی سیم ببین.
03. SOCKS — وقتی برنامه فقط مقصد می‌خواهد، نه فهم HTTP.
04. Build proxy — دو socket و دو جهت جریان را با دست بساز.
05. TLS — قفل دقیقاً تا کجا ادامه دارد؟
06. Chaining — هر hop یک اتصال و یک محل خرابی تازه.
07. VPN model — از برنامه به route و kernel تغییر مدل بده.
08. WireGuard — endpoint، tunnel IP و AllowedIPs را قاطی نکن.
09. OpenVPN — هویت قابل صدور/لغو را از route جدا کن.
10. Routing/NAT — tunnel سالم است؛ packet کجا گم شد؟
11. DNS — resolver و route به resolver دو سؤال جدا هستند.
12. Performance — «کند است» را به اندازه‌گیری تبدیل کن.
13. Monitoring — هر چراغ سبز فقط یک ادعای کوچک را ثابت می‌کند.
14. Hardening — از «چه چیزی کار می‌کند» به «چه کسی نباید بتواند» برو.
15. Project 1 — یک HTTP proxy محدود و قابل اثبات بساز.
16. Project 2 — چند peer، route و DNS با شواهد مستقل.
17. Project 3 — gateway کامل آزمایشگاهی با tunnel، proxy، firewall، DNS و پایش.

## پاس انتهایی

فایل‌ها از انتها به ابتدا هم بررسی شدند تا لحن تمرین‌ها، پاسخ‌ها و پروژه‌ها به لحن خشک documentation برنگردد.
