۱۸تمرینexercises

interface بالا است، ولی کاربر می‌گوید دسترسی نداردThe interface is up, but a user cannot reach the service

`ip link` می‌گوید wg0 UP است. آیا peer handshaked؟ counterها جلو می‌روند؟ route به مقصد درست است؟ سرویس مقصد پاسخ می‌دهد؟ هر کدام شاهد دیگری است. پایش مفید این‌ها را کنار هم می‌گذارد—نه اینکه یک چراغ سبز را به معنی «همه‌چیز سالم است» جا بزند.

`ip link` says wg0 is UP. Has a peer handshaked? Are counters moving? Does the route select the intended interface? Does the service respond? Each is different evidence. Useful monitoring puts them together instead of treating one green light as “everything works.”

برای VPN، metadata عملیاتی مثل زمان handshake، bytes، restart و endpoint می‌تواند برای عیب‌یابی لازم باشد؛ payload کاربر را logکردن معمولاً لازم نیست و privacy risk می‌سازد. قبل از افزودن collector بپرس چه سؤال عملیاتی را جواب می‌دهد و چه داده‌ای را واقعاً باید نگه دارد.

VPN operational metadata—handshake time, byte counters, restarts, endpoint—can aid troubleshooting; logging user payload usually is unnecessary and creates privacy risk. Before adding a collector, define the operational question and the minimum data that must be retained.

link، peer، route و سرویس را جدا پایش کن؛ payload خصوصی را وارد log نکن.

Monitor link, peer, route, and service separately; keep private payload out of logs.

WireGuard: handshake عمر و counter، نه «کاربر آنلاین»WireGuard: handshake age and counters, not “user online”

`wg show wg0` peer endpoint، latest handshake، transfer counters و AllowedIPs را می‌دهد. `latest handshake` تازه نشان می‌دهد peer اخیراً با این کلید دادهٔ معتبر ردوبدل کرده؛ اگر idle است ممکن است handshake قدیمی یا صفر باشد، بی‌آنکه user حتماً قطع باشد. bytes صعودی یعنی تبادل WireGuard رخ داده، نه موفقیت application.

`wg show wg0` reports peer endpoints, latest handshake, transfer counters, and AllowedIPs. A recent handshake means authenticated traffic was exchanged recently; an idle peer may have an old or zero handshake without proving a user is disconnected. Rising bytes prove WireGuard traffic, not application success.

sudo wg show wg0
ip -s link show dev wg0
ip route get REMOTE_SERVICE_IP

`ip -s link` آمار interface network را نشان می‌دهد؛ drop/error هم می‌تواند نشانه بدهد. route lookup می‌گوید kernel مقصد را از کدام dev می‌فرستد. این‌ها را با service probe جفت کن—مثلاً ping اگر مجاز است یا TCP port check. ICMP خاموش ممکن است ping را fail کند درحالی‌که application زنده است.

`ip -s link` reports interface packets, errors, and drops. Route lookup shows the kernel-selected device. Pair these with a service probe—ping if permitted or a TCP port check. Blocked ICMP can make ping fail while the application works.

یک گزارش کوچک و فقط‌خواندنی بسازBuild a small, read-only report

در lab یک health snapshot می‌خواهیم: link، handshake age به‌صورت aggregate، bytes aggregate، route و reachability. این script key خام و payload چاپ نمی‌کند؛ public keyها هم در report عمداً پنهان‌اند. آدرس مقصد را با service test خودت عوض کن. Ping failure را WARN می‌نامیم، نه اینکه VPN interface را down اعلام کنیم.

In the lab, capture link, aggregate handshake age, aggregate bytes, route, and reachability. This script prints neither raw keys nor payload; even public keys are omitted from the report. Substitute your test service address. A failed ping is reported as a warning, not as proof the VPN interface is down.

#!/usr/bin/env bash
set -u
IFACE="${1:-wg0}"
CHECK_IP="${2:-10.77.0.2}"
NOW="$(date +%s)"

if ! ip link show dev "$IFACE" >/dev/null 2>&1; then
  echo "link=missing interface=$IFACE"; exit 1
fi
ip -brief link show dev "$IFACE"

wg show "$IFACE" latest-handshakes |
  awk -v now="$NOW" '{
    peers++;
    if ($2 == 0) never++;
    else { age=now-$2; if (age > 180) stale++; }
  } END {
    printf "peers=%d never=%d older_than_180s=%d\n", peers, never, stale
  }'

wg show "$IFACE" transfer |
  awk '{rx+=$2; tx+=$3; peers++} END {
    printf "peers=%d rx_bytes=%d tx_bytes=%d\n", peers, rx, tx
  }'

ip route get "$CHECK_IP" || true
if ping -c 1 -W 1 "$CHECK_IP" >/dev/null 2>&1; then
  echo "icmp_probe=ok"
else
  echo "icmp_probe=failed_or_filtered"
fi

عدد 180 فقط threshold آزمایش است؛ keepalive و traffic profile را معیار واقعی کن. script به Bash/Linux tools و دسترسی wg نیاز دارد؛ Windows/macOS معادل جدا دارند. خروجی aggregate برای trend است، نه alert کامل و نه نسبت‌دادن bytes به یک آدم. اگر report را هر دقیقه به journal بفرستی، retention و دسترسی log را محدود کن.

180 seconds is only a lab threshold; choose one based on keepalive and traffic patterns. The script assumes Bash/Linux tools and permission to inspect wg; Windows/macOS need different tooling. Aggregates help trends but are not a complete alert or user attribution. If you run it every minute and send output to a journal, restrict retention and log access.

systemd journal و OpenVPN status را با context بخوانRead the systemd journal and OpenVPN status in context

اگر WireGuard با wg-quick service بالا آمده، unit name معمولاً شامل interface است؛ ابتدا `systemctl list-units '*wg-quick*'` را ببین، بعد همان unit را query کن. مثال زیر ممکن است با distro فرق کند:

If WireGuard was started via wg-quick, the unit commonly includes the interface name. First list matching units, then query the actual one. Names vary by distribution:

systemctl list-units '*wg-quick*'
journalctl -u wg-quick@wg0 --since "1 hour ago" --no-pager

WireGuard protocol عمداً کم‌حرف است؛ log خالی به معنی packet سالم نیست. `wg show` و counters اصلی‌ترند. OpenVPN foreground log یا systemd unit log می‌دهد؛ status file هم با directive و interval قابل تنظیم است، اما path/service name بسته به package فرق می‌کند. از log line برای TLS/auth error و restart زمان‌مند کمک بگیر و آن را با route/capture correlate کن.

WireGuard is intentionally quiet; an empty log does not prove packets are healthy. `wg show` and counters are primary signals. OpenVPN can log in foreground or through systemd; a status file can be configured with an interval, but paths and unit names vary by package. Use logs for TLS/auth errors and restarts, then correlate them with routes and captures.

journalctl -u openvpn-server@lab --since "30 minutes ago" --no-pager
sudo openvpn --config client.conf --verb 3

فرمان unit اول نمونه است؛ نام واقعی را از `systemctl list-units '*openvpn*'` پیدا کن. `verb` بالا ممکن است اطلاعات حساس/زیاد بنویسد؛ فقط موقت روی lab فعال کن. status file فرمت و فاصلهٔ update دارد؛ در parser نسخهٔ خودت را بررسی کن.

The unit name is illustrative; find the actual one with `systemctl list-units '*openvpn*'`. Higher verbosity can expose more data and volume; use it temporarily in the lab. Status-file format and update interval vary; check your version before parsing it.

خرابی عمدی: interface UP، peer staleDeliberate failure: interface UP, peer stale

VM-B را خاموش یا UDP port را در firewall lab ببند، ولی wg0 را روی client دست‌نخورده نگه دار. `ip link` هنوز UP می‌گوید؛ handshake age رشد می‌کند و counters دیگر جلو نمی‌روند. `ip route get` ممکن است همچنان wg0 را انتخاب کند. حالا یک probe بزن و log/error را ثبت کن. این سناریو ثابت می‌کند administrative link state با reachability peer یکی نیست.

Stop VM-B or block its UDP port in the lab firewall while leaving the client’s wg0 untouched. `ip link` may still say UP; handshake age grows and counters stop increasing. Route lookup may still select wg0. Run a probe and capture errors/logs. This demonstrates that administrative link state is not peer reachability.

بعد firewall lab را به حالت قبلی برگردان؛ handshake را با traffic بی‌خطر trigger کن و همان snapshot/probe را دوباره بگیر. اگر peer در محیط سالم idle می‌ماند، stale threshold را با expected keepalive و traffic تعریف کن—نه یک عدد ثابت برای همه.

Restore the lab firewall, trigger a handshake with harmless traffic, and rerun the same snapshot/probe. If a healthy peer is idle, define the stale threshold from expected keepalive and traffic—not one universal number.

خرابی کم‌صداتر: logها دیسک را پر می‌کنندA quieter incident: logs fill the disk

debug verbosity را برای همیشه روشن گذاشتی، journal یا status log رشد می‌کند و disk پر می‌شود. دوره‌ای `df -h`, `df -i` و حجم journal/log directory را ببین؛ inode هم می‌تواند تمام شود. retention را در journald/logrotate یا logging platform همین host تنظیم کن، ولی فایل فعال را دستی پاک نکن و مقدار را حدس نزن. disk-full روی همان host می‌تواند tunnel config، DNS و system serviceهای دیگر را هم مختل کند.

Verbose debug stays on, journals/status logs grow, and the disk fills. Periodically inspect `df -h`, `df -i`, and journal/log-directory size; inodes can run out too. Set retention through journald/logrotate or the host’s logging system. Do not manually truncate active files or guess at a deletion. A full disk can also break tunnel config, DNS, and unrelated system services.

df -h
df -i
journalctl --disk-usage
sudo journalctl --vacuum-time=14d

vacuum command destructive است و بخشی از journal قدیمی را حذف می‌کند؛ اول retention need و disk usage را بسنج و فقط روی lab اجرا کن. برای production از policy مرکزی/تأییدشده پیروی کن، log لازم incident را export کن و بعد cleanup کن. «حذف همهٔ لاگ‌ها» default fix نیست.

The vacuum command deletes older journal entries; assess retention needs and disk usage first and use it only in a lab here. In production, follow approved policy, preserve incident-relevant logs, and then clean up. “Delete all logs” is not the default fix.

پایش به معنی زیرنظرگرفتن payload نیستMonitoring does not mean inspecting payload

handshake age، packet count، byte volume و exit status معمولاً برای availability کافی‌اند. public key و endpoint هم گرچه secret نیستند، می‌توانند دستگاه/مکان را link کنند. log identity را pseudonymize کن، دسترسی و retention را محدود و clockها را همگام کن. payload capture را فقط با مجوز، scope و مدت مشخص برای تشخیص انجام بده؛ capture را پس از حل incident نگه ندار مگر policy می‌گوید.

Handshake age, packet/byte volume, and exit status are often enough for availability. Public keys/endpoints are not private keys, but can still link a device or location. Pseudonymize identifiers, restrict access/retention, and synchronize clocks. Capture payload only with authorization, scope, and duration; do not keep it after diagnosis unless policy requires it.

lab: یک صفحهٔ وضعیت، نه یک پلتفرم تازهLab: a status snapshot, not a new monitoring platform

روی peerهای lab script بخش قبل را اجرا و خروجی هر دقیقه را برای چند دقیقه بگیر. یک بار peer را خاموش کن؛ بعد firewall را برگردان. جدول دستی بساز: timestamp، link، freshest handshake، rx/tx delta، route dev، ICMP/service probe، restart/log event. delta مهم است: total bytes می‌تواند بزرگ بماند حتی اگر peer الان قطع باشد.

Run the prior script on the lab peer once per minute for a few minutes. Stop the peer, then restore its firewall. Build a small table: timestamp, link, newest handshake, rx/tx delta, route device, ICMP/service probe, and restart/log event. Deltas matter: total bytes remain large even while the peer is currently down.

پیش از shareکردن جدول، endpoint/keyها و نام‌های private را حذف یا pseudonymize کن. دادهٔ capture‌شده را بعد از تمرین پاک کن و confirm کن report هیچ payload یا private key نداشته باشد. این lab health snapshot است، نه alerting production؛ threshold و notification باید false positive و on-call context را هم بسنجند.

Before sharing, remove or pseudonymize endpoints, keys, and private names. Delete captures after the exercise and confirm the report contains no payload or private key. This is a health snapshot, not production alerting; thresholds and notifications need false-positive and on-call context.

هر سبزی، یک ادعای کوچکEvery green light proves only a small claim

link UP یعنی interface فعال است؛ handshake age یعنی peer اخیراً packet معتبر ردوبدل کرده؛ counter delta یعنی bytes جابه‌جا شده؛ route lookup یعنی kernel کدام راه را انتخاب می‌کند؛ probe یعنی endpoint مشخصی جواب داد. این‌ها را کنار هم بچین تا تشخیص بسازی. logها را کمینه، امن و با retention روشن نگه دار؛ metadata هم می‌تواند حساس باشد و disk هم محدود است.

Link UP means the interface is active; handshake age means a peer recently exchanged authenticated packets; counter deltas mean bytes moved; route lookup shows the kernel’s path; a probe shows one endpoint answered. Combine them to diagnose. Keep logs minimal, protected, and retained deliberately; metadata can be sensitive and disk is finite.
