عملگرهای مجموعه‌ای؛ UNION، INTERSECT و EXCEPT

Set operators: UNION, INTERSECT, and EXCEPT

سامانهٔ قدیمی و سامانهٔ جدید هرکدوم فهرست مشتری دارن. تیم می‌خواد همه رو در یک خروجی ببیند، فقط اشتراک رو پیدا کند یا رکوردهایی رو که هنوز مهاجرت نشده‌اند جدا کند. این‌ها JOIN نیستند: خروجی دو query هم‌شکل رو روی هم می‌گذاریم و بعد دربارهٔ duplicateها تصمیم می‌گیریم.

The old and new systems each have a customer list. The team needs a combined list, the intersection, or records not yet migrated. These are not joins: we combine the outputs of compatible queries and then decide how duplicates should behave.

گزارش وقتی جدی می‌شه که فقط «لیست» نباشهA report becomes serious when it is more than a list

تا اینجا گرفتن چند ردیف آسون بود. درد واقعی وقتی شروع می‌شه که یکی می‌گه «فروش هر شهر رو بده، نسبت به ماه قبل مقایسه کن، فقط شهرهای بالای فلان عدد رو نگه دار و رتبه هم بده». «عملگرهای مجموعه‌ای؛ UNION، INTERSECT و EXCEPT» رو برای همین جنس سؤال‌ها می‌خوایم. قدم‌به‌قدم می‌ریم جلو تا query هم درست باشه، هم بشه فهمید چرا درست کار می‌کنه.

Selecting rows is the easy part. Real reporting starts when someone asks for sales by city, a comparison with last month, a threshold, and a rank. “Set operators: UNION, INTERSECT, and EXCEPT” belongs to that kind of problem. We build the query step by step so it is not only correct but explainable.

قرارمون توی این فصلOur rule for this chapter

هرجا query یا command می‌زنیم، همون‌جا می‌گیم چرا زدیمش، کدوم قسمت خروجی مهمه و اگه نتیجه فرق داشت اول چی رو چک کنی. قرار نیست چیزی رو فقط چون «معمولاً این‌طوریه» قبول کنیم.

Whenever we run a query or command, we state why, identify the important evidence, and say what to check first if the result differs. We do not accept behaviour merely because it is “usually like that.”

ستون‌ها روی هم میان، نه کنار هم / Stack columns vertically, do not join them side by side

UNION ALL نتیجهٔ query دوم رو زیر نتیجهٔ اول می‌ذاره. هر دو SELECT باید تعداد ستون برابر داشته باشند و ستون‌های هم‌موقعیت باید از نظر نوع داده سازگار باشند. اسم ستون خروجی از query اول میاد؛ aliasهای query دوم نام جدیدی برای همان موقعیت نمی‌سازند.

UNION ALL appends the second query’s rows beneath the first. Both SELECTs need the same number of columns, and corresponding positions need compatible data types. Output column names come from the first query; aliases in the second do not rename that position.

این تکه کد رو فقط کپی نکن. اول برای خودت بگو اگه مدل ذهنی‌مون درست باشه چه چیزی باید ببینیم، بعد اجراش کن.

Do not just copy this block. First state what you expect to observe if the mental model is correct, then run it.

فهرست دو منبع، با برچسب منبع / Combine two sources with a source label
SELECT CustomerId, FullName, N'Shop customer' AS SourceName
FROM shop.Customers
UNION ALL
SELECT CustomerId, FullName, N'Order customer' AS SourceName
FROM shop.Orders AS o
JOIN shop.Customers AS c ON c.CustomerId=o.CustomerId
ORDER BY CustomerId, SourceName;
GO

چیزی که باید از این مثال نگه داری اسم دستور نیست؛ رابطهٔ بین ورودی، خروجی و مدلیه که داریم می‌سازیم.

The thing to keep from this example is not the command name but the relationship between input, output, and the model we are building.

توی این مثال مشتری ممکنه به تعداد سفارش‌هایش چند بار بیاید، چون UNION ALL duplicate رو حفظ می‌کنه. ترتیب سطرها هم فقط با ORDER BY نهایی تعیین می‌شه؛ ORDER BY در هر شاخه معمولاً برای قرارداد خروجی مجموعه‌ای نیست.

A customer may appear once per order here because UNION ALL preserves duplicates. Final row order comes only from the outer ORDER BY; branch ordering is not the set result’s ordering contract.

UNION duplicateها رو حذف می‌کنه؛ UNION ALL حفظشان می‌کنه / UNION removes duplicates; UNION ALL preserves them

اگه دو query مقدارهای کاملاً یکسان در تمام ستون‌های انتخابی بدهند، UNION آن ردیف تکراری رو حذف می‌کنه. UNION ALL همه رو نگه می‌داره و معمولاً وقتی duplicate مجاز است، قصد رو صریح می‌کنه. حذف duplicate هزینه هم داره؛ اون رو صرفاً برای تمیز به‌نظررسیدن نتیجه انتخاب نکن.

If both queries produce rows equal in every selected column, UNION removes duplicate result rows. UNION ALL keeps all rows and states intent when duplicates are meaningful. Duplicate elimination also costs work; do not choose it merely to make output look tidy.

اینجا هدف خود دستور نیست؛ داریم باهاش یک ادعا رو امتحان می‌کنیم. قبل از Run، نتیجهٔ مورد انتظار رو توی یک جمله بگو.

The command is not the point; it is an experiment. Before Run, state the expected observation in one sentence.

مقایسه روی دادهٔ موقت قابل‌پیش‌بینی / Compare on a predictable temporary fixture
DROP TABLE IF EXISTS #Legacy,#Current;
CREATE TABLE #Legacy (CustomerId int, City nvarchar(30));
CREATE TABLE #Current (CustomerId int, City nvarchar(30));
INSERT #Legacy VALUES (1,N'تهران'),(2,N'شیراز');
INSERT #Current VALUES (2,N'شیراز'),(3,N'تبریز');

SELECT CustomerId,City FROM #Legacy
UNION ALL
SELECT CustomerId,City FROM #Current;
GO

SELECT CustomerId,City FROM #Legacy
UNION
SELECT CustomerId,City FROM #Current;
GO

اگه خروجی سیستم تو فرق داشت، سریع نتیجه نگیر که فصل غلطه. اول نسخه، دادهٔ تمرینی، database جاری و session رو چک کن؛ بعد سراغ فرضیهٔ بعدی برو.

If your output differs, do not jump to a conclusion. Check version, fixture, current database, and session state before changing the hypothesis.

در UNION ALL چهار ردیف داریم؛ UNION ردیف کاملاً تکراری `(2, شیراز)` رو یکی می‌کنه. اگه CustomerId یکی باشه اما City فرق کند، چون کل row متفاوت هست هر دو می‌مانند. اگه قصد deduplicate بر اساس CustomerId است، باید قاعدهٔ انتخاب رکورد برنده رو جدا تعریف کنی.

UNION ALL returns four rows; UNION collapses the identical `(2, Shiraz)` row. If CustomerId matches but City differs, both rows remain because the complete rows differ. If deduplication is by CustomerId, define a winner rule separately.

INTERSECT اشتراک است؛ EXCEPT تفاضل سمت چپ از راست / INTERSECT finds overlap; EXCEPT subtracts right from left

INTERSECT مقدارهای موجود در هر دو نتیجه رو می‌ده و duplicateهای خروجی رو حذف می‌کنه. `A EXCEPT B` فقط مقدارهایی رو می‌ده که در A هستن و در B نیستند. جهت مهمه؛ جای دو SELECT رو عوض کنی نتیجهٔ تفاضل عوض می‌شه.

INTERSECT returns values present in both results and removes duplicates. `A EXCEPT B` returns values in A but not B. Direction matters: swapping the SELECTs reverses the difference.

مقایسهٔ دو فهرست مشتری / Compare two customer lists
SELECT CustomerId,City FROM #Legacy
INTERSECT
SELECT CustomerId,City FROM #Current;
GO

SELECT CustomerId,City FROM #Legacy
EXCEPT
SELECT CustomerId,City FROM #Current;
GO

INTERSECT و EXCEPT روی تمام ستون‌های هم‌موقعیت مقایسه می‌کنن؛ اگه فقط شناسه مهمه، فقط شناسه رو انتخاب کن. این عملگرها duplicateها رو حذف می‌کنن و مقایسه‌شان با NULL قواعد set operator داره؛ اون رو با `=` در predicate یکی نگیر.

INTERSECT and EXCEPT compare every corresponding selected column; select only the ID if that is the intended key. These operators eliminate duplicates and treat NULL according to set-operator semantics, not ordinary `=` predicate behavior.

دو query باید از نظر شکل قابل‌ترکیب باشند / Both queries must have compatible shapes

تعداد ستون‌ها باید برابر باشه و نوع‌های متناظر باید قابل تبدیل ضمنی باشند. ستون اول با ستون اول مقایسه می‌شه، نه براساس نام. اگه یکی int و دیگری متن است، تبدیل صریح و معنایی لازم رو انجام بده؛ به precedence ضمنی تکیه نکن. اسم و ترتیب ستون‌های خروجی رو در شاخهٔ اول طراحی کن.

Column counts must match and corresponding types must be implicitly compatible. Position one compares to position one, not by name. If one side is numeric and the other text, perform an explicit, meaningful conversion instead of relying on implicit precedence. Design output names and order in the first branch.

ستون‌ها رو هم‌موقعیت و هم‌معنا نگه دار / Align columns by position and meaning
SELECT CustomerId AS EntityId, FullName AS DisplayName
FROM shop.Customers
UNION ALL
SELECT CustomerId, FullName
FROM shop.Orders AS o
JOIN shop.Customers AS c ON c.CustomerId=o.CustomerId;
GO

aliasهای SELECT اول نام خروجی رو مشخص می‌کنه. اگه ترتیب دو ستون رو در شاخهٔ دوم برعکس کنی، ممکنه خطای نوع بگیری یا تبدیل نامناسبی رخ دهد؛ شکل query رو قبل از اجرا بررسی کن.

Aliases from the first SELECT define output names. Reversing columns in the second branch may cause an error or an unintended conversion; inspect shape before execution.

سه عملگر، سه سؤال دربارهٔ دو خروجی / Three operators, three questions about two results

پیکان‌ها دو نتیجه shape هم‌ساز رو نشان می‌دهند. عملگر، ردیف‌ها رو کنار هم می‌چیند؛ JOIN ستون‌ها رو از رابطهٔ دو جدول کنار هم می‌آورد.

The arrows represent compatible result shapes. A set operator combines rows; JOIN combines columns through a relationship.

قبل از انتخاب set operator / Before choosing a set operator

بپرس: همهٔ ردیف‌ها رو با duplicate می‌خواهم؟ اشتراک؟ یا فقط سمت چپ؟ بعد ستون‌های هر شاخه رو از نظر تعداد، ترتیب و type بررسی کن. اگه duplicate رو حذف می‌کنی، مشخص کن برابری روی کدوم ستون‌هاست؛ UNION کل row انتخاب‌شده رو مقایسه می‌کنه، نه یک کلید پنهان.

Ask: do I need every row including duplicates, the intersection, or only the left-side difference? Then verify each branch’s column count, position, and types. If removing duplicates, state which selected columns define equality; UNION compares the projected row, not a hidden key.

  • UNION ALL: append and preserve duplicates.
  • UNION: append and deduplicate complete rows.
  • INTERSECT: rows present in both.
  • EXCEPT: left rows absent from right.
  • ORDER BY نهایی برای ترتیب خروجی.
