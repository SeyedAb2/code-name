اتصال برنامه به SQL Server

Application integration with SQL Server

query در SSMS درسته، اما endpoint برنامه خطا می‌ده یا نتیجهٔ تکراری می‌سازه. تفاوت فقط connection string نیست: type mapping، transaction، timeout، principal و رفتار retry بخشی از قراردادند.

A query works in SSMS, but the application endpoint fails or duplicates results. Integration is more than a connection string: type mapping, transactions, timeouts, identity, and retries are part of the contract.

مشکل همیشه خود SQL نیستThe database is not always the problem

ممکنه query خوب باشه و SQL Server هم سالم باشه، ولی برنامه هنوز کند یا ناپایدار باشه. pool، timeout، retry، ORM و migration بین اپ و دیتابیس رفتار واقعی سیستم رو می‌سازن. توی «اتصال برنامه به SQL Server» از هر دو طرف نگاه می‌کنیم: هم SQL Server چی می‌بینه، هم اپ چه چیزی فکر می‌کنه اتفاق افتاده.

The query may be fine and SQL Server healthy while the application is still slow or fragile. Pools, timeouts, retries, ORMs, and migrations shape the real system between app and database. In “Application integration with SQL Server” we observe both sides: what SQL Server sees and what the application believes happened.

قرارمون توی این فصلOur rule for this chapter

هرجا query یا command می‌زنیم، همون‌جا می‌گیم چرا زدیمش، کدوم قسمت خروجی مهمه و اگه نتیجه فرق داشت اول چی رو چک کنی. قرار نیست چیزی رو فقط چون «معمولاً این‌طوریه» قبول کنیم.

Whenever we run a query or command, we state why, identify the important evidence, and say what to check first if the result differs. We do not accept behaviour merely because it is “usually like that.”

برنامه و دیتابیس دو process مستقل‌اند / The app and database are separate processes

connection string رو از source خارج کن، secret رو امن تزریق کن و connection رو با driver پشتیبانی‌شده بساز. مقدارها parameter باشند؛ query text رو با input نچسبان. TCP/TLS، authentication و database permission هرکدوم مرحلهٔ جدا دارن.

Keep connection strings out of source, inject secrets safely, and use a supported driver. Pass values as parameters rather than concatenating query text. TCP/TLS, authentication, and database permissions are separate stages.

این تکه کد رو فقط کپی نکن. اول برای خودت بگو اگه مدل ذهنی‌مون درست باشه چه چیزی باید ببینیم، بعد اجراش کن.

Do not just copy this block. First state what you expect to observe if the mental model is correct, then run it.

الگوی query parameterized / Parameterized query pattern
-- Application driver should bind @CustomerId as an integer parameter.
SELECT OrderId,OrderDate,TotalAmount
FROM dbo.Orders
WHERE CustomerId=@CustomerId
ORDER BY OrderDate DESC,OrderId DESC;

چیزی که باید از این مثال نگه داری اسم دستور نیست؛ رابطهٔ بین ورودی، خروجی و مدلیه که داریم می‌سازیم.

The thing to keep from this example is not the command name but the relationship between input, output, and the model we are building.

timeout، commit و retry رو از هم جدا کن / Separate timeout, commit, and retry

timeout client ثابت نمی‌کنه query یا transaction روی server لغو شده. اگه response بعد از commit گم بشه، caller نمی‌دونه عملیات انجام شده یا نه؛ idempotency key یا قرارداد قابل‌استعلام طراحی کن. retry رو محدود و فقط برای خطای گذرا اجرا کن؛ transaction رو کوتاه نگه دار.

A client timeout does not prove the server query/transaction was canceled. If the response is lost after commit, the caller may not know whether the operation happened; design an idempotency key or queryable contract. Bound retries to transient failures and keep transactions short.

type و نتیجه بخشی از API هستن / Types and results are part of the API

decimal precision/scale، NULLability، datetime zone و Unicode رو بین application و SQL هماهنگ کن. همهٔ ردیف‌ها رو بی‌دلیل materialize نکن؛ pagination و batch size داشته باش. سلامت query کم‌هزینه باشه و database load واقعی رو شبیه‌سازی نکند.

Align decimal precision/scale, nullability, time-zone semantics, and Unicode across app and SQL. Avoid unbounded materialization; paginate and bound batches. A health query should be cheap and not mimic full production load.

با همان identity برنامه تست کن / Test with the application's identity

SSMS admin موفقیت برنامه رو ثابت نمی‌کنه. تست integration باید با app principal محدود اجرا بشه، TLS hostname validation فعال باشه و خطاها بدون secret log شوند. connection pooling به‌معنی connection فیزیکی دائمی برای هر درخواست نیست؛ transaction/زمینه session رو درست reset کن.

An admin SSMS session does not prove application success. Integration tests should use the app's limited principal, validate TLS hostname, and log errors without secrets. Pooling does not mean one permanent physical connection per request; reset session state/context correctly.
