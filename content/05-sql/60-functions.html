Functionهای T-SQL و مرز استفاده

T-SQL functions and their boundaries

تابعی برای مالیات نوشته‌اند؛ گزارش بزرگ کند شده. function بد نیست، اما جای استفاده و نسخهٔ SQL Server مهمه. با query و plan تصمیم می‌گیریم، نه با قانون «function همیشه کند هست».

A tax function slowed a large report. Functions are not inherently bad, but usage and SQL Server version matter. We choose by query and plan, not by the myth that every function is slow.

وقتی منطق رو می‌بری داخل دیتابیس، باید دلیل داشته باشیIf logic moves into the database, have a reason

یه stored procedure یا trigger می‌تونه کار رو خیلی تمیز کنه؛ همون ابزار می‌تونه شش ماه بعد تبدیل بشه به چیزی که هیچ‌کس نمی‌دونه از کجا اجرا شده. توی «Functionهای T-SQL و مرز استفاده» فقط syntax نمی‌زنیم. می‌سنجیم این منطق چرا باید داخل SQL Server باشه، چطور خطاش رو می‌بینیم و چطور مطمئن می‌شیم رفتار پنهان درست نکردیم.

A stored procedure or trigger can make a design cleaner, and the same feature can become mysterious hidden behaviour six months later. In “T-SQL functions and their boundaries” we go beyond syntax: why should this logic live in SQL Server, how do we observe failures, and how do we avoid invisible side effects?

قرارمون توی این فصلOur rule for this chapter

هرجا query یا command می‌زنیم، همون‌جا می‌گیم چرا زدیمش، کدوم قسمت خروجی مهمه و اگه نتیجه فرق داشت اول چی رو چک کنی. قرار نیست چیزی رو فقط چون «معمولاً این‌طوریه» قبول کنیم.

Whenever we run a query or command, we state why, identify the important evidence, and say what to check first if the result differs. We do not accept behaviour merely because it is “usually like that.”

function مقدار یا relation می‌ده / A function returns a value or relation

scalar function یک مقدار می‌ده. inline table-valued function یک relation برمی‌گردونه که optimizer اغلب می‌تونه با query مصرف‌کننده ترکیب کند. multi-statement TVF نتیجه رو در ساختاری جدا می‌سازه و تخمین/plan متفاوتی داره. procedure برای عملیات و چند خروجی مناسب است؛ جایگزین عمومی function نیست.

A scalar function returns one value. An inline TVF returns a relation the optimizer can often combine with its caller. A multi-statement TVF builds a separate result structure and may have different estimates and plans. Procedures suit operations and multiple result sets; neither is a universal replacement for the other.

قبل از اجرا یه حدس بزن: از خروجی این مثال دقیقاً دنبال چه نشونه‌ای هستی؟ عدد دقیق لازم نیست؛ فقط معلوم کن چی قراره ادعای این بخش رو تأیید یا رد کنه.

Before running this, predict what evidence you expect from the output. You do not need the exact value; decide what would support or reject the claim in this section.

inline TVF در FROM / Inline TVF in FROM
CREATE OR ALTER FUNCTION dbo.OrdersForCustomer(@CustomerId int)
RETURNS TABLE
AS
RETURN
(
  SELECT OrderId, OrderDate, Status
  FROM dbo.Orders WHERE CustomerId=@CustomerId
);
GO
SELECT f.OrderId,f.OrderDate
FROM dbo.OrdersForCustomer(42) AS f
ORDER BY f.OrderDate DESC,f.OrderId DESC;

بعد از اجرا فقط دنبال «موفق شد» نباش. خروجی رو با حدسی که قبلش داشتی مقایسه کن؛ اگه فرق داشت، همون اختلاف بهترین نقطه برای ادامهٔ بررسیه.

Do not stop at “it succeeded.” Compare the output with your prediction; any mismatch is the best place to continue investigating.

تابع داده رو ذخیره نمی‌کنه؛ خروجی‌اش بخشی از query اصلی هست. schema نمونه رو با دیتابیس آزمایش تطبیق بده.

The function does not persist data; its output participates in the caller query. Adapt the assumed schema to your lab.

scalar UDF رو روی حجم واقعی بسنج / Measure scalar UDFs at realistic scale

scalar UDF قدیمی ممکنه اجرای ردیف‌به‌ردیف یا plan مبهم بسازد. در نسخه‌های جدید، inlining برای بعضی تابع‌ها و شرایط ممکنه، اما خودکار و همیشگی نیست. compatibility level، شکل تابع، تنظیمات و Actual Plan رو بررسی کن. expression مستقیم هم باید با همان داده مقایسه بشه.

Older scalar UDFs may result in row-by-row work or opaque plans. Newer versions can inline eligible functions under specific conditions; it is not universal. Check compatibility level, function shape, settings, and actual plan. Compare an inline expression on the same data.

function محدودیت دستوری داره / Functions have statement restrictions

UDF برای محاسبه/خواندن هست و نمی‌تونه هر دستور T-SQL رو اجرا کند یا side effect دلخواه داشته باشه. برای تغییر داده، transaction orchestration یا چند خروجی معمولاً procedure مرز روشن‌تری داره. محدودیت‌ها رو برای نسخهٔ هدف در مستند رسمی بررسی کن.

A UDF is for computation/querying; it cannot run every T-SQL statement or perform arbitrary side effects. Data changes, transaction orchestration, and multiple outputs usually fit procedures better. Check restrictions for the target version in official documentation.

NULL، rounding و determinism رو تعریف کن / Define NULL, rounding, and determinism

اگه ورودی NULL باشه، خروجی چه معنایی داره؟ rounding چطور است؟ deterministic بودن روی ویژگی‌هایی مثل indexable computed expression اثر می‌ذاره؛ چند خروجی یکسان، اثبات کافی نیست. تابع وابسته به زمان یا state بیرونی رو deterministic فرض نکن.

What does NULL input mean? How is rounding handled? Determinism affects features such as indexable computed expressions; a few identical outputs do not prove it. Do not assume a time- or external-state-dependent function is deterministic.

اینجا هدف خود دستور نیست؛ داریم باهاش یک ادعا رو امتحان می‌کنیم. قبل از Run، نتیجهٔ مورد انتظار رو توی یک جمله بگو.

The command is not the point; it is an experiment. Before Run, state the expected observation in one sentence.

آزمایش مقدار مرزی و NULL / Test NULL and boundaries
CREATE OR ALTER FUNCTION dbo.TaxRate(@Amount decimal(12,2))
RETURNS decimal(5,4)
AS
BEGIN
 RETURN CASE WHEN @Amount IS NULL THEN NULL
             WHEN @Amount < 1000 THEN 0.0500 ELSE 0.0800 END;
END;
GO
SELECT dbo.TaxRate(NULL) AS NullCase,
       dbo.TaxRate(999.99) AS Below,
       dbo.TaxRate(1000.00) AS Boundary;

اگه خروجی سیستم تو فرق داشت، سریع نتیجه نگیر که فصل غلطه. اول نسخه، دادهٔ تمرینی، database جاری و session رو چک کن؛ بعد سراغ فرضیهٔ بعدی برو.

If your output differs, do not jump to a conclusion. Check version, fixture, current database, and session state before changing the hypothesis.

قاعدهٔ مالیاتی صرفاً آموزشی هست. precision و rounding واقعی رو با مالک محصول تثبیت و با test مرزی پوشش بده.

The tax rule is illustrative. Confirm real precision and rounding with the product owner and test boundaries.

function رو مثل کد برنامه تست کن / Test functions like application code

NULL، مرز، overflow و collation رو بسنج؛ نتیجه رو با query مستقل validate کن. تغییر function روی چند caller اثر داره؛ dependencyها رو پیش از انتشار پیدا کن و plan مصرف‌کننده‌ها رو دوباره ببین.

Test NULL, boundaries, overflow, and collation; validate against an independent query. A function change affects multiple callers; identify dependencies and inspect caller plans before release.
