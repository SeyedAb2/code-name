SQL Injection: ورودی، داده هست

SQL injection: input is data

جست‌وجوی نام با یک مقدار عادی کار می‌کنه؛ ورودی دارای quote نتیجه رو عوض می‌کنه. این رفتار رو فقط روی جدول کوچک آزمایشی و قابل‌حذف می‌بینیم، رشته‌سازی رو کنار می‌گذاریم و همان ورودی رو پس از parameterization دوباره می‌سنجیم.

A name search works for ordinary input, but a quote changes the query. We reproduce this only on a tiny disposable table, remove concatenation, and rerun the same input after parameterization.

این دفعه سؤال اینه: چه کسی اجازه داره؟This time the question is: who is allowed?

خیلی از دیتابیس‌ها از نظر query درستن ولی از نظر دسترسی نه؛ چون اپ با کاربری وصل می‌شه که تقریباً همه‌چیز بلده و همه‌چیز می‌تونه. «SQL Injection: ورودی، داده هست» رو با حساب محدود جلو می‌بریم. هر مجوزی که می‌دیم، با همون کاربر امتحانش می‌کنیم تا فرق «فکر می‌کنم بسته‌ست» با «واقعاً بسته‌ست» روشن بشه.

Many databases are query-correct but permission-wrong because the application connects with an account that can do almost anything. In “SQL injection: input is data” we work with restricted principals and test permissions as those principals so “I think it is locked down” becomes demonstrable behaviour.

قرارمون توی این فصلOur rule for this chapter

هرجا query یا command می‌زنیم، همون‌جا می‌گیم چرا زدیمش، کدوم قسمت خروجی مهمه و اگه نتیجه فرق داشت اول چی رو چک کنی. قرار نیست چیزی رو فقط چون «معمولاً این‌طوریه» قبول کنیم.

Whenever we run a query or command, we state why, identify the important evidence, and say what to check first if the result differs. We do not accept behaviour merely because it is “usually like that.”

تزریق وقتی رخ می‌ده که value به syntax تبدیل بشه / Injection turns a value into syntax

اگه input رو داخل SQL text concatenate کنیم، quote و comment marker می‌تونه ساختار query رو عوض کند. این فصل payloadها رو برای آموزش فقط در database آزمایشی با دادهٔ تمرینی ساختگی نشان می‌ده؛ هیچ دستوری برای هدف واقعی اجرا نکن. اصل repair این هست: داده رو از کد جدا نگه دار.

When input is concatenated into SQL text, quotes and comment markers can change query structure. Payloads here are for a fake lab fixture only; never run them against a real target. The repair principle is to keep data separate from code.

این تکه کد رو فقط کپی نکن. اول برای خودت بگو اگه مدل ذهنی‌مون درست باشه چه چیزی باید ببینیم، بعد اجراش کن.

Do not just copy this block. First state what you expect to observe if the mental model is correct, then run it.

دادهٔ تمرینی بی‌خطر / Harmless fixture
CREATE TABLE dbo.LabUsers(Id int PRIMARY KEY, DisplayName nvarchar(100) NOT NULL);
INSERT dbo.LabUsers VALUES (1,N'Ada'),(2,N'R&D'),(3,N'علی');
DECLARE @Name nvarchar(100)=N'Ada';
SELECT Id,DisplayName FROM dbo.LabUsers WHERE DisplayName=@Name;

چیزی که باید از این مثال نگه داری اسم دستور نیست؛ رابطهٔ بین ورودی، خروجی و مدلیه که داریم می‌سازیم.

The thing to keep from this example is not the command name but the relationship between input, output, and the model we are building.

query ثابت با parameter برای value ساده‌ترین مرز هست. در application، از API پارامتری driver استفاده کن؛ format string یا quote دستی دفاع معتبر نیست.

A fixed query with a parameter is the simplest value boundary. In applications, use the driver's parameter API; formatting or manually quoting strings is not a reliable defense.

همان ورودی رو با parameter اجرا کن / Run the same input as a parameter

اینجا هدف خود دستور نیست؛ داریم باهاش یک ادعا رو امتحان می‌کنیم. قبل از Run، نتیجهٔ مورد انتظار رو توی یک جمله بگو.

The command is not the point; it is an experiment. Before Run, state the expected observation in one sentence.

dynamic statement امن‌تر / Parameterized dynamic statement
DECLARE @sql nvarchar(max)=N'
 SELECT Id,DisplayName FROM dbo.LabUsers WHERE DisplayName=@Name;';
DECLARE @Name nvarchar(100)=N''' OR 1=1--';
EXEC sys.sp_executesql @sql,N'@Name nvarchar(100)',@Name=@Name;

اگه خروجی سیستم تو فرق داشت، سریع نتیجه نگیر که فصل غلطه. اول نسخه، دادهٔ تمرینی، database جاری و session رو چک کن؛ بعد سراغ فرضیهٔ بعدی برو.

If your output differs, do not jump to a conclusion. Check version, fixture, current database, and session state before changing the hypothesis.

ورودی hostile اکنون یک value است؛ نباید syntax تازه بسازد. این کار authorization رو جایگزین نمی‌کنه: principal همچنان باید فقط دسترسی لازم داشته باشه و تعداد ردیف خروجی باید assertion بشه.

The hostile input is now a value and must not create syntax. This does not replace authorization: the principal still needs narrow access, and result counts should be asserted.

identifier مسیر جدا داره / Identifiers need a separate path

پارامتر فقط value می‌گیره، نه نام ستون یا جهت sort. برای identifier از allowlist کوچک استفاده کن و بعد QUOTENAME؛ برای ASC/DESC دو branch ثابت بنویس. quote کردن رشتهٔ دلخواه authorization نیست.

Parameters accept values, not column names or sort direction. For identifiers, use a small allowlist and then QUOTENAME; use fixed branches for ASC/DESC. Quoting arbitrary text is not authorization.

یه مکث کوتاه؛ واقعاً چی فهمیدیم؟Quick pause: what do we actually know now?

قبل از اینکه بریم بخش بعد، سعی کن بدون نگاه‌کردن به بالا در دو جمله بگی این فصل چه مسئله‌ای رو حل می‌کنه و از کدوم خروجی می‌فهمی راه‌حلت درست بوده. اگه فقط اسم دستورها یادت مونده، هنوز یه دور دیگه مثال قبلی رو با دادهٔ متفاوت اجرا کن.

Before moving on, explain in two sentences what problem this chapter solves and which output proves your solution is correct. If you only remember command names, rerun the previous example with different data.

parameterization تنها لایهٔ دفاع نیست / Parameterization is not the only defense

مجوز حداقلی، validation دامنه، محدودکردن طول ورودی، error handling امن و تست driver هم لازم‌اند. LIKE wildcardها رو ممکنه به‌عنوان pattern تفسیر کند؛ این رفتار با SQL injection یکی نیست و باید جدا تعریف بشه. هر خطا رو با payload ثابت، نتیجهٔ مورد انتظار و عدم تغییر داده بررسی کن.

Least privilege, business validation, bounded input length, safe error handling, and driver tests also matter. LIKE may interpret wildcard characters as patterns; that is separate from SQL injection and needs an explicit contract. Verify each case with fixed input, expected output, and no unintended data change.
