Extended Events، Error Log و Waitها

Extended Events, error logs, and waits

blocking تمام شده و query زنده دیگر در DMV نیست. کاربر فقط می‌گه «صبح کند بود». برای رخداد بعدی باید شواهد کم‌هزینه و زمان‌دار جمع کنیم، بدون اینکه capture خودش سرور رو سنگین کند.

The blocking is over and the live request has disappeared from DMVs. The user only says “it was slow this morning.” We need low-overhead, timestamped evidence for next time without making capture itself expensive.

فصل‌های عملیاتی وقتی ارزش دارن که روز خراب‌شدن سیستم به کارت بیان. برای «Extended Events، Error Log و Waitها» قرار نیست فقط اسم DMV یا گزینهٔ backup رو حفظ کنیم. یه وضعیت قابل‌تکرار می‌سازیم، شواهد جمع می‌کنیم، تغییر رو کنترل‌شده انجام می‌دیم و آخرش ثابت می‌کنیم سیستم واقعاً برگشته؛ نه اینکه فقط یک command بدون خطا تموم شده.

Operations chapters matter when the system is actually broken at 3 a.m. In “Extended Events, error logs, and waits” we do not memorise DMV names or backup options. We create a reproducible state, collect evidence, make a controlled change, and prove recovery rather than trusting a command that merely completed without error.

قرارمون توی این فصلOur rule for this chapter

هرجا query یا command می‌زنیم، همون‌جا می‌گیم چرا زدیمش، کدوم قسمت خروجی مهمه و اگه نتیجه فرق داشت اول چی رو چک کنی. قرار نیست چیزی رو فقط چون «معمولاً این‌طوریه» قبول کنیم.

Whenever we run a query or command, we state why, identify the important evidence, and say what to check first if the result differs. We do not accept behaviour merely because it is “usually like that.”

Extended Events رو هدفمند capture کن / Capture targeted events

Extended Events ابزار سبک و قابل‌تنظیم SQL Server برای ثبت رویدادهاست. event، predicate، target و retention رو براساس سؤال انتخاب کن؛ capture همهٔ SQL text می‌تونه اطلاعات حساس و حجم زیاد داشته باشه. system_سلامت برای برخی رخدادهای سیستم مفید است، اما retention و دسترسی/target رو بررسی کن.

Extended Events is SQL Server's configurable event-capture system. Choose events, predicates, targets, and retention for a specific question; capturing all SQL text can collect sensitive data and large volumes. system_health is useful for selected system events, but inspect retention, access, and target.

این تکه کد رو فقط کپی نکن. اول برای خودت بگو اگه مدل ذهنی‌مون درست باشه چه چیزی باید ببینیم، بعد اجراش کن.

wait نام علت نیست / A wait name is not a root cause

wait type می‌گه thread منتظر چه دسته منبعی است، اما زمینه درخواست، blocker، plan، مدت و بار کاری باید. wait statistic تجمعی رو با اختلاف زمان‌دار بخوان. یک wait غالب در کل عمر instance علت رخداد این صبح نیست.

A wait type describes a category of resource a worker is waiting for, not the cause. Add request context, blocker, plan, duration, and workload. Read cumulative wait statistics as timestamped deltas; a lifetime top wait is not automatically this morning's incident.

Error Log و رویدادها خط زمانی می‌سازند / Logs and events build a timeline

SQL Server Error Log برای راه‌اندازی، errorهای منتخب و پیام‌های engine مفید است؛ rotation می‌تونه تاریخچه رو حذف کند. XE file target و application logs رو با UTC time correlate کن. buffer ممکنه ring شده یا event از دست رفته باشه؛ loss counters و retention رو ثبت کن.

The SQL Server Error Log records startup, selected errors, and engine messages; rotation can remove history. Correlate XE file targets and application logs in UTC. Buffers can wrap or lose events; record loss counters and retention.

capture خودش باید امن باشه / Capture must itself be safe

روی lab session بساز، فیلتر مناسب بگذار، file target با سقف/rollover تعریف کن و دسترسی فایل رو محدود کن. پیش از ثبت SQL text، secret و personal data رو در نظر بگیر. system_سلامت رو بی‌دلیل stop/recreate نکن و شواهد فعال رو پاک نکن.

Build a lab session, filter appropriately, configure bounded file rollover, and restrict file access. Consider secrets and personal data before capturing SQL text. Do not casually stop/recreate system_health or delete active evidence.

راهنما / HintHint
Preserve chain of custody.
پاسخ و توضیحSolution and reasoning

اول مسئله رو به یک خروجی قابل‌سنجش تبدیل کن، بعد query یا command رو اجرا کن. جواب خوب هم نتیجه رو نشون می‌ده، هم دو خط توضیح می‌ده چرا این نتیجه به‌دست اومده.

Turn the task into a measurable outcome before running anything. A strong answer shows the result and briefly explains why that result occurred.

Evidence زمان‌دار از تشخیص حدسی بهتره / Timestamped evidence beats guesses

DMV نمونهٔ لحظه‌ای زنده، XE event، error log و application خط زمانی هرکدوم بخشی از ماجرا رو می‌دهند. wait رو علت قطعی نخواندیم و overhead/privacy capture رو سنجیدیم. فصل بعد از همین شواهد برای تشخیص رخداد مرحله‌به‌مرحله استفاده می‌کنه.

Live DMV snapshots, XE events, error logs, and application timelines each contribute evidence. We did not call a wait a root cause and considered capture overhead/privacy. Next we use evidence for a systematic incident diagnosis.
