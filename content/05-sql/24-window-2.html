Window functionها؛ LAG، LEAD و frame

Window functions: LAG, LEAD, and frames

تیم مالی می‌خواد تغییر مبلغ رو از سفارش قبلی ببیند و نمودار فروش تجمعی بسازد؛ بدون اینکه ردیف‌های روزانه جمع شوند. LAG و LEAD ردیف همسایه رو در ترتیب پنجره می‌خوانند و frame محدودهٔ ردیف‌هایی رو می‌سازه که یک aggregate پنجره‌ای برای هر ردیف می‌بینه.

Finance wants the change from the previous order and a cumulative sales chart without collapsing daily rows. LAG and LEAD read neighboring rows in a window order; a frame defines which rows a window aggregate sees for each current row.

ردیف قبلی در جدول لزوماً سفارش قبلی نیست / Previous in storage is not previous in time

برای مقایسهٔ سفارش‌های یک مشتری، باید ترتیب زمانی رو داخل OVER تعریف کنیم و tie زمان رو با OrderId بشکنیم. `LAG` مقدار ردیف قبلی و `LEAD` مقدار ردیف بعدی در همین ترتیب منطقی رو می‌آورد. این توابع ردیف‌ها رو حذف نمی‌کنن و به خودی خود نتیجه رو مرتب هم نمی‌کنن.

To compare one customer’s orders, define chronological order inside OVER and break timestamp ties with OrderId. LAG returns the prior row’s value and LEAD the next row’s value in that logical order. They do not remove rows or sort the final result by themselves.

قبل از اجرا یه حدس بزن: از خروجی این مثال دقیقاً دنبال چه نشونه‌ای هستی؟ عدد دقیق لازم نیست؛ فقط معلوم کن چی قراره ادعای این بخش رو تأیید یا رد کنه.

مقایسه با سفارش پیش و پس / Compare the prior and next order
SELECT CustomerId, OrderId, OrderedAt, OrderStatus,
       LAG(OrderStatus) OVER
         (PARTITION BY CustomerId ORDER BY OrderedAt, OrderId) AS PreviousStatus,
       LEAD(OrderStatus) OVER
         (PARTITION BY CustomerId ORDER BY OrderedAt, OrderId) AS NextStatus
FROM shop.Orders
ORDER BY CustomerId, OrderedAt, OrderId;
GO

بعد از اجرا فقط دنبال «موفق شد» نباش. خروجی رو با حدسی که قبلش داشتی مقایسه کن؛ اگه فرق داشت، همون اختلاف بهترین نقطه برای ادامهٔ بررسیه.

اولین ردیف هر customer مقدار قبلی نداره و LAG به‌طور پیش‌فرض NULL می‌ده؛ برای آخرین ردیف هم LEAD چنین هست. اگه خود مقدار status nullable باشه، برای تمایز «ردیف قبلی نیست» از «ردیف قبلی status=NULL داره» می‌توان ستون کلید قبلی رو هم با LAG بخوانی.

The first row per customer has no prior row, so LAG returns NULL by default; LEAD does the same at the end. If status itself can be NULL, lag a key too to distinguish “no prior row” from “prior status is NULL.”

offset و مقدار جایگزین رو صریح کن / Make offset and fallback explicit

offset پیش‌فرض LAG/LEAD برابر یک است؛ می‌توانی دو ردیف قبل یا بعد رو بخوانی. آرگومان سوم مقدار جایگزین برای وقتی هست که offset از محدوده بیرون می‌زند. این جایگزین با NULL ذخیره‌شده فرق داره، پس به‌عنوان مقدار نمایشی طراحی‌اش کن.

LAG/LEAD default to an offset of one; you can read two rows back or ahead. The third argument supplies a fallback when the offset is out of range. It is different from a stored NULL, so choose it as a display value deliberately.

این تکه کد رو فقط کپی نکن. اول برای خودت بگو اگه مدل ذهنی‌مون درست باشه چه چیزی باید ببینیم، بعد اجراش کن.

مبلغ سفارش قبلی و فاصلهٔ دو مبلغ / Previous order amount and change
;WITH OrderTotals AS
(
  SELECT o.CustomerId,o.OrderId,o.OrderedAt,
         SUM(oi.Quantity*oi.UnitPriceAtSale) AS Total
  FROM shop.Orders AS o JOIN shop.OrderItems AS oi ON oi.OrderId=o.OrderId
  GROUP BY o.CustomerId,o.OrderId,o.OrderedAt
)
SELECT CustomerId,OrderId,OrderedAt,Total,
       LAG(Total,1,0) OVER
         (PARTITION BY CustomerId ORDER BY OrderedAt,OrderId) AS PreviousTotal,
       Total-LAG(Total) OVER
         (PARTITION BY CustomerId ORDER BY OrderedAt,OrderId) AS ChangeFromPrevious
FROM OrderTotals
ORDER BY CustomerId,OrderedAt,OrderId;
GO

چیزی که باید از این مثال نگه داری اسم دستور نیست؛ رابطهٔ بین ورودی، خروجی و مدلیه که داریم می‌سازیم.

The thing to keep from this example is not the command name but the relationship between input, output, and the model we are building.

در PreviousTotal مقدار fallback صفر است؛ اما ChangeFromPrevious برای اولین سفارش NULL می‌شه، چون این‌جا fallback نگذاشته‌ایم. صفر رو فقط وقتی جایگزین کن که از نظر metric معنی‌دار باشه.

PreviousTotal uses zero as a fallback; ChangeFromPrevious is NULL for the first order because no fallback was supplied there. Use zero only when it is meaningful for the metric.

frame، پنجرهٔ در حال حرکت رو تعریف می‌کنه / A frame defines the moving subset

با `ORDER BY` داخل OVER، aggregate می‌تونه برای هر ردیف از ابتدای partition تا ردیف جاری ادامه پیدا کند. برای running total قابل‌فهم، `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` می‌نویسیم. این frame بر اساس ردیف‌ها حرکت می‌کنه؛ اگه ترتیب tie داشته باشه، کلید یکتا اضافه کن تا ترتیب تجمعی قطعی بشه.

With ORDER BY inside OVER, an aggregate can accumulate from the start of a partition through the current row. For a clear running total, specify `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`. This frame advances by rows; add a unique tie-breaker for deterministic accumulation.

running total برای هر مشتری / Running total per customer
;WITH OrderTotals AS
(
  SELECT o.CustomerId,o.OrderId,o.OrderedAt,
         SUM(oi.Quantity*oi.UnitPriceAtSale) AS Total
  FROM shop.Orders AS o JOIN shop.OrderItems AS oi ON oi.OrderId=o.OrderId
  GROUP BY o.CustomerId,o.OrderId,o.OrderedAt
)
SELECT CustomerId,OrderId,OrderedAt,Total,
       SUM(Total) OVER
         (PARTITION BY CustomerId
          ORDER BY OrderedAt,OrderId
          ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS RunningTotal
FROM OrderTotals
ORDER BY CustomerId,OrderedAt,OrderId;
GO

ROWS frame دقیقاً تا ردیف جاری در ترتیب کامل میاد. اگه فقط تاریخ رو مرتب کنی و دو سفارش زمان برابر داشته باشند، ترتیب تجمعی بین اون‌ها قطعی نیست. با کلید یکتا، هم ترتیب پنجره و هم خروجی بیرونی رو روشن کن.

The ROWS frame reaches the current row in a complete order. If you sort only by timestamp and two orders tie, their cumulative order is not deterministic. Use a unique key in both window and final ordering.

ROWS با RANGE یکی نیست / ROWS is not RANGE

ROWS تعداد جایگاه‌های ردیف رو می‌شمارد؛ `ROWS BETWEEN 1 PRECEDING AND CURRENT ROW` ردیف جاری و ردیف بلافاصله قبل رو می‌گیره. RANGE بر اساس مقدار کلید ORDER BY و peerهای برابر عمل می‌کنه و می‌تونه چند ردیف هم‌مقدار رو در یک frame بگنجاند. برای running total ردیفی، ROWS رو صریح بنویس و tieها رو بشکن.

ROWS counts row positions: `ROWS BETWEEN 1 PRECEDING AND CURRENT ROW` includes the current and immediately preceding rows. RANGE is based on ORDER BY values and peers, potentially grouping equal sort values into the same frame. For a row-by-row running total, specify ROWS and break ties.

میانگین متحرک دو ردیفی / Two-row moving average
SELECT OrderId,ProductId,UnitPriceAtSale,
       AVG(CONVERT(decimal(10,2),UnitPriceAtSale)) OVER
         (ORDER BY OrderId,ProductId
          ROWS BETWEEN 1 PRECEDING AND CURRENT ROW) AS MovingAvg2
FROM shop.OrderItems
ORDER BY OrderId,ProductId;
GO

این frame برای ردیف اول یک عضو، و از ردیف دوم به بعد حداکثر دو عضو داره. frame تجاری دیگری ممکنه بر اساس بازهٔ زمانی باشه؛ اون رو با frame ردیفی اشتباه نگیر.

The first row’s frame has one member; later frames have up to two. A business window may instead be based on a time range; do not confuse it with a row-count frame.

ردیف جاری، پنجرهٔ frame رو جلو می‌برد / The current row moves the frame

مربع سبز ردیف جاری و مربع قبلی frame دو‌ردیفی رو نشان می‌ده؛ در ردیف بعد frame به جلو می‌ره. ORDER BY یکتا تعیین می‌کنه «قبلی» کدوم ردیف هست.

The green cell is current and its predecessor is the two-row frame; the frame advances on the next row. A unique ORDER BY defines which row is “previous.”
