Helm

بسته‌بندی و پیکربندی چند محیط با یک chart.

Package and configure environments from one chart.

۸۰دقیقهminutes
۱۸تمرینexercises

سه محیط؛ سه YAML تقریباً یکسانThree environments, three almost-identical YAML sets

dev، staging و production سه نسخه از Deployment/Service دارند که فقط image tag، replica و port فرق می‌کند. یکی اصلاح شده، دو تای دیگر نه. Helm این manifestها را در Chart بسته‌بندی می‌کند و valueها را به template می‌دهد؛ اما chart نباید Kubernetes را از تو پنهان کند.

Dev, staging, and production have three nearly identical Deployment/Service sets differing only in image tag, replicas, and port. One was fixed, two were not. Helm packages manifests into a Chart and renders templates with values—but should not hide Kubernetes from you.

Chart.yaml هویت و نسخهٔ package، values.yaml مقدارهای پیش‌فرض، و templates فایل‌های manifest templateشده را نگه می‌دارند. Release یک نصب مشخص از chart با values در یک cluster/namespace است. اول render را ببین، بعد به API بفرست.

Chart.yaml identifies and versions a package; values.yaml defines defaults; templates hold rendered manifests. A release is one installation of a chart with values in a cluster/namespace. Inspect the rendering before sending it to the API.

render موفق manifest را نشان می‌دهد؛ rollout موفق و اپ سالم را هنوز ثابت نمی‌کند.

A successful render proves manifests were generated, not that rollout or application behavior is healthy.

از دو manifest یک chart جمع‌وجور بسازTurn two manifests into a small chart

با helm create می‌توان اسکلت ساخت، اما قبل از نگه‌داشتنش templateهای تولیدشده را بخوان و اضافی‌ها را حذف کن. برای این مثال chart فقط Deployment و Service دارد. image repository/tag، replica count و Service port در values باشند؛ label name ثابت باشد و template پیچیده نشود.

helm create can scaffold a chart, but inspect and remove generated extras before keeping it. This example needs only Deployment and Service. Put image repository/tag, replicas, and Service port in values; keep labels stable and templates simple.

Chart.yaml: apiVersion v2, name web, version 0.1.0
values.yaml: replicaCount: 2, image.repository, image.tag, service.port
templates/deployment.yaml: Deployment using those values
templates/service.yaml: Service selecting the Deployment labels

Go template از عبارت‌های {{ }}، شرط و default استفاده می‌کند؛ هر expression اضافی نگهداری را سخت می‌کند. helm lint ./web-chart خطاهای ساختار/قواعد را پیدا می‌کند؛ helm template demo ./web-chart -f values-staging.yaml خروجی YAML را بدون نصب نشان می‌دهد. خروجی را با kubectl/kubeconform policy تیم مرور کن؛ lint همهٔ رفتار cluster را نمی‌سنجد.

Go templates use {{ }} expressions, conditionals, and defaults; needless logic makes charts harder to maintain. helm lint checks chart structure and conventions. helm template renders YAML without installing it. Review output with your cluster/schema policy; lint does not validate every runtime behavior.

شکست عمدی: در template نام value اشتباه یا quote را حذف کن. helm template یا lint باید قبل از apply به خطا برسد یا YAML نامعتبر بدهد. مسیر value و خروجی را بررسی و اصلاح کن؛ اگر template آن‌قدر پیچیده است که خروجی قابل‌فهم نیست، ساده‌اش کن.

Deliberately mistype a value path or remove quoting. helm template or lint should catch an error or invalid YAML before apply. Inspect the value path and output, fix it, and simplify the template if its output is hard to reason about.

Release را ارتقا بده و به عقب برگردUpgrade a release and roll it back

helm install web-dev ./web-chart -n dev --create-namespace -f values-dev.yaml یک release می‌سازد. برای تغییر tag یا replica از helm upgrade استفاده کن؛ helm history نشان می‌دهد کدام revisionها ثبت شده‌اند، helm rollback نسخهٔ قبلی release را بازمی‌گرداند. بعد از هر مرحله kubectl rollout status را هم اجرا کن؛ Helm موفقیت API operation را با health اپ یکی نمی‌کند.

helm install creates a release. Use helm upgrade to change tag or replicas; helm history lists release revisions, and helm rollback restores an earlier release revision. Also check kubectl rollout status after each step—Helm operation success is not application health.

values-dev.yaml و values-prod.yaml برای مقدارهای غیرمحرمانه مناسب‌اند. password را در values، --set، command history یا release values ذخیره نکن؛ Helm release metadata در cluster نگه‌داری می‌شود و secret values ممکن است در آن باقی بمانند. از Secret/external secret workflow جدا و حداقل دسترسی استفاده کن. نسخهٔ Helm را با helm version ببین و syntax را با راهنمای همان نسخه تطبیق بده.

Environment values files are fine for non-secret settings. Do not put passwords in values, --set, shell history, or release values; Helm stores release metadata in the cluster and secret values may remain there. Use a separate Secret/external-secret workflow and least privilege. Check helm version and match syntax to its docs.

dependencies را با version constraint روشن تعریف کن و lockfile chart را نگه دار؛ update ناخواستهٔ dependency می‌تواند render را عوض کند. helm uninstall منابع release را حذف می‌کند و ممکن است دادهٔ وابسته را هم تحت‌تأثیر بگذارد؛ قبل از آن PVC/resource lifecycle را بخوان.

Declare chart dependency version constraints and keep the lock file; an unplanned dependency update can change rendering. helm uninstall removes release resources and may affect dependent data; inspect PVC/resource lifecycles first.

lab: render، install، upgrade، rollbackLab: render, install, upgrade, roll back

Deployment و Service کوچک فصل قبل را به chart منتقل کن. ابتدا lint و render dev/staging را اجرا و diff خروجی را مقایسه کن؛ تعداد objectها و namespace/labels درست‌اند؟ بعد cluster محلی disposable را انتخاب، install کن و get/rollout status بگیر.

Move the small Deployment and Service into a chart. First lint and render dev/staging, comparing outputs and checking object count, namespaces, and labels. Then target a disposable local cluster, install, and verify get/rollout status.

replicaCount یا image tag را در values عوض و upgrade کن. history و Deployment image را بخوان و rollout را verify کن. سپس مقدار خراب را وارد کن و helm template را پیش از upgrade اجرا کن؛ خطا را پیدا کن. برای تمرین rollback به revision قبلی برگرد و از روی history و rollout status ثابت کن کدام نسخه برگشت. در پایان فقط release lab را uninstall کن.

Change replicaCount or image tag and upgrade. Inspect history and Deployment image, then verify rollout. Introduce a bad value and run helm template before upgrade; diagnose it. Practice rollback to the previous revision and prove the restored version from history and rollout status. Uninstall only the lab release.

Helm تکرار را کم می‌کند، نه مسئولیت راHelm reduces repetition, not responsibility

Chart و values برای ساخت manifestهای چند محیط‌اند؛ lint/render پیش از install، history و rollback پس از آن‌اند. secret را در values نگذار و release را سالم فرض نکن تا workload را verify کنی. فصل بعد به جای render، با Pod خراب روبه‌رو می‌شویم و از شواهد status/event/log سرنخ می‌گیریم.

Charts and values generate environment-specific manifests; lint/render come before install, history and rollback after it. Keep secrets out of values and verify workloads before calling a release healthy. Next we investigate broken Pods through status, events, and logs.
