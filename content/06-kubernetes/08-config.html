ConfigMap و Secret

ConfigMaps and Secrets

image را ثابت نگه دار؛ config را جدا عوض کن. ولی Secret را به اسمش نسپار.

Keep the image fixed and change config around it—but do not trust the word Secret by itself.

همان image، سه محیط متفاوتOne image, three environments

اپ در dev به API آزمایشی می‌رود، در staging به مقصد آزمایشی دیگر و در production به سرویس واقعی. rebuild کردن image برای هر محیط یعنی artifactها از هم دور می‌شوند. اما اگر config و password را داخل image بگذاری، جداسازی محیط و چرخاندن credential سخت می‌شود.

In dev the app calls a test API; staging points elsewhere; production has a real endpoint. Rebuilding an image per environment makes artifacts diverge. Baking config and passwords into the image makes environment separation and credential rotation harder.

ConfigMap برای دادهٔ پیکربندی غیرمحرمانه است؛ Secret برای دادهٔ حساس، اما به‌خودی‌خود encryption at rest یا دسترسی امن تضمین نمی‌کند. RBAC، control-plane configuration، audit و نحوهٔ تحویل به Pod همگی بخشی از مسیر اعتمادند.

ConfigMap stores non-confidential configuration; Secret is for sensitive data, but does not by itself guarantee encryption at rest or safe access. RBAC, control-plane configuration, audit, and delivery to Pods all form the trust boundary.

جدا بودن مسیرها تضمین امنیت نیست؛ مجوز API و تنظیم encryption at rest را هم باید بررسی کرد.

Separate delivery paths do not guarantee security; API permissions and encryption-at-rest configuration still matter.

Env و file به شکل متفاوت به‌روز می‌شوندEnvironment variables and files refresh differently

key/value ساده را می‌توان به env داد؛ فایل تنظیمات را می‌توان از volume mount کرد. env داخل process هنگام شروع خوانده می‌شود و تغییر ConfigMap/Secret مقدار process موجود را عوض نمی‌کند؛ Pod restart لازم است. فایل volume-mounted ممکن است با تأخیر kubelet به‌روز شود، اما برنامه باید فایل را دوباره بخواند. mount با subPath رفتار refresh متفاوت دارد و معمولاً خودکار update نمی‌شود.

Simple key/value config can be injected as environment variables; whole files can be mounted. A process reads its environment at startup, so changing a ConfigMap or Secret does not change the existing process; restart the Pod. Mounted files may update after kubelet propagation delay, but the app must reread them. A subPath mount behaves differently and does not normally receive automatic updates.

برای تغییر کنترل‌شده، ConfigMap را عوض کن و rollout status را پس از rollout restart ببین. الگوی versioned ConfigMap (نام شامل hash/version) باعث می‌شود تغییر config در Pod template ثبت و rollout قابل‌ردگیری شود. immutable: true از تغییر محتوا جلوگیری می‌کند؛ برای تغییر، object تازه و rollout تازه بساز.

For a controlled change, update the ConfigMap and watch a restart/rollout. Versioned ConfigMap names (with a hash/version) make config changes part of the Pod template and easier to trace. immutable: true prevents data mutation; create a new object and roll out again.

base64 قفل نیستBase64 is not a lock

Secret manifest معمولاً data را base64 می‌پذیرد؛ این encoding قابل‌برگشت است، نه encryption. stringData ورودی متنی راحت‌تری است و API آن را به data تبدیل می‌کند؛ مقدار stringData معمولاً در پاسخ object بازنمایی نمی‌شود. kubectl get secret -o yaml دادهٔ base64شده را نشان می‌دهد؛ دسترسی read به Secret حساس است و باید با RBAC محدود شود.

A Secret manifest commonly accepts base64-encoded data; encoding is reversible, not encryption. stringData is a convenient text input that the API converts into data and generally does not return as stringData. kubectl get secret -o yaml exposes encoded values; read permission is sensitive and must be restricted with RBAC.

در بسیاری از تنظیمات، Secretهای etcd تا وقتی encryption at rest پیکربندی نشده باشد به شکل رمزنگاری‌نشده در backing store می‌مانند. این رفتار به نسخه و distribution و provider وابسته است. cluster admin باید encryption provider، کلیدها، backup و RBAC را بررسی کند؛ Secret را در Git یا log چاپ نکن. برای تولید واقعی، external secret managerها می‌توانند منبع و چرخش credential را بیرون cluster نگه دارند؛ اتصالش موضوع همین یک دستور نیست.

In many configurations, Secrets in etcd are not encrypted at rest unless encryption is configured. Exact behavior depends on version, distribution, and provider. Cluster admins must verify encryption providers, keys, backups, and RBAC. Never commit or log Secret values. External secret managers can keep source and rotation outside the cluster; integration is more than a single command.

lab: پیام عوض می‌شود، credential نهLab: change the message, not the credential

یک ConfigMap با APP_MESSAGE=hello و Secret آزمایشی با DEMO_TOKEN=not-a-real-secret بساز؛ این مقدار فقط demo است و هرگز واقعی نباشد. Pod اپ message را env و token را جداگانه مصرف کند. اول log برنامه را بخوان: مطمئن شو token را چاپ نمی‌کند. اگر Secret را ConfigMap کردی یا log کردی، مسیر افشا را توضیح بده، سپس به Secret و log امن برگرد.

Create a ConfigMap with APP_MESSAGE=hello and a Secret with the explicitly fake DEMO_TOKEN=not-a-real-secret. The value is a demo and must never be real. Let the app consume message and token separately. Check logs to ensure the token is not printed. If you put it in a ConfigMap or log it, explain the exposure path, then correct it.

با یک terminal مقدار message را عوض کن. اگر env است، process موجود همان مقدار قبلی را می‌بیند تا Pod restart شود؛ restart rollout را با status تأیید کن. اگر file mount را هم آزمایش می‌کنی، تغییر را پس از propagation روی فایل ببین و رفتار reload خود برنامه را جدا بیازما؛ secret/config روی همهٔ توزیع‌ها آنی نیست.

Change the message. If delivered as env, the existing process retains its old value until Pods restart; verify the rollout status. If testing a file mount, observe it after propagation and separately test application reload. Updates are not instantaneous across all distributions.

kubectl get configmap demo-config -n lab -o yaml
kubectl get secret demo-secret -n lab -o yaml
kubectl rollout restart deployment/demo -n lab
kubectl rollout status deployment/demo -n lab

خروجی secret را share نکن؛ حتی base64شده حساس است. در گزارش lab نام resource، RBAC principle و نتیجهٔ restart را ثبت کن، نه مقدار credential را. در cluster آزمایشی پس از اتمام namespace disposable را حذف کن.

Do not share Secret output; base64 is still sensitive. Record resource names, RBAC principle, and restart results, never the credential value. Delete the disposable namespace after the lab.

نام Secret جای سیاست امنیتی را نمی‌گیردThe name Secret is not a security policy

ConfigMap برای config غیرمحرمانه است؛ Secret یک مسیر مدیریتی بهتر برای مقدار حساس است، اما RBAC، encryption at rest، log و rotation را باید جدا طراحی کرد. تفاوت env و volume هم می‌گوید هر تغییر چه‌طور به process می‌رسد. فصل بعد داده را از چرخهٔ عمر Pod جدا می‌کنیم و storage پایدار را می‌سازیم.

ConfigMap is for non-confidential settings. Secret provides a better management path for sensitive values, but RBAC, encryption at rest, logging, and rotation need separate design. Env and volume delivery also determine how changes reach a process. Next we separate data from Pod lifecycle with persistent storage.
