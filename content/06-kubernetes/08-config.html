ConfigMap و Secret

ConfigMaps and Secrets

image رو ثابت نگه دار؛ config رو جدا عوض کن. ولی Secret رو به اسمش نسپار.

Keep the image fixed and change config around it—but do not trust the word Secret by itself.

۱۸تمرینexercises

همان image، سه محیط متفاوتOne image, three environments

یه image داری که روی dev خوبه. برای staging فقط آدرس API فرق می‌کنه و برای production همون برنامه با credential دیگه اجرا می‌شه. اگه برای هر محیط دوباره image بسازی، چیزی که تست کردی دقیقاً همون چیزی نیست که منتشر می‌کنی. پس کد و تنظیمات رو از هم جدا می‌کنیم.

In dev the app calls a test API; staging points elsewhere; production has a real endpoint. Rebuilding an image per environment makes artifacts diverge. Baking config and passwords into the image makes environment separation and credential rotation harder.

ConfigMap برای دادهٔ پیکربندی غیرمحرمانه است؛ Secret برای دادهٔ حساس، ولی به‌خودی‌خود encryption at rest یا دسترسی امن تضمین نمی‌کنه. RBAC، control-plane configuration، audit و نحوهٔ تحویل به Pod همگی بخشی از مسیر اعتمادند.

ConfigMap stores non-confidential configuration; Secret is for sensitive data, but does not by itself guarantee encryption at rest or safe access. RBAC, control-plane configuration, audit, and delivery to Pods all form the trust boundary.

جدا بودن مسیرها تضمین امنیت نیست؛ مجوز API و تنظیم encryption at rest رو هم باید بررسی کرد.

Separate delivery paths do not guarantee security; API permissions and encryption-at-rest configuration still matter.

Env و file به شکل متفاوت به‌روز می‌شنEnvironment variables and files refresh differently

حالا سؤال مهم‌تر: این تنظیمات چطور به برنامه می‌رسن؟ env و فایل از دور شبیه هم به نظر میان، ولی موقع تغییر رفتار یکسانی ندارن. env معمولاً با شروع process گرفته می‌شه؛ فایل mountشده ممکنه بعداً عوض بشه. برنامه هم باید بلد باشه تغییر رو بخونه.

Simple key/value config can be injected as environment variables; whole files can be mounted. A process reads its environment at startup, so changing a ConfigMap or Secret does not change the existing process; restart the Pod. Mounted files may update after kubelet propagation delay, but the app must reread them. A subPath mount behaves differently and does not normally receive automatic updates.

برای تغییر کنترل‌شده، ConfigMap رو عوض کن و rollout status رو پس از rollout restart ببین. الگوی versioned ConfigMap (نام شامل hash/version) باعث می‌شه تغییر config در Pod template ثبت و rollout قابل‌ردگیری بشه. immutable: true از تغییر محتوا جلوگیری می‌کنه؛ برای تغییر، object تازه و rollout تازه بساز.

For a controlled change, update the ConfigMap and watch a restart/rollout. Versioned ConfigMap names (with a hash/version) make config changes part of the Pod template and easier to trace. immutable: true prevents data mutation; create a new object and roll out again.

base64 قفل نیستBase64 is not a lock

اسم Secret یه حس امنیت کامل می‌ده، ولی گول اسمش رو نخور. base64 رمزنگاری نیست. اگه هر کسی مجوز خواندن Secret رو داشته باشه، داستان تمومه. امنیت واقعی از RBAC، encryption at rest، روش تحویل و مدیریت چرخه عمر credential میاد.

A Secret manifest commonly accepts base64-encoded data; encoding is reversible, not encryption. stringData is a convenient text input that the API converts into data and generally does not return as stringData. kubectl get secret -o yaml exposes encoded values; read permission is sensitive and must be restricted with RBAC.

در بسیاری از تنظیمات، Secretهای etcd تا وقتی encryption at rest پیکربندی نشده باشه به شکل رمزنگاری‌نشده در backing store می‌مونن. این رفتار به نسخه و distribution و provider وابسته است. cluster admin باید encryption provider، کلیدها، backup و RBAC رو بررسی کند؛ Secret رو در Git یا log چاپ نکن. برای تولید واقعی، external secret managerها می‌تونن منبع و چرخش credential رو بیرون cluster نگه دارن؛ اتصالش موضوع همین یک دستور نیست.

In many configurations, Secrets in etcd are not encrypted at rest unless encryption is configured. Exact behavior depends on version, distribution, and provider. Cluster admins must verify encryption providers, keys, backups, and RBAC. Never commit or log Secret values. External secret managers can keep source and rotation outside the cluster; integration is more than a single command.

lab: پیام عوض می‌شه، credential نهLab: change the message, not the credential

یک ConfigMap با APP_MESSAGE=hello و Secret آزمایشی با DEMO_TOKEN=not-a-real-secret بساز؛ این مقدار فقط demo است و هرگز واقعی نباشه. Pod اپ message رو env و token رو جداگانه مصرف کند. اول log برنامه رو بخوان: مطمئن شو token رو چاپ نمی‌کنه. اگه Secret رو ConfigMap کردی یا log کردی، مسیر افشا رو توضیح بده، سپس به Secret و log امن برگرد.

Create a ConfigMap with APP_MESSAGE=hello and a Secret with the explicitly fake DEMO_TOKEN=not-a-real-secret. The value is a demo and must never be real. Let the app consume message and token separately. Check logs to ensure the token is not printed. If you put it in a ConfigMap or log it, explain the exposure path, then correct it.

با یک ترمینال مقدار message رو عوض کن. اگه env است، process موجود همان مقدار قبلی رو می‌بینه تا Pod restart بشه؛ restart rollout رو با status تأیید کن. اگه file mount رو هم آزمایش می‌کنی، تغییر رو پس از propagation روی فایل ببین و رفتار reload خود برنامه رو جدا بیازما؛ secret/config روی همهٔ توزیع‌ها آنی نیست.

Change the message. If delivered as env, the existing process retains its old value until Pods restart; verify the rollout status. If testing a file mount, observe it after propagation and separately test application reload. Updates are not instantaneous across all distributions.

kubectl get configmap demo-config -n lab -o yaml
kubectl get secret demo-secret -n lab -o yaml
kubectl rollout restart deployment/demo -n lab
kubectl rollout status deployment/demo -n lab

خروجی secret رو share نکن؛ حتی base64شده حساس است. در گزارش lab نام resource، RBAC principle و نتیجهٔ restart رو ثبت کن، نه مقدار credential رو. در cluster آزمایشی پس از اتمام namespace آزمایشی رو حذف کن.

Do not share Secret output; base64 is still sensitive. Record resource names, RBAC principle, and restart results, never the credential value. Delete the disposable namespace after the lab.

نام Secret جای سیاست امنیتی رو نمی‌گیرهThe name Secret is not a security policy

ConfigMap و Secret کمک می‌کنن config رو از image جدا کنیم؛ همین. Secret خودش گاوصندوق کامل نیست. هر بار با داده حساس کار کردی، از خودت بپرس چه کسی می‌تونه بخونتش، کجا ذخیره می‌شه و چطور عوضش می‌کنیم.

ConfigMap is for non-confidential settings. Secret provides a better management path for sensitive values, but RBAC, encryption at rest, logging, and rotation need separate design. Env and volume delivery also determine how changes reach a process. Next we separate data from Pod lifecycle with persistent storage.
