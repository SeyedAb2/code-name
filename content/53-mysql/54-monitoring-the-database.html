پایش MySQL با شواهد خود سرورMonitoring MySQL with server evidence

Performance Schema رویدادهای runtime رو جمع می‌کنه و Information Schema بیشتر metadata رو می‌ده. خلاصهٔ digest برای یافتن queryهای پرتکرار یا پرهزینه مفید است، اما نمونهٔ SQL ممکنه ناقص یا حاوی دادهٔ حساس باشه. Slow log فقط طبق threshold و مقصد پیکربندی‌شده می‌نویسه؛ فعال‌بودن آن تضمین نمی‌کنه خروجی در فایل باشه. برای lock wait رابطهٔ blocker و waiter رو ببین. قبل از reset کردن summaryها snapshot بگیر، چون reset evidence تاریخی رو از بین می‌برد.

Performance Schema collects runtime events, while Information Schema primarily exposes metadata. Digest summaries can find frequent or expensive query shapes, but sampled SQL may be truncated or sensitive. The slow log writes according to configured thresholds and destinations; enabling it does not guarantee file output. For lock waits, identify both blocker and waiter. Snapshot summaries before resetting them because reset destroys historical evidence.
