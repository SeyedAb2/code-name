یک query تنظیم رو عوض کرد؛ چرا connection دیگر هیچ تغییری ندید؟

One query changed a setting. Why did another connection see no change?

توسعه‌دهنده در یک connection مقدار sql_mode رو تغییر داده، اما برنامه رفتار متفاوتی دارد. شاید تغییر session بوده، شاید global، یا server بعد از restart مقدار رو از فایل دیگری خوانده. هر متغیر scope و چرخهٔ عمر خودش رو دارد. قبل از SET، مقدار مؤثر و دامنهٔ تغییر رو از خود server می‌خونیم.

A developer changed sql_mode in one connection, but the application behaves differently. Perhaps the change was session-scoped, global, or overwritten at restart by persistent configuration. Each variable has a scope and lifecycle. Before SET, inspect the effective value and scope on the server.

scope رو پیش از تغییر بخوانInspect scope before changing a value

متغیر session فقط روی connection جاری اثر دارد؛ connection pool می‌تونه sessionهای متعددی با مقدارهای متفاوت داشته باشه. متغیر global روی مقدار پیش‌فرض sessionهای تازه اثر می‌ذاره و هر متغیر اجازهٔ تغییر runtime ندارد. تنظیم پایدار هم ممکنه در restart حفظ شود. scope و Dynamic رو از مستند همان متغیر بخوان؛ همه رو قابل SET فرض نکن.

A session variable affects the current connection; a pool may contain sessions with different values. A global variable affects defaults for new sessions, and not every variable can be changed at runtime. Persisted configuration may survive restart. Check each variable's scope and dynamic status instead of assuming all variables are settable.

SELECT @@hostname, CONNECTION_ID();
SELECT @@SESSION.sql_mode AS session_mode,
       @@GLOBAL.sql_mode AS global_mode;
SHOW VARIABLES LIKE 'time_zone';
SHOW GLOBAL VARIABLES LIKE 'max_connections';

SHOW VARIABLES بدون GLOBAL معمولاً مقدار session جاری رو نشان می‌ده. مقدار رو روی connectionی بخوان که واقعاً query برنامه رو اجرا می‌کنه.

SHOW VARIABLES without GLOBAL reports the current session value. Inspect the connection that actually runs the application's query.

اول در یک session آزمایش کنExperiment in one session first

تغییر session برای آزمایش محدود هست و با پایان connection از بین می‌ره. از آن برای فهم اثر یک sql_mode یا timezone روی query خودت استفاده کن؛ بعد connection دوم رو مقایسه کن. این کار برای config برنامه جایگزین migration یا تنظیم مدیریت‌شدهٔ محیط نیست.

A session change is limited to one connection and ends with it. Use it to test how sql_mode or time_zone affects a query, then compare another connection. This is not a substitute for managed application configuration.

SET SESSION time_zone = '+00:00';
SELECT @@SESSION.time_zone, NOW(), UTC_TIMESTAMP();

SET SESSION sql_mode = 'STRICT_TRANS_TABLES';
SELECT @@SESSION.sql_mode;

sql_mode کامل ممکنه شامل modeهای دیگری باشه؛ برای تمرین مقدار رو ثبت و پس از آزمایش connection رو ببند. رشتهٔ ثابت بالا جایگزین config server نیست.

The full sql_mode may include additional modes. Record the original value and close the lab session afterward; this sample string is not a server-wide configuration recommendation.

SET GLOBAL و SET PERSIST رو بی‌برنامه نزنDo not issue SET GLOBAL or SET PERSIST casually

تغییر global معمولاً روی sessionهای تازه اثر می‌ذاره، نه sessionهای از قبل باز. SET PERSIST برای متغیرهای پشتیبانی‌شده مقدار رو هم runtime و هم برای restart ثبت می‌کنه؛ این یعنی تغییر ماندگارتر و نیازمند کنترل تغییر. قبل از هر دست‌کاری، نسخه، مستند، مقدار قبلی، اثر، دسترسی لازم و روش برگشت رو ثبت کن. آزمایش این فصل رو در server اصلی انجام نده.

A global change generally affects new sessions, not sessions already open. SET PERSIST stores supported variables for runtime and restart, so it is a more durable configuration change. Record version, documentation, prior value, impact, required privilege, and rollback before changing it. Do not use production for this lab.

SHOW GLOBAL VARIABLES LIKE 'max_connections';
SELECT VARIABLE_NAME, VARIABLE_VALUE
FROM performance_schema.global_variables
WHERE VARIABLE_NAME = 'max_connections';

برنامه و pool ممکنه چند مقدار مؤثر داشته باشندAn app and its pool may have several effective values

connection تازه در pool الزاماً از همان config قبلی ساخته نمی‌شه: environment یا option file می‌تونه مقدار رو عوض کند؛ pool هم connection قدیمی رو reuse می‌کنه. برای عیب‌یابی، connection id، host، version و مقدار session رو کنار request ثبت کن. password و رشتهٔ اتصال کامل رو log نکن.

A new pooled connection may not use the same configuration as an earlier one: environment or option files can override values, while a pool may reuse old sessions. For diagnosis, record connection ID, host, version, and session values with the request. Never log passwords or full connection strings.

اول scope تنظیم رو بفهمUnderstand variable scope before changing it

GLOBAL و SESSION دو اثر متفاوت دارن. بعضی variableها فقط یکی از این scopeها رو پشتیبانی می‌کنن. قبل از SET، مقدار هر دو scope و مستند نسخه رو بخون.

GLOBAL and SESSION settings have different lifetimes, and not every variable supports both scopes. Read current values and version-specific scope before changing anything.
