GTID، lag و تضمین خواندنGTIDs, lag, and read-after-write

GTID هویت تراکنش رو مستقل از نام فایل و offset نگه می‌دارد؛ اما به‌تنهایی داده رو جلو نمی‌برد. `WAIT_FOR_EXECUTED_GTID_SET` می‌تونه روی همان سروری که query رو می‌زنیم برای set مشخص‌شده تا timeout منتظر بماند؛ صفر، timeout و NULL رو با مستند نسخه تفسیر کن. این wait روی source چیزی دربارهٔ replica نمی‌گه. برای تضمین اپ، می‌توان پس از write به source خواند یا تا رسیدن GTID روی replica صبر کرد و در timeout به source برگشت. `Seconds_Behind_Source` رو با thread state، timestamp و workload کنار هم بخوان؛ clock skew و thread متوقف آن رو گمراه می‌کنه.

A GTID identifies a transaction independently of a binlog filename and offset, but it does not move data by itself. `WAIT_FOR_EXECUTED_GTID_SET` can wait on the server receiving the query for a specified set, up to a timeout; interpret zero, timeout, and NULL using the release documentation. Waiting on the source says nothing about a replica. An application can read from the source after a write, or wait for that GTID on a replica and fall back to the source on timeout. Interpret `Seconds_Behind_Source` alongside thread state, timestamps, and workload; clock skew and stopped threads can mislead.
