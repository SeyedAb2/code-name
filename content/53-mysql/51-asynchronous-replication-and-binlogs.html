The new order is missing on the replica. Is replication broken?

یک رکورد روی source ثبت شده اما replica نتیجهٔ قدیمی می‌ده. در replication ناهمگام، commit روی source منتظر اجرای تغییر در replica نمی‌مونه. به‌جای حدس، ثبت در binlog، دریافت event و اجرای آن رو جدا بررسی می‌کنیم؛ فقط روی سرورهای تمرینی و بدون دادهٔ واقعی.

A row was committed on the source but the replica still returns old data. With asynchronous replication, a source commit does not wait for the replica to apply it. We will inspect binary logging, event receipt, and application separately, using disposable servers and no real data.

تغییر از سه ایستگاه می‌گذردA change passes through three stages

source تغییر رو در binary log می‌نویسه. receiver thread روی replica آن رو به relay log می‌آورد و applier بعداً اجرا می‌کنه. این فاصله طبیعی هست و به معنی خرابی قطعی نیست. Binlog رو با error log یا slow query log اشتباه نگیر؛ هرکدام پرسش جداگانه‌ای رو پاسخ می‌ده.

The source writes changes to its binary log. The replica receiver fetches them into the relay log; the applier executes them later. This delay can be normal and does not prove failure. Do not confuse the binary log with the error log or slow query log; each answers a different question.

ثبت، دریافت و اجرا سه مرحله و سه شاهد جدا هستن.
