درخواست‌ها کند شدند؛ همه دارن connection تازه می‌سازند

Requests are slow; every request opens a new connection

در ساعت شلوغ، برنامه با خطای Too many connections روبه‌رو می‌شه. بالا بردن max_connections شاید علامت رو عقب بیندازد، اما اگه هر worker pool بزرگی داشته باشه، تعداد اتصال‌ها چندبرابر می‌شه. قبل از دست‌کاری سرور، مقصد و credential و timeout رو می‌خونیم، سپس ظرفیت pool رو از تعداد instanceها حساب می‌کنیم.

At peak time, the app reports Too many connections. Raising max_connections may postpone the symptom, but a large pool in every worker multiplies sessions. Before changing the server, inspect destination, credentials, and timeout behavior, then calculate pool capacity across all instances.

سه timeout داریم؛ یکی نیستندThere are several different timeouts

connect timeout زمان تلاش برای برقراری اتصال است؛ pool queue timeout مربوط به انتظار برای connection آزاد می‌شه؛ query timeout یا deadline برنامه به مدت اجرای کار مربوط هست. نام و رفتار دقیق گزینه‌ها به driver وابسته هست. پیام timeout رو کنار stage و duration واقعی ثبت کن تا timeout اشتباه رو افزایش ندهی.

A connect timeout bounds connection establishment; pool queue waiting concerns time spent waiting for an available connection; a query timeout or application deadline concerns work duration. Exact options are driver-specific. Record the failing stage and elapsed time before increasing the wrong timeout.

pool تعداد connectionهای هم‌زمان رو محدود می‌کنه؛ queue و query هرکدام زمان و شواهد جدا دارن.

A pool limits concurrent connections; queue wait and query execution need separate timing evidence.

pool اندازه‌دار بساز و همیشه اتصال رو آزاد کنBound the pool and always release checked-out connections

mysql2 می‌تونه connection رو هنگام نیاز تا سقف limit بسازد؛ لازم نیست startup همه رو باز کند. query از متدهای pool معمولاً connection رو پس از اجرا آزاد می‌کنه. اگه دستی getConnection گرفتی، release رو در finally انجام بده؛ نگه‌داشتن ناخواستهٔ connectionها ظرفیت pool رو می‌خورد.

mysql2 can create connections on demand up to its limit; it need not open all of them at startup. Pool query helpers release a connection after the operation. If you call getConnection manually, release in finally—leaked connections consume pool capacity.

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 8,
  maxIdle: 8,
  idleTimeout: 60000,
  queueLimit: 40,
  connectTimeout: 10000
});

const [rows] = await pool.execute(
  'SELECT id FROM jobs WHERE status = ? LIMIT ?',
  ['ready', 25]
);

این اعداد نمونه‌اند، نه نسخهٔ تجویزی. queueLimit صفر در بعضی پیکربندی‌ها به معنی صف نامحدود است؛ بر اساس رفتار driver نسخهٔ خودت، بار و deadline برنامه تصمیم بگیر.

These are examples, not universal recommendations. In some configurations, queueLimit zero means an unlimited queue; verify your driver version and size limits against workload and request deadlines.

اگه چهار replica داری و هرکدام pool limit برابر ۸ دارد، برنامه می‌تونه تا ۳۲ connection بسازد؛ workerهای جدا، jobها و ابزارهای عملیاتی هم به آن اضافه می‌شوند. این عدد رو با max_connections و ظرفیت memory server مقایسه کن. بالا بردن max_connections بدون برآورد resource می‌تونه مشکل رو به memory و latency منتقل کند.

deadline رو لایه‌به‌لایه تنظیم کنSet deadlines by layer

یک request نباید بی‌نهایت پشت pool منتظر بماند. deadline برنامه باید جا برای query، network و پاسخ داشته باشه؛ retry هم باید محدود، با backoff و فقط برای عملیات قابل‌تکرار باشه. connection قطع‌شده رو با query timeout اشتباه نگیر و در هر خطا stage، duration و request id رو ثبت کن.

A request should not wait forever in a pool queue. The application deadline must leave room for query, network, and response work; retries should be bounded, use backoff, and apply only to safe operations. Distinguish a broken connection from a query timeout and record stage, duration, and request ID.

Connection timeout با query timeout یکی نیستConnection timeout and query timeout are different failures

یکی می‌گه نتونستم connection بسازم؛ اون یکی می‌گه connection داشتم ولی command بیشتر از حد مجاز طول کشید. اگه این دو رو با یه عدد بزرگ‌تر «حل» کنی، فقط مشکل رو دیرتر می‌بینی.

A connection timeout means the client could not establish a usable connection in time. A command timeout means a query on an established connection took too long. Treat them separately.
