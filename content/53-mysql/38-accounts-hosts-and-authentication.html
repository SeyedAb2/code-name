نام کاربری درست است؛ چرا MySQL هنوز می‌گه اجازه نداری؟

The username is correct. Why does MySQL still deny access?

برنامه با username و password ظاهراً درست وصل نمی‌شه؛ ولی شاید accountای که ساخته‌ای برای host دیگری است، plugin احراز هویت با client جور نیست یا اتصال TLS شرط دارد. MySQL هویت رو فقط از نام کاربر نمی‌سازد: user و host با هم account رو مشخص می‌کنن. بیاییم این مسیر رو از شواهد اتصال پیدا کنیم.

The application cannot connect with what looks like the right username and password. Perhaps the account belongs to a different host, its authentication plugin does not match the client, or TLS is required. MySQL identity is not just a username: user and host together select an account. We will trace that decision with connection evidence.

یک username، چند account ممکنOne username, several possible accounts

در MySQL این دو account یک چیز نیستند: 'reporter'@'localhost' و 'reporter'@'10.20.%'. بخش host می‌گه اتصال از کجا مجاز هست. server هنگام اتصال user و host طرف مقابل رو تطبیق می‌ده، بعد plugin همان account رو برای احراز هویت به کار می‌برد. اگه اتصال شکست خورد، قبل از دست‌کاری password باید بفهمیم به کدام مقصد و از چه جایی وصل شده‌ایم.

These are distinct MySQL accounts: 'reporter'@'localhost' and 'reporter'@'10.20.%'. The host part describes where the connection may come from. MySQL matches an account using the incoming user and host, then uses that account's authentication plugin. Before changing a password, verify the destination and source of the connection.

تطبیق account قبل از بررسی مجوز query انجام می‌شه؛ خطای اتصال با خطای دسترسی به جدول یکی نیست.

Account matching happens before query privileges are checked; a connection error is not a table-access error.

ببین server تو رو چه کسی می‌شناسدAsk the server who it authenticated

پس از اتصال، USER() مقدار معرفی‌شده و مبدأ اتصال رو نشان می‌ده؛ CURRENT_USER() account مؤثری رو که server برای بررسی دسترسی انتخاب کرده گزارش می‌کنه. این دو در شرایطی مثل anonymous account ممکنه متفاوت باشند. از این queryها برای شواهد استفاده کن، نه برای حدس‌زدن از روی فایل تنظیمات برنامه.

USER() reports the presented identity and connection origin; CURRENT_USER() reports the account MySQL selected for privilege checking. They can differ, for example with an anonymous account. Use these queries as evidence rather than guessing from application configuration.

SELECT USER() AS presented_identity,
       CURRENT_USER() AS matched_account,
       @@hostname AS server_name,
       @@port AS server_port;
SHOW STATUS LIKE 'Ssl_cipher';

مقدار خالی Ssl_cipher معمولاً یعنی این session از TLS استفاده نمی‌کنه؛ خروجی رو با تنظیمات client و الزام account تطبیق بده. در سیستم واقعی، مقدارهای افشاگر رو در گزارش عمومی منتشر نکن.

An empty Ssl_cipher usually means this session is not using TLS; compare it with client configuration and account requirements. Do not expose sensitive values in public reports.

یک حساب تمرینی بساز؛ با مجوز کمCreate a lab account with limited privileges

این نمونه فقط در دیتابیس آزمایشی اجرا بشه. password نمایشی رو با secret مدیریت‌شدهٔ محیط خودت عوض کن؛ رمز رو در Git، history یا screenshot نگذار. برنامه معمولاً به account جدا و مجوزهای مشخص نیاز دارد؛ root برای اتصال برنامه نیست.

Run this only in a disposable database. Replace the illustrative password with an environment-managed secret; do not put it in Git, shell history, or screenshots. Applications need a dedicated account with specific grants, not root.

CREATE USER 'codenames_reader'@'localhost'
  IDENTIFIED BY 'REPLACE-IN-DISPOSABLE-LAB';
GRANT SELECT ON codenames_lab.* TO 'codenames_reader'@'localhost';
SHOW GRANTS FOR 'codenames_reader'@'localhost';

اگه برنامه از container دیگری وصل می‌شه، source host احتمالاً localhost نیست. host مناسب رو با توپولوژی و مستند server تعیین کن؛ wildcard گسترده رو راه‌حل پیش‌فرض نکن. آخر آزمایش حساب رو حذف کن.

If the app connects from another container, its source host is probably not localhost. Choose the host part for the actual topology; a broad wildcard is not the default fix. Drop the test account after the lab.

plugin احراز هویت بخشی از قرارداد اتصال هستThe authentication plugin is part of the connection contract

MySQL account به authentication plugin متصل هست. server و connector باید روی روش پشتیبانی‌شده توافق کنند؛ پس از ارتقا، connector قدیمی یا تنظیم ناسازگار ممکنه اتصال رو خراب کند. پیش از تغییر plugin، driver واقعی برنامه و نسخه‌های آن رو بررسی کن. plugin رو کورکورانه عوض نکن تا فقط خطا ناپدید شود.

A MySQL account uses an authentication plugin. The server and connector must agree on a supported method; an old connector or incompatible configuration can break after an upgrade. Check the application's real driver and versions before changing a plugin. Do not switch plugins blindly just to hide an error.

SELECT user, host, plugin, account_locked
FROM mysql.user
WHERE user = 'codenames_reader';

خواندن جدول سیستمی به مجوز مدیریتی نیاز دارد و schema داخلی رو مستقیم تغییر نده. برای ساخت و تغییر account از CREATE USER و ALTER USER استفاده کن؛ نمایش plugin رو فقط در محیط مجاز انجام بده.

Reading this system table requires administrative access; do not edit internal tables directly. Use CREATE USER and ALTER USER for account management, and inspect plugins only where authorized.

رمز عبور جای TLS رو نمی‌گیرهA password does not replace TLS

password جلوی شنود مسیر شبکه رو به‌تنهایی نمی‌گیره. اتصال remote رو مطابق محیط با TLS تنظیم و در صورت نیاز برای account شرط TLS بگذار. گزینه‌های client برای CA و اعتبارسنجی گواهی رو از مستند connector بگیر؛ صرف encrypted بودن بدون اعتبارسنجی درست، هویت سرور رو تضمین نمی‌کنه.

A password alone does not prevent network interception. Configure remote connections with TLS and require it for an account when appropriate. Use the connector's CA and certificate-validation settings; encryption without proper verification does not prove server identity.

ALTER USER 'codenames_reader'@'10.20.%'
  REQUIRE SSL;
SHOW CREATE USER 'codenames_reader'@'10.20.%';

host نمونه رو با محدودهٔ واقعی جایگزین کن. پیش از REQUIRE SSL مطمئن شو client گواهی رو درست اعتبارسنجی می‌کنه؛ در غیر این صورت اتصال قطع می‌شه.

Replace the sample host with the real scope. Before requiring SSL, ensure the client validates the certificate correctly or connections will fail.

خطای اتصال رو مرحله‌به‌مرحله جدا کنSeparate connection failures by stage

خطای 1045 معمولاً authentication یا account matching رو مطرح می‌کنه، اما خودش نمی‌گه کدام فرض غلط هست. مقصد و port، user@host مؤثر، plugin/connector، TLS و credential رو جداگانه بررسی کن. اگه اتصال موفق شد ولی SELECT رد شد، آن وقت مجوز request رو با SHOW GRANTS بررسی کن.

Error 1045 commonly points toward authentication or account matching, but does not identify which assumption is wrong. Check destination and port, effective user@host, plugin and connector, TLS, and credentials separately. If connection succeeds but SELECT fails, inspect request privileges with SHOW GRANTS.
