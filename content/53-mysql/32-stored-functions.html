گزارش می‌خواهد قیمت نهایی هر کالا رو ببیند

A report needs each item’s final price

در فصل قبل یک عملیات رو با CALL راه انداختیم و نتیجه رو با OUT گرفتیم. حالا گزارش باید برای هر ردیف، یک مقدار محاسبه‌شده رو داخل خود query نمایش دهد. این‌جا Stored Function مطرح می‌شه: تابعی در server که یک مقدار می‌ده و مثل expression در query جا می‌گیره.

In the previous chapter, we ran an operation with CALL and captured an OUT value. Now a report needs a calculated value for each row inside the query itself. This is where a stored function fits: a server-side routine that returns one value and can appear as an expression.

Procedure نتیجه می‌ده؛ Function خودش یک مقدار هستA procedure performs work; a function is a value

فرض کن تیم فروش تخفیف رو با فرمول‌های کمی متفاوت در چند گزارش تکرار کرده هست. به‌جای این‌که هر گزارش فرمول رو جدا بنویسد، می‌خوایم یک مقدار واحد مثل قیمت پس از تخفیف رو در SELECT استفاده کنیم. Function برای این شکل از سؤال مناسب است؛ مثل یک تابع داخلی SQL صدا زده می‌شه، نه با CALL.

Suppose several sales reports repeat the discount formula with small differences. Instead of duplicating the formula in every report, we want one value—the discounted price—inside SELECT. A function fits that shape of question: it is invoked like a SQL expression, not through CALL.

سمت چپ Procedure با statement مستقل فراخوانی می‌شه؛ سمت راست Function در expression یک SELECT مقدار می‌ده.

A procedure on the left is invoked as a separate statement; a function on the right supplies a value inside a SELECT expression.

این شکل فراخوانی به معنی «ارزان‌تر» یا «بهتر» نیست. Function در SELECT می‌تونه برای ردیف‌های زیادی اجرا بشه و اگه جدول بخواند یا کار سنگین انجام دهد، گزارش رو کند کند. اول مسئله رو اندازه بگیر؛ بعد تصمیم بگیر فرمول رو در Function نگه داری، در query بنویسی، یا نتیجه رو از قبل ذخیره کنی.

This invocation style does not mean “cheaper” or “better.” A function in SELECT may run for many rows, and a function that reads tables or does expensive work can slow a report. Measure the problem first, then decide whether the formula belongs in a function, directly in the query, or in precomputed data.

یک Function کوچک با RETURNA small function with RETURN

قیمت بعد از تخفیف از روی دو ورودی محاسبه می‌شه. Function باید نوع خروجی رو در RETURNS اعلام کند و در هر مسیر قابل‌اجرا یک مقدار با RETURN بده. پارامترهای Function ورودی‌اند؛ OUT و INOUT که برای Procedure دیدیم این‌جا نداریم.

The discounted price is computed from two inputs. A function declares its result type with RETURNS and supplies a value through RETURN on every executable path. Function parameters are inputs; the OUT and INOUT modes from procedures do not apply here.

تعریف رو در mysql CLI اجرا کنCreate it in the mysql CLI
DELIMITER //
CREATE FUNCTION codenames_deadlock_lab.discounted_price(
  p_price DECIMAL(10,2),
  p_discount_percent DECIMAL(5,2)
)
RETURNS DECIMAL(10,2)
DETERMINISTIC
NO SQL
SQL SECURITY INVOKER
RETURN ROUND(p_price * (100 - p_discount_percent) / 100, 2)//
DELIMITER ;

این Function برای ورودی‌های یکسان، خروجی یکسان دارد و هیچ جدول یا ساعت/عدد تصادفی نمی‌خواند؛ برای همین DETERMINISTIC و NO SQL توصیف‌های درست این نمونه‌اند. این برچسب‌ها قول اجرایی server نیستند: MySQL صداقت نویسنده رو بررسی نمی‌کنه و characteristicهای data access راهنمایی‌اند، نه محدودکنندهٔ بدنه.

This function returns the same value for the same inputs and reads no table, clock, or random value, so DETERMINISTIC and NO SQL accurately describe this example. These declarations are not server-enforced promises: MySQL does not verify the author’s claim, and data-access characteristics are advisory rather than body restrictions.

قبل از query با چند ورودی قابل‌پیش‌بینی امتحانش کنTest predictable inputs before using it in a query
SELECT
  codenames_deadlock_lab.discounted_price(120.00,10.00) AS case_1,
  codenames_deadlock_lab.discounted_price(80.00,25.00) AS case_2,
  codenames_deadlock_lab.discounted_price(45.50,0.00) AS case_3;

باید به‌ترتیب ۱۰۸، ۶۰ و ۴۵٫۵۰ ببینی. اگه با نوع DECIMAL نمایش متفاوتی دیدی، مقدار عددی و scale رو بررسی کن؛ صفر آخر در نمایش، لزوماً تفاوت در مقدار نیست.

Expect 108, 60, and 45.50 respectively. If DECIMAL formatting differs, inspect the numeric value and scale; a trailing zero in display does not imply a different value.

حالا Function رو داخل SELECT بگذارNow place the function inside SELECT

Function رو با هر ردیف جدول صدا می‌زنیم. از نظر query، خروجی آن یک expression عددی دیگر است؛ alias معمولی می‌گیره و می‌تونیم آن رو با مقدار پایه کنار هم ببینیم.

We call the function for each product row. To the query, its result is another numeric expression; it can receive an ordinary alias and appear beside the base value.

قیمت‌ها رو با تخفیف ۱۰ درصد گزارش کنReport prices after a 10 percent discount
SELECT product_id,product_name,base_price,
       codenames_deadlock_lab.discounted_price(base_price,10.00)
         AS final_price
FROM codenames_deadlock_lab.product_price
ORDER BY product_id;

برای این fixture باید ۱۰۸، ۷۲ و ۴۰٫۹۵ در ستون final_price ببینی. query رو با SELECT سادهٔ قیمت پایه مقایسه کن؛ تابع ستون جدیدی به جدول اضافه نکرد و چیزی رو ذخیره نکرد، فقط هنگام اجرا مقدار رو ساخت.

For this fixture, final_price should show 108, 72, and 40.95. Compare it with a plain SELECT of base prices: the function added no column and stored nothing; it computed values during query execution.

This table is not a mechanical selection checklist. Some logic should remain directly in SQL and never become a routine. If a function is trivial and used once, another name may reduce clarity; if a short rule is shared, a function can prevent formula drift.

Function با Procedure یکی نیست؛ این محدودیت‌ها رو حس کنA function is not a procedure; experience its restrictions

چون Function می‌تونه وسط expression اجرا بشه، MySQL روی کارهایی که داخلش انجام می‌دیم محدودیت می‌ذاره. Function نمی‌تونه result set مستقل بیرون بده؛ برای خواندن چند مقدار باید آن‌ها رو به متغیر محلی بخواند یا cursor به کار ببرد. نمی‌تونه transaction رو شروع یا commit/rollback کند و recursion هم مجاز نیست.

Because a function can run inside an expression, MySQL restricts what it may do. A function cannot emit an independent result set; to consume multiple values it must use local variables or a cursor. It cannot start, commit, or roll back a transaction, and recursion is not permitted.

جدول فراخوان رو از داخل Function تغییر ندهDo not modify the invoking statement’s table from the function

Stored Function یا trigger نمی‌تونه جدولی رو تغییر بده که statement فراخواننده همان موقع برای خواندن یا نوشتن استفاده می‌کنه. مثلاً Functionای رو که جدول product_price رو تغییر می‌ده داخل UPDATE همان جدول صدا نزن. برای side effect از Procedure یا DML صریح در لایهٔ درست استفاده کن.

A stored function or trigger cannot modify a table that the invoking statement is already reading or writing. For example, do not call a function that changes product_price from an UPDATE of that same table. Use a procedure or explicit DML at the appropriate layer for side effects.

برای همین تابع تخفیف ما فقط محاسبه می‌کنه. اگه با هر فراخوانی discount رو در جدول ثبت کند، یک SELECT ساده دیگر فقط «گزارش» نیست و در queryهای چندردیفی side effect پنهان خواهد داشت.

That is why our discount function only computes. If each call wrote a discount record, a simple SELECT would no longer be “just a report” and multi-row queries would hide side effects.

قابل‌استفاده در WHERE بودن، مساوی index-friendly بودن نیستUsable in WHERE does not mean index-friendly

Function در WHERE از نظر syntax مجاز است، اما وقتی دور ستون indexشده تابع می‌پیچی، optimizer ممکنه نتواند شرط رو مثل range مستقیم روی خود ستون به کار ببرد. این حکم قطعی برای هر plan نیست؛ باید با EXPLAIN روی داده و نسخهٔ خودت بررسی‌اش کنی.

A function is syntactically usable in WHERE, but wrapping an indexed column may prevent the optimizer from using the predicate as a direct range on that column. This is not an absolute rule for every plan; inspect EXPLAIN with your data and server version.

دو صورت شرط رو کنار هم EXPLAIN کنEXPLAIN both predicate forms

برای تخفیف ثابت ۲۰٪، قیمت نهایی حداقل ۱۰۰ یعنی قیمت پایه حداقل ۱۲۵؛ صورت دوم امکان استفاده از index رو مستقیم‌تر بیان می‌کنه. با سه ردیف نتیجهٔ plan ممکنه به‌خاطر هزینهٔ تخمینی full scan باشه؛ fixture کوچک برای اثبات برتری performance کافی نیست. اول منطق دو شرط رو ثابت کن، بعد با دادهٔ واقعی اندازه بگیر.

At a fixed 20% discount, a final price of at least 100 means a base price of at least 125; the second form exposes the indexed column more directly. With only three rows, the optimizer may choose a scan based on estimated cost, so this fixture cannot prove a performance win. First prove the predicates are equivalent, then measure on representative data.

همچنین یک Function ممکنه در هر row اجرا بشه؛ فرض نکن MySQL نتیجه رو خودکار cache می‌کنه. اگه Function جدول‌خوان، پرهزینه یا دارای side effect باشه، query بزرگ رو به چند فراخوانی پنهان تبدیل می‌کنه. شمار ردیف‌ها و plan رو کنار هم بخوان.

A function may also execute for each row; do not assume MySQL automatically caches its result. If it reads tables, is expensive, or has side effects, a large query can hide many repeated operations. Read row counts and the plan together.

DETERMINISTIC یک ادعای نویسنده است، نه آزمایش serverDETERMINISTIC is the author’s claim, not a server test

تابع deterministic برای ورودی یکسان همیشه نتیجهٔ یکسان دارد. تابعی که به NOW()، RAND()، دادهٔ mutable یا وضعیت session تکیه کند معمولاً nondeterministic هست. MySQL این ادعا رو از بدنه به‌طور کامل استنتاج نمی‌کنه؛ برچسب نادرست می‌تونه روی plan یا binary logging اثر بد بگذارد.

A deterministic function always returns the same result for the same inputs. A function that depends on NOW(), RAND(), mutable table data, or session state is generally nondeterministic. MySQL does not fully infer this claim from the body; a false declaration can affect plans or binary logging.

همین‌طور NO SQL، READS SQL DATA و MODIFIES SQL DATA رو برای توصیف صادقانه بنویس، نه برای محدودکردن server. این characteristicها advisory هستن. اگه binary logging فعال باشه، تعریف Function ممکنه به privilege یا تنظیمات ویژهٔ server وابسته شود؛ روی محیط مقصد و مستندات نسخهٔ خودش verify کن.

Likewise, use NO SQL, READS SQL DATA, or MODIFIES SQL DATA as honest descriptions, not as server enforcement. These characteristics are advisory. With binary logging enabled, creating a function can depend on server privileges or configuration; verify against the target environment and its version-specific documentation.

ادعای ذخیره‌شده رو inspect کنInspect the stored declaration
SHOW CREATE FUNCTION codenames_deadlock_lab.discounted_price\G
SELECT ROUTINE_NAME,IS_DETERMINISTIC,SQL_DATA_ACCESS,SECURITY_TYPE

metadata می‌گه چه چیزی declare شده، نه این‌که Function واقعاً همان رو رعایت می‌کنه یا سریع هست. برای رفتار، چند ورودی رو تست کن؛ برای کارایی، query مصرف‌کننده رو EXPLAIN کن.

Metadata tells you what was declared, not whether the function actually obeys it or is fast. Test behavior with multiple inputs; EXPLAIN the consuming query to investigate cost.

وقتی Function در جای اشتباه قرار می‌گیرهWhen a function is used in the wrong place

به‌جای CALL از function استفاده می‌کنم

Function رو در SELECT یا expression صدا بزن؛ برای Procedure از CALL استفاده کن. نتیجهٔ Function scalar است، نه OUT parameter.

I use a function like CALL

Invoke a function in SELECT or another expression; use CALL for a procedure. A function returns a scalar, not an OUT parameter.

با SELECT داخل Function نتیجهٔ جدولی می‌دهم

Function result set مستقل نمی‌ده. مقدار query رو با SELECT ... INTO داخل متغیر بخوان یا نیاز رو با Procedure/Query حل کن.

I return a table using SELECT inside a function

A function cannot emit an independent result set. Read a selected value into a local variable or use a procedure/query for the requirement.

هر Function رو DETERMINISTIC اعلام می‌کنم

همان ورودی رو چند بار و با وضعیت‌های متفاوت امتحان کن؛ وابستگی به زمان، داده یا session رو در نظر بگیر. declaration جای تست نیست.

I mark every function DETERMINISTIC

Test the same input repeatedly under relevant states and inspect time, data, or session dependencies. A declaration is not a test.

روی ستون indexشده تابع می‌گذارم و انتظار range دارم

EXPLAIN دو فرم شرط رو مقایسه کن. اگه می‌تونی قاعدهٔ معادل روی خود ستون بنویسی، آن رو اندازه بگیر؛ از نام Function نتیجهٔ optimizer رو حدس نزن.

I wrap an indexed column and expect a range scan

Compare both predicate forms with EXPLAIN. If an equivalent condition can target the column directly, measure it; do not infer the plan from the function’s name.
