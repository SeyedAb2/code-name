دو database داریم؛ آیا واقعاً دو MySQL server هم داریم؟

We have two databases. Do we really have two MySQL servers?

گزارش باید سفارش‌ها رو از یک database و مرجع محصولات رو از یکی دیگر بخواند. هر دو شاید در یک MySQL instance باشند، شاید هم هرکدام روی server جدا. قبل از ساخت connection دوم، این تفاوت رو از hostname، port و @@server_uuid ثابت می‌کنیم؛ بعد می‌فهمیم کدام query با یک session ممکنه و کدام نیاز به هماهنگی برنامه دارد.

A report reads orders from one database and product data from another. Both databases may live on one MySQL instance, or each may be on a different server. Before creating another connection, we will prove the distinction using hostname, port, and server identity, then identify which queries can share one session.

database نام یک container منطقی است؛ server یک instanceA database is a logical namespace; a server is an instance

دو schema روی یک server رو می‌توان با نام کامل table در یک query join کرد، اگه account مجوز لازم رو داشته باشه. اما دو hostname یا instance متفاوت دو connection و دو failure domain می‌سازند. نام‌هایی مثل production و reporting به‌تنهایی ثابت نمی‌کنن دو server جدا هستن.

Two schemas on one server can be joined with qualified table names in one query if the account has the required privileges. Different hosts or instances require separate connections and create separate failure domains. Names such as production and reporting do not prove that servers are distinct.

SELECT @@hostname, @@port, @@server_uuid, VERSION();
SELECT TABLE_SCHEMA, TABLE_NAME
FROM information_schema.tables
WHERE TABLE_SCHEMA IN ('sales_lab','catalog_lab')
ORDER BY TABLE_SCHEMA, TABLE_NAME;

server_uuid در یک instance شناسهٔ server رو می‌ده؛ در clone یا محیط‌های خاص باید تفسیرش رو با روش provisioning تطبیق بدهی. credential رو چاپ نکن.

server_uuid identifies the instance, but clones and special provisioning can affect interpretation. Correlate it with environment setup; never print credentials.

دو schema در یک query؛ یک connectionTwo schemas in one query, one connection

اگه هر دو schema روی همین server هستن، نام table رو schema-qualified بنویس. account برنامه باید فقط مجوزهای لازم در هر دو محدوده رو داشته باشه. این query هنوز در همان instance اجرا می‌شه؛ جابه‌جایی schema آن رو به distributed query تبدیل نمی‌کنه.

If both schemas are on the same server, qualify table names with their schemas. The application account needs only the necessary grants in both scopes. The query still runs on one instance; separate schemas do not make it a distributed query.

SELECT o.order_id, p.product_name
FROM sales_lab.order_items AS o
JOIN catalog_lab.products AS p
  ON p.product_id = o.product_id
WHERE o.order_id = ?;

placeholder برای order_id رو از application driver bind کن. پیش از production، query plan و grantها رو بررسی کن.

Bind order_id through the application driver. Review the plan and grants before production.

دو server یعنی دو pool و دو healthTwo servers mean two pools and two health states

برای دو مقصد جدا، config و pool هرکدام رو صریح نام‌گذاری کن. hostname و database رو از environment بگیر، credential جدا نگه دار و log رو با نام مقصد علامت بزن. اگه یکی unavailable شد، گزارش ناقص رو بی‌صدا موفق اعلام نکن.

For separate targets, name each pool and configuration explicitly. Load hosts and schemas from environment, keep credentials separate, and tag logs with the destination. If one target is unavailable, do not silently report a partial result as success.

These pools execute separate queries. Promise.all provides concurrency, not a shared transaction or consistent snapshot.

نتیجهٔ دو server ممکنه هم‌زمان نباشهResults from two servers may not be simultaneous

اگه داده‌ها بین دو مقصد replication می‌شوند یا جدا نگه داشته شده‌اند، زمان queryها مهم هست. دو خواندن پشت‌سرهم snapshot مشترک ندارن. برای گزارش حساس باید freshness، lag و رفتار هنگام شکست رو در قرارداد مشخص کنی؛ روی join محلی بین schemaها فرض نکن.

If data is replicated or independently maintained, query timing matters. Two reads do not share one snapshot. For a sensitive report, define freshness, lag, and failure behavior; do not assume a local cross-schema join.

دو database روی یک Server هنوز یه connection دارنTwo databases on one server still share one server connection
