عیب‌یابی رخداد دیتابیسDatabase incident diagnosis

اول اثر رو محدود کن: همهٔ اتصال‌ها یا یک endpoint؟ زمان شروع با deploy، تغییر schema یا افزایش بار هم‌زمان است؟ وضعیت threadها، connectionها، digestها، lock waitها، error log، disk و memory رو کنار هم بگذار. query تشخیصی رو کم‌هزینه و read-only نگه دار. هنگام incident، summary رو پاک یا table رو بی‌برنامه restart/kill نکن. Repair کوچک رو انجام بده، سپس همان queryها و user-facing check رو تکرار کن.

First scope impact: all connections or one endpoint? Does the start time align with a deploy, schema change, or workload increase? Correlate thread and connection state, digests, lock waits, error logs, disk, and memory. Keep diagnostic queries cheap and read-only. During an incident, do not clear summaries or restart/kill blindly. Apply a small repair, then repeat the same diagnostics and user-facing check.
