راه‌اندازی MariaDB و اتصال امن

Installing and Connecting to MariaDB

«به دیتابیس وصل نمی‌شم» هنوز نمی‌گه کجای مسیر خراب شده. شاید Docker به Engine نمی‌رسه؛ شاید Server آماده نیست؛ شاید host یا port را اشتباه زده‌ایم؛ شاید هم login رد شده. بیا هر مرز را جدا آزمایش کنیم تا رمز را بی‌دلیل عوض نکنیم.

“I cannot connect to the database” does not tell us which boundary failed. Docker may not reach its Engine; the server may not be ready; the host or port may be wrong; or authentication may have failed. We test each boundary rather than change passwords at random.

پیش‌نیاز / Prerequisite: Chapter 1, Docker basicsMariaDB 11.8.9۸۰ دقیقه · ۱۸ تمرین / 80 minutes · 18 exercises

اولین خطا را پیدا کن / Find the first failing boundary

اگر docker version بخش Server را نشان ندهد، درخواست هنوز به Engine نرسیده؛ MariaDB و password نقشی ندارند. اگر log می‌گوید initialization ادامه دارد، login زودهنگام طبیعی است. Access denied یعنی TCP به Server رسیده و حالا باید account را بررسی کنیم.

If docker version cannot show Server, the request has not reached the Engine. If logs show initialization, early login failure is expected. Access denied means TCP reached the server; now inspect the account.

قاعده / Rule:شاهد را به‌ترتیب بگیر: Engine، container، آمادگی، port، TCP، authentication.Collect evidence in order: Engine, container, readiness, port, TCP, authentication.

پیش از Server، مقصد Docker را بشناس / Identify Docker’s target

CLI نصب‌شده فقط ابزار درخواست‌فرستادن است. Engine باید از context فعال جواب بدهد. این دو فرمان را اجرا کن.

An installed CLI is only a request-sending tool. The Engine must answer through the active context. Run these commands.

CLI تا Engine / CLI to Engine
docker version
docker context ls

اگر فقط Client را دیدی، در Windows Docker Desktop و در Linux سرویس Engine را بررسی کن. در WSL هم context و integration باید با محیط فعلی یکی باشد. تغییر password دیتابیس این مرحله را درست نمی‌کند.

If only Client appears, inspect Docker Desktop on Windows or the Engine service on Linux. In WSL, context and integration must match your current shell. A database password cannot fix this boundary.

Server دورریختنی با port محدود / Disposable server with a scoped port

image رسمی را با tag ثابت می‌آوریم. host port 3307 فقط روی loopback منتشر می‌شود و به 3306 داخل container می‌رسد. passwordهای نمونه ساختگی‌اند؛ environment در تنظیمات container قابل مشاهده است و این روش secret تولیدی نیست.

We use a fixed tag from the official image. Host port 3307 binds only to loopback and forwards to container port 3306. Passwords are disposable; environment values are inspectable, so this is not production secret management.

ساخت آزمایش / Create the lab
docker run -d --name mariadb-connect-lab -p 127.0.0.1:3307:3306 -e MARIADB_ROOT_PASSWORD=lab-root-only -e MARIADB_DATABASE=connect_lab -e MARIADB_USER=lab_user -e MARIADB_PASSWORD=lab-user-only mariadb:11.8.9

image متغیرهای MARIADB_* را موقع initialization می‌خواند؛ برای data directory موجود، تغییر env لزوماً حساب را تغییر نمی‌دهد. موفقیت docker run هم آمادگی را ثابت نمی‌کند. وضعیت، log و mapping را جدا بخوان:

The image reads MARIADB_* at initialization; changing env does not necessarily alter accounts in an existing data directory. A successful docker run does not prove readiness. Inspect state, logs, and mapping separately:

سه شاهد / Three signals
docker ps --filter name=mariadb-connect-lab
docker logs --tail 30 mariadb-connect-lab
docker port mariadb-connect-lab

Running یعنی process زنده است؛ log باید پایان initialization را نشان دهد. image رسمی healthcheck دارد؛ healthy فقط موفقیت همان آزمون را می‌گوید، نه دسترسی همهٔ accountها را.

Running means the process is alive; logs should show initialization completed. The official image has a health check; healthy reports that test only, not that every account can connect.

اتصال واقعی میزبان را تست کن / Test a real host connection

با --protocol=TCP مطمئن می‌شویم Client از port منتشرشده می‌رود. --password را بی‌مقدار می‌دهیم تا prompt تعاملی بیاید.

Explicit --protocol=TCP ensures the client uses the published port. Leaving --password without a value prompts interactively.

Client میزبان / Host client
mariadb --protocol=TCP --host=127.0.0.1 --port=3307 --user=lab_user --password connect_lab

بعد از ورود، query را در prompt خود MariaDB اجرا کن. USER() هویت ارائه‌شده و CURRENT_USER() حسابی را می‌دهد که grantهایش اعمال می‌شود. database تازه ممکن است خالی باشد؛ Access denied با timeout یکی نیست.

After login, run the query at the MariaDB prompt. USER() reports presented identity; CURRENT_USER() reports the account whose grants apply. A new database may be empty; Access denied is not a timeout.

پرس‌وجو در نشست / Query inside the session
SELECT VERSION(), @@version_comment, @@hostname, @@port, DATABASE(), USER(), CURRENT_USER();
SHOW TABLES;

نصب native را با Docker قاطی نکن / Keep native separate from Docker

روی Linux، package سیستم‌عامل و مخزن MariaDB چرخهٔ نسخه و defaultهای متفاوت دارند؛ راهنمای توزیع خودت را دنبال کن. این نمونه فرض می‌کند systemd و unit به نام mariadb داری؛ نام unit و authentication محلی ممکن است فرق کند.

Distribution packages and MariaDB’s repository have different release streams and defaults; follow your distribution guide. This example assumes systemd and a unit named mariadb; unit names and local authentication vary.

وضعیت service / Service status
sudo systemctl status mariadb --no-pager
mariadb --protocol=socket -u root -p -e "SELECT VERSION(), @@version_comment;"

systemctl فقط وضعیت unit را می‌گوید؛ listener، firewall و authentication جدا هستند. برای نصب دقیق از مستندات جاری MariaDB و توزیعت استفاده کن.

systemctl reports unit state only; listener, firewall, and authentication are separate. Use current MariaDB and distribution instructions for installation.

شاهدها را ثبت کن، بعد پاک کن / Record evidence, then clean up

نسخه، state، port و نتیجهٔ login را ثبت کن؛ بعد فقط همین container را حذف کن. volume نام‌دار نساختیم. پیش از حذف هر volume بپرس چه داده‌ای دارد.

Record version, state, port, and login result; then remove only this container. We created no named volume. Before deleting any volume, ask what data it contains.

پاک‌سازی هدفمند / Scoped cleanup
docker rm -f mariadb-connect-lab
docker ps -a --filter name=mariadb-connect-lab
از prune عمومی استفاده نکن / Avoid global prune. It may remove resources used by other projects.

۱۸ تمرین اجرایی / 18 hands-on exercises

1) Docker جواب نمی‌دهد / Docker does not answer

docker version فقط Client دارد؛ بعد چه می‌کنی؟

docker version shows only Client; what next?

شاهد و تفسیر / Evidence and interpretation
docker context ls

مقصد فعال و daemon را بررسی کن؛ هنوز MariaDB درگیر نیست.

Check target and daemon; MariaDB is not involved yet.

2) Running اما login ناموفق / Running, login fails

پیش از retry چه شاهدهایی می‌گیری؟

Which signals before retry?

شاهد و تفسیر / Evidence and interpretation
docker logs --tail 30 mariadb-connect-lab

ممکن است initialization تمام نشده باشد.

Initialization may not be finished.

3) تفسیر port / Interpret the port

127.0.0.1:3307->3306/tcp؛ Client میزبان کدام port؟

Which port should the host client use?

شاهد و تفسیر / Evidence and interpretation
docker port mariadb-connect-lab

3307 میزبان است؛ 3306 داخل container.

3307 is the host port; 3306 is inside.

4) loopback / Loopback binding

چرا bind به 127.0.0.1 محدودتر است؟

Why is binding to 127.0.0.1 more restrictive?

شاهد و تفسیر / Evidence and interpretation

فقط اتصال محلی میزبان؛ جای firewall را نمی‌گیرد.

Host-local only; it does not replace a firewall.

5) timeout روی 3308 / Timeout on 3308

Server روی 3307 است. password را عوض می‌کنی؟

Server is on 3307. Change the password?

شاهد و تفسیر / Evidence and interpretation

نه؛ timeout پیش از authentication رخ داده.

No; timeout occurs before authentication.

6) Access denied / Access denied

TCP جواب داده؛ فرض‌های مرتبط چیست؟

TCP answered; what hypotheses matter?

شاهد و تفسیر / Evidence and interpretation

credential و account host matching را بررسی کن.

Check credentials and account host matching.

7) TCP صریح / Explicit TCP

فرمان اتصال host را بنویس.

Write the host connection command.

شاهد و تفسیر / Evidence and interpretation
mariadb --protocol=TCP -h 127.0.0.1 -P 3307 -u lab_user -p connect_lab

TCP را مجبور می‌کند و password را تعاملی می‌پرسد.

Forces TCP and prompts for the password.

8) هویت Server / Server identity

محصول، نسخه و port داخلی را بخوان.

Read product, version, and internal port.

شاهد و تفسیر / Evidence and interpretation
SELECT VERSION(), @@version_comment, @@port;

port میزبان را Docker گزارش می‌کند.

Docker reports the host port.

9) state و health / State and health

هر دو وضعیت را با inspect بخوان.

Read both states with inspect.

شاهد و تفسیر / Evidence and interpretation
docker inspect --format '{{.State.Status}} / {{if .State.Health}}{{.State.Health.Status}}{{end}}' mariadb-connect-lab

اولی process state است؛ دومی نتیجهٔ healthcheck.

First is process state; second is health-check result.

10) سه نسخه / Three versions

image، Client، Server را جدا ثابت کن.

Prove image, client, and server separately.

شاهد و تفسیر / Evidence and interpretation
docker inspect --format '{{.Config.Image}}' mariadb-connect-lab

tag به‌تنهایی نسخهٔ Server مقصد query را ثابت نمی‌کند.

The tag alone does not prove the server your query reached.

11) account matchشده / Matched account

هویت ارائه‌شده و حساب مجوزدار را مقایسه کن.

Compare presented identity and privilege account.

شاهد و تفسیر / Evidence and interpretation
SELECT USER(), CURRENT_USER();

CURRENT_USER حسابی را نشان می‌دهد که grantهایش اعمال می‌شوند.

CURRENT_USER identifies the account whose grants apply.

12) database خالی / Empty database

login موفق است ولی table نیست؛ چه می‌خوانی؟

Login succeeds but there are no tables; what do you query?

شاهد و تفسیر / Evidence and interpretation
SELECT DATABASE(), @@hostname, @@port; SHOW TABLES;

database تازه ممکن است خالی باشد.

A new database may be empty.

13) env بی‌اثر / Environment had no effect

چرا تغییر MARIADB_PASSWORD روی data موجود بی‌اثر است؟

Why may changing MARIADB_PASSWORD not affect existing data?

شاهد و تفسیر / Evidence and interpretation

image متغیر را در initialization می‌خواند؛ account را با SQL تغییر بده.

The image reads it at initialization; change the account through SQL.

14) daemon یا password / Daemon or password

Cannot connect to daemon و Access denied را طبقه‌بندی کن.

Classify both errors.

شاهد و تفسیر / Evidence and interpretation

اول CLI-to-Engine؛ دومی server-to-account.

First is CLI-to-Engine; second is server-to-account.

15) پاک‌سازی محدود / Scoped cleanup

فقط container این lab را پاک کن و نبودش را ثابت کن.

Remove only this lab container and prove it is gone.

شاهد و تفسیر / Evidence and interpretation
docker rm -f mariadb-connect-lab; docker ps -a --filter name=mariadb-connect-lab

prune عمومی نزن.

Do not use global prune.

16) service فعال، TCP نامعلوم / Service active, TCP unknown

چرا systemctl موفق port را ثابت نمی‌کند؟

Why does systemctl not prove the port works?

شاهد و تفسیر / Evidence and interpretation

unit state، listener، firewall و authentication جدا هستند.

Unit state, listener, firewall, and authentication are separate.

17) گزارش timeout / Report a timeout

نشانه، شاهد، تشخیص و verification را بنویس.

Write symptom, evidence, diagnosis, and verification.

شاهد و تفسیر / Evidence and interpretation

timeout روی 3308 و mapping روی 3307، فرضیهٔ port اشتباه را می‌سازد؛ با TCP به 3307 دوباره query بگیر.

Timeout on 3308 with a 3307 mapping suggests a wrong port; retry over TCP on 3307.

18) healthy ولی Access denied / Healthy but Access denied

قدم بعدی پس از تأیید health و port چیست؟

What next after health and port are verified?

شاهد و تفسیر / Evidence and interpretation

credential، user و grant را بررسی کن؛ health همهٔ accountها را نمی‌آزماید.

Check credentials, user, and grants; health does not test every account.
