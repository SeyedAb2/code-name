برنامه از راه دور وصل می‌شه؛ از کجا بفهمیم ارتباط واقعاً TLS داره؟

The application connects remotely. The team says the port is open, so traffic must be encrypted. How can we tell?

بازبودن port 3306 فقط ثابت می‌کنه TCP به جایی می‌رسه. ثابت نمی‌کنه data رمز شده، certificate معتبر هست یا client واقعاً به همان server موردنظر وصل شده. این فصل این سه مرز رو جدا می‌کنه.

An open port 3306 only proves that TCP reaches something. It does not prove encrypted traffic, certificate validation, or that the client reached the intended server. This chapter separates those boundaries.

قبل از کد، مسئله رو درست ببینFrame the problem before the code

این فصل رو با syntax شروع نمی‌کنیم. مسئله اینه: TLS، encryption و اعتبار هویت server. اول یه پیش‌بینی می‌سازیم، بعد با query یا command کوچیک آزمایشش می‌کنیم. هر جا خروجی خلاف انتظار بود، همون‌جا درس اصلی شروع می‌شه.

This chapter does not begin with syntax. The problem is TLS, encryption, and server identity validation. We will form a prediction, test it with a small query or command, and treat unexpected output as the beginning of the investigation.

Connectivity، encryption و identity سه سؤال‌اندConnectivity, encryption, and identity are different questions

اول network connection رو داریم، بعد TLS cipher رو از همان session می‌خونیم، و تازه بعد می‌پرسیم client certificate/CA و hostname رو چطور validate کرده.

اگه Ssl_cipher مقدار داره، encryption برقرار هست؛ ولی این به‌تنهایی نمی‌گه client هویت server رو درست verify کرده.

First establish network connectivity, then inspect the TLS cipher from the same database session, and only then ask how the client validated the CA and hostname.

A non-empty Ssl_cipher proves encryption is in use, but by itself it does not prove correct server identity validation.

SHOW GLOBAL VARIABLES LIKE 'have_ssl';

این query قرار نیست چیزی رو تعمیر کنه؛ فقط state رو قابل‌دیدن می‌کنه. مقدارهای مرتبط با Ssl_cipher، نسخه TLS، account requirement و hostname validation رو ثبت کن و قبل از هر تغییر بعدی snapshot رو نگه دار.

This query is observational. Capture the relevant state before changing anything so later conclusions about TLS, encryption, and server identity validation can be tied to evidence.

Server می‌تونه TLS رو الزام کندThe server can require TLS

برای account حساس می‌توان REQUIRE SSL یا در سناریوی certificate authentication محدودیت قوی‌تر گذاشت. بعد باید اتصال بدون TLS عمداً fail شود.

Failure اینجا feature هست؛ ثابت می‌کنه policy فقط روی کاغذ نیست.

Sensitive accounts can require TLS with REQUIRE SSL, with stronger certificate requirements where appropriate. A connection without TLS should then fail deliberately.

That failure is useful evidence: it proves the policy is enforced rather than documented only.

ALTER USER 'api_user'@'10.%' REQUIRE X509;

این تغییر رو فقط روی fixture انجام بده و before/after رو نگه دار. موفق‌شدن statement به‌تنهایی کافی نیست؛ نتیجهٔ واقعی رو با Ssl_cipher، نسخه TLS، account requirement و hostname validation verify کن.

Run the change only on the fixture and preserve before/after evidence. A successful statement alone does not prove the desired end state.

Hostname verification رو عمداً خراب کنBreak hostname validation deliberately

در lab با hostnameی که داخل SAN certificate نیست وصل شو. اگه client واقعاً identity رو verify کند، این اتصال باید رد شود.

بعد با hostname درست تکرار کن. این آزمایش فرق encryption و authentication of endpoint رو خیلی بهتر از تعریف تئوری جا می‌اندازد.

In the lab, connect using a hostname that is absent from the certificate SAN. A client that truly verifies server identity should reject it.

Repeat using the correct hostname. This experiment makes the distinction between encryption and endpoint authentication concrete.

Certificate هم lifecycle دارهCertificates have a lifecycle

گواهی expire می‌شه، rotate می‌شه و trust store عوض می‌شه. اگه فقط روز نصب تست کنی، چند ماه بعد outage غافلگیرت می‌کنه.

تاریخ انقضا، مسیر CA و procedure rotation رو مستند کن و rotation رو در lab با reconnect واقعی تمرین کن.

Certificates expire, rotate, and depend on trust stores that can change. A one-time installation test does not protect against a future outage.

Document expiry, CA distribution, and rotation steps, then rehearse rotation with a real reconnect in the lab.
