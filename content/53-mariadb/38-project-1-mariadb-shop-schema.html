پروژهٔ ۱ — مهاجرت آزمایشی MySQL به MariaDB

Project 1 — A test migration from MySQL to MariaDB

فروشگاه روی MySQL کار می‌کنه و تیم می‌خواهد پیش از تصمیم production، یک کپی disposable رو به MariaDB ببرد و اختلاف‌ها رو با query پیدا کند.

A shop runs on MySQL. Before any production decision, the team wants to migrate a disposable copy to MariaDB and identify differences with queries.

عملی · Practicalتحویل با evidence · Evidence-based handoff

ماموریتMission

schema، دادهٔ ساختگی، JSON، collation، routineها و queryهای حساس رو مقایسه کن. پروژه با SQL قابل‌اجرا و شواهد row/aggregate کامل می‌شه؛ توضیح «سازگار است» کافی نیست.

Compare schema, synthetic data, JSON, collations, routines, and sensitive queries. Deliver runnable SQL and row/aggregate evidence; a claim that it is compatible is not enough.

پروژه رو روی دادهٔ disposable انجام بده. پاسخ تشریحی به‌تنهایی قبولی نیست؛ query، خروجی، فایل artifact یا تست باید قابل‌بررسی باشد.

Use disposable data. Explanations alone do not pass; queries, outputs, artifacts, or tests must be reviewable.

مراحل مأموریتMission milestones

1) ساختار مبدا1) Source structure

از MySQL فقط schema و fixture بی‌خطر بساز و نسخه رو ثبت کن.

Export only schema and safe fixtures from MySQL and record its release.

SELECT VERSION(); SHOW CREATE TABLE products;

مدرک: DDL مبدا و row counts رو نگه دار.

Proof: Preserve source DDL and row counts.

راهنماییHint

از production data و credential واقعی استفاده نکن.

Do not use production data or real credentials.

2) مقصد disposable2) Disposable target

MariaDB رو با نسخهٔ انتخابی در محیط جدا بالا بیاور و مقصد رو verify کن.

Start the chosen MariaDB release in isolation and verify the target identity.

SELECT VERSION(),@@hostname;

مدرک: خروجی مقصد نشان دهد با MySQL اشتباه نشده.

Proof: Prove the target is MariaDB, not the source.

راهنماییHint

data directory مشترک ممنوع.

Never share the source data directory.

3) تفاوت‌ها3) Differences

JSON، collation و routineهای استفاده‌شده رو به queryهای کوچک تبدیل و دو طرف اجرا کن.

Turn used JSON, collation, and routine features into small queries and run them on both servers.

SHOW CREATE TABLE products; SELECT JSON_VALID(payload) FROM fixtures;

مدرک: جدول compatibility matrix با خروجی واقعی بساز.

Proof: Build a compatibility matrix from actual output.

راهنماییHint

فقط featureهای واقعاً مصرف‌شده رو بررسی کن.

Focus on features the app actually uses.

4) انتقال و اعتبارسنجی4) Migration and validation

dump رو import کن و count، aggregate و queryهای API رو compare کن.

Import the dump and compare counts, aggregates, and API queries.

SELECT COUNT(*),SUM(price) FROM products;

مدرک: خروجی‌ها با baseline سازگار باشند یا اختلاف مستند شود.

Proof: Results match the baseline or differences are documented.

راهنماییHint

هیچ mismatch رو با تغییر داده پنهان نکن.

Do not hide mismatches by altering data.

5) تصمیم و handoff5) Decision and handoff

موارد blocker، remediation، rollback و تست قابل‌تکرار رو تحویل بده.

Hand off blockers, remediation, rollback, and reproducible tests.

-- README: versions, commands, evidence, differences, rollback

مدرک: نفر دیگر بتواند از clean setup تکرار کند.

Proof: Another person can reproduce from a clean setup.

راهنماییHint

سازگاری binary و row-based replication رو بدون آزمایش ادعا نکن.

Do not claim replication compatibility without testing.

بازبینی تحویلHandoff review

پروژه رو از صفر در محیط تمیز اجرا کن. مطمئن شو artifact قابل‌خواندن و restore هست، secret جا نمانده و شخص دیگری می‌تونه نتیجه رو تکرار کند.

Run the project from scratch in a clean environment. Verify the artifact is readable and restorable, no secret remains, and another person can reproduce the result.
