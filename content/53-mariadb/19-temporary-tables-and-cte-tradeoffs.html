یک query چندمرحله‌ای یا CTE داره یا جدول موقت. کدام‌یک واقعاً بهتر هست؟

A multi-step report can use a CTE or a temporary table. Which one is actually better?

CTE و temporary table هر دو می‌تونن query پیچیده رو خواناتر کنند، ولی lifecycle و رفتار optimizerشان یکی نیست. سؤال این فصل «کدام بهتر هست؟» نیست؛ «برای این workload کدام هزینه رو می‌خواهم؟» هست.

CTEs and temporary tables can both make complex work easier to express, but they have different lifetimes and optimizer behavior. The question is not “which is always better?” but “which cost model fits this workload?”

قبل از کد، مسئله رو درست ببینFrame the problem before the code

این فصل رو با syntax شروع نمی‌کنیم. مسئله اینه: انتخاب CTE یا temporary table با evidence. اول یه پیش‌بینی می‌سازیم، بعد با query یا command کوچیک آزمایشش می‌کنیم. هر جا خروجی خلاف انتظار بود، همون‌جا درس اصلی شروع می‌شه.

This chapter does not begin with syntax. The problem is evidence-based choice between CTEs and temporary tables. We will form a prediction, test it with a small query or command, and treat unexpected output as the beginning of the investigation.

CTE رو table مخفی فرض نکنDo not assume a CTE is a hidden table

CTE اسم دادن به یک query داخل همان statement هست. optimizer می‌تونه بسته به query آن رو merge یا materialize کند؛ پس جملهٔ «CTE یک بار اجرا می‌شه» قرارداد مطمئنی نیست.

EXPLAIN رو روی نسخهٔ CTE و نسخهٔ مستقیم می‌گیریم تا تصمیم واقعی optimizer رو ببینیم.

A CTE names a query within one statement. The optimizer may merge or materialize it depending on the query, so “a CTE runs once” is not a reliable contract.

Explain both the CTE and direct-query forms to observe what the optimizer actually chooses.

WITH x AS (SELECT id FROM customers) SELECT * FROM x;

Temporary table state واقعی دارهA temporary table has real session state

Temporary table در connection ساخته می‌شه، می‌تونی رویش index بسازی و در چند statement همان session دوباره استفاده‌اش کنی. همین مزیت، وقتی connection pool داری، می‌تونه خطر نشت state هم باشد.

دو connection باز می‌کنیم و نشان می‌دهیم table موقت یکی در دیگری دیده نمی‌شه. بعد cleanup صریح رو وارد الگو می‌کنیم.

A temporary table exists in a connection, can have indexes, and can be reused across statements in that session. The same property can leak state when connection pooling is involved.

Open two connections to prove session isolation, then make explicit cleanup part of the pattern.

Reuse واقعی می‌تونه materialization رو توجیه کندRepeated reuse can justify materialization

اگه یک intermediate result رو سه بار لازم داری و محاسبه‌اش سنگین هست، temporary table شاید ارزش داشته باشد. اگه فقط یک بار لازم هست، materialization می‌تونه صرفاً هزینهٔ اضافه باشد.

به‌جای قانون کلی، duration، temp storage و plan هر دو روش رو روی همان dataset ثبت کن.

If an expensive intermediate result is reused multiple times, a temporary table may be worthwhile. If it is used once, materialization may only add cost.

Compare runtime, temporary storage, and plans on the same dataset instead of relying on a universal rule.

CREATE TEMPORARY TABLE tmp_customer_ids
AS SELECT id FROM customers WHERE status='active';
SELECT COUNT(*) FROM tmp_customer_ids;
SELECT c.id FROM customers c JOIN tmp_customer_ids t ON t.id=c.id;

این object عمداً کوچک و آزمایشیه تا behavior رو بدون سر و صدای production ببینیم. بعد از ساخت، با metadata یا یک query مستقل ثابت کن چیزی که می‌خواستیم واقعاً ساخته شده.

The object is intentionally small and disposable. After creating it, use independent metadata or a query to prove that the intended behavior really exists.

Recursive CTE باید مرز داشته باشدRecursive CTEs need a stopping rule

Recursive CTE برای hierarchy عالی هست تا وقتی termination روشن باشد. cycle یا شرط ناقص می‌تونه query رو بی‌دلیل بزرگ کند.

روی fixture کوچک depth رو محدود می‌کنیم، بعد عمداً cycle می‌سازیم و رفتار محدودکنندهٔ server رو می‌بینیم.

Recursive CTEs are useful for hierarchies only when termination is explicit. Cycles or weak stopping conditions can make a query explode.

Bound recursion on a small fixture, then introduce a cycle deliberately and observe the server's limiting behavior.
