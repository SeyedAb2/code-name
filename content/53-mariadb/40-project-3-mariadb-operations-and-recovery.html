پروژهٔ ۳ — backup و خوشهٔ MariaDB

Project 3 — MariaDB backup and clustering

شما on-call پایگاه‌داده هستی؛ باید backup رو واقعاً restore کنی، سلامت replication یا Galera رو prove کنی و runbook تحویل بدهی.

You are on database on-call. You must actually restore a backup, prove replication or Galera health, and hand over a runbook.

عملی · Practicalتحویل با evidence · Evidence-based handoff

ماموریتMission

یک مسیر انتخاب کن: standard replication یا Galera. backup مستقل، restore در target disposable، health evidence و failure drill لازم‌اند. cluster جای backup نیست و failover رو بدون اثبات quorum/مسیر client اعلام نکن.

Choose one path: standard replication or Galera. Require an independent backup, restore into a disposable target, health evidence, and a failure drill. A cluster is not a backup; do not claim failover without proving quorum and client routing.

پروژه رو روی دادهٔ disposable انجام بده. پاسخ تشریحی به‌تنهایی قبولی نیست؛ query، خروجی، فایل artifact یا تست باید قابل‌بررسی باشد.

Use disposable data. Explanations alone do not pass; queries, outputs, artifacts, or tests must be reviewable.

تحویل و معیار قبولیDeliverables and acceptance

  • README شامل نسخه، پیش‌نیاز، دستور اجرا و rollback / README with release, prerequisites, run, and rollback steps
  • SQL/scripts و data fixtures بدون secret واقعی / SQL/scripts and fixtures without real secrets
  • خروجی‌های واقعی و نتیجهٔ verify / Actual outputs and verification result
  • محدودیت‌ها و موردهای آزمایش‌نشده مشخص / Limitations and untested assumptions stated

مراحل مأموریتMission milestones

1) محدوده و طراحی1) Scope and design

RPO/RTO، topology، node role و exposed portها رو تعریف کن.

Define RPO/RTO, topology, node roles, and exposed ports.

-- README diagram: client → app/proxy → DB topology

مدرک: DB فقط روی شبکهٔ خصوصی باشد.

Proof: Keep the database on a private network.

راهنماییHint

داده و credential واقعی وارد lab نکن.

Keep real data and credentials out of the lab.

2) backup مستقل2) Independent backup

با mariadb-dump یا mariadb-backup، artifact بساز و version/coordinate رو ثبت کن.

Create an artifact with mariadb-dump or mariadb-backup; record release and coordinates.

mariadb-dump --single-transaction --routines --events labdb > lab.sql

مدرک: artifact و checksum رو تحویل بده.

Proof: Submit the artifact and checksum.

راهنماییHint

روش و engine رو با هم تطبیق بده.

Match method to engine and workload.

3) restore test3) Restore test

artifact رو در server جدا restore و known record رو verify کن.

Restore into a separate server and verify a known record.

mariadb restore_lab < lab.sql

مدرک: restore موفق و query نتیجه رو ذخیره کن.

Proof: Save restore success and validation output.

راهنماییHint

هرگز تنها live data رو overwrite نکن.

Never overwrite the only live data.

4) topology سلامت4) Topology health

replication یا Galera رو بالا بیاور و state رو با status/row marker ثابت کن.

Start replication or Galera and prove state with status and a row marker.

SHOW SLAVE STATUS\\G; SHOW STATUS LIKE 'wsrep_cluster_status';

مدرک: فقط از فرمان‌های مربوط به topology انتخابی استفاده کن.

Proof: Use evidence matching the chosen topology.

راهنماییHint

node online به‌تنهایی prove نیست.

An online node alone is not proof.

5) failure drill5) Failure drill

یک failure محدود در lab بساز، evidence جمع کن و recovery رو انجام بده.

Create a bounded lab failure, collect evidence, and recover.

-- preserve logs/status before intervention

مدرک: نشان بده data و channel سالم برگشته‌اند.

Proof: Prove data and channel health recovered.

راهنماییHint

از قطع شبکهٔ host اصلی خودداری کن.

Do not disrupt the host network.

6) runbook6) Runbook

backup schedule، retention، success/failure signal و restore commands رو مستند کن.

Document backup schedule, retention, success/failure signals, and restore commands.

-- include tested commands and expected output

مدرک: گام‌ها بدون حدس باشند.

Proof: Steps must not require guesswork.

راهنماییHint

مسئول و زمان آخرین restore test رو بنویس.

Record owner and latest restore-test date.

7) security review7) Security review

users، grants، TLS، firewall و artifact access رو audit کن.

Audit users, grants, TLS, firewall, and artifact access.

SHOW GRANTS FOR 'app'@'%';

مدرک: secret رو از Git و log پاک کن.

Proof: Remove secrets from Git and logs.

راهنماییHint

audit رو با یک تغییر قابل‌اثبات ببند.

Close findings with verifiable changes.

8) operational metrics8) Operational metrics

disk، connections، replication status/cluster size و errorها رو در handoff بگذار.

Include disk, connections, replication/cluster state, and errors in handoff.

SHOW GLOBAL STATUS LIKE 'Threads_connected';

مدرک: snapshot با timestamp تهیه کن.

Proof: Capture a timestamped snapshot.

راهنماییHint

وعدهٔ uptime بدون معماری نده.

Do not promise uptime without architecture.

9) تحویل capstone9) Capstone handoff

README، diagram، scripts، restore proof، recovery limits و owner رو تحویل بده.

Submit README, diagram, scripts, restore proof, recovery limits, and owner.

-- final checklist: restore, health, failure drill, rollback

مدرک: نفر دیگر از clean environment نتیجه رو reproduce کند.

Proof: Another person reproduces from a clean environment.

راهنماییHint

هر چیزی که آزمایش نشده، به‌عنوان فرض ثبت شود.

Label anything untested as an assumption.

بازبینی تحویلHandoff review

پروژه رو از صفر در محیط تمیز اجرا کن. مطمئن شو artifact قابل‌خواندن و restore هست، secret جا نمانده و شخص دیگری می‌تونه نتیجه رو تکرار کند.

Run the project from scratch in a clean environment. Verify the artifact is readable and restorable, no secret remains, and another person can reproduce the result.
