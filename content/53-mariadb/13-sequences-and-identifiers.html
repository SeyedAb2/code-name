شمارهٔ فاکتور باید از شناسهٔ داخلی سفارش مستقل باشد و چند جدول هم از counterهای جدا استفاده کنند.

Invoice numbers must be independent from internal order IDs, and multiple tables need separate counters.

AUTO_INCREMENT برای کلید داخلی خیلی وقت‌ها کافی هست، ولی همیشه همان چیزی نیست که کسب‌وکار به‌عنوان شماره می‌خواهد. MariaDB SEQUENCE هم داره؛ object مستقلی که می‌تونی بین مصرف‌کننده‌ها استفاده کنی. این فصل فرق «شناسهٔ فنی» و «شمارهٔ کسب‌وکار» رو جدی می‌گیره.

AUTO_INCREMENT is often enough for an internal key, but it is not automatically the same thing as a business-facing number. MariaDB also provides independent SEQUENCE objects. This chapter separates technical identity from business numbering.

قبل از کد، مسئله رو درست ببینFrame the problem before the code

این فصل رو با syntax شروع نمی‌کنیم. مسئله اینه: تولید شناسه و فرق کلید فنی با شمارهٔ کسب‌وکار. اول یه پیش‌بینی می‌سازیم، بعد با query یا command کوچیک آزمایشش می‌کنیم. هر جا خروجی خلاف انتظار بود، همون‌جا درس اصلی شروع می‌شه.

This chapter does not begin with syntax. The problem is identifier generation and the distinction between technical keys and business numbers. We will form a prediction, test it with a small query or command, and treat unexpected output as the beginning of the investigation.

AUTO_INCREMENT رو با business number یکی نکنDo not equate AUTO_INCREMENT with a business number

کلید داخلی سفارش فقط باید آن ردیف رو قابل اشاره کند. شمارهٔ فاکتور ممکن هست rule، prefix، sequence مستقل یا lifecycle دیگری داشته باشد. اگه این دو رو یکی کنی، بعداً هر gap یا migration تبدیل به مشکل کسب‌وکار می‌شه.

اول یک table ساده با AUTO_INCREMENT می‌سازیم و می‌بینیم LAST_INSERT_ID() دقیقاً چه چیزی رو از همان connection به ما می‌ده.

An internal order key only needs to identify the row. An invoice number may have different rules, prefixes, sequences, or lifecycle. Conflating the two turns gaps and migrations into business problems.

Start with a simple AUTO_INCREMENT table and observe what LAST_INSERT_ID() actually reports for the current connection.

CREATE SEQUENCE invoice_seq START WITH 1000 INCREMENT BY 1 CACHE 20;

این object عمداً کوچک و آزمایشیه تا behavior رو بدون سر و صدای production ببینیم. بعد از ساخت، با metadata یا یک query مستقل ثابت کن چیزی که می‌خواستیم واقعاً ساخته شده.

The object is intentionally small and disposable. After creating it, use independent metadata or a query to prove that the intended behavior really exists.

Sequence یک object مستقل استA sequence is an independent object

با CREATE SEQUENCE counter رو از table جدا می‌کنیم. همین استقلال برای سناریوهایی که چند table یا چند نوع سند numbering مستقل دارن مفید هست.

SHOW CREATE SEQUENCE و metadata رو می‌خونیم تا تنظیم‌هایی مثل START, INCREMENT و CACHE رو از روی تعریف واقعی ببینیم.

CREATE SEQUENCE moves number generation out of a single table. That independence can be useful when multiple tables or document types need their own numbering streams.

Inspect SHOW CREATE SEQUENCE and metadata so START, INCREMENT, and CACHE are verified from the actual object definition.

Gap طبیعی هست؛ باگ نیستGaps are normal, not a bug

Sequence شماره رو وقتی می‌گیری رزرو می‌کنه. rollback لزوماً آن شماره رو پس نمی‌ده، cache هم می‌تونه بعد از restart gap بسازد. پس sequence رو برای نیاز «حتماً بدون فاصله» انتخاب نکن مگر مدل کسب‌وکار رو جدا حل کرده باشی.

همین آزمایش رو داخل transaction انجام می‌دهیم: عدد می‌گیریم، rollback می‌کنیم، بعد عدد بعدی رو می‌خونیم.

A sequence value is reserved when requested. Rolling back does not necessarily return it, and caching can create additional gaps after lifecycle events. Do not use a sequence as a guarantee of gapless numbering.

Make the behavior visible by requesting a value inside a transaction, rolling back, and then requesting the next value.

Topology و privilege هم بخشی از طراحی‌اندTopology and privileges are part of the design

اگه چند writer یا replication داری، numbering رو فقط روی یک laptop تست نکن. domain نوشتن، binlog format و نحوهٔ دسترسی client به sequence باید روشن باشد.

برنامه هم لازم نیست privilege وسیع داشته باشد. همان دسترسی حداقلی لازم برای گرفتن مقدار رو بده و با account واقعی برنامه تست کن.

With multiple writers or replication, do not validate numbering only on one laptop. Define the write topology, replication implications, and how clients access the sequence.

The application also does not need broad privileges. Grant the minimum required access and test using the actual application account.
