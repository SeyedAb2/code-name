The old release is nearing end of support. The team wants to open its data directory directly with a newer version.

Upgrade MariaDB و مهاجرت MySQL→MariaDB دو کار متفاوتن. در upgrade هنوز داخل خانوادهٔ MariaDB حرکت می‌کنی؛ در migration ممکنه semantics featureها عوض بشه. هر دو هم باید روی copy قابل‌دورریختن شروع بشن، نه تنها data directory موجود.

A MariaDB version upgrade and a MySQL-to-MariaDB migration are different projects. An upgrade stays within MariaDB release paths, while a migration can change feature semantics. Both should begin on a disposable copy, never on the only existing data directory.

Backup باید قبلش restore شده باشدThe backup must already have passed a restore drill

Rollback plan هم «downgrade می‌کنیم» نیست مگر مستندات صریحاً پشتیبانی کنه. معمولاً restore به نسخهٔ قبلی امن‌تر و قابل‌فهم‌تره.

Sign-off باید تفاوت‌ها رو هم ثبت کندSign-off must document differences, not just success

هدف migration این نیست که ثابت کنیم «هیچ فرقی نیست». برعکس، می‌خوایم فرق‌های مهم رو پیدا کنیم، owner و mitigationشون رو بنویسیم و بعد تصمیم بگیریم قابل‌قبول هستن یا نه.

گزارش نهایی باید versionها، تست‌ها، تفاوت‌ها، downtime/rollout و recovery path رو کنار هم داشته باشه.

A migration is not successful because it proves “there are no differences.” The useful outcome is identifying meaningful differences, assigning owners and mitigations, and deciding whether they are acceptable.

The final sign-off should contain versions, tests, observed differences, rollout/downtime expectations, and the recovery path.
