شل و فایل‌سیستمThe shell and the filesystem

به سروری تازه وصل شده‌ای. همکارت می‌گوید «فایل تنظیمات را پیدا کن»، اما هنوز نمی‌دانی کجایی یا چه مسیری امن است. قبل از دست‌زدن به چیزی، از شل یک نقشه بسازیم.

You have just connected to a new server. A teammate says, “Find the configuration file,” but you do not yet know where you are or which paths are safe. Before changing anything, let us use the shell to build a map.

۷۵دقیقهminutes
۱۸تمرینexercises
۲نمودارdiagrams

اول: کجاییم؟First: where are we?

در prompt معمولاً نام کاربر، میزبان و گاهی cwd می‌آید؛ خود prompt فرمان نیست. چیزی که بعد از آن می‌نویسی نام فرمان و آرگومان‌هایش است و shell آن را با توجه به cwd اجرا می‌کند. زدن ls پیش از دانستن پوشهٔ جاری مثل نگاه‌کردن به نقشه بدون دانستن شهر است: اول pwd، بعد ls -la.

A prompt commonly shows a user, host, and sometimes the cwd; the prompt itself is not a command. What you type after it is a command and its arguments, which the shell runs in the cwd. Running ls before knowing that directory is like looking at a map without knowing the city: ask pwd first, then use ls -la.

sara@server
pwd
/home/sara
ls -la
... . .. .bashrc .profile projects

~ در prompt معمولاً مخفف home است. . یعنی همین پوشه و .. پوشهٔ والد. پیش از فرمان تغییردهنده، دوباره pwd بزن: این کار خطر را حذف نمی‌کند، اما جلوی خطای «فکر می‌کردم جای دیگری‌ام» را می‌گیرد.

~ in a prompt usually abbreviates home. . means this directory and .. its parent. Before a command that changes files, run pwd again: it does not remove all risk, but helps prevent “I thought I was somewhere else” errors.

قاعدهٔ این فصلThis chapter’s rule

همهٔ تغییرها و حذف‌های تمرینی فقط زیر $HOME/linux-lab انجام می‌شوند؛ نه زیر مسیرهای سیستمی و نه روی فایل واقعی.

All practice changes and removals stay under $HOME/linux-lab—never in system paths or on real files.

مطلق از ریشه؛ نسبی از همین‌جاAbsolute from root; relative from here

مسیر مطلق با / شروع می‌شود و به cwd وابسته نیست. مسیر نسبی از پوشهٔ جاری resolve می‌شود. اگر cwd برابر /home/sara/work باشد، notes/todo.txt زیر همان پوشه جست‌وجو می‌شود.

An absolute path begins with / and does not depend on the cwd. A relative path is resolved from the current directory. With cwd /home/sara/work, notes/todo.txt is searched for beneath that directory.

درخت مسیرها را نشان می‌دهد: شاخهٔ آبی cwd است. مسیر نسبی از آنجا و مسیر مطلق از ریشه حل می‌شود؛ خط‌ها رابطهٔ والد/فرزندند.

The tree shows paths; the blue node is the cwd. Relative paths start there and absolute paths at root; connectors represent parent-child relationships.

دایرکتوری‌های رایج را نقشهٔ تقریبی بدان، نه قانون یکسان همهٔ توزیع‌ها: /home خانهٔ کاربران، /etc معمولاً تنظیمات، /var دادهٔ متغیر مثل log، /tmp فایل موقت، /usr بخش بزرگی از نرم‌افزارها و /proc نمای مجازی وضعیت پردازه/هسته است.

Treat common directories as a rough map, not an identical rule for every distribution: /home for users’ homes, /etc commonly for configuration, /var for changing data such as logs, /tmp for temporary files, /usr for much installed software, and /proc as a virtual view of process/kernel state.

«همه‌چیز فایل است» استعاره است“Everything is a file” is a metaphor

این ایده برای فهم ابزارهای سادهٔ مسیر و ورودی/خروجی مفید است، اما لفظی و همگانی نیست؛ دایرکتوری، pipe، socket و ورودی‌های /proc مثل فایل عادی روی دیسک رفتار نمی‌کنند.

The idea helps explain simple path and input/output tools, but it is not universal literally: directories, pipes, sockets, and /proc entries do not behave like ordinary disk files.

یک جای امن برای آزمایشA safe place to experiment

cd cwd را عوض می‌کند؛ .. به والد، ~ به home و - به مسیر قبلی می‌رود. پوشهٔ تمرین را با mkdir -p بسازیم؛ این گزینه والدهای لازم را هم ایجاد می‌کند.

cd changes the cwd; .. goes to the parent, ~ to home, and - to the previous path. Create a practice tree with mkdir -p, which also creates missing parents.

create the sandbox
mkdir -p "$HOME/linux-lab/work/notes" "$HOME/linux-lab/archive"
cd "$HOME/linux-lab/work"
pwd
/home/sara/linux-lab/work

مسیر home روی دستگاه تو ممکن است فرق کند؛ مهم این است که pwd نشان دهد داخل $HOME/linux-lab هستی. از work به notes برو و با مسیر مطلق archive را پیدا کن. قبل از عملیات حساس، دوباره مقصد را بررسی کن.

Your home path may differ; what matters is that pwd shows you are beneath $HOME/linux-lab. Move from work to notes, then reach archive by its absolute path. Recheck the destination before sensitive operations.

relative then absolute
cd notes
pwd
/home/sara/linux-lab/work/notes
cd "$HOME/linux-lab/archive"
pwd
cd -

cd - معمولاً مسیر قبلی را چاپ می‌کند و به آن برمی‌گردد. برای حذف یا جابه‌جایی به حافظه تکیه نکن؛ pwd شاهد بهتر است.

cd - usually prints and returns to the previous path. Do not rely on memory before removing or moving files; pwd is better evidence.

شل قبل از برنامه، ستاره را باز می‌کندThe shell expands the star before the program runs

در Bash، *.log معمولاً پیش از اجرای برنامه به نام‌های منطبق در cwd گسترش می‌یابد. نام‌های نقطه‌دار با glob معمولی match نمی‌شوند؛ اگر چیزی match نشود، Bash به‌طور پیش‌فرض معمولاً خود الگو را نگه می‌دارد. برای فهمیدن نتیجه، اول preview بگیر.

In Bash, *.log usually expands into matching names in the cwd before the program runs. Dot-prefixed names are not matched by an ordinary glob; if nothing matches, Bash normally leaves the pattern unchanged by default. Preview the result first.

preview arguments
cd "$HOME/linux-lab/work"
touch alpha.log beta.log .private.log "meeting notes.txt"
printf '<%s>\n' *.log
<alpha.log> <beta.log>

خروجی نمونه است؛ ترتیب و نتیجه به فایل‌ها و تنظیمات shell بستگی دارد. نام دارای فاصله را quote کن. اگر می‌خواهی pattern به find برسد، آن را quote کن تا shell زودتر گسترشش ندهد. .* را برای حذف به کار نبر؛ ممکن است نام‌های ویژه را هم بگیرد.

Output is representative; order and results depend on files and shell settings. Quote names with spaces. Quote a pattern intended for find so the shell does not expand it first. Never use .* for deletion; it may include special names.

اول preview، بعد تصمیمPreview before deciding

برای دیدن گسترش، printf '<%s>\n' PATTERN را اجرا کن. preview فقط آرگومان‌های تولیدشده را نشان می‌دهد؛ مقصد درست یا بی‌خطر بودن حذف را تضمین نمی‌کند.

Use printf '<%s>\n' PATTERN to inspect expansion. A preview only shows generated arguments; it does not guarantee a correct destination or safe deletion.

فلش یعنی ترتیب اجرا: shell الگو را باز می‌کند و بعد برنامه آرگومان‌ها را می‌گیرد. برای find، quote باعث می‌شود الگو تا خود find دست‌نخورده بماند.

The arrows show execution order: the shell expands the pattern, then the program receives arguments. Quoting a find pattern keeps it intact until find receives it.

کپی، انتقال و حذف با مرز روشنCopy, move, and remove within a clear boundary

cp کپی می‌کند و mv جابه‌جا/rename می‌کند. گزینهٔ -- در ابزارهای GNU پایان گزینه‌ها را مشخص می‌کند؛ برای نامی که با خط تیره شروع شود کمک می‌کند، اما مقصد اشتباه را امن نمی‌کند.

cp copies; mv moves or renames. GNU tools use -- to end option parsing, useful for names beginning with a dash, but it cannot make a wrong destination safe.

copy and rename inside the lab
cd "$HOME/linux-lab/work"
cp -- alpha.log "$HOME/linux-lab/archive/alpha-copy.log"
mv -- beta.log beta-old.log
ls -la "$HOME/linux-lab/archive"

rm معمولاً سطل زباله ندارد. فقط نام دقیق فایلی را حذف کن که خودت زیر sandbox ساخته‌ای؛ پیش از آن pwd و پس از آن listing را بررسی کن. این درس به حذف بازگشتی یا پاک‌سازی گسترده نیاز ندارد.

rm usually has no trash bin. Remove only an exact file you created under the sandbox; check pwd first and list the directory afterward. This lesson needs no recursive or broad cleanup.

one exact sandbox file
cd "$HOME/linux-lab/work"
pwd
rm -- alpha.log
ls -la

نوع، مشخصات و جست‌وجوType, metadata, and search

پسوند فقط سرنخ است. file نوع قابل تشخیص را از محتوا حدس می‌زند؛ stat اندازه، مالک، مجوز و زمان‌های فایل‌سیستم را گزارش می‌کند. قالب دقیق stat میان GNU و نسخه‌های دیگر فرق دارد و هیچ‌کدام معنای برنامه‌ای فایل را ثابت نمی‌کنند.

An extension is only a clue. file identifies a likely type from recognizable content; stat reports size, ownership, permissions, and filesystem timestamps. Exact stat formatting varies, and neither tool proves application-level meaning.

inspect, then search
file "meeting notes.txt"
stat "meeting notes.txt"
find "$HOME/linux-lab" -type f -name '*.log' -print

در find، ریشهٔ جست‌وجو را صریح و محدود بده؛ -type f یعنی فایل معمولی، -type d دایرکتوری و -name شرط نام. quote دور glob لازم است تا خود find آن را دریافت کند. خروجی فقط انطباق با شرط‌ها را ثابت می‌کند، نه محتوای فایل یا نبودن آن در مسیرهای دیگر.

Give find an explicit, bounded root; -type f means regular file, -type d directory, and -name a name predicate. Quote the glob so find receives it. Output proves only that paths matched, not file contents or absence elsewhere.

symlink کپی نیستA symlink is not a copy

symlink به مسیر دیگری اشاره می‌کند. مقصد نسبی نسبت به پوشه‌ای محاسبه می‌شود که خود link در آن قرار دارد، نه cwd شل. با ls -l مقصد را ببین؛ اگر مقصد جابه‌جا یا حذف شود، link می‌تواند باقی بماند اما شکسته باشد.

A symlink points to another path. A relative target is resolved from the directory containing the link, not from the shell cwd. Inspect it with ls -l; if the target moves or disappears, the link may remain but be broken.

relative link
cd "$HOME/linux-lab"
ln -s work/notes notes-shortcut
ls -l notes-shortcut
... notes-shortcut -> work/notes
pwd -P

pwd -P در پیاده‌سازی‌های رایج مسیر فیزیکی را نشان می‌دهد؛ pwd ساده ممکن است مسیر منطقی شامل symlink باشد. تفاوت نمایش را با مسیر واقعی اشتباه نگیر.

pwd -P commonly requests the physical path; plain pwd may show a logical path containing a symlink. Do not confuse different displays with different targets.

خرابی عمدی: فایل هست، اما مسیر اشتباه استDeliberate failure: the file exists, but the path is wrong

از archive فرمان cat notes/todo.txt خطا می‌دهد. این خطا نبودن فایل در کل سیستم را نمی‌گوید؛ فقط مسیر نسبی را از cwd فعلی پیدا نکرده است. اول شاهد جمع کنیم.

From archive, cat notes/todo.txt fails. This does not say the file is absent from the whole machine; it says this relative path was not found from the current cwd. Gather evidence first.

برای بازتولید امن، اول فایل آزمایشی را در sandbox بساز و بعد عمداً از archive مسیر نسبی اشتباه را امتحان کن:

To reproduce this safely, first create a test file in the sandbox, then deliberately try the wrong relative path from archive:

diagnose before repair
touch "$HOME/linux-lab/work/notes/todo.txt"
cd "$HOME/linux-lab/archive"
pwd
/home/sara/linux-lab/archive
cat notes/todo.txt
cat: notes/todo.txt: No such file or directory
find "$HOME/linux-lab" -type f -name todo.txt -print
/home/sara/linux-lab/work/notes/todo.txt

اکنون می‌دانیم فایل در work/notes است و فرمان را از archive اجرا کرده‌ایم. با مسیر مطلق بخوان یا به پوشهٔ درست برو. اگر هنوز فایل را نساخته‌ای، خطا درست است؛ آن را فقط در sandbox بساز و همان بررسی را تکرار کن. پس از repair همان آزمونی را اجرا کن که پیش‌تر شکست خورد.

Now we know the file is in work/notes while the command ran from archive. Read it by absolute path or change to the right directory. If you never created it, the error is correct; create it only in the sandbox and repeat the same check. After repair, rerun the check that failed.

دام‌های معمولCommon traps

«ls نشان نداد، پس نیست»“ls did not show it, so it is gone”

cwd را با pwd و dotfileها را با ls -la بررسی کن؛ بعد جست‌وجو را محدود کن.Check cwd with pwd, dotfiles with ls -la, then search a bounded area.

«glob فقط متن است»“A glob is just text”

shell ممکن است پیش از برنامه آن را گسترش دهد؛ با printf پیش‌نمایش کن و برای find quote کن.The shell may expand it before the program; preview with printf and quote patterns for find.

«symlink مقصد را از cwd می‌گیرد»“A symlink target uses cwd”

مقصد نسبی از پوشهٔ خود link محاسبه می‌شود؛ مقصد را جداگانه آزمایش کن.A relative target is resolved from the link’s directory; test the target separately.

«یک rm بزرگ مرتبش می‌کند»“One big rm will clean it up”

توقف: cwd، الگو و مقصد را تأیید کن. تمرین این فصل فقط حذف نام دقیق زیر sandbox است.Stop: verify cwd, pattern, and destination. This chapter removes only exact names under the sandbox.

۱۸ تمرین؛ از پیش‌بینی تا عیب‌یابی18 exercises: from prediction to debugging

تغییرها را فقط در sandbox انجام بده. هر پاسخ باید بگوید شاهد چه چیزی را ثابت می‌کند و چه چیزی را نه.

Make changes only in the sandbox. Each answer should say what the evidence proves—and what it does not.

۱. prompt و واقعیت1. Prompt versus reality

prompt برابر ~ است؛ آیا cwd قطعاً home است؟

The prompt shows ~; is the cwd certainly home?

پاسخSolution

pwd را اجرا کن؛ prompt قابل سفارشی‌سازی است و به‌تنهایی شاهد قطعی نیست.

Run pwd; prompts are customizable and are not definitive evidence.

۲. resolve مسیر2. Resolve the path

از /home/sara/work مسیر ../archive/a کجاست؟

From /home/sara/work, where is ../archive/a?

پاسخSolution

/home/sara/archive/a؛ .. یک سطح به home برمی‌گردد.

/home/sara/archive/a; .. moves up one level to home.

۳. وابستگی به cwd3. Cwd dependency

/var/log/app.log با تغییر cwd به مسیر دیگری اشاره می‌کند؟

Does /var/log/app.log point somewhere else when cwd changes?

پاسخSolution

خیر؛ مطلق است. وجود فایل موضوع جداگانه‌ای است.

No; it is absolute. Whether the file exists is a separate question.

۴. dotfile ناپیدا4. Hidden dotfile

ls فایل را نشان نمی‌دهد. پیش از اعلام حذف‌شدن چه می‌کنی؟

ls does not show the file. What do you check before declaring it deleted?

پاسخSolution

pwd و ls -la؛ سپس در صورت لزوم جست‌وجوی محدود با find.

Check pwd and ls -la, then search a bounded scope with find if needed.

۵. glob به find5. A glob for find

چرا '*.log' را در فرمان find quote می‌کنیم؟

Why quote '*.log' in a find command?

پاسخSolution

برای رسیدن الگو به find بدون گسترش زودهنگام توسط shell.

So the pattern reaches find without early shell expansion.

۶. نام فاصله‌دار6. A spaced name

چطور یک نام واحد meeting notes.txt را به file می‌دهی؟

How do you pass one filename, meeting notes.txt, to file?

پاسخSolution

file "meeting notes.txt"؛ quote فاصله را در همان آرگومان نگه می‌دارد.

file "meeting notes.txt"; quoting keeps the space within one argument.

۷. preview حذف7. Preview before deletion

بی‌خطر چطور می‌بینی *.tmp چه آرگومان‌هایی می‌سازد؟

How can you safely see which arguments *.tmp produces?

پاسخSolution

printf '<%s>\n' *.tmp. این فقط گسترش را نشان می‌دهد، نه ایمنی مقصد را.

printf '<%s>\n' *.tmp. It previews expansion, not destination safety.

۸. پوشهٔ چندسطحی8. Nested directories

زیر home پوشهٔ linux-lab/a/b بساز و ثابت کن در محدودهٔ درست هستی.

Create linux-lab/a/b under home and prove you are in the intended boundary.

پاسخSolution

mkdir -p "$HOME/linux-lab/a/b"؛ سپس واردش شو و pwd را بخوان.

mkdir -p "$HOME/linux-lab/a/b", then enter it and check pwd.

۹. پسوند یا محتوا9. Extension or content

برای شناخت نوع محتوا و metadata یک فایل چه می‌زنی؟

Which commands inspect a file’s likely content type and metadata?

پاسخSolution

file و stat. این‌ها نوع و مشخصات را می‌دهند، نه اینکه برنامه حتماً فایل را بپذیرد.

file and stat. They report type and metadata, not guaranteed application acceptance.

۱۰. find محدود10. Bounded find

فایل‌های معمولی *.conf را فقط زیر sandbox پیدا کن.

Find regular *.conf files only under the sandbox.

پاسخSolution

find "$HOME/linux-lab" -type f -name '*.conf' -print. ریشهٔ صریح جست‌وجو محدوده را نگه می‌دارد.

find "$HOME/linux-lab" -type f -name '*.conf' -print. The explicit search root bounds the operation.

۱۱. حفظ اصل11. Preserve the original

می‌خواهی یک نسخه به archive برود و اصل بماند. کدام فرمان و چه شاهدی؟

You want a copy in archive while preserving the original. Which command and evidence?

پاسخSolution

cp؛ سپس هر دو مسیر را با ls -l بررسی کن. مقصد تنها کافی نیست.

Use cp, then inspect both paths with ls -l. The destination alone is insufficient.

۱۲. خطای مسیر نسبی12. Relative-path error

cat notes/a شکست خورد. فایل ممکن است جای دیگری باشد؛ دو بررسی بعدی؟

cat notes/a failed. The file may be elsewhere; what two checks come next?

پاسخSolution

pwd مبدأ resolve را نشان می‌دهد؛ find محدود به sandbox محل فایل را می‌یابد. خطای یک مسیر نبودن کلی را ثابت نمی‌کند.

pwd shows the resolution base; bounded find locates the file. One failed path does not prove general absence.

۱۳. symlink نسبی13. Relative symlink

link در /home/sara/lab به work/notes اشاره می‌کند؛ مقصد نسبت به کجاست؟

A link in /home/sara/lab points to work/notes; relative to what?

پاسخSolution

پوشهٔ خود symlink؛ مقصد /home/sara/lab/work/notes است.

The symlink’s containing directory; the target is /home/sara/lab/work/notes.

۱۴. link شکسته14. Broken link

ls -l link را نشان می‌دهد اما مقصد باز نمی‌شود. چه چیزی جداست؟

ls -l shows a link but its target cannot be opened. What is distinct?

پاسخSolution

وجود خود link و دسترسی‌پذیری مقصد. هر دو را جدا بررسی کن.

The link’s existence and target accessibility. Check them separately.

۱۵. خطر نقطه‌ستاره15. The dot-star risk

چرا rm -r .* را اجرا نمی‌کنی؟ preview امن چیست؟

Why should you not run rm -r .*? What is a safe preview?

پاسخSolution

ممکن است نام‌های خاص match شوند و حذف بازگشتی خطرناک است. با printf در sandbox preview کن و حذف را به نام دقیق محدود کن.

It may match special names and recursive deletion is dangerous. Preview with printf in the sandbox and restrict removal to an exact name.

۱۶. /proc16. /proc

یک ورودی مجازی را بخوان و فرقش را با فایل ذخیره‌شده بگو.

Read a virtual entry and explain how it differs from a stored file.

پاسخSolution

cat /proc/uptime؛ داده نمای وضعیت جاری است، نه محتوای عادی ذخیره‌شده روی دیسک.

cat /proc/uptime; it presents current state rather than ordinary disk-stored content.

۱۷. اندازهٔ صفر17. Zero-byte file

stat اندازهٔ صفر گزارش می‌کند. آیا فایل خراب است؟

stat reports zero bytes. Is the file corrupt?

پاسخSolution

نه لزوماً؛ ممکن است marker باشد. از file و قرارداد برنامه کمک بگیر؛ اندازه علت را ثابت نمی‌کند.

Not necessarily; it may be a marker. Consult file and the application contract; size does not establish cause.

۱۸. بلیت پایانی18. Final ticket

اسکریپت پوشه‌ای را پیدا نمی‌کند که دیروز ساختی. ترتیب تشخیص و تأیید را بنویس؛ چیزی را حذف نکن.

A script cannot find a directory you created yesterday. Give an evidence-first diagnosis and verification; delete nothing.

پاسخSolution

pwd، ls -la، سپس find "$HOME/linux-lab" -type d -name 'directory-name' -print. اگر یافت شد مسیر مطلق یا cwd درست را به اسکریپت بده، همان آزمون را تکرار کن. نتیجه فقط محدودهٔ جست‌وجو را پوشش می‌دهد.

Run pwd, ls -la, then find "$HOME/linux-lab" -type d -name 'directory-name' -print. If found, supply the absolute path or correct cwd, then repeat the same test. The result covers only the search scope.

مأموریت: میز کارت را مرتب کنMission: organize the workbench

زیر sandbox پوشهٔ incoming بساز، دو log و یک dotfile ایجاد کن، logها را با find پیدا کن، یکی را به archive کپی کن، symlink نسبی بساز و یک فایل موقت دقیق را حذف کن. پیش از حذف cwd و نام را بررسی کن؛ پس از آن وجود کپی، مقصد link، dotfile و نبودن فایل موقت را ثابت کن.

Under the sandbox, create incoming, two logs, and a dotfile; find the logs, copy one to archive, create a relative symlink, and remove one exact temporary file. Before removal verify cwd and name; afterward prove the copy, link target, dotfile, and temporary file’s absence.

راهنماHint

هر مرحله را جدا اجرا کن؛ glob را preview کن، link را با ls -l بخوان و cleanup را محدود نگه دار.

Run each step separately; preview the glob, inspect the link with ls -l, and keep cleanup bounded.
