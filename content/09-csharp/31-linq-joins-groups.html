LINQ: گروه‌بندی، join و ترکیب

LINQ: grouping, joins and composition

گزارش فروش فقط فیلتر نیست: باید سفارش را به مشتری وصل کنیم، جمع هر گروه را حساب کنیم و مشتری بی‌سفارش را هم نگه داریم. هر operator را از همین نیازهای واقعی درمی‌آوریم؛ بعد cardinality خروجی را با fixture می‌سنجیم.

A sales report is more than filtering: join orders to customers, aggregate groups, and preserve customers without orders. We derive operators from these needs and verify output cardinality with fixtures.

Join زوج می‌سازد؛ cardinality را حدس نزنJoin forms pairs; do not guess cardinality

Join برای هر کلید مشترک زوج می‌سازد. order بی‌مشتری در inner join ناپدید می‌شود؛ اگر یک شناسه در سمت customer دو بار باشد، هر order دو خروجی می‌سازد. پیش از aggregate، تعداد و یکتایی کلیدها را در دادهٔ واقعی بررسی کن؛ خروجی غلط اغلب از رابطهٔ چندبه‌چند ناخواسته می‌آید.

Join creates a pair for each matching key. An order without a customer disappears in an inner join; duplicate customer IDs multiply output rows. Check key uniqueness and cardinality before aggregating—unexpected many-to-many matches often explain wrong totals.

گزارش تجمیعی / Aggregate report
var totals = orders
    .GroupBy(o => o.CustomerId)
    .Select(g => new { CustomerId = g.Key,
                       Count = g.Count(),
                       Total = g.Sum(o => o.Total) });

قبل از join خروجی را روی سه customer و چند سفارش دستی پیش‌بینی کن؛ بعد تعداد ردیف و مبلغ را assert کن. syntax زیبا جای بررسی cardinality را نمی‌گیرد.

Predict output for a tiny fixture before joining, then assert row counts and totals. Elegant syntax does not replace cardinality checks.

GroupBy گروه می‌سازد؛ همهٔ اعضا را بی‌دلیل نگه ندارGroupBy creates groups; do not retain every item needlessly

اگر فقط جمع و count لازم است، همان‌ها را project کن؛ نگه‌داشتن entityهای کامل ممکن است حافظه را بالا ببرد. برای مشتری بی‌سفارش، GroupJoin سمت چپ را نگه می‌دارد و گروه خالی می‌دهد. DefaultIfEmpty راه ساخت left join است، اما null و مقدار جایگزین باید طبق نیاز دامنه تعریف شوند.

If only sum and count are needed, project those rather than retaining full entities. GroupJoin preserves left-side customers and gives an empty group for those without orders. DefaultIfEmpty can form a left join, but null and fallback values must follow domain requirements.

SelectMany و Zip رابطه‌های متفاوتی‌اندSelectMany and Zip model different relationships

SelectMany sequenceهای تو در تو را flatten می‌کند؛ Zip عنصرها را بر اساس موقعیت جفت می‌کند و وقتی یکی تمام شد متوقف می‌شود. Zip برای اتصال با کلید نیست. Aggregate هم fold عمومی است، ولی برای جمع عددی Sum معمولاً قصد را روشن‌تر منتقل می‌کند.

SelectMany flattens nested sequences; Zip pairs by position and stops when either source ends. Zip is not a key join. Aggregate is a general fold, while Sum usually communicates numeric intent more clearly.

در IQueryable، provider وارد ماجرا می‌شودWith IQueryable, a provider enters the picture

روی IEnumerable معمولاً delegate در برنامه اجرا می‌شود؛ IQueryable expression tree را به provider می‌دهد تا ترجمه کند. همهٔ تابع‌های C# ترجمه‌پذیر نیستند. مرز ToList اجرای بعدی را به حافظه می‌آورد و ممکن است دادهٔ زیادی انتقال دهد. SQL و تعداد round-trip را log کن؛ از روی ظاهر query حدس نزن.

With IEnumerable, delegates usually run in-process; IQueryable supplies an expression tree for a provider to translate. Not every C# function translates. ToList moves later work into memory and may transfer too much data. Log SQL and round trips instead of guessing from query syntax.

آزمایشگاه: گزارش مشتری و سفارشLab: customer and order report

fixture کوچک بساز: مشتری بی‌سفارش، سفارش با مشتری، و کلید تکراری کنترل‌شده. گزارش باید نام مشتری و جمع را بسازد. ابتدا نتیجهٔ هر رابطه را پیش‌بینی کن، سپس تست cardinality بنویس؛ repair را در query نهایی اعمال کن. اگر provider دیتابیس داری، SQL و تعداد query را هم ثبت کن.

Create a small fixture with a customer without orders, a matched order, and a controlled duplicate key. Build a customer-total report. Predict relationship results, write cardinality tests, then repair the final query. If using a database provider, record SQL and query count.

  1. خروجی مورد انتظار را روی کاغذ/تست ثبت کن.
  2. Record expected output in a test.
  3. inner و left join را روی همان fixture مقایسه کن.
  4. Compare inner and left joins on the same fixture.
  5. جمع نهایی و SQL یا شمارنده را بررسی کن.
  6. Inspect final totals and SQL or counters.

اول رابطه را بفهم، بعد operator را انتخاب کنUnderstand the relationship before choosing an operator

Join کلیدمحور است، GroupJoin گروه سمت راست را حفظ می‌کند، SelectMany flatten می‌کند و Zip موقعیتی است. duplicate key می‌تواند خروجی و جمع را چندبرابر کند؛ پس cardinality بخشی از صحت است. فصل بعد بررسی می‌کند query چه زمانی اجرا می‌شود و چند بار منبع را می‌خواند.

Join matches keys, GroupJoin preserves right-side groups, SelectMany flattens, and Zip matches positions. Duplicate keys can multiply rows and totals, so cardinality is part of correctness. Next we inspect when a query runs and how often it reads its source.
