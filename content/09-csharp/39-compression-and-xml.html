فشرده‌سازی و XML

Compression and XML

شریک ما archive می‌خواهد و بعد XML نامطمئنی می‌فرستد. فشرده‌سازی schema را حل نمی‌کند؛ XML قابل parse هم لزوماً امن یا معتبر نیست. مرزهای هر دو را با fixture واقعی می‌آزماییم.

A partner requires an archive, then sends untrusted XML. Compression does not solve schema validation; parseable XML is not necessarily safe or valid. We test both boundaries with real fixtures.

GZip جریان bytes را wrap می‌کندGZip wraps a byte stream

GZipStream در مسیر write فشرده و در مسیر read باز می‌کند. نسبت فشرده‌سازی به داده بستگی دارد؛ متن تکراری کم می‌شود ولی دادهٔ تصادفی ممکن است بزرگ‌تر شود. GZip encryption یا authentication نیست. Dispose wrapper هم پایان stream را می‌نویسد؛ مالکیت stream داخلی را صریح نگه دار.

GZipStream compresses on write and decompresses on read. Ratios depend on data; repetitive text shrinks while random data may grow. GZip is not encryption or authentication. Disposing the wrapper writes the stream trailer; define ownership of the inner stream.

پایان stream را کامل کن / Finalize the stream
using var output = new MemoryStream();
using (var gzip = new GZipStream(output, CompressionMode.Compress, leaveOpen: true))
{
    byte[] input = Encoding.UTF8.GetBytes("order report");
    gzip.Write(input);
}
output.Position = 0;

برای proof، archive را باز و byteها را مقایسه کن؛ صرف وجود فایل compressed نشان نمی‌دهد محتوا سالم برگشته است.

For proof, decompress and compare bytes; a compressed file's existence does not establish a valid round trip.

نام entry در ZIP را قابل‌اعتماد فرض نکنDo not trust ZIP entry paths

entry می‌تواند مسیر نسبی مخرب داشته باشد؛ پیش از extract مسیر canonical مقصد را با root مقایسه کن. archive کوچک هم ممکن است پس از باز شدن دادهٔ عظیمی بسازد؛ تعداد entry و total expanded bytes را محدود کن و در staging استخراج کن. compressed size سقف فضای خروجی نیست.

An entry may contain a malicious relative path; compare its canonical destination with the extraction root. A small archive can expand enormously; bound entry count and total expanded bytes, and extract to staging. Compressed size does not cap output size.

DOM یا reader: دسترسی آسان در برابر حافظهDOM or reader: navigation versus memory

XDocument کل tree را می‌سازد و برای سند کوچک و query چندمرحله‌ای راحت است. XmlReader جلوبرنده است و برای سند بزرگ مناسب‌تر، اما state record را خودت مدیریت می‌کنی. namespace جزو نام element است؛ prefix صرفاً نام مستعار URI است. برای نوشتن XML از XmlWriter استفاده کن تا escaping درست انجام شود.

XDocument builds the full tree and is convenient for small documents and rich queries. XmlReader is forward-only and fits large files, but you manage record state. Namespace URI is part of an element name; a prefix is only an alias. Use XmlWriter for correct escaping.

XML untrusted را با مرز امن parse کنParse untrusted XML at a secure boundary

ورودی نامطمئن را با DtdProcessing.Prohibit بخوان و XmlResolver را null بگذار؛ DTD و external entity می‌توانند فایل/شبکه را درگیر یا منابع را مصرف کنند. سقف اندازه هم لازم است. اگر DTD واقعاً لازم است، resolver و resourceها را محدود کن؛ exception parser را مستقیم برای کاربر افشا نکن.

Parse untrusted input with DtdProcessing.Prohibit and a null XmlResolver; DTDs and external entities can access files/network or consume resources. Also limit document size. If DTD is essential, restrict resolvers and resources; do not expose raw parser exceptions.

تنظیم صریح / Explicit settings
var settings = new XmlReaderSettings
{
    DtdProcessing = DtdProcessing.Prohibit,
    XmlResolver = null,
    MaxCharactersInDocument = 1_000_000
};
using var reader = XmlReader.Create(input, settings);

عدد سقف نمونه است نه policy همگانی؛ با اندازهٔ مجاز دامنه تنظیمش کن و ورودی DOCTYPE را در test رد کن.

The limit is illustrative, not universal; tune it to the domain and test rejection of a DOCTYPE input.

امنیت بخشی از فرمت و مسیر استSecurity is part of the format boundary

GZip فشرده می‌کند؛ ZIP مسیر و اندازهٔ entry را قابل‌اعتماد نمی‌کند؛ DOM حافظه می‌خواهد؛ XmlReader جریانی است؛ DTD و resolver مرز امنیتی‌اند. فصل بعد همین انتخاب میان مدل، DOM و parser جریانی را برای JSON می‌سازد.

GZip compresses; ZIP does not make entry paths or sizes trustworthy; DOM costs memory; XmlReader streams; DTD and resolver settings are security boundaries. Next we make the same model/DOM/streaming choice for JSON.
