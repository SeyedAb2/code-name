رشته، قالب‌بندی و متن خام

Strings, formatting and raw text

در فصل قبل، منطق سفارش را از چاپ جدا کردیم. حالا سفارش واقعی داریم، اما رسید بدخوان است: مبلغ‌ها بی‌قالب‌اند، فاصله‌ها نامنظم‌اند و متن چندخطی پر از علامت‌های escape شده. بیایید داده را عوض نکنیم؛ فقط راه ساختن متن را درست کنیم.

In the previous chapter we separated order logic from printing. Now we have an order, but its receipt is hard to read: raw amounts, inconsistent spacing and multiline text full of escapes. Let’s keep the data intact and improve how we build the text.

رسید را از اتصال تکه‌ها نجات بدهRescue the receipt from concatenation

خروجی Order A-42 total: 1250000 اطلاعات دارد، اما خواندنش راحت نیست. اگر با + رشته‌ها را بچسبانیم، فاصله و جداکننده و شرط‌های نمایش کم‌کم در همه‌جا پخش می‌شوند.

The output Order A-42 total: 1250000 contains the facts, but is hard to scan. Concatenating strings with + spreads spacing, separators and display rules throughout the code.

C# · Program.cs
string orderId = "A-42";
decimal total = 1_250_000m;

string receipt = $"Order {orderId} | Total: {total:N0}";
Console.WriteLine(receipt);

پیشوند $ اجازه می‌دهد عبارت C# را داخل آکولاد بنویسیم. N0 قالب عددی است: گروه‌بندی رقم‌ها و صفر رقم اعشار. جداکنندهٔ دقیق به culture جاری وابسته است؛ پس این متن نمایشی است، نه خروجی تضمین‌شدهٔ یکسان روی هر ماشین.

The $ prefix lets us place C# expressions inside braces. N0 groups digits and requests zero fractional digits. Exact separators depend on the current culture, so this is display text, not guaranteed identical output on every machine.

اول داده، بعد شکل نمایشData first, presentation second

total همچنان decimal است؛ N0 فقط نمایش رشته‌ای می‌سازد. تا وقتی نیاز به نمایش نداریم مبلغ را به string تبدیل نکن. رشته جایگزین نوع عددی در محاسبه نیست.

total remains a decimal; N0 only creates a textual representation. Do not convert an amount to string before display is needed. A string is not a replacement for a numeric type in calculations.

مقدار نوع‌دار را برای خواننده قالب می‌دهیم؛ منبع داده برای محاسبه دست‌نخورده می‌ماند.

We format a typed value for its reader and leave the source data intact for calculations.

سه شکل نوشتن رشته برای سه نیازThree string literal forms for different needs

برای متن ساده، نقل‌قول معمولی کافی است؛ اما escapeها در مسیر و متن چندخطی خوانایی را کم می‌کنند. شکل literal را بر اساس محتوا انتخاب کن.

For plain text, a regular quoted literal is enough. Escapes can hurt readability in paths and multiline text, so choose a literal form for the content.

C# · regular and verbatim
string line = "Order\tA-42\nPaid";
string path = @"C:\receipts\2026\A-42.txt";
string quote = "She said: \"paid\"";

Console.WriteLine(line);
Console.WriteLine(path);

در رشتهٔ معمولی، \n و \t به‌ترتیب خط تازه و tab هستند؛ برای backslash واقعی باید آن را escape کنیم. پیشوند @ رشتهٔ verbatim می‌سازد و backslash را عادی می‌کند. کوتیشن داخل آن را دوتا می‌نویسیم. برای هر رشته‌ای لازم نیست سراغ @ برویم.

In a regular string, \n and \t mean newline and tab; a literal backslash must be escaped. The @ prefix creates a verbatim string where backslashes are ordinary. Double a quote inside it. Verbatim syntax is not needed for every string.

C# 11+ · raw string
string template = """
{
  "orderId": "A-42",
  "note": "gift-ready"
}
""";
Console.WriteLine(template);

raw string با دست‌کم سه کوتیشن شروع و تمام می‌شود و escapeهای معمول رشته را تفسیر نمی‌کند؛ کوتیشن داخلی همان‌طور می‌ماند. اگر متن خودش سه کوتیشن پیاپی داشت delimiter را بلندتر کن. تورفتگی به جای delimiter پایانی وابسته است؛ برای whitespace مهم، خروجی را واقعاً اجرا و بررسی کن.

A raw string starts and ends with at least three quotes and does not process ordinary string escapes, so inner quotes stay unchanged. Use a longer delimiter if the content contains three consecutive quotes. Indentation follows the closing delimiter; run the code to inspect significant whitespace.

raw string اعتبار قالب را تضمین نمی‌کندA raw string does not validate a format

این literal فقط escapeهای C# را کم می‌کند؛ معتبر بودن JSON یا encode امن ورودی را تضمین نمی‌کند. اینجا متن نمونه می‌سازیم، نه serialization واقعی.

This literal only reduces C# escaping; it does not validate JSON or safely encode input. We are building sample text, not performing actual serialization.

جای‌گذاری مقدار را خوانا و کنترل‌شده بنویسKeep inserted values readable and controlled

در interpolation می‌توان عبارت نوشت و پس از colon قالب داد. عدد پیش از colon پهنا و هم‌ترازی را تعیین می‌کند. عبارت پیچیده را پیش از چاپ در متغیر جدا حساب کن.

Interpolation accepts expressions with an optional format after a colon. A number before the colon sets width and alignment. Calculate a complex expression in a separate variable before formatting it.

C# · alignment and format
string orderId = "A-42";
decimal subtotal = 1_250_000m;
decimal taxRate = 0.09m;
decimal tax = subtotal * taxRate;

string row = $"{orderId,-10} {subtotal,14:N0} {tax,12:N0}";
Console.WriteLine(row);
Console.WriteLine($"Tax rate: {taxRate:P0}");
Console.WriteLine($"Receipt {{preview}}: {orderId}");

عدد منفی چپ‌چین و مثبت راست‌چین می‌کند. N0 قالب عدد و P0 قالب درصد است. هم‌ترازی متن کنسول برای گزارش ساده مفید است، اما به فونت monospace و عرض ثابت وابسته می‌شود؛ جایگزین layout رابط کاربری نیست.

A negative width left-aligns and a positive width right-aligns. N0 formats a number and P0 a percentage. Console alignment can help a simple report, but depends on monospace fonts and fixed widths; it is not UI layout.

در P0 مقدار 0.09 به‌صورت ۹ درصد دیده می‌شود. فرمت مقدار را تغییر نمی‌دهد. در رشتهٔ interpolated، {{ و }} برای آکولاد literal هستند.

P0 displays 0.09 as 9 percent. Formatting does not mutate the value. In an interpolated string, {{ and }} represent literal braces.

کوتاه‌ترین کد همیشه خواناتر نیستThe shortest code is not always clearest

اگر expression داخل رشته سخت‌خوان شد، قبلش متغیر بساز. raw interpolated string هم delimiter آکولاد خودش را دارد؛ آن را build کن و خروجی را ببین، نه اینکه فقط از روی ظاهر حدس بزنی.

If an expression makes the string hard to read, name it beforehand. Raw interpolated strings have their own brace delimiters; build and inspect them instead of guessing from appearance.

متن انسان و متن ماشین را یکی نگیرDo not conflate human display with machine text

مبلغ روی سیستم توسعه درست دیده می‌شود، اما روی سرور جداکننده عوض شده است. این لزوماً باگ محاسبه نیست: قالب پیش‌فرض از culture جاری استفاده می‌کند. culture را صریح بده تا تفاوت روشن شود.

An amount looks right on a developer machine but has different separators on a server. This is not necessarily a calculation bug: default formatting uses the current culture. Pass cultures explicitly to see the difference.

C# · explicit culture
using System.Globalization;

decimal amount = 1234.5m;
string us = amount.ToString("N2", CultureInfo.GetCultureInfo("en-US"));
string de = amount.ToString("N2", CultureInfo.GetCultureInfo("de-DE"));
string stable = amount.ToString("G", CultureInfo.InvariantCulture);

Console.WriteLine(us);     // 1,234.50
Console.WriteLine(de);     // 1.234,50
Console.WriteLine(stable); // 1234.5

N2 دو رقم اعشار می‌خواهد؛ culture جداکننده را تعیین می‌کند. InvariantCulture نمایش وابسته به فرهنگ جاری نمی‌سازد، اما به‌تنهایی قرارداد کامل تبادل داده یا serializer نیست. برای پروتکل و قالب داده، قواعد همان قالب را دنبال کن.

N2 requests two fractional digits; culture supplies separators. InvariantCulture avoids dependence on the current culture, but is not by itself a complete interchange contract or serializer. Follow the target format’s rules for protocols and data.

نماد پول را حدس نزنDo not guess the currency symbol

قالب C نماد پول را از تنظیمات culture می‌گیرد و آن نماد شاید واحد سفارش نباشد. اگر قرارداد می‌گوید IRR یا تومان، واحد را صریح نگه دار؛ تنظیم رایانه قرارداد تجاری نیست.

The C format gets its currency symbol from culture, and that symbol may not match the order. If the contract says IRR or another unit, state it explicitly; machine settings are not a business contract.

برای رسید انسانی، فرهنگ نمایش مخاطب مهم است؛ برای دادهٔ پایدار، قالب قراردادی مهم است. نیاز این دو را در یک رشته قاطی نکن.

For a human receipt, the reader’s display culture matters; for stable data, the format contract matters. Do not mix these needs in one string.

قالب چندخطی را وقتی واقعاً چندخطی است ساده کنSimplify text that is truly multiline

یادداشت پشتیبانی گاهی باید چند خط و شامل آکولاد باشد. raw string escapeهای اضافی را کم می‌کند؛ interpolation در raw string هم تعداد آکولادهای مرزی خودش را دارد.

A support note may need multiple lines and literal braces. A raw string reduces escape noise; interpolation in a raw string has its own brace delimiter count.

C# 11+ · interpolated raw string
string orderId = "A-42";
decimal total = 1250m;

string note = $$"""
{
  "order": "{{orderId}}",
  "message": "Thank you!",
  "total": {{total}}
}
""";

Console.WriteLine(note);

با دو علامت $، interpolation با {{...}} آغاز می‌شود و آکولاد تک می‌تواند متن عادی باشد. این برای نمونهٔ JSON مانند خواناتر است؛ اما serializer نیست. اگر دادهٔ کاربر یا قرارداد دقیق داری، اتصال دستی رشته جای ابزار تخصصی را نمی‌گیرد.

With two $ characters, interpolation uses {{...}}, leaving a single brace as ordinary content. This can clarify JSON-like examples, but it is not a serializer. For user data or a strict contract, manual concatenation is no substitute for a dedicated tool.

Console.WriteLine($"Payable: {payable:N2}");

نام‌گذاری مرحله‌ها اجازه می‌دهد هر مقدار را جدا بررسی کنیم، به‌جای اینکه عبارت تو‌در‌تو را وسط رشته debug کنیم.

Named steps let us inspect each value separately rather than debugging a nested expression inside the string.

۱۵) رسید چندخطی را بازبینی کن15) Review a multiline receipt

رسیدی شامل شناسه، مبلغ، نرخ مالیات و واحد IRR بساز؛ دو culture را امتحان کن و مشخص کن کدام بخش ثابت و کدام بخش وابسته به culture است.

Build a receipt with ID, amount, tax rate and IRR; test two cultures and identify fixed versus culture-dependent parts.

یک پاسخ ممکن و دلیلOne possible solution and reasoning
C# 11+
using System.Globalization;

string Build(string id, decimal amount, decimal rate, CultureInfo culture)
{
    decimal tax = amount * rate;
    decimal payable = amount + tax;
    return $$"""
Order: {{id}}
Subtotal: {{amount.ToString("N2", culture)}} IRR
Tax: {{tax.ToString("N2", culture)}} ({{rate.ToString("P0", culture)})
Payable: {{payable.ToString("N2", culture)}} IRR
""";
}

Console.WriteLine(Build("A-42", 100m, 0.09m,
    CultureInfo.GetCultureInfo("en-US")));

فرمول و واحد ثابت‌اند؛ جداکنندهٔ عدد و درصد به culture وابسته است. در برنامهٔ واقعی ورودی‌ها را اعتبارسنجی کن و اگر خروجی machine-readable است، قرارداد همان قالب را رعایت کن.

The formula and unit are fixed; number and percent separators depend on culture. Validate inputs in a real program and follow the target format contract for machine-readable output.

جمع‌بندی: رشته مقصد داده است، نه خود دادهReview: a string is where data is presented, not the data itself

برای متن کوتاه interpolation خواناست؛ برای مسیرها verbatim گاهی بهتر است و برای متن چندخطی raw string. قالب‌های N و P و C نمایش را تغییر می‌دهند و ممکن است cultureمحور باشند. واحد پول را از قرارداد بگیر، نه از تنظیم رایانه؛ متن machine-readable را هم با قرارداد خودش بساز.

Interpolation is clear for short text; verbatim strings can help with paths, and raw strings with multiline content. N, P and C formats alter display and may be culture-sensitive. Get the currency from the contract, not machine settings, and build machine-readable text to its own contract.

در فصل بعد چند مقدار هم‌نوع را کنار هم نگه می‌داریم: آرایه، tuple و بازه. تا آن موقع، رسید را با چند ورودی اجرا کن و مطمئن شو چیزی که فقط برای نمایش است وارد محاسبه نشده.

Next we will keep multiple values together using arrays, tuples and ranges. Until then, run the receipt with different inputs and ensure presentation has not leaked into calculation.
