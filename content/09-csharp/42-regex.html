Regex امن و قابل‌اندازه‌گیری

Safe, measurable regular expressions

یک endpoint جست‌وجو برای نام فایل‌ها regex می‌سازد. روی عبارت‌های معمولی خوب است؛ با ورودی‌ای که تقریباً match می‌شود، CPU بالا می‌رود و درخواست‌ها پشت هم می‌مانند. قبل از آن‌که pattern را پیچیده‌تر کنیم، باید بپرسیم: این مسئله واقعاً regex می‌خواهد؟ ورودی از کجا می‌آید و بدترین حالت چقدر هزینه دارد؟

A search endpoint builds a regex for file names. It works on ordinary input, but a near-match drives CPU usage up and requests queue. Before making the pattern more complex, ask: does this problem need regex at all, where does the input come from, and what is the worst-case cost?

هر متنی regex لازم نداردNot every text task needs a regex

برای پیشوند، پسوند، جداکردن با delimiter یا parse عدد، APIهای رشته و parser اختصاصی اغلب خواناترند. regex زمانی ارزش دارد که شکل متن واقعاً یک زبان الگو باشد؛ آن هم با نام‌گذاری گروه‌ها و تست نمونه‌های match، non-match و مرزی. هدف «یک خط جادویی» نیست؛ هدف بیان قرارداد ورودی است.

For prefixes, suffixes, delimiters or numeric parsing, string APIs and dedicated parsers are often clearer. Regex earns its place when text genuinely follows a pattern language; use named groups and test matches, non-matches and boundaries. The goal is not a magical one-liner but an executable input contract.

گروه نام‌دار / Named group
var match = Regex.Match(
    "INV-2026-0042",
    @"^(?<kind>[A-Z]{3})-(?<year>\d{4})-(?<id>\d{4})$",
    RegexOptions.CultureInvariant,
    TimeSpan.FromMilliseconds(100));

if (match.Success)
    Console.WriteLine(match.Groups["id"].Value);

timeout را برای ورودی‌ای که ممکن است از بیرون کنترل شود صریح گذاشتیم. مرزهای ^ و $ کل رشته را می‌خواهند؛ اگر فقط بخشی از متن را می‌خواهی، این انتخاب را آگاهانه عوض کن. \d به رقم‌های Unicode هم می‌تواند بخورد؛ اگر قرارداد فقط رقم ASCII است، کلاس [0-9] را به‌کار ببر.

We set an explicit timeout for potentially untrusted input. Anchors require the whole string; change them deliberately if searching for a substring. \d can match Unicode digits; use [0-9] when the contract requires ASCII digits only.

هزینهٔ backtracking از ورودی نزدیک به match می‌آیدNear-matches can trigger expensive backtracking

موتور معمولی .NET با backtracking تلاش‌های قبلی را نگه می‌دارد و هنگام شکست مسیرهای جایگزین را می‌آزماید. بعضی quantifierهای تو‌در‌تو و بخش‌های هم‌پوشان می‌توانند تعداد این تلاش‌ها را خیلی سریع زیاد کنند. ورودی‌ای که دقیقاً match می‌شود شاید مشکلی نشان ندهد؛ رشته‌ای بلند که فقط در آخر رد می‌شود، اغلب آزمایش مهم‌تری است. این ریسک را ReDoS می‌نامند، اما timeout هم حد کل پردازش درخواست نیست؛ طول ورودی و concurrency را هم محدود کن.

The normal .NET engine uses backtracking, retaining earlier choices and trying alternatives after failure. Nested quantifiers and overlapping alternatives can multiply attempts rapidly. A successful match may look harmless; a long string rejected only near the end is often a more revealing test. This risk is known as ReDoS, but a regex timeout is not a request-wide resource limit—bound input length and concurrency too.

timeout و پاسخ کنترل‌شده / Timeout and controlled failure
var regex = new Regex(
    pattern,
    RegexOptions.CultureInvariant,
    TimeSpan.FromMilliseconds(100));

if (input.Length > 4_096)
    return SearchResult.InputTooLong;

try
{
    return regex.IsMatch(input)
        ? SearchResult.Match
        : SearchResult.NoMatch;
}
catch (RegexMatchTimeoutException)
{
    return SearchResult.TimedOut;
}

timeout پیش‌فرض موتور می‌تواند بی‌نهایت باشد؛ برای patternهای backtracking روی ورودی غیرقابل‌اعتماد، timeout صریح توصیه می‌شود. timeout را خیلی کوچک انتخاب نکنی که بار لحظه‌ای سالم را هم fail کند؛ با ورودی و بار نماینده اندازه بگیر. بعد از timeout همان ورودی را بی‌نهایت retry نکن.

The engine’s default timeout can be infinite; an explicit timeout is recommended for backtracking patterns on untrusted input. Do not make it so short that normal load causes false failures; measure representative inputs and traffic. Do not retry the same timed-out input indefinitely.

NonBacktracking: وقتی زبان pattern اجازه می‌دهدNonBacktracking when the pattern language allows it

از .NET 7، RegexOptions.NonBacktracking یک engine بدون backtracking ارائه می‌کند که زمان match را متناسب با طول ورودی نگه می‌دارد؛ اما همهٔ قابلیت‌های syntax را پشتیبانی نمی‌کند، از جمله lookaround و backreference. اگر pattern به این قابلیت‌ها وابسته است، نمی‌توان فقط گزینه را روشن کرد؛ باید pattern را بازطراحی یا timeout و محدودیت ورودی را نگه داشت. این گزینه pattern مخربِ تولیدشده توسط خود کاربر را امن نمی‌کند.

Since .NET 7, RegexOptions.NonBacktracking provides a non-backtracking engine with processing proportional to input length, but it does not support every syntax feature, including lookarounds and backreferences. If the pattern relies on those, simply setting the option is not possible; redesign it or retain timeouts and input limits. The option does not make user-generated malicious patterns safe.

انتخاب engine / Select an engine
var safeForLongInput = new Regex(
    @"^[A-Z0-9_-]{1,64}$",
    RegexOptions.CultureInvariant | RegexOptions.NonBacktracking,
    TimeSpan.FromMilliseconds(100));

bool valid = safeForLongInput.IsMatch(candidate);

pattern این نمونه ساده است، طولش در خود الگو و در boundary محدود شده و timeout هم دارد. اگر متن جست‌وجوی کاربر را می‌خواهی literal حساب کنی، آن را مستقیم به‌عنوان pattern نچسبان؛ از Regex.Escape استفاده کن یا اصلاً contains معمولی.

This pattern is simple, bounded both in the expression and at the boundary, and still has a timeout. If user search text should be literal, never concatenate it as regex syntax; use Regex.Escape or ordinary substring search.

گروه‌ها، culture و replace هم قرارداد دارندGroups, culture and replacement are part of the contract

گروه‌های بدون نام و capture اضافه، فهم خروجی را سخت می‌کنند؛ از (?:...) برای grouping بدون capture و از نام‌های خوانا برای captureهای لازم استفاده کن. IgnoreCase می‌تواند با قواعد culture رفتار کند؛ برای syntax machine، CultureInvariant معمولاً مناسب‌تر است. در replace، replacement string هم زبان خودش را دارد: $1 یا نام گروه را کورکورانه نگذار؛ تست کن که علامت دلار و متن جایگزین چطور تفسیر می‌شوند.

Unnamed and unnecessary captures make results harder to reason about; use (?:...) for grouping without capture and descriptive names where capture is needed. IgnoreCase can interact with culture; CultureInvariant is often right for machine syntax. Replacement strings have their own syntax too—do not insert $1 or group names blindly; test how dollar signs and replacement text are interpreted.

pattern ثابت پرتکرار را در build آماده کنMove fixed, repeated patterns toward build time

اگر pattern در کد ثابت است و زیاد اجرا می‌شود، ساخت مکرر Regex هزینه دارد. regex source generator با [GeneratedRegex] می‌تواند پیاده‌سازی را زمان build تولید کند؛ در patternهای ثابت اغلب از Compiled انتخاب بهتری است و برای trimming/AOT هم مناسب‌تر می‌شود. اگر pattern در runtime از تنظیم کاربر می‌آید، source generation نمی‌تواند آن را از پیش تولید کند؛ آن ورودی را محدود و validate کن.

Repeated construction has a cost for fixed, frequently used patterns. The regex source generator can emit an implementation at build time with [GeneratedRegex]; for fixed patterns it is often preferable to Compiled and can better support trimming/AOT. A runtime pattern from user configuration cannot be generated ahead of time, so constrain and validate it.

regex تولیدشده / Generated regex
public static partial class InvoicePatterns
{
    [GeneratedRegex(
        @"^INV-[0-9]{4}-[0-9]{4}$",
        RegexOptions.CultureInvariant,
        matchTimeoutMilliseconds: 100)]
    public static partial Regex InvoiceId();
}

bool valid = InvoicePatterns.InvoiceId().IsMatch(value);

source generation هزینهٔ طراحی اشتباه را حذف نمی‌کند؛ همان الگوی پرریسک می‌تواند مشکل‌ساز بماند. برای NonBacktracking هم generator ممکن است پیاده‌سازی سفارشی تولید نکند و به مسیر دیگری fallback کند؛ قابلیت و نتیجهٔ build را برای target واقعی بررسی کن، نه فقط کد را.

Source generation does not fix a poorly designed pattern; a risky expression can remain risky. For NonBacktracking, the generator may not emit a custom implementation and can fall back to another path. Verify behavior and builds for the actual target, not just the source.

کدی فقط دنبال پیشوند INV- می‌گردد؛ نسخهٔ string API را بنویس و مقایسه کن.

Code only checks an INV- prefix; implement and compare a string-API version.

پاسخ فنیTechnical reasoning

StartsWith با StringComparison.Ordinal روشن‌تر و ارزان‌تر است.

StartsWith with StringComparison.Ordinal is clearer and cheaper.

۲) گروه نام‌دار2) Named groups

pattern شمارهٔ فاکتور را با گروه‌های year و serial استخراج کند و نامعتبر را رد کند.

Extract invoice year and serial using named groups, and reject invalid values.

پاسخ فنیTechnical reasoning

از گروه‌های نام‌دار و anchor کل رشته استفاده کن؛ بعد محدودهٔ عددی سال را جدا validate کن.

Use named groups and whole-string anchors, then validate the year’s numeric range separately.

۳) رقم ASCII3) ASCII digits

contract فقط رقم انگلیسی می‌خواهد؛ ورودی شامل رقم فارسی را با دو pattern مقایسه کن.

The contract allows ASCII digits only; compare two patterns using Persian-digit input.

پاسخ فنیTechnical reasoning

[0-9] را برای ASCII به‌کار ببر؛ \d را معادل آن فرض نکن.

Use [0-9] for ASCII and do not assume it is equivalent to \d.

۴) کل رشته4) Whole-string validation

اعتبارسنجی ایمیل بخشی از متن را قبول می‌کند؛ anchor را اضافه و caseهای suffix را تست کن.

An email-like validator accepts a substring; add anchors and test suffix cases.

پاسخ فنیTechnical reasoning

از anchorهای ابتدا و انتها یا \A/\z مطابق نیاز استفاده کن؛ regex کامل email استاندارد را بازسازی نمی‌کند.

Use start/end anchors or \A/\z as required; a regex does not recreate the full email standard.

۵) near-match5) Near-match

برای pattern تو‌در‌تو رشته‌ای بساز که در آخر fail شود و زمان را با طول‌های محدود مقایسه کن.

Create a bounded near-match for a nested pattern and compare timing across input lengths.

پاسخ فنیTechnical reasoning

ورودی نزدیک به match ممکن است backtracking را بدتر کند؛ اندازه‌ها را محدود و timeout بگذار.

Near-matches can amplify backtracking; keep inputs bounded and set a timeout.

۶) timeout6) Timeout

روی ورودی غیرقابل‌اعتماد timeout تنظیم و RegexMatchTimeoutException را به پاسخ کنترل‌شده تبدیل کن.

Set a timeout on untrusted input and turn RegexMatchTimeoutException into a controlled result.

پاسخ فنیTechnical reasoning

یک instance با TimeSpan محدود بساز و timeout را جدا از no-match گزارش کن.

Construct a regex with a bounded TimeSpan and distinguish timeout from no-match.

۷) ورودی literal7) Literal user input

جست‌وجوی کاربر شامل .* است اما باید literal باشد؛ pattern را امن بساز.

User search contains .* but must be literal; build the pattern safely.

پاسخ فنیTechnical reasoning

ورودی را با Regex.Escape escape کن یا از جست‌وجوی substring استفاده کن.

Escape the input with Regex.Escape or use substring search instead.

۸) NonBacktracking8) NonBacktracking

یک pattern با backreference را زیر این option اجرا کن؛ محدودیت را مشاهده و بازطراحی کن.

Run a backreference pattern with this option, observe the limitation and redesign it.

پاسخ فنیTechnical reasoning

backreference پشتیبانی نمی‌شود؛ الگو را به grammar ساده‌تر تبدیل کن یا engine پیش‌فرض را با timeout و ورودی محدود به‌کار ببر.

Backreferences are unsupported; simplify the grammar or use the default engine with a timeout and bounded input.

۹) طول ورودی9) Input length

timeout به تنهایی کافی نیست؛ boundary را با حداکثر طول و تست ۴۰۹۶/۴۰۹۷ کاراکتر کامل کن.

A timeout alone is insufficient; add a maximum-length boundary and test 4096/4097 characters.

پاسخ فنیTechnical reasoning

قبل از regex طول را reject کن و مرز پذیرش/رد را assert کن.

Reject overlong input before matching and assert the acceptance boundary.

۱۰) گروه اضافه10) Unneeded capture

pattern پر از group شماره‌ای است ولی فقط یک مقدار لازم است؛ خروجی را خواناتر کن.

A pattern has many numbered groups but only one value is needed; improve readability.

پاسخ فنیTechnical reasoning

گروه‌های غیرضروری را (?:...) کن و capture لازم را نام‌گذاری کن.

Convert unnecessary groups to (?:...) and name the capture that is needed.

۱۱) culture invariant11) Culture invariant

با تغییر culture تست، matching شناسهٔ ماشینی را پایدار کن.

Make machine-identifier matching stable under a changed test culture.

پاسخ فنیTechnical reasoning

گزینهٔ CultureInvariant را برای syntax مستقل از زبان فعال و تست چند culture را اجرا کن.

Use CultureInvariant for language-independent syntax and run tests under multiple cultures.

۱۲) replace و دلار12) Replacement and dollar signs

مقدار جایگزین کاربر $1 دارد؛ خروجی را از تفسیر اشتباه group نجات بده.

User replacement text contains $1; prevent it from being interpreted as a group reference.

پاسخ فنیTechnical reasoning

از overload مبتنی بر evaluator برای تولید replacement literal یا escaping متناسب استفاده کن؛ fixture دلار را assert کن.

Use an evaluator overload for literal replacement or appropriate escaping; assert a dollar-containing fixture.

۱۳) GeneratedRegex13) GeneratedRegex

pattern ثابت پرتکرار را به source-generated regex تبدیل و اندازهٔ build/publish را ثبت کن.

Convert a fixed, frequently used pattern to a source-generated regex and record build/publish output.

پاسخ فنیTechnical reasoning

کلاس partial و متد partial دارای GeneratedRegex بساز؛ عملکرد و artifact را مقایسه کن، نه فقط benchmark ساختگی.

Create a partial class and method with GeneratedRegex; compare the artifact and workload, not a synthetic benchmark alone.

۱۴) incident جست‌وجو14) Search incident

یک pattern از query باعث timeout در production شده؛ برنامهٔ triage و regression test بنویس.

A query-driven pattern times out in production; write a triage plan and regression test.

پاسخ فنیTechnical reasoning

منبع pattern و طول ورودی را ثبت کن، payload را امن نگه دار، match/near-match بساز، timeout و سقف طول تعیین و یک اصلاح را regression-test کن.

Record pattern source and input length, handle payload safely, reproduce match and near-match cases, bound time and length, then regression-test the fix.

آزمایشگاه: validator شناسهٔ سندLab: a document-ID validator

یک validator برای شناسهٔ سند با grammar روشن بساز؛ اول بررسی کن regex لازم است یا چند API رشته کافی است. تست‌های معتبر، invalid، Unicode digit، suffix اضافه، رشتهٔ خالی و بیش از حد بلند را بنویس. نسخهٔ backtracking و در صورت سازگاری نسخهٔ NonBacktracking را روی ورودی‌های match و near-match اندازه بگیر. برای ورودی runtime timeout بگذار؛ متن pattern را از کاربر نپذیر یا به syntax محدودش کن. در README محدودیت‌ها و تصمیم engine را توضیح بده.

Build a validator for a document ID with an explicit grammar; first decide whether regex is needed or string APIs suffice. Test valid, invalid, Unicode-digit, trailing-suffix, empty and overlong input. Measure backtracking and, if compatible, NonBacktracking on matches and near-matches. Set a timeout for runtime input; do not accept arbitrary user patterns, or restrict their syntax. Document engine choice and limitations.

  2. Write the grammar and length limit before coding.
  3. هر failure class را تست و نتیجهٔ زمان را ثبت کن.
  4. Test each failure class and record timing evidence.
  5. در صورت بی‌نیازی regex، نسخهٔ ساده‌تر را تحویل بده.
  6. If regex is unnecessary, deliver the simpler implementation.

قابل‌قبول بودن regex را با بدترین ورودی بسنجJudge a regex by its worst plausible input

pattern ثابت و کوتاه به معنی امن بودن خودکار نیست. ورودی طول‌محدود، timeout، تست near-match و انتخاب engine با syntax سازگار، هزینه را کنترل می‌کنند؛ source generation برای هزینهٔ build/runtime pattern ثابت است، نه درمان backtracking. اگر مسئله با StartsWith حل می‌شود، ساده‌ترین و امن‌ترین regex همان regex ننوشتن است. فصل بعد سراغ refactoring و analyzers می‌رویم تا کیفیت این قراردادها را زودتر در build پیدا کنیم.

A short fixed pattern is not automatically safe. Bounded input, a timeout, near-match tests and a compatible engine control risk; source generation addresses build/runtime costs for fixed patterns, not backtracking itself. If StartsWith solves the problem, the safest regex is the one you do not write. Next we use refactoring and analyzers to catch contract problems earlier in the build.
