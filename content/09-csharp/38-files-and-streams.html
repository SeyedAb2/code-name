فایل و Stream

Files and streams

سرویس گزارش یک فایل چندصد مگابایتی رو با ReadAllText باز می‌کنه و حافظه پر می‌شه. راه‌حل همیشه «async کن» نیست؛ اول باید بدانیم داده چطور از دیسک به برنامه می‌رسه، چه encoding داره و چه کسی stream رو می‌بندد.

A reporting service loads a hundreds-of-megabytes file with ReadAllText and exhausts memory. “Make it async” is not a complete fix. We inspect how bytes flow, which encoding is used and who owns the stream.

Stream یعنی داده مرحله‌به‌مرحله میادA Stream delivers data incrementally

ReadAllText کل متن رو می‌سازه؛ Stream فقط تکه‌ای از byteها رو در هر لحظه در دسترس می‌ذاره. اگه لازم نیست همهٔ فایل هم‌زمان حافظه باشه، خط‌به‌خط یا buffer بخوان. این کار peak memory رو کم می‌کنه، ولی ممکنه تعداد I/O و latency رو عوض کند؛ معیار رو اندازه بگیر.

ReadAllText creates the full string; a Stream exposes bytes incrementally. If the entire file need not be in memory, read by lines or buffers. This can reduce peak memory but changes I/O and latency; measure the actual workload.

پردازش خط‌به‌خط / Process line by line
using var reader = File.OpenText(path);
while (await reader.ReadLineAsync(cancellationToken) is { } line)
{
    if (line.Contains("PAID", StringComparison.Ordinal))
        await ProcessAsync(line, cancellationToken);
}

این نمونه خط‌ها رو به‌ترتیب می‌خونه و token لغو رو عبور می‌ده. هزینهٔ ProcessAsync و نگهداری state همچنان مهمه؛ streaming تضمین نمی‌کنه کل پردازش O(1) حافظه بماند.

This reads lines sequentially and propagates cancellation. Processing cost and retained state still matter; streaming does not guarantee the whole pipeline uses O(1) memory.

فایل متن، byte هست نه حروف آمادهA text file is bytes, not ready-made characters

Reader باید بداند byteها رو با چه encoding به char تبدیل کند. اگه writer و reader توافق نکنند، فارسی خراب می‌شه یا replacement character می‌بینی. UTF-8 رو آگاهانه انتخاب و round-trip متن غیر ASCII رو تست کن. BOM هم byteهای ابتدای فایل هست و رفتار consumerها باید روشن باشه.

A reader needs an encoding to convert bytes into characters. If writer and reader disagree, Persian text may become corrupted or show replacement characters. Choose UTF-8 deliberately and test non-ASCII round trips. A BOM is also part of the leading bytes; document consumer behaviour.

buffer و مالکیت رو جدا تصمیم بگیرDecide buffering and ownership separately

buffer بزرگ‌تر الزاماً سریع‌تر نیست؛ disk، OS، تعداد فایل و الگوی دسترسی دخیل‌اند. اگه متد Stream caller رو می‌گیره، قرارداد مشخص کند آیا آن رو می‌بندد؛ StreamReader گزینهٔ leaveOpen داره. File.Exists پیش از Open هم تضمین نمی‌کنه فایل هنوز همان‌جاست؛ عمل اصلی رو انجام بده و exception مرتبط رو مدیریت کن.

A larger buffer is not automatically faster; disk, OS, file count and access pattern matter. If a method receives a caller-owned Stream, state whether it closes it; StreamReader offers leaveOpen. File.Exists before Open cannot guarantee the file remains present—perform the operation and handle relevant exceptions.

دادهٔ باینری قرارداد دقیق می‌خوادBinary data needs an explicit contract

BinaryReader/Writer مقدارهای typed می‌خونن و می‌نویسن؛ این با متن فرق داره. file format باید نوع‌ها، ترتیب بایت، نسخه و مرز رکورد رو تعریف کند. فرض معماری یا endianness رو وارد قرارداد نکن. MemoryStream برای تست سریع عالی هست ولی permission، lock و sharing فایل واقعی رو اثبات نمی‌کنه.

BinaryReader/Writer read and write typed values, unlike text. A file format must define types, byte order, version and record boundaries. Do not smuggle architecture assumptions into it. MemoryStream is useful for isolated tests but does not prove real file permissions, locking or sharing.

async نخ رو آزاد می‌کنه، نه دیسک رو نامحدودAsync frees a thread, not the disk's limits

ReadAsync می‌تونه thread رو هنگام I/O معطل نکند، اما throughput storage محدود می‌مونه. خواندن هم‌زمان صدها فایل ممکنه دیسک رو بدتر کند؛ concurrency رو محدود، cancellation رو عبور و latency/memory رو اندازه بگیر. در نوشتن bufferشده، Flush به‌تنهایی تضمین durability فیزیکی نیست.

ReadAsync can avoid blocking a thread during I/O, but storage throughput remains bounded. Reading hundreds of files concurrently may worsen the disk; bound concurrency, propagate cancellation, and measure latency and memory. For buffered writes, Flush alone does not prove physical durability.
