فایل و Stream

Files and streams

سرویس گزارش یک فایل چندصد مگابایتی را با ReadAllText باز می‌کند و حافظه پر می‌شود. راه‌حل همیشه «async کن» نیست؛ اول باید بدانیم داده چطور از دیسک به برنامه می‌رسد، چه encoding دارد و چه کسی stream را می‌بندد.

A reporting service loads a hundreds-of-megabytes file with ReadAllText and exhausts memory. “Make it async” is not a complete fix. We inspect how bytes flow, which encoding is used and who owns the stream.

Stream یعنی داده مرحله‌به‌مرحله می‌آیدA Stream delivers data incrementally

ReadAllText کل متن را می‌سازد؛ Stream فقط تکه‌ای از byteها را در هر لحظه در دسترس می‌گذارد. اگر لازم نیست همهٔ فایل هم‌زمان حافظه باشد، خط‌به‌خط یا buffer بخوان. این کار peak memory را کم می‌کند، ولی ممکن است تعداد I/O و latency را عوض کند؛ معیار را اندازه بگیر.

ReadAllText creates the full string; a Stream exposes bytes incrementally. If the entire file need not be in memory, read by lines or buffers. This can reduce peak memory but changes I/O and latency; measure the actual workload.

پردازش خط‌به‌خط / Process line by line
using var reader = File.OpenText(path);
while (await reader.ReadLineAsync(cancellationToken) is { } line)
{
    if (line.Contains("PAID", StringComparison.Ordinal))
        await ProcessAsync(line, cancellationToken);
}

این نمونه خط‌ها را به‌ترتیب می‌خواند و token لغو را عبور می‌دهد. هزینهٔ ProcessAsync و نگهداری state همچنان مهم است؛ streaming تضمین نمی‌کند کل پردازش O(1) حافظه بماند.

This reads lines sequentially and propagates cancellation. Processing cost and retained state still matter; streaming does not guarantee the whole pipeline uses O(1) memory.

فایل متن، byte است نه حروف آمادهA text file is bytes, not ready-made characters

Reader باید بداند byteها را با چه encoding به char تبدیل کند. اگر writer و reader توافق نکنند، فارسی خراب می‌شود یا replacement character می‌بینی. UTF-8 را آگاهانه انتخاب و round-trip متن غیر ASCII را تست کن. BOM هم byteهای ابتدای فایل است و رفتار consumerها باید روشن باشد.

A reader needs an encoding to convert bytes into characters. If writer and reader disagree, Persian text may become corrupted or show replacement characters. Choose UTF-8 deliberately and test non-ASCII round trips. A BOM is also part of the leading bytes; document consumer behaviour.

buffer و مالکیت را جدا تصمیم بگیرDecide buffering and ownership separately

buffer بزرگ‌تر الزاماً سریع‌تر نیست؛ disk، OS، تعداد فایل و الگوی دسترسی دخیل‌اند. اگر متد Stream caller را می‌گیرد، قرارداد مشخص کند آیا آن را می‌بندد؛ StreamReader گزینهٔ leaveOpen دارد. File.Exists پیش از Open هم تضمین نمی‌کند فایل هنوز همان‌جاست؛ عمل اصلی را انجام بده و exception مرتبط را مدیریت کن.

A larger buffer is not automatically faster; disk, OS, file count and access pattern matter. If a method receives a caller-owned Stream, state whether it closes it; StreamReader offers leaveOpen. File.Exists before Open cannot guarantee the file remains present—perform the operation and handle relevant exceptions.

دادهٔ باینری قرارداد دقیق می‌خواهدBinary data needs an explicit contract

BinaryReader/Writer مقدارهای typed می‌خوانند و می‌نویسند؛ این با متن فرق دارد. file format باید نوع‌ها، ترتیب بایت، نسخه و مرز رکورد را تعریف کند. فرض معماری یا endianness را وارد قرارداد نکن. MemoryStream برای تست سریع عالی است ولی permission، lock و sharing فایل واقعی را اثبات نمی‌کند.

BinaryReader/Writer read and write typed values, unlike text. A file format must define types, byte order, version and record boundaries. Do not smuggle architecture assumptions into it. MemoryStream is useful for isolated tests but does not prove real file permissions, locking or sharing.

async نخ را آزاد می‌کند، نه دیسک را نامحدودAsync frees a thread, not the disk's limits

ReadAsync می‌تواند thread را هنگام I/O معطل نکند، اما throughput storage محدود می‌ماند. خواندن هم‌زمان صدها فایل ممکن است دیسک را بدتر کند؛ concurrency را محدود، cancellation را عبور و latency/memory را اندازه بگیر. در نوشتن bufferشده، Flush به‌تنهایی تضمین durability فیزیکی نیست.

ReadAsync can avoid blocking a thread during I/O, but storage throughput remains bounded. Reading hundreds of files concurrently may worsen the disk; bound concurrency, propagate cancellation, and measure latency and memory. For buffered writes, Flush alone does not prove physical durability.

فایل را با قراردادش بخوانRead a file according to its contract

Stream مصرف مرحله‌ای می‌دهد؛ encoding byte را به متن معنی‌دار تبدیل می‌کند؛ ownership تعیین می‌کند چه کسی Dispose کند؛ async نخ را آزاد می‌کند، اما ظرفیت دیسک را زیاد نمی‌کند. برای XML، ترتیب و حجم فایل مهم‌تر می‌شود: DOM یا parser جریانی را با نیاز واقعی انتخاب خواهیم کرد.

Stream enables incremental consumption; encoding maps bytes to text; ownership determines who disposes; async frees threads but does not increase disk capacity. For XML, document size and access patterns guide the choice between a DOM and streaming parser.
