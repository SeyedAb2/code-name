foreach، iterator و yield

foreach, iterators and yield

کاربر فقط صفحهٔ اول گزارش را می‌خواهد، اما برنامه پیش از نمایش، کل فایل را در List می‌ریزد. آیا واقعاً باید همهٔ داده را همین حالا بخوانیم؟ با iterator تولید را مرحله‌ای می‌کنیم و زمان اجرای کد را دنبال می‌کنیم.

The user needs only the first report page, but the program loads the entire file into a List first. Must we read everything now? We use an iterator to produce items incrementally and trace when code actually runs.

yield یعنی تولید هر بار درخواستyield means producing on demand

متدی که IEnumerable برمی‌گرداند ممکن است هنوز هیچ آیتمی نساخته باشد. yield return مرز بین دو مرحلهٔ تولید است؛ MoveNext اجرای iterator را تا yield بعدی جلو می‌برد. وقتی مصرف‌کننده Dispose کند یا enumeration تمام شود، iterator هم متوقف می‌شود.

A method returning IEnumerable may not have produced any item yet. Each yield return is a boundary; MoveNext advances execution to the next yield. When the consumer disposes or enumeration ends, the iterator stops.

نمونه / Example
static IEnumerable<string> ReadLines(string path)
{
    using var reader = File.OpenText(path);
    while (reader.ReadLine() is { } line)
        yield return line;
}

خروجی نماینده: MoveNext → read one line → yield → consumer handles it. این مشاهده اجرای منبع را نشان می‌دهد؛ دربارهٔ هزینهٔ کل یا تکرارپذیری بدون آزمایش دیگر چیزی ثابت نمی‌کند.

Representative output: MoveNext → read one line → yield → consumer handles it. This shows the source being consumed; it does not prove total cost or repeatability without further tests.

تعویق اجرای queryDeferred execution

ساخت sequence را با مصرفش اشتباه نکن. می‌توانی query را بسازی، دادهٔ منبع را تغییر بدهی، بعد iterate کنی؛ آن‌وقت نتیجه ممکن است مقدار تازه را ببیند. ToArray/ToList materialize می‌کند، ولی هزینهٔ حافظه و زمان دارد.

Creating a sequence is not consuming it. Build a query, mutate its source, then enumerate; it may observe the later value. ToArray/ToList materialize, with time and memory costs.

single-pass و چندبارهSingle-pass and repeated enumeration

IEnumerable تضمین نمی‌کند منبع ارزان یا تکرارپذیر باشد. فایل، شبکه یا generator ممکن است دوباره از ابتدا اجرا شود یا اصلاً دوباره‌خوانی نداشته باشد. اگر چند بار لازم داری، یا یک‌بار materialize کن، یا الگوریتم را یک‌گذره بساز.

IEnumerable does not promise cheap or repeatable enumeration. A file, network source or generator may rerun or may not support another pass. If multiple passes are required, materialize once or redesign for one pass.

منابع و لغوResources and cancellation

iteratorای که فایل باز می‌کند باید عمر فایل را تا پایان enumeration کنترل کند. consumer ممکن است زودتر break کند؛ using/iterator باید cleanup را انجام دهد. برای I/O ناهمگام از async iterator و cancellation استفاده می‌کنیم، نه Thread.Sleep داخل yield.

An iterator opening a file must scope it across enumeration. A consumer may break early; disposal must clean up. For asynchronous I/O use async iterators and cancellation, not Thread.Sleep inside yield.

یک پروژهٔ کنسولی و fixture کوچک بساز. رفتار baseline را با تست و خروجی ثبت کن، یک فرض را عمداً بشکن، failure را در نزدیک‌ترین مرز پیدا کن، اصلاح کن و همان تست را دوباره اجرا کن. گزارشت باید کد، خروجی، تفسیر و چیزی را که هنوز ثابت نشده در بر بگیرد.

Create a console project and a small fixture. Capture baseline behaviour with a test and output, deliberately break one assumption, locate the nearest failure boundary, repair it and rerun the same test. Report code, output, interpretation, and what remains unproven.

  1. baseline و انتظار را ثبت کن.
  2. Record baseline and expected behaviour.
  3. تغییر کنترل‌شده و failure را بازتولید کن.
  4. Make a controlled change and reproduce failure.
  5. repair را با همان acceptance test اثبات کن.
  6. Prove the repair with the same acceptance test.
