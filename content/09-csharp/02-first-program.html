اول یک برنامهٔ قابل تکرار بسازیمFirst, make a reproducible program

به‌جای چسباندن کد در یک فایل ناشناس، از SDK پروژهٔ معمولی بساز. پروژه می‌گوید کدام framework هدف است و build چه فایل‌هایی را باید بشناسد.

Instead of pasting code into an unknown file, use the SDK to create a regular project. The project declares its target framework and the files and settings the build understands.

terminal
dotnet new console --framework net10.0 --name OrderHello
cd OrderHello
dotnet run
representative output
Hello, World!

در قالب جدید، ممکن است `Program.cs` فقط یک دستور top-level داشته باشد و `Main` را نبینی. این به معنی حذف نقطهٔ شروع نیست؛ compiler ساختار لازم را تولید می‌کند. فعلاً با `Console.WriteLine` خروجی بگیریم و از رفتار قابل مشاهده شروع کنیم.

A current template may show only a top-level statement in `Program.cs`, with no visible `Main`. The entry point has not disappeared; the compiler supplies the required structure. For now, use `Console.WriteLine` and start from observable behavior.

برنامه را تغییر بده؛ فقط فایل را نگاه نکنChange the program; do not just inspect the file

`Program.cs` را با این کد عوض کن. برنامه نام را از آرگومان می‌گیرد و اگر ورودی نداشته باشیم، مقدار پیش‌فرض دارد.

Replace `Program.cs` with this code. The program reads a name from an argument and has a default when no input is supplied.

Program.cs
string name = args.Length > 0 ? args[0] : "دوست";
Console.WriteLine($"سلام، {name}!");

حالا دو شکل اجرا را مقایسه کن:

Now compare two invocation forms:

terminal
dotnet run
dotnet run -- نگار

`--` به `dotnet run` می‌گوید آرگومان‌های بعدش را به برنامه بدهد، نه اینکه آن‌ها را خودش تفسیر کند. خط دوم باید «سلام، نگار!» چاپ کند. اگر `args[0]` را بی‌بررسی بخوانی، اجرای بدون آرگومان می‌تواند `IndexOutOfRangeException` بدهد؛ مقدار پیش‌فرض این مسیر را امن می‌کند.

`--` tells `dotnet run` to pass the remaining arguments to the application instead of interpreting them itself. The second command should print “سلام، نگار!”. Reading `args[0]` without checking can throw `IndexOutOfRangeException` when no argument is supplied; the default protects that path.

ورودی‌ها رشته‌اندArguments are strings

حتی اگر کاربر `42` وارد کند، `args[0]` متن است. تبدیل و اعتبارسنجی را در فصل نوع‌ها و بعدتر در پروژهٔ CLI دقیق‌تر انجام می‌دهیم؛ فعلاً این تفاوت را با عدد و متن اشتباه نگیر.

Even when a user enters `42`, `args[0]` is text. We will handle conversion and validation in the types module and the CLI project; for now, do not confuse a string with a number.

دو جور شکست: قبل از اجرا و حین اجراTwo failures: before execution and during it

یک حرف را در نام متغیر اشتباه کن و `dotnet build` بگیر. compiler خطا می‌دهد و برنامه شروع نمی‌شود. بعد کد را طوری عوض کن که `args[0]` را بدون بررسی بخواند و بدون آرگومان اجرا کن؛ این بار compile موفق است ولی runtime exception می‌دهد.

Mistype a variable name and build. The compiler reports an error and the app never starts. Then read `args[0]` without checking and run with no arguments; this time compilation succeeds but the runtime throws.

به پیام شکست نگاه کن، اما فقط پیام را حفظ نکن. سؤال تشخیصی این است: آیا برنامه اصلاً به مرحلهٔ اجرا رسیده؟ این سؤال نیمی از مسیرهای بی‌ربط عیب‌یابی را حذف می‌کند.

Read the failure message, but do not merely memorize it. Ask: did execution start at all? That question eliminates many irrelevant debugging paths.

۱) آرگومان را به خروجی وصل کن1) Connect an argument to output

برنامه را تغییر بده تا `dotnet run -- Mina` نام را در خروجی نشان دهد. سپس حالت بدون آرگومان را هم اجرا و خروجی هر دو را ثبت کن. در کدام خط `--` نقش دارد؟

Change the program so `dotnet run -- Mina` includes the name in output. Run the no-argument case too and record both results. Which boundary does `--` affect?

پاسخ و توضیحSolution and explanation
Program.cs
string name = args.Length > 0 ? args[0] : "دوست";
Console.WriteLine($"سلام، {name}!");

آرگومان برنامه پس از `--` می‌آید. خروجی نمونه برای ورودی `Mina`: `سلام، Mina!`. حالت بی‌ورودی باید از مقدار پیش‌فرض استفاده کند. این تمرین parsing عدد و اعتبارسنجی ورودی را هنوز حل نکرده.

Application arguments follow `--`. For `Mina`, representative output is `سلام، Mina!`; the empty case uses the default. This does not yet solve numeric parsing or input validation.

۲) با ورودی خالی crash نکن2) Do not crash on empty input

کد را موقتاً به `args[0]` تغییر بده؛ بدون آرگومان اجرا کن و exception را ببین. بعد guard یا مقدار پیش‌فرض را برگردان و همان دستور را دوباره اجرا کن.

Temporarily change the code to `args[0]`, run without arguments and observe the exception. Restore a guard or default, then repeat the same invocation.

پاسخ و توضیحSolution and explanation

آرایهٔ خالی اندیس صفر ندارد، پس دسترسی runtime exception می‌دهد. `args.Length > 0` شرط دسترسی را برقرار می‌کند؛ اجرای دوباره باید بدون exception مقدار پیش‌فرض را چاپ کند. این فقط نبودن آرگومان را پوشش می‌دهد، نه رشتهٔ خالی یا ورودی نامعتبر.

An empty array has no index zero, so access throws at run time. The length check guards the access; repeating the command should print the default without an exception. It does not handle an empty string or invalid input.

۳) خطای اسم را تشخیص بده3) Diagnose a name error

`Console.WriteLine(greeting);` را بنویس، درحالی‌که متغیرت `name` است. build بگیر، خطای compiler را ثبت کن و اصلاح کن. چرا stack trace برای این خطا نداری؟

Write `Console.WriteLine(greeting);` while the variable is named `name`. Build, record the compiler diagnostic and fix it. Why is there no stack trace?

پاسخ و توضیحSolution and explanation

نام تعریف‌نشده خطای compile-time می‌دهد و executable قابل اجرا ساخته نمی‌شود؛ بنابراین exception زمان اجرا و stack trace هم نداریم. شناسه را به `name` اصلاح کن و build را تکرار کن.

An undefined name is a compile-time error, so no runnable program is produced; there is no run-time exception or stack trace. Correct the identifier and build again.

۴) exit code را مقایسه کن4) Compare exit codes

برنامه‌ای بساز که برای ورودی درست exit code صفر و برای ورودی نامعتبر کد غیرصفر بدهد. در PowerShell بلافاصله بعد از اجرا `$LASTEXITCODE` را بخوان. خروجی متن به‌تنهایی چه چیزی را از این کد نمی‌فهماند؟

Make the program return zero for valid input and non-zero for invalid input. In PowerShell, read `$LASTEXITCODE` immediately after each run. What does this code tell you that text output alone does not?

پاسخ و توضیحSolution and explanation
C#
if (args.Length == 0)
{
    Console.Error.WriteLine("نام لازم است.");
    return 2;
}
Console.WriteLine($"سلام، {args[0]}!");
return 0;

کد خروجی قرارداد برنامه با shell و ابزارهای بعدی است؛ متن خروجی تشخیص انسانی را کمک می‌کند. در PowerShell مقدار `$LASTEXITCODE` را بلافاصله بعد از `dotnet run --` بخوان. عدد ۲ فقط انتخاب برنامهٔ ماست، نه یک کد جهانی C#.

The exit code is the program's contract with the shell and automation; text helps a human diagnose. In PowerShell, inspect `$LASTEXITCODE` immediately after `dotnet run --`. Code 2 is our program's choice, not a universal C# code.
