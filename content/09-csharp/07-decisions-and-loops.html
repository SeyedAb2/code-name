شرط، switch و حلقه

Conditions, switch and loops

سفارش ممکن است تازه، پرداخت‌شده، در راه یا لغوشده باشد. اگر برای هر حالت یک if جدا و بی‌ارتباط بنویسیم، ممکن است یک سفارش هم‌زمان از دو مسیر عبور کند. بیایید جریان تصمیم را با دادهٔ واقعی روشن کنیم.

An order may be new, paid, shipping or cancelled. Independent `if` statements can send one order down two paths at once. Let us make the decision flow explicit with real states.

وقتی حالت‌ها انحصاری‌اند، زنجیره بسازChain mutually exclusive states

با دو `if` مستقل چه اتفاقی می‌افتد؟ شرط اول true است؛ اما اجرای برنامه پس از آن ادامه دارد و شرط بعدی را هم می‌سنجد.

What happens with two independent `if` statements? Even when the first is true, execution continues and checks the next condition too.

C#
if (status == "paid") Console.WriteLine("ثبت ارسال");
if (status != "cancelled") Console.WriteLine("قابل بررسی");

برای status برابر `paid` هر دو پیام می‌آیند. اگر قرار است دقیقاً یک مسیر انتخاب شود، `if / else if / else` یا `switch` شکل مسئله را بهتر نشان می‌دهد. اول invariant را تعریف کن: آیا حالت‌ها واقعاً متقابلاً انحصاری‌اند؟

For `paid`, both messages appear. If exactly one path should be selected, `if / else if / else` or `switch` better represents the rule. Start with the invariant: are these states truly mutually exclusive?

C#
string message = status switch
{
    "new" => "منتظر پرداخت",
    "paid" => "آمادهٔ ارسال",
    "cancelled" => "لغوشده",
    _ => "وضعیت ناشناخته"
};

switch expression یک مقدار می‌سازد. الگوی `_` حالت‌های باقی‌مانده را می‌گیرد؛ اگر این fallback پیام خطا را پنهان می‌کند، بهتر است وضعیت نامعتبر را تشخیص‌پذیر کنیم. switch statement برای اجرای چند دستور در هر case هم وجود دارد.

A switch expression produces a value. `_` handles remaining cases; if that fallback hides invalid state, make it diagnosable instead. A switch statement is also available when each case performs multiple statements.

حلقه را با مرز پایان تعریف کنDefine a loop's stopping boundary

وقتی چند ردیف را می‌خوانیم، حلقه باید سه سؤال را جواب دهد: از کجا شروع می‌کنیم؟ چه زمانی ادامه می‌دهیم؟ در هر دور چه چیزی تغییر می‌کند؟

When processing rows, a loop should answer three questions: where do we start, when do we continue, and what changes each iteration?

C#
string[] orderIds = ["A-10", "A-11", "A-12"];
for (int i = 0; i < orderIds.Length; i++)
{
    Console.WriteLine(orderIds[i]);
}

شرط `i < Length` از آخرین اندیس معتبر عبور نمی‌کند؛ بعد از هر دور i زیاد می‌شود. یک `<` اشتباه یا تغییرنکردن i می‌تواند یک ردیف را حذف یا حلقه را بی‌نهایت کند. برای خواندن همهٔ عضوها، `foreach` اغلب کم‌خطاتر است؛ وقتی خود اندیس لازم است `for` را انتخاب کن.

The `i < Length` condition stops before the first invalid index, and `i` advances each iteration. A wrong comparison or a missing increment can skip a row or loop forever. `foreach` is often safer when visiting every element; use `for` when the index itself matters.

`break` حلقه را تمام می‌کند؛ `continue` فقط به دور بعد می‌رود؛ `return` از متد خارج می‌شود. این سه یکی نیستند. وقتی داخل چند حلقه و شرط تو در تو هستی، زودتر از همه تصمیم بگیر کدام سطح باید تمام شود.

`break` exits a loop; `continue` advances to the next iteration; `return` leaves the method. They are not interchangeable. In nested loops and conditions, decide which level should stop.

while، ورودی و پایان قابل پیش‌بینیwhile, input and predictable termination

`while` وقتی مناسب است که تعداد دورها را از قبل نمی‌دانیم، اما باید شرط توقف مشخص باشد. حلقه‌ای که فقط با `continue` می‌چرخد و هیچ حالت پایان ندارد، باگ است—even اگر امروز ورودی کوچک باشد.

`while` fits when the iteration count is unknown but the stopping condition is explicit. A loop that keeps continuing without a termination path is a bug—even if today's input is small.

C#
int attempts = 0;
while (attempts < 3)
{
    attempts++;
    Console.WriteLine($"تلاش {attempts}");
}

افزایش داخل حلقه تضمین می‌کند شرط بعد از حداکثر سه دور false شود. اگر `attempts++` را حذف کنی، حلقه متوقف نمی‌شود. در شبکه و ورودی خارجی، به شرط توقف علاوه بر counter ممکن است cancellation و timeout هم نیاز داشته باشیم؛ آن‌ها را در ماژول async می‌آموزیم.

The increment guarantees the condition becomes false after at most three iterations. Remove it and the loop never stops. Network and external-input loops may need cancellation and timeouts in addition to a counter; those belong in the async module.

۱) دو پیام ناخواسته را حذف کن1) Remove the unexpected second message

شرط‌های مستقل فصل را به ساختاری تبدیل کن که برای `paid` فقط «آمادهٔ ارسال» و برای `cancelled` فقط «لغوشده» چاپ شود. با هر دو ورودی تست کن.

Replace the independent conditions so `paid` prints only “ready to ship” and `cancelled` only “cancelled.” Test both inputs.

پاسخ و دلیلSolution and reasoning
C#
if (status == "paid")
    Console.WriteLine("آمادهٔ ارسال");
else if (status == "cancelled")
    Console.WriteLine("لغوشده");

شاخه‌ها به هم وابسته‌اند؛ بعد از match موفق، else if دیگر اجرا نمی‌شود. وضعیت‌های دیگر هنوز بی‌پاسخ‌اند؛ در برنامهٔ واقعی برایشان رفتار مشخص یا خطای قابل‌مشاهده اضافه کن.

The branches are mutually exclusive; after one matches, the next is skipped. Other states remain unspecified, so a real program should handle them explicitly.

۲) case ناشناخته را پنهان نکن2) Do not hide an unknown case

switch expression وضعیت را دریافت می‌کند. آن را طوری تغییر بده که state ناشناخته با exception تشخیص‌پذیر شود. برای ورودی درست و غلط اجرا کن.

Change the switch expression so an unknown state produces a detectable exception. Run one valid and one invalid input.

پاسخ و دلیلSolution and reasoning
C#
string message = status switch
{
    "new" => "منتظر پرداخت",
    "paid" => "آمادهٔ ارسال",
    "cancelled" => "لغوشده",
    _ => throw new ArgumentOutOfRangeException(nameof(status), status, "وضعیت ناشناخته")
};

fallback دیگر خطا را به متن عادی تبدیل نمی‌کند؛ خطای داده به caller می‌رسد. اگر unknown state رخداد مورد انتظار است، شاید Result یا مسیر خطای کنترل‌شده مناسب‌تر باشد—این مثال فقط تشخیص را روشن می‌کند.

The fallback no longer turns invalid data into an ordinary message; it surfaces the failure to the caller. If unknown state is expected, a result type or handled error path may be better—this example makes the failure visible.

۳) off-by-one را پیدا کن3) Find the off-by-one bug

شرط `i <= orderIds.Length` را در for امتحان کن. آخرین خروجی و exception را ببین، بعد شرط را repair کن و تعداد چاپ‌شده‌ها را با طول آرایه مقایسه کن.

Try `i <= orderIds.Length` in the loop. Observe the last output and exception, then repair it and compare printed count with array length.

پاسخ و دلیلSolution and reasoning

اندیس معتبر تا `Length - 1` است، پس `<= Length` یک دور اضافه اجرا می‌کند و index خارج محدوده می‌خواند. شرط درست `i < orderIds.Length` است. تعداد چاپ‌ها باید با طول آرایه برابر باشد.

Valid indices end at `Length - 1`, so `<= Length` performs one extra iteration and reads out of range. Use `i < orderIds.Length`; the printed count should equal array length.

۴) break و continue را از هم جدا کن4) Distinguish break from continue

از آرایهٔ `[3, -1, 8]` فقط مقدارهای مثبت را چاپ کن. نسخهٔ اول روی مقدار منفی کل حلقه را تمام کند؛ نسخهٔ دوم فقط از آن عضو بگذرد. تفاوت خروجی را ثبت کن.

From `[3, -1, 8]`, print positive values. In one version stop at a negative; in another skip only that item. Record the output difference.

پاسخ و دلیلSolution and reasoning
C#
foreach (int value in values)
{
    if (value < 0) continue; // 3, 8
    Console.WriteLine(value);
}

با `continue`، -1 رد می‌شود و 8 هنوز چاپ می‌شود. با `break` حلقه همان‌جا تمام می‌شود و فقط 3 چاپ خواهد شد. انتخاب به معنی «رد یک عضو» یا «پایان کل پیمایش» بستگی دارد.

`continue` skips -1 and still reaches 8. `break` ends the loop there, so only 3 prints. Choose based on whether the rule means “skip this item” or “stop the traversal.”

۵) یک حلقهٔ تضمین‌شده بساز5) Build a loop with guaranteed termination

با while حداکثر سه تلاش چاپ کن. یک نسخهٔ خراب بساز که counter جلو نرود؛ آن را اجرا نکن—با code review توضیح بده چرا termination ندارد. سپس نسخهٔ درست را run کن.

Print at most three attempts with while. Create a broken version without counter progress but do not run it; explain why it cannot terminate, then run the correct version.

پاسخ و دلیلSolution and reasoning
C#
int attempts = 0;
while (attempts < 3)
{
    attempts++;
    Console.WriteLine(attempts);
}

counter از ۰ به ۳ می‌رسد و شرط false می‌شود. نسخهٔ بدون increment مقدار را عوض نمی‌کند، پس اگر شرط ابتدا true است همیشه true می‌ماند. code review برای این مورد از اجرای حلقهٔ بی‌نهایت امن‌تر است.

The counter advances from 0 to 3, making the condition false. Without the increment, a true initial condition remains true forever. Reviewing this case is safer than running an infinite loop.

وقتی تصمیم‌ها زیاد شدند، کد را تکه‌تکه می‌کنیمWhen decisions grow, we split the code into methods

شرط و حلقه جریان همین بخش از برنامه را کنترل می‌کنند. وقتی همین منطق در چند جا تکرار شود، باید آن را به یک رفتار نام‌دار تبدیل کنیم. در فصل بعد متد می‌سازیم و ورودی/خروجی‌اش را دقیق تعریف می‌کنیم.

Conditions and loops control this part of the program. When the same logic appears in several places, it deserves a named behavior. Next we will create methods and define their inputs and outputs.
