شرط، switch و حلقه

Conditions, switch and loops

سفارش ممکنه تازه، پرداخت‌شده، در راه یا لغوشده باشه. اگه برای هر حالت یک if جدا و بی‌ارتباط بنویسیم، ممکنه یک سفارش هم‌زمان از دو مسیر عبور کند. بیایید جریان تصمیم رو با دادهٔ واقعی روشن کنیم.

An order may be new, paid, shipping or cancelled. Independent `if` statements can send one order down two paths at once. Let us make the decision flow explicit with real states.

وقتی حالت‌ها انحصاری‌اند، زنجیره بسازChain mutually exclusive states

با دو `if` مستقل چه اتفاقی می‌افتد؟ شرط اول true هست؛ اما اجرای برنامه پس از آن ادامه داره و شرط بعدی رو هم می‌سنجد.

What happens with two independent `if` statements? Even when the first is true, execution continues and checks the next condition too.

C#
if (status == "paid") Console.WriteLine("ثبت ارسال");
if (status != "cancelled") Console.WriteLine("قابل بررسی");

برای status برابر `paid` هر دو پیام میان. اگه قرار هست دقیقاً یک مسیر انتخاب بشه، `if / else if / else` یا `switch` شکل مسئله رو بهتر نشان می‌ده. اول invariant رو تعریف کن: آیا حالت‌ها واقعاً متقابلاً انحصاری‌اند؟

For `paid`, both messages appear. If exactly one path should be selected, `if / else if / else` or `switch` better represents the rule. Start with the invariant: are these states truly mutually exclusive?

C#
string message = status switch
{
    "new" => "منتظر پرداخت",
    "paid" => "آمادهٔ ارسال",
    "cancelled" => "لغوشده",
    _ => "وضعیت ناشناخته"
};

switch expression یک مقدار می‌سازه. الگوی `_` حالت‌های باقی‌مانده رو می‌گیره؛ اگه این fallback پیام خطا رو پنهان می‌کنه، بهتره وضعیت نامعتبر رو تشخیص‌پذیر کنیم. switch statement برای اجرای چند دستور در هر case هم وجود داره.

A switch expression produces a value. `_` handles remaining cases; if that fallback hides invalid state, make it diagnosable instead. A switch statement is also available when each case performs multiple statements.

شرط‌ها وقتی سخت می‌شن که business ruleها روی هم جمع بشنBranches get hard when business rules pile up

`if` و `for` به‌خودی‌خود سخت نیستن. چیزی که کد رو سخت می‌کنه اینه که تخفیف، وضعیت سفارش، موجودی و نقش کاربر کم‌کم روی هم سوار بشن و هیچ‌کس ندونه کدوم branch واقعاً اجرا می‌شه. این فصل از چند شرط ساده شروع می‌کنه ولی هدفش اینه که کنترل جریان رو بتونی روی کاغذ دنبال کنی.

`if` and `for` are not difficult by themselves. Code becomes difficult when discounts, order state, inventory, and user roles accumulate until nobody is sure which branch actually runs. We start with simple conditions, but the real goal is to trace control flow on paper and in execution.

هر جا branch اضافه می‌کنی، یه ورودی نمونه هم کنارش داشته باش. اگه نمی‌تونی بگی کد با اون ورودی از چه مسیرهایی رد می‌شه، ساختار هنوز برای خودت هم روشن نیست. بعداً pattern matching و polymorphism بعضی شاخه‌ها رو کم می‌کنن؛ فعلاً اول خود جریان رو درست ببین.

Whenever you add a branch, keep a concrete input beside it. If you cannot say which path that input follows, the structure is not yet clear even to you. Later, pattern matching and polymorphism will remove some branching; first learn to see the flow accurately.

حلقه رو با مرز پایان تعریف کنDefine a loop's stopping boundary

وقتی چند ردیف رو می‌خونیم، حلقه باید سه سؤال رو جواب دهد: از کجا شروع می‌کنیم؟ چه زمانی ادامه می‌دهیم؟ در هر دور چه چیزی تغییر می‌کنه؟

When processing rows, a loop should answer three questions: where do we start, when do we continue, and what changes each iteration?

C#
string[] orderIds = ["A-10", "A-11", "A-12"];
for (int i = 0; i < orderIds.Length; i++)
{
    Console.WriteLine(orderIds[i]);
}

شرط `i < Length` از آخرین اندیس معتبر عبور نمی‌کنه؛ بعد از هر دور i زیاد می‌شه. یک `<` اشتباه یا تغییرنکردن i می‌تونه یک ردیف رو حذف یا حلقه رو بی‌نهایت کند. برای خواندن همهٔ عضوها، `foreach` اغلب کم‌خطاتر هست؛ وقتی خود اندیس لازمه `for` رو انتخاب کن.

The `i < Length` condition stops before the first invalid index, and `i` advances each iteration. A wrong comparison or a missing increment can skip a row or loop forever. `foreach` is often safer when visiting every element; use `for` when the index itself matters.

`break` حلقه رو تمام می‌کنه؛ `continue` فقط به دور بعد می‌ره؛ `return` از متد خارج می‌شه. این سه یکی نیستن. وقتی داخل چند حلقه و شرط تو در تو هستی، زودتر از همه تصمیم بگیر کدوم سطح باید تمام بشه.

`break` exits a loop; `continue` advances to the next iteration; `return` leaves the method. They are not interchangeable. In nested loops and conditions, decide which level should stop.

while، ورودی و پایان قابل پیش‌بینیwhile, input and predictable termination

`while` وقتی مناسب هست که تعداد دورها رو از قبل نمی‌دانیم، اما باید شرط توقف مشخص باشه. حلقه‌ای که فقط با `continue` می‌چرخد و هیچ حالت پایان نداره، باگ است—even اگه امروز ورودی کوچک باشه.

`while` fits when the iteration count is unknown but the stopping condition is explicit. A loop that keeps continuing without a termination path is a bug—even if today's input is small.

C#
int attempts = 0;
while (attempts < 3)
{
    attempts++;
    Console.WriteLine($"تلاش {attempts}");
}

افزایش داخل حلقه تضمین می‌کنه شرط بعد از حداکثر سه دور false بشه. اگه `attempts++` رو حذف کنی، حلقه متوقف نمی‌شه. در شبکه و ورودی خارجی، به شرط توقف علاوه بر counter ممکنه cancellation و timeout هم نیاز داشته باشیم؛ آن‌ها رو در ماژول async می‌آموزیم.

The increment guarantees the condition becomes false after at most three iterations. Remove it and the loop never stops. Network and external-input loops may need cancellation and timeouts in addition to a counter; those belong in the async module.

پاسخ و دلیلSolution and reasoning
C#
string message = status switch
{
    "new" => "منتظر پرداخت",

The fallback no longer turns invalid data into an ordinary message; it surfaces the failure to the caller. If unknown state is expected, a result type or handled error path may be better—this example makes the failure visible.

برای بستن تمرین، خروجی یا test result رو نگه دار و یک بار نسخهٔ قبل و بعد رو کنار هم ببین. هدف فقط سبزشدن کد نیست؛ باید معلوم باشه کدوم رفتار واقعاً عوض شده.

پاسخ و دلیلSolution and reasoning

اندیس معتبر تا `Length - 1` هست، پس `<= Length` یک دور اضافه اجرا می‌کنه و index خارج محدوده می‌خونه. شرط درست `i < orderIds.Length` هست. تعداد چاپ‌ها باید با طول آرایه برابر باشه.

پاسخ و دلیلSolution and reasoning
C#
foreach (int value in values)
{
    if (value < 0) continue; // 3, 8
    Console.WriteLine(value);
}

با `continue`، -1 رد می‌شه و 8 هنوز چاپ می‌شه. با `break` حلقه همان‌جا تمام می‌شه و فقط 3 چاپ خواهد شد. انتخاب به معنی «رد یک عضو» یا «پایان کل پیمایش» بستگی داره.

وقتی تصمیم‌ها زیاد شدند، کد رو تکه‌تکه می‌کنیمWhen decisions grow, we split the code into methods

شرط و حلقه جریان همین بخش از برنامه رو کنترل می‌کنن. وقتی همین منطق در چند جا تکرار بشه، باید آن رو به یک رفتار نام‌دار تبدیل کنیم. در فصل بعد متد می‌سازیم و ورودی/خروجی‌اش رو دقیق تعریف می‌کنیم.

Conditions and loops control this part of the program. When the same logic appears in several places, it deserves a named behavior. Next we will create methods and define their inputs and outputs.

اگه کدهای این فصل رو خودت اجرا کردی و می‌تونی شکست نزدیکشون رو توضیح بدی، آماده‌ای بریم سراغ «متدها و پارامترها». قرار نیست از صفر شروع کنیم؛ همین مدل رو با خودمون می‌بریم.

If you ran the examples yourself and can explain the nearby failure, you are ready for “Methods and parameters”. We will not restart from zero; we will carry this model forward.
