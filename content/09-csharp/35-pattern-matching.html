pattern matching برای شاخه‌های پیچیده

Pattern matching for complex branching

یک switch ده‌شرطی وضعیت سفارش را بررسی می‌کند؛ شاخه‌ای که null یا مقدار نامعتبر می‌بیند، بی‌صدا به مسیر پرداخت می‌افتد. به‌جای کوتاه‌کردن شرط‌ها، می‌خواهیم الگوی داده را رو‌به‌رو ببینیم و شاخه‌ها را تست کنیم.

A ten-branch switch handles order status; null or invalid values silently fall into payment. Rather than merely shortening conditions, we make data shapes visible and test each branch.

switch expression خروجی می‌سازدSwitch expressions produce a value

وقتی هر شاخه یک مقدار می‌دهد، switch expression خروجی را در یک محل جمع می‌کند. ترتیب patternها مهم است؛ شاخهٔ عمومی زودهنگام می‌تواند شاخهٔ خاص بعدی را unreachable کند. compiler بخشی از خطا را می‌گیرد، اما کامل‌بودن مدل دامنه را تست هم باید ثابت کند.

When each branch yields a value, a switch expression centralizes the result. Pattern order matters; an early general case can make a later specific case unreachable. The compiler catches some issues, but tests must prove domain completeness.

نمونه / Example
static string Describe(object? value) => value switch
{
    null => "missing",
    int count when count < 0 => "invalid count",
    int count => $"count: {count}",
    string { Length: 0 } => "empty",
    string text => $"text: {text}",
    _ => "other"
};

در مسیر موفق، خروجی متناسب با الگوی داده است؛ مسیر null، مرز و خطا را جدا تست کن. اجرای نمونه، کامل بودن مدل دامنه را به‌تنهایی ثابت نمی‌کند.

The successful path follows the data shape; test null, boundaries and failures separately. A sample run alone does not prove domain completeness.

property و relational patternProperty and relational patterns

می‌توانی status، count یا چند property را در یک الگو بررسی کنی. guard با when شرطی را اضافه می‌کند، اما اگر شرط‌ها از هم جداشدنی‌ترند، متد نام‌دار خواناتر است. null را صریح در model و branch مشخص کن.

Match status, count or several properties. A when guard adds a condition, but named methods may be clearer when rules deserve independent tests. Handle null explicitly in the model and branches.

list و logical patternList and logical patterns

list pattern طول و جایگاه‌های sequence را می‌سنجد و logical patternها شرط‌ها را ترکیب می‌کنند. این syntax برای شکل کوتاه داده عالی است، نه برای جایگزین‌کردن الگوریتم پیچیده یا پیمایش پرهزینه.

List patterns inspect sequence length and positions; logical patterns combine conditions. They fit compact shape checks, not complex algorithms or costly repeated traversal.

اثبات branchهاProve the branches

برای enum، null، ورودی ناقص و مقدار آیندهٔ ناشناخته تست بنویس. default همیشه معنای «درست» ندارد؛ ممکن است بهتر باشد نسخهٔ جدید را رد کنیم یا خطای مشخص بدهیم. هرچه pattern فشرده‌تر شد، test matrix اهمیت بیشتری دارد.

Test enum values, null, incomplete input and future unknown values. A default case is not automatically correct; rejecting a new version may be safer. The more compact the pattern, the more important the test matrix.

آزمایشگاه رخدادIncident lab

یک پروژهٔ کنسولی با ورودی کوچک بساز. baseline و تست رفتار را ثبت کن، failure را با تغییر کنترل‌شده بازتولید کن، مدرک را از نزدیک‌ترین مرز جمع کن و اصلاح را با همان acceptance test ثابت کن. در تحویل کد، خروجی و محدودیت چیزی را که نتیجه گرفته‌ای بنویس.

Create a console project with a small fixture. Record baseline tests, reproduce a failure with a controlled change, collect evidence at the nearest boundary and prove the repair with the same acceptance test. Submit code, output and limits of your conclusion.

  1. baseline و انتظار را ثبت کن.
  2. Record baseline and expected behaviour.
  3. failure و evidence را مستند کن.
  4. Document failure and evidence.
  5. repair و regression test را اجرا کن.
  6. Run the repair and regression test.
