آرایه، tuple و برش بازه

Arrays, tuples, and range slicing

تیم فروشگاه فایل روزانه‌ای از مبلغ سفارش‌ها فرستاده، اما قبل از گزارش باید تعدادها رو درست بخوانیم: چند سفارش در هر نوبت بوده؟ آخرین دو مبلغ کدوم‌اند؟ اگه یک خانه رو اشتباه برداریم، جمع کل عوض می‌شه. بیایید شکل داده رو اول روشن کنیم، بعد برش بزنیم.

The shop team sent daily batches of order totals, but before reporting we need to read the data correctly: how many orders were in each batch, and what were the last two totals? One off-by-one mistake changes the sum. Let’s understand the data shape before slicing it.

گزارش سفارش‌ها یک ردیف جابه‌جا شدهThe order report is off by one row

رسید فصل قبل رو ساختیم؛ داده تا وقتی نمایش لازم نشد عددی ماند. حالا یک ورودی تازه داریم: مبلغ‌های سفارش به شکل چند مقدار هم‌نوع رسیده‌اند. اگه هر مقدار رو در متغیری جدا بگذاریم، با زیادشدن سفارش‌ها کد از دستمان در می‌ره. از طرف دیگر، اگه خانهٔ اشتباه رو بخوانیم، خروجی ممکنه همچنان عدد معتبری باشه و خطا رو پنهان کند.

Last chapter we formatted a receipt while keeping its data numeric. Now order totals arrive as a sequence of same-typed values. Separate variables will not scale, but reading the wrong slot can still produce a plausible number and hide the bug.

C# 12 · Program.cs
decimal[] totals = [125_000m, 80_000m, 210_000m, 95_000m];
Console.WriteLine(totals[0]);
Console.WriteLine(totals.Length);
خروجی
125000
4

آرایه یک تعداد ثابت از خانه‌های هم‌نوع داره. `Length` تعداد خانه‌ها رو می‌ده، اما شمارهٔ خانه‌ها از صفر شروع می‌شه؛ پس چهار خانه شماره‌های ۰ تا ۳ دارن. `totals[0]` اولین مبلغ هست، نه «مبلغ شمارهٔ یک» با شماره‌گذاری انسانی.

An array has a fixed number of same-typed slots. `Length` reports how many slots exist, but indexing starts at zero: four slots are numbered 0 through 3. `totals[0]` is the first total, not “total number one” in human numbering.

این نمونه از collection expression یعنی `[...]` استفاده می‌کنه که از C# 12 در دسترس هست. اگه پروژهٔ قدیمی‌تری داری، همین مقدارها رو با `new decimal[] { ... }` بنویس. نوع مقصد باید معلوم باشه؛ خود `[...]` به‌تنهایی یک نوع مستقل برای آرایه تعیین نمی‌کنه.

This sample uses the `[...]` collection expression available from C# 12. In an older project, write the same values as `new decimal[] { ... }`. The target type must be known; `[...]` alone does not determine an array type.

تعداد خانه‌ها رو با آخرین index قاطی نکنDo not confuse the length with the last index

از گزارش می‌خوایم همهٔ مبلغ‌ها رو چاپ کنیم. اگه حلقه رو تا `i <= totals.Length` ادامه بدهیم، آخرین نوبت `totals[4]` رو می‌خونه؛ چنین خانه‌ای نداریم. شرط درست با index صفرمبنا، `i < Length` هست.

We want to print every total. If the loop continues while `i <= totals.Length`, its last iteration reads `totals[4]`, which does not exist. With zero-based indices, the correct condition is `i < Length`.

حلقهٔ درست
for (int i = 0; i < totals.Length; i++)
{
    Console.WriteLine($"slot {i}: {totals[i]}");
}
خروجی نمونه
slot 0: 125000
slot 1: 80000
slot 2: 210000

مرز بالایی معتبر `Length - 1` هست؛ اما در حلقه لازم نیست آن رو دستی حساب کنیم. با `i < Length` خانهٔ صفر تا آخرین خانه رو می‌خونیم و اگه آرایه خالی باشه، بدنه حتی یک‌بار هم اجرا نمی‌شه. نسخهٔ خرابِ `<=` روی آرایهٔ غیرخالی در runtime به `IndexOutOfRangeException` می‌رسه.

The largest valid index is `Length - 1`, but a loop need not calculate it manually. `i < Length` visits slot zero through the last slot and naturally skips the body for an empty array. The broken `<=` version throws `IndexOutOfRangeException` at runtime for a non-empty array.

قانون سریعA quick rule

تعداد خانه‌ها: `Length`. آخرین index: `Length - 1` فقط وقتی خانه‌ای وجود داره. اگه `Length` صفر باشه، `Length - 1` اصلاً index معتبر نمی‌سازه.

Number of slots: `Length`. Last index: `Length - 1`, only when an element exists. For an empty array, `Length - 1` is not a valid index.

یک جدول منظم یا چند ردیف با طول متفاوت؟A regular grid or rows of different lengths?

برای داشبورد، می‌خوایم تعداد فروش هر انبار رو در هر روز نگه داریم. همهٔ انبارها برای هر روز یک خانه دارن؛ یک آرایهٔ دوبعدی مستطیلی طبیعی هست. اما ردیف‌های سفارش طول یکسان ندارن؛ یک سفارش ممکنه یک قلم و دیگری پنج قلم داشته باشه. آنجا ساختار jagged مناسب‌تر هست.

For a dashboard, we want each warehouse’s sales for each day. Every warehouse has one slot per day, so a rectangular two-dimensional array fits. Order lines vary in count: one order may have one item and another five. A jagged array fits that shape better.

دو شکل متفاوت
// 2 warehouses × 3 days: every row has the same number of columns
int[,] salesByWarehouseAndDay =
{
    { 12, 15, 9 },
    { 8, 11, 14 }
};
Console.WriteLine(salesByWarehouseAndDay[1, 2]); // 14
Console.WriteLine(salesByWarehouseAndDay.GetLength(0)); // 2 rows
Console.WriteLine(salesByWarehouseAndDay.GetLength(1)); // 3 columns

// Order lines: each order can contain a different number of items
string[][] orderItems =
{
    new[] { "keyboard", "mouse" },
    new[] { "monitor" },
    new[] { "cable", "stand", "adapter" }
};
Console.WriteLine(orderItems[2][1]); // stand

در `int[,]` همهٔ ردیف‌ها و ستون‌ها یک شبکهٔ مستطیلی می‌سازن؛ دسترسی با دو index و یک جفت کاما هست. `Length` تعداد کل خانه‌ها رو می‌ده؛ برای تعداد ردیف و ستون از `GetLength(0)` و `GetLength(1)` استفاده کن.

An `int[,]` is a rectangular grid; access uses two indices separated by a comma. `Length` returns the total number of cells. Use `GetLength(0)` and `GetLength(1)` for row and column counts.

در `string[][]` آرایهٔ بیرونی خانه‌هایی داره که هرکدوم به یک آرایهٔ داخلی اشاره می‌کنن. طول هر ردیف می‌تونه فرق کند؛ اما خانهٔ داخلیِ ساخته‌نشده `null` هست. قبل از `orderItems[i].Length` مطمئن شو آن ردیف مقدارههی شده، وگرنه به‌جای خطای index، `NullReferenceException` می‌گیری.

With `string[][]`, the outer array contains references to inner arrays. Each row can have a different length, but an uninitialized inner slot is `null`. Ensure `orderItems[i]` exists before reading its `Length`, or you get `NullReferenceException` rather than an index error.

`int[][]` و `int[,]` دو نگارش برای یک چیز نیستن. در jagged، `a[0]` خودش یک آرایه هست و می‌توان طول هر ردیف رو جدا دید؛ در مستطیلی، ابعاد بخشی از شکل آرایه‌اند و همهٔ خانه‌ها در همان شبکه تعریف می‌شن.

`int[][]` and `int[,]` are not two spellings for the same thing. In a jagged array, `a[0]` is another array whose length can be inspected independently. In a rectangular array, the dimensions describe one grid shared by all cells.

وقتی یک محاسبه دو نتیجه دارهWhen one calculation has two results

برای گزارش روزانه فقط جمع مبلغ‌ها کافی نیست؛ تعداد سفارش‌ها رو هم می‌خوایم. دو متغیر بیرونی بسازیم یا نتیجه رو یک‌جا برگردانیم؟ یک tuple سبک می‌تونه برای نتیجهٔ کوچک و محلی مناسب باشه.

The daily report needs both the sum and the number of orders. Should we fill two outer variables, or return one grouped result? A tuple can suit a small, local result like this.

تابع جمع‌بندی
static (decimal Total, int Count) Summarize(decimal[] values)
{
    decimal total = 0m;
    foreach (decimal value in values)
        total += value;

    return (Total: total, Count: values.Length);
}

var summary = Summarize(totals);
Console.WriteLine($"{summary.Count} orders · {summary.Total}");
var (total, count) = Summarize(totals);
Console.WriteLine($"deconstructed: {count} · {total}");
خروجی
4 orders · 510000
deconstructed: 4 · 510000

امضای متد می‌گه دو مقدار با نام‌های `Total` و `Count` برمی‌گردن. می‌تونیم عضوها رو با همین نام‌ها بخوانیم یا tuple رو با deconstruction به دو متغیر باز کنیم. هر دو مقدار به ترتیب جایگاه و نوعشان وصل‌اند.

The method signature returns two values named `Total` and `Count`. We can read those members by name or deconstruct the tuple into two variables. The elements correspond by position and type.

نام عضوهای tuple برای خوانایی و زمان کامپایل هست؛ هویت یک نوع تازه با نام‌های تجاری ایجاد نمی‌کنه. دو tuple با ترتیب و نوع سازگار رو می‌توان حتی با نام عضو متفاوت به هم نسبت داد. پس برای قراردادی بزرگ، پایدار یا عمومی، tuple چندعضوی معمولاً جای نوع دامنه‌ای نام‌دار رو نمی‌گیره؛ این فصل فقط نتیجهٔ کوچک محاسبه رو جمع کرده.

Tuple element names improve readability at compile time; they do not create a new nominal type. Compatible tuples can be assigned by position and type even when their element names differ. A large, stable or public contract usually deserves a named domain type; here we are grouping a small calculation result.

tuple با anonymous type یکی نیستA tuple is not an anonymous type

در `var preview = new { summary.Total, summary.Count };` یک anonymous type برای projection محلی می‌سازی؛ propertyهایش فقط‌خواندنی‌اند. tuple به شکل `(summary.Total, summary.Count)` عضوهای قابل‌تغییر داره و امکان deconstruction/بازگشت مستقیم داره. هیچ‌کدوم جای type نام‌دار رو برای قرارداد مهم و منتشرشده پر نمی‌کنن.

`var preview = new { summary.Total, summary.Count };` creates an anonymous type for a local projection with read-only properties. A tuple such as `(summary.Total, summary.Count)` has mutable fields and supports direct deconstruction/return. Neither replaces a named type for an important published contract.

آخرین دو سفارش، بدون شمردن از آخرThe last two orders, without counting backward

مدیر فروش فقط مبلغ‌های دو سفارش آخر رو برای پیش‌نمایش می‌خواد. اگه خودمان `Length - 2` و `Length - 1` رو در چند جا حساب کنیم، مرزها رو راحت اشتباه می‌زنیم. C# دو ابزار داره: `^` برای index از انتها و `..` برای بازه.

The sales lead wants a preview of the last two totals. Repeating `Length - 2` and `Length - 1` calculations invites boundary mistakes. C# provides `^` for an index from the end and `..` for a range.

Index و Range
decimal last = totals[^1];
decimal[] lastTwo = totals[^2..];
decimal[] withoutFirstAndLast = totals[1..^1];
decimal[] firstThree = totals[..3];

Console.WriteLine(last);             // 95000
Console.WriteLine(string.Join(", ", lastTwo)); // 210000, 95000
Console.WriteLine(string.Join(", ", withoutFirstAndLast)); // 80000, 210000

`^1` یعنی آخرین خانه. `^0` مرز بعد از آخرین خانه هست و برای انتهای بازه درست هست، اما index یک عنصر نیست. در `totals[1..^1]` از index ۱ شروع می‌کنیم و تا یک خانه مانده به آخر می‌رویم. پایان range همیشه بیرون می‌مونه.

`^1` means the last element. `^0` is the boundary just after the last element: valid as a range endpoint, but not as an element index. `totals[1..^1]` starts at index 1 and stops before the last element. A range’s end is always excluded.

چون `totals` یک آرایهٔ یک‌بعدی هست، range روی آن مجاز هست و یک آرایهٔ تازه می‌سازه. این کپی از خانه‌ها shallow هست: برای آرایهٔ عددها مقدارها کپی می‌شن؛ برای آرایهٔ referenceها خود referenceها کپی می‌شن، نه شیءهای پشتشان. برش `int[,]` با این syntax پشتیبانی نمی‌شه؛ برای jagged باید اول یک ردیف رو برداری و بعد همان ردیف یک‌بعدی رو برش بزنی.

Because `totals` is a one-dimensional array, range indexing is supported and creates a new array. The element copy is shallow: numeric values are copied, while an array of references copies the references—not the referenced objects. This syntax does not slice an `int[,]`; with a jagged array, select a row first, then slice that one-dimensional row.

مرز نسخهٔ زبانLanguage-version boundary

Index و Range از C# 8 در دسترس‌اند؛ collection expression از C# 12 هست. این دوره با .NET 10 و SDK 10 جلو می‌ره، اما اگه `LangVersion` پروژه رو پایین آورده‌ای، syntax رو با نسخهٔ تنظیم‌شده مقایسه کن. `.NET` هدف و نسخهٔ زبان مفاهیم مرتبط‌اند اما یک گزینهٔ واحد نیستن.

Index and Range are available from C# 8; collection expressions are from C# 12. This course targets .NET 10 and SDK 10, but if the project lowers `LangVersion`, check syntax against that setting. The target framework and language version are related, but they are not the same setting.

آزمایشگاه: بستهٔ فروش روز رو خلاصه کنLab: summarize the day’s sales batches

فروشگاه سه نوبت ورود سفارش داره. نوبت اول و دوم تعداد سفارش برابر دارن، نوبت آخر نه. یک گزارش کوچک می‌سازیم که هم شکل داده رو درست انتخاب کند، هم جمع و تعداد رو از هم جدا نگه داره و هم دو مبلغ آخر رو برای بازبینی نشان بدهد.

The shop receives orders in three batches. The first two batches have equal lengths; the last does not. We’ll build a small report that chooses the right shapes, keeps total and count distinct, and previews the final two amounts.

  1. داده رو به صورت `decimal[][]` بساز: هر خانهٔ بیرونی یک نوبت و هر آرایهٔ داخلی مبلغ همان نوبت باشه. دست‌کم سه نوبت با طول‌های متفاوت داشته باش.
  2. Represent batches as `decimal[][]`: each outer slot is a batch and each inner array contains its totals. Use at least three batches of different lengths.
  3. تابع `Summarize` رو برای یک آرایه بنویس که `(Total, Count)` برگرداند؛ برای هر نوبت آن رو اجرا کن و مجموع روز رو هم حساب کن.
  4. Write `Summarize` for one array, returning `(Total, Count)`. Call it for each batch and calculate the daily total.
  5. عمداً یک ردیف داخلی رو مقدارههی نکن. خطا رو ثبت کن، ردیف null رو از روی شواهد پیدا کن و قبل از خواندن `Length` آن رو اصلاح یا رد کن.
  6. Deliberately leave one inner row uninitialized. Record the failure, identify the null row from evidence, and initialize or reject it before reading `Length`.
  7. از آخرین نوبت دو مبلغ آخر رو با `^2..` بگیر. ثابت کن که خروجی slice آرایهٔ جداگانه‌ای هست و تغییر خانهٔ خروجی به آرایهٔ اصلی برنمی‌گردد.
  8. Take the last two totals from the final batch with `^2..`. Prove the slice is a separate array and changing its slot does not replace a slot in the source array.
  9. گزارش رو با تعداد نوبت‌ها، جمع کل، تعداد سفارش‌ها و preview چاپ کن. خروجی رو برای دادهٔ خالی و یک نوبت تک‌مقداری هم بررسی کن؛ در صورت کافی نبودن عناصر، قبل از `^2` تصمیم روشن بگیر.
  10. Print batch count, daily total, order count and preview. Also test empty input and a one-item final batch; decide explicitly before using `^2` when too few elements exist.
یک مسیر حل، بعد از آزمایش خودت بازش کنOne solution path—open after trying it
C# · نمونهٔ جمع‌بندی
decimal[][] batches =
[
    [125_000m, 80_000m],
    [210_000m],
    [95_000m, 42_000m, 63_000m]
];

static (decimal Total, int Count) Summarize(decimal[] values)
{
    decimal total = 0m;
    foreach (var value in values) total += value;
    return (total, values.Length);
}

decimal dayTotal = 0m;
int orderCount = 0;
foreach (decimal[] batch in batches)
{
    var (total, count) = Summarize(batch);
    dayTotal += total;
    orderCount += count;
}

decimal[] preview = [];
if (batches.Length > 0)
{
    decimal[] lastBatch = batches[^1];
    preview = lastBatch.Length >= 2
        ? lastBatch[^2..]
        : lastBatch[..];
}

Console.WriteLine($"batches={batches.Length}, orders={orderCount}, total={dayTotal}");
Console.WriteLine(string.Join(", ", preview));
خروجی نمونه
batches=3, orders=6, total=615000
42000, 63000

شرط `Length >= 2` جلوی range نامعتبر برای نوبت کوتاه رو می‌گیره. آرایهٔ داخلیِ null رو باید جدا با `batches.Any(batch => batch is null)` یا حلقهٔ بررسی پیدا کرد؛ null-check رو با empty-array یکی نگیر: آرایهٔ خالی وجود داره اما عنصری نداره.

اول `Length` آرایهٔ بیرونی رو بررسی می‌کنیم تا مجموعهٔ خالی رو از انتها اندیس‌گذاری نکنیم؛ بعد پیش از استفاده از `^2`، کوتاه‌بودن نوبت آخر رو می‌سنجیم. آرایهٔ داخلی `null` رو هم باید پیش از خواندن `Length` جداگانه بررسی کرد؛ `null` با آرایهٔ خالی فرق داره.

First check the outer `Length` so an empty collection is not indexed from the end; then guard the final batch before using `^2`. Detect a null inner array before reading its `Length`; null and an empty array are different—an empty array exists but contains no elements.
