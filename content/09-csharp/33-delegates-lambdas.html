delegate، method group و lambda

Delegates, method groups and lambdas

دو مشتری برای تخفیف قانون متفاوت دارند اما مراحل محاسبهٔ صورتحساب یکی است. به‌جای کپی کل متد، تصمیم متغیر را به‌عنوان ورودی می‌دهیم. delegate همین مرز را می‌سازد: کد قابل‌فراخوانی با امضای مشخص.

Two customers have different discount rules but share invoice processing. Instead of copying the method, we pass the varying decision as input. A delegate defines that callable boundary with a specific signature.

امضای callback بخشی از قرارداد API استA callback signature is part of the API contract

اگر ورودی یک Order و خروجی decimal است، Func این شکل را بیان می‌کند. Action برای کاری بدون مقدار بازگشتی و Predicate برای تصمیم bool است. این نام‌ها فقط shorthand هستند؛ باید معلوم باشد چه زمانی فراخوانی می‌شوند، چندبار، با چه ورودی و اگر خطا رخ داد چه می‌شود.

If input is an Order and result is decimal, Func<Order, decimal> expresses that shape. Action has no result; Predicate<T> models a Boolean decision. These are shorthand, not the whole contract: specify when and how often the callback runs and how failures behave.

رفتار قیمت‌گذاری ورودی است / Pricing as an input
static decimal InvoiceTotal(
    Order order, Func<Order, decimal> discount)
{
    return order.Total - discount(order);
}
var total = InvoiceTotal(order, LoyaltyDiscount);

LoyaltyDiscount می‌تواند method group باشد؛ لازم نیست آن را در lambda بی‌نام بپیچیم. امضای متد باید با delegate مقصد سازگار باشد. کد caller هم حالا policy را آشکار می‌کند.

LoyaltyDiscount can be passed as a method group without an unnecessary lambda wrapper. Its signature must match the target delegate. The call site now exposes the chosen policy.

lambda راه نوشتن تابع کوتاه است، نه جادوA lambda is concise syntax, not magic

lambda می‌تواند پارامتر بگیرد، مقدار برگرداند یا statement block داشته باشد. اگر منطق نام دارد، چندجا استفاده می‌شود یا برایش تست مستقل لازم است، method نام‌دار خواناتر است. اگر رفتار محلی و کوتاه است، lambda کنار جایی که مصرف می‌شود کمک می‌کند. هر دو در نهایت با delegate target-type می‌شوند.

A lambda can take parameters, return a value or use a statement block. Named methods help when logic has a domain name, is reused or deserves isolated tests. Local short behaviour can be clearer inline. Both are target-typed to a delegate.

delegate چندپخشی و eventMulticast delegates and events

چند handler می‌توانند به delegate اضافه شوند و به ترتیب invocation list فراخوانی شوند. event سطح عمومی امن‌تری می‌دهد: بیرون کلاس می‌تواند subscribe/unsubscribe کند، اما نمی‌تواند event را دلخواه invoke یا پاک کند. با این حال publisher مرجع handler را نگه می‌دارد؛ عمر اشتباه و فراموشی unsubscribe ممکن است subscriber را زنده نگه دارد.

Multiple handlers can be added to a delegate and are invoked in invocation-list order. An event exposes safer subscription: outside code can add/remove handlers but cannot invoke or clear the event. The publisher still retains handler references; incorrect lifetime and missed unsubscription can retain subscribers.

اگر handler اول exception بدهد، flow عادی multicast ممکن است به handler بعدی نرسد. اگر جداسازی خطا نیاز دامنه است، سیاست اجرای هر handler را صریح پیاده و تست کن.

If an early handler throws, normal multicast invocation may not reach later handlers. If isolation is required, explicitly implement and test a per-handler failure policy.

lambda می‌تواند متغیر و عمرش را capture کندA lambda can capture a variable and its lifetime

closure متغیر را capture می‌کند، نه لزوماً snapshot مقدارش را. در حلقه ممکن است چند lambda یک متغیر مشترک را ببینند. همچنین handler ثبت‌شده روی publisher بلندعمر، شیء کوتاه‌عمر را زنده نگه می‌دارد. اینجا مسئله فقط syntax نیست؛ lifetime و مالکیت رفتار مهم‌اند.

A closure captures a variable, not necessarily a snapshot of its value. Loop lambdas may share one variable. A handler registered on a long-lived publisher can retain a short-lived object. This is not merely syntax; lifetime and ownership matter.

  2. Assert both policy results.
  3. ثبت و حذف subscription را در تست پوشش بده.
  4. Test subscription and unsubscription.
  5. سیاست exception callback را مستند کن.

callback هم مرز، عمر و failure داردCallbacks have boundaries, lifetimes and failures

Func، Action و Predicate شکل امضا را می‌دهند؛ method group و lambda شکل نوشتن‌اند؛ event کنترل subscription را بهتر می‌کند، اما عمر handler را حل نمی‌کند. closure متغیر را می‌گیرد و exception می‌تواند flow را قطع کند. فصل بعد از شاخه‌های شرطی پیچیده می‌پرسد: می‌شود شکل داده را مستقیم در شرط شناخت؟

Func, Action and Predicate express signatures; method groups and lambdas are syntax choices; events improve subscription boundaries but do not solve handler lifetime. Closures capture variables and exceptions can interrupt flow. Next we ask whether complex branches can match data shapes directly.
