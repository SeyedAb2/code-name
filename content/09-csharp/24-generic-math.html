ریاضی عمومی و static abstract

Generic math and static abstract members

یک کتابخانه برای هر نوع عدد overload جدا دارد: int، long، decimal و چند نوع دامنه‌ای. generic معمولی کافی نیست؛ بدنه نمی‌داند T را چطور با هم جمع کند. C# 11 راهی داد تا interface قرارداد operatorهای static را بیان کند و generic از همان قرارداد استفاده کند.

A library has separate overloads for int, long, decimal and domain-specific numbers. An ordinary generic is not enough: the body does not know how to add T values. C# 11 lets interfaces describe static operator contracts so a generic algorithm can use them.

فصل ۲۳پیش‌نیازprerequisite

وقتی generic عملیات نداردWhen a generic has no operation

در فصل قبل دیدیم generic نوع را پارامتر می‌کند؛ اما این کد کامپایل نمی‌شود، چون compiler نمی‌داند + برای هر T تعریف شده است. overloadهای جدا کار می‌کنند اما با هر نوع جدید تکرار می‌شوند. نیاز واقعی را محدود کنیم: جمع دو T و گرفتن صفر مناسب همان T.

Last chapter showed how generics parameterize a type, but this code cannot compile because the compiler does not know that + exists for every T. Separate overloads work but repeat for every new type. Let’s state the actual requirement: add two T values and obtain a zero for that T.

T به‌تنهایی قابلیت جمع ندارد / Unconstrained T
static T Add<T>(T left, T right)
{
    return left + right; // compiler error: + is not known for every T
}

اضافه‌کردن where T : struct کمکی نمی‌کند؛ هر struct الزاماً operator جمع ندارد. constraint باید دقیقاً قراردادی باشد که الگوریتم استفاده می‌کند.

Adding where T : struct does not help; not every struct defines addition. The constraint must state the exact contract used by the algorithm.

static abstract: قرارداد عضو type-levelstatic abstract: a type-level member contract

interface معمولی می‌تواند بگوید هر instance متدی دارد. static abstract می‌گوید خود نوع پیاده‌کننده باید عضو static مشخصی فراهم کند—مثلاً operator +. این قابلیت در C# 11 معرفی شد و برای generic math کتابخانهٔ .NET استفاده شده است.

An ordinary interface can require an instance method. static abstract requires the implementing type itself to provide a particular static member—for example, operator +. This feature arrived in C# 11 and is used by .NET generic math.

حداقل قرارداد جمع / Minimal addition contract
interface IAddable<TSelf> where TSelf : IAddable<TSelf>
{
    static abstract TSelf operator +(TSelf left, TSelf right);
}

static T Add<T>(T left, T right)
    where T : IAddable<T>
    => left + right;

فراخوانی از طریق type parameter محدودشده انجام می‌شود؛ نمی‌نویسیم IAddable<T>.operator + چون خود interface یک پیاده‌سازی یکتا ندارد. وقتی T واقعی معلوم است، compiler می‌داند کدام static operator را فراخوانی کند.

The call is made through the constrained type parameter; we do not invoke IAddable<T>’s operator directly because the interface has no single implementation. Once T is known, the compiler resolves the implementing static operator.

این قرارداد آموزشی است. در برنامهٔ واقعی معمولاً از interfaceهای استانداردی مثل IAdditionOperators یا INumber استفاده می‌کنیم تا API با کتابخانه‌های .NET هم‌خوان باشد.

This is an instructional contract. Real applications usually use standard interfaces such as IAdditionOperators or INumber so APIs interoperate with .NET libraries.

INumber برای الگوریتم عددی عمومیINumber<T> for a general numeric algorithm

برای جمع، مقدار آغازین T.Zero و operatorهای عددی لازم‌اند. INumber این مجموعهٔ گسترده‌تر را فراهم می‌کند. اگر الگوریتم فقط جمع می‌خواهد، constraint ظریف‌تر ممکن است بهتر باشد؛ قرارداد بزرگ‌تر می‌تواند بی‌دلیل typeهای قابل‌قبول را محدود کند.

Summation needs an initial T.Zero and numeric operators. INumber<T> provides that broader set. If an algorithm needs only addition, a finer-grained constraint may fit better; a larger contract can unnecessarily restrict accepted types.

مجموع generic / Generic sum
using System.Numerics;

static T Sum<T>(ReadOnlySpan<T> values)
    where T : INumber<T>
{
    T total = T.Zero;
    foreach (var value in values)
        total += value;
    return total;
}

Console.WriteLine(Sum<int>([1, 2, 3]));
Console.WriteLine(Sum<decimal>([1.25m, 2.5m]));
خروجی / Output
6
3.75

ReadOnlySpan داده را برای مدت فراخوانی می‌خواند و به collection تازه‌ای تبدیل نمی‌کند؛ ولی این انتخاب برای همهٔ منبع‌ها مناسب نیست. مهم‌تر اینکه Sum برای decimal و integer قواعد دقت و overflow متفاوت دارد. generic شدن الگوریتم، سیاست عددی دامنه را پاک نمی‌کند.

ReadOnlySpan reads data for the call without creating a new collection, but it is not the right source shape for every caller. More importantly, decimal and integer sums have different precision and overflow behaviour. Generalizing the algorithm does not erase numeric-domain policy.

نوع دامنه‌ای باید قرارداد را با معنای درست پیاده کندA domain type must implement the contract with correct meaning

اگر Money را INumber پیاده کنیم، ادعای بزرگی دربارهٔ division، ordering، parsing و بقیهٔ عملیات عددی می‌کنیم. اگر فقط جمع ارز هم‌نوع لازم است، IAdditionOperators محدودتر است. هر interface استاندارد سطح انتظارات مصرف‌کننده را بالا می‌برد؛ همهٔ اعضا و invariantهایش را پیش از پیاده‌سازی بخوان.

Implementing INumber for Money makes a broad promise about division, ordering, parsing and other numeric operations. If only same-currency addition is needed, IAdditionOperators is narrower. Each standard interface raises consumer expectations; read all its members and invariants before implementing it.

جمع در نوع سفارشی / Addition on a custom type
using System.Numerics;

readonly record struct Money(decimal Amount, string Currency)
    : IAdditionOperators<Money, Money, Money>
{
    public static Money operator +(Money left, Money right)
    {
        if (!StringComparer.Ordinal.Equals(left.Currency, right.Currency))
            throw new InvalidOperationException("Currencies must match.");
        return new Money(left.Amount + right.Amount, left.Currency);
    }
}

static T Add<T>(T left, T right)
    where T : IAdditionOperators<T, T, T>
    => left + right;

IAdditionOperators سه نقش را مشخص می‌کند: نوع سمت چپ، نوع سمت راست و نتیجه. اگر جمع ارز متفاوت را رد می‌کنیم، این exception بخشی از قرارداد دامنه است؛ نمونهٔ آموزشی Money هنوز باید برای currency تهی/نامعتبر validation داشته باشد. generic بودن خطای طراحی مدل را درمان نمی‌کند.

IAdditionOperators names three roles: left operand, right operand and result. If mixed-currency addition is rejected, that exception is part of the domain contract; this instructional Money still needs validation for null or invalid currency. Generics do not repair a flawed domain model.

generic math هرجا جمع می‌بینی لازم نیستGeneric math is not needed wherever addition appears

یک متد generic با static abstract می‌تواند overloadهای تکراری را حذف کند، اما compile-time contract و complexity API را بیشتر می‌کند. اگر فقط دو نوع لازم داریم، overloadهای ساده ممکن است خواناتر باشند. performance را هم از روی کلمهٔ generic نتیجه نگیر؛ workload نماینده و runtime را اندازه بگیر.

A static-abstract generic method can remove repeated overloads, but it increases compile-time contract and API complexity. If only two types are needed, simple overloads may be clearer. Do not infer performance from the word generic; measure a representative workload and runtime.

معیار پایانDefinition of done

یک implementation روی چند numeric type اجرا می‌شود؛ constraint فقط قابلیت لازم را می‌خواهد؛ و overflow، دقت و currency همچنان قراردادهای آشکارند.

One implementation works across numeric types; constraints request only needed capabilities; overflow, precision and currency remain explicit contracts.

static abstract برای الگوریتم واقعاً عمومیUse static abstract for genuinely generic algorithms

C# 11 static abstract به interface اجازه می‌دهد operator و عضو type-level را قرارداد کند؛ INumber و خانوادهٔ generic math این قابلیت را در کتابخانهٔ .NET به‌کار می‌گیرند. constraint را به عملیات واقعی محدود کن و semantics عددی، overflow و domain policy را مستقل نگه دار. در فصل بعد از operatorها به قرارداد مجموعه‌ها می‌رویم و API مصرف‌کننده را از capability لازم انتخاب می‌کنیم.

C# 11 static abstract lets interfaces contract operators and other type-level members; INumber and generic math use it in .NET. Constrain only to real operations and keep numeric semantics, overflow and domain policy explicit. Next we move from operators to collection contracts and choose consumer APIs by required capabilities.
