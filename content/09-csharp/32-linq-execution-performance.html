اجرای LINQ و هزینهٔ پیمایش

LINQ execution and enumeration cost

query رو یک بار برای count و یک بار برای render اجرا می‌کنیم. اگه منبع فایل یا دیتابیس باشه، آیا کار هم دو بار انجام شده؟ اینجا با شمارنده، buffering و مرز materialize پاسخ می‌گیریم.

We enumerate a query once for count and again for rendering. If its source is a file or database, did the work run twice? We use counters, buffering and materialization boundaries to find out.

ساخت query، اجرای آن نیستCreating a query is not executing it

Where معمولاً predicate رو برای زمان پیمایش نگه می‌داره. قبل از foreach ممکنه source هنوز نخوانده باشه. ToArray و ToList نتیجه رو در همان لحظه materialize می‌کنن. با counter می‌بینیم خط اجرا کجا اتفاق می‌افتد، به‌جای اینکه از syntax نتیجه بگیریم.

Where usually stores its predicate for enumeration. Before foreach the source may not have been read. ToArray and ToList materialize at that point. A counter reveals when work runs instead of inferring from syntax.

منبع شمارنده‌دار / Counted source
int reads = 0;
IEnumerable<int> Source()
{
    foreach (var value in new[] { 2, 4, 6 })
    {
        reads++;
        yield return value;
    }
}
var query = Source().Where(x => x > 2);
Console.WriteLine(reads); // 0
_ = query.ToArray();
Console.WriteLine(reads); // 3

خروجی ۰ و سپس ۳ نشان می‌ده source در زمان ساخت query مصرف نشده و ToArray هر سه عضو رو خوانده. این شاهد زمان اجراست؛ تعداد queryهای database یا هزینهٔ شبکه رو به‌تنهایی ثابت نمی‌کنه.

The 0 then 3 shows that query construction did not consume the source and ToArray read all three items. This proves execution timing, not database round trips or network cost by itself.

query وقتی خرج داره که enumerate بشهA query starts costing you when it is enumerated

یه متغیر LINQ ممکنه شبیه نتیجه به نظر برسه، درحالی‌که هنوز فقط دستورالعمل محاسبه‌ست. اگه همون sequence رو سه بار enumerate کنی، شاید سه بار کار انجام بشه؛ اگه source شبکه یا دیتابیس باشه، هزینه از چند loop ساده خیلی بیشتر می‌شه. پس مرز materialization رو آگاهانه انتخاب کن.

A LINQ variable can look like a result while still being only a recipe for producing one. Enumerate the same sequence three times and you may perform the work three times; if the source is a network or database provider, the cost can be much larger than another in-memory loop. Choose the materialization boundary deliberately.

این فصل performance رو با شعار «ToList بده تا سریع شه» جلو نمی‌بره. یه بار بدون materialize اندازه می‌گیریم، یه بار باهاش، بعد می‌بینیم trade-off کجاست: CPU، حافظه، freshness و تعداد اجرا. هیچ‌کدوم همیشه برنده نیست.

This chapter does not optimize by slogan such as “call ToList to make it fast.” Measure once without materializing and once with it, then identify the trade-off among CPU, memory, freshness, and repeated execution. No single choice always wins.

IEnumerable قول چندبارپذیری نمی‌دهIEnumerable does not promise repeatability

هر foreach می‌تونه منبع رو دوباره اجرا کند. روی query دیتابیس، Count و سپس حلقه ممکنه دو فرمان جدا بفرستد. materialize کردن جلوی اجرای دوباره رو می‌گیره ولی حافظه می‌گیره؛ اگه یک گذر کافی هست، accumulator تک‌گذره معمولاً روشن‌تر هست.

Every foreach may rerun the source. A database query counted and then looped may issue separate commands. Materializing prevents reruns but costs memory; when one pass suffices, a single-pass accumulator is often clearer.

همهٔ operatorها streaming نیستنNot every operator streams

Select اغلب موردبه‌مورد جلو می‌ره؛ OrderBy برای تعیین اولین نتیجهٔ مرتب باید ورودی رو بررسی کند و GroupBy ممکنه گروه‌ها رو نگه داره. پس «LINQ lazy است» جملهٔ کافی نیست. operator، منبع و provider رو کنار هم تحلیل کن و در ورودی بزرگ حافظه رو اندازه بگیر.

Select often advances item by item; OrderBy must inspect input to identify the first sorted result, and GroupBy may retain groups. “LINQ is lazy” is not enough. Analyze operator, source and provider together, and measure memory on large input.

IQueryable مرز ترجمه استIQueryable is a translation boundary

IQueryable expression tree رو به provider می‌ده. یک تابع محلی ممکنه ترجمه نشه؛ پس از ToList همان تابع در حافظه اجرا می‌شه و شاید دادهٔ بیش‌ازحد به برنامه منتقل بشه. query log، SQL و تعداد round-trip رو ببین. اگه count و render دو بار query می‌زنن، repair رو با همان log ثابت کن.

IQueryable supplies an expression tree to a provider. A local method may not translate; after ToList it runs in memory and can transfer too much data. Inspect query logs, SQL and round trips. If count and rendering issue two queries, prove the repair with the same logs.
