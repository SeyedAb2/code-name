نوع‌های عددی و سرریز

Numeric types and overflow

قیمت ۲۹٫۹۹ است، تعداد کالا ۳ است و دما ۲۹٫۹۹ درجه. هر سه «عدد» هستند، اما یک نوع عددی برای هر سه انتخاب خوبی نیست. نوع داده بخشی از قرارداد محاسبه است.

A price is 29.99, an item count is 3, and a temperature is 29.99 degrees. They are all numbers, but one numeric type is not ideal for all three. A type is part of a calculation's contract.

فصل ۴پیش‌نیازprerequisite

همهٔ عددها یک مسئله نیستندNot all numbers represent the same problem

برای تعداد سفارش معمولاً عدد صحیح می‌خواهیم. برای پول، اعشار ده‌دهی و قاعدهٔ گردکردن مهم است. برای محاسبهٔ علمی، بازه و سرعت floating point ممکن است اولویت داشته باشد. قبل از انتخاب نوع، معنای داده را مشخص کن.

Order counts are usually whole numbers. Money involves decimal quantities and explicit rounding. Scientific calculations may prioritize floating-point range and speed. Identify the meaning before choosing a type.

C#
int itemCount = 3;
decimal unitPrice = 29.99m;
decimal total = itemCount * unitPrice;
Console.WriteLine(total);
output
89.97

`int` برای شمارش مناسب است؛ `decimal` برای مقدارهای اعشاری مالی معمولاً انتخاب مناسب‌تری از `float` و `double` است. پسوند `m` لازم است تا literal از همان ابتدا decimal باشد. این انتخاب به‌تنهایی سیاست مالی نمی‌سازد: مالیات، نرخ، و گردکردن هر مرحله را باید محصول تعریف کند.

`int` suits counting; `decimal` is commonly preferable to `float` or `double` for decimal financial quantities. The `m` suffix makes the literal decimal from the start. This choice does not define financial policy: the product must specify tax, rates and rounding at each step.

چرا ۰٫۱ + ۰٫۲ دقیقاً ۰٫۳ نیست؟Why is 0.1 + 0.2 not exactly 0.3?

این آزمایش را اجرا کن:

Run this experiment:

C#
double a = 0.1;
double b = 0.2;
Console.WriteLine(a + b == 0.3);
Console.WriteLine($"{a + b:R}");

معمولاً خط اول `False` است. بسیاری از کسرهای ده‌دهی نمایش دودویی محدود ندارند؛ عدد ذخیره‌شده نزدیک‌ترین مقدار قابل نمایش است، نه دقیقاً همان کسری که نوشته‌ای. قالب `R` نمایش round-trip را نشان می‌دهد. این رفتار خرابی محاسبه نیست؛ محدودیت نمایش floating point است.

The first line is commonly `False`. Many decimal fractions have no finite binary representation, so the stored value is the nearest representable one, not the exact written fraction. The `R` format shows a round-trip representation. This is not a broken calculation; it is a floating-point representation limit.

برای مقایسهٔ اندازه‌گیری‌شده، گاهی tolerance مناسب لازم است؛ اما tolerance دلخواه هم سیاست است و می‌تواند مقادیر متفاوت را برابر فرض کند. برای مبلغی که باید با رقم اعشار مشخص نگهداری شود، `decimal` را بررسی کن. برای محاسبهٔ علمی یا گرافیکی، `double` به‌دلیل دامنه و کارایی مناسب است. نوع را از مسئله انتخاب کن.

Measured values may need an explicit tolerance, but an arbitrary tolerance is also a policy and can treat distinct values as equal. For amounts requiring decimal digits, consider `decimal`; for scientific or graphics calculations, `double` may fit its range and performance needs. Choose from the problem.

وقتی عدد از محدوده بیرون می‌زندWhen a value exceeds its range

`int` بازهٔ محدودی دارد. رفتار overflow برای محاسبهٔ integer معمولی معمولاً wraparound است و exception خودکار نیست. وقتی سرریز باید به خطای قابل‌تشخیص تبدیل شود، `checked` را امتحان کن.

`int` has a finite range. Ordinary integer overflow commonly wraps and does not automatically throw. When overflow must become a detectable failure, use `checked`.

C#
int max = int.MaxValue;
Console.WriteLine(unchecked(max + 1));
Console.WriteLine(checked(max + 1));

خط اول بعد از wrap به `int.MinValue` می‌رسد؛ خط دوم `OverflowException` می‌دهد. `checked` را می‌توان روی expression یا block گذاشت. این تنظیم را به همهٔ محاسبات کورکورانه نچسبان؛ نقطه‌ای را انتخاب کن که overflow واقعاً نقض قرارداد باشد.

The first addition wraps to `int.MinValue`; the second throws `OverflowException`. `checked` can apply to an expression or block. Do not add it blindly everywhere; choose boundaries where overflow violates a real contract.

checked یک محافظ همه‌چیز نیستchecked is not a universal guard

باید رفتار عملگر و زمینه را شناخت؛ overflow در integer با خطای دقت floating point یکی نیست. برای عددهای اعشاری، `checked` دقت را بالا نمی‌برد و مسئلهٔ نمایش دودویی را حل نمی‌کند.

Know the operation and context: integer overflow is not the same as floating-point precision error. `checked` does not increase decimal precision or fix binary representation.

تبدیل نوع، گردکردن و ورودی کاربرConversions, rounding and user input

تبدیل از `double` به `int` ممکن است بخش اعشاری را حذف کند؛ این همان گردکردن مالی نیست. برای parse متن از culture آگاه باش: نقطه و ویرگول اعشار در localeهای مختلف یکسان نیستند. در CLI و پروژه‌ها ورودی را صریح اعتبارسنجی می‌کنیم.

Converting `double` to `int` can discard the fractional part; that is not a financial rounding policy. Parsing text is culture-sensitive: decimal separators differ across locales. We will validate input explicitly in the CLI project.

C#
double measurement = 12.8;
int truncated = (int)measurement;
decimal charge = 12.825m;
decimal rounded = Math.Round(charge, 2, MidpointRounding.AwayFromZero);
Console.WriteLine($"{truncated} / {rounded}");

این خروجی `12 / 12.83` است. cast عدد را truncate می‌کند؛ `Math.Round` با policy صریح عمل می‌کند. انتخاب midpoint strategy باید از قاعدهٔ domain بیاید، چون روش پیش‌فرض ممکن است با انتظارت از گردکردن مالی فرق داشته باشد.

This prints `12 / 12.83`. The cast truncates; `Math.Round` applies an explicit policy. The midpoint strategy should come from domain rules, because the default may differ from a financial rounding expectation.

۱) قیمت سفارش را محاسبه کن1) Calculate an order total

سه قلم با قیمت `19.95m` را محاسبه کن. برای تعداد و مبلغ چه نوعی انتخاب می‌کنی؟ خروجی و دلیل انتخاب را بنویس.

Calculate three items priced at `19.95m`. Which types do you choose for quantity and amount? Record output and reasoning.

پاسخ و توضیحSolution and explanation
C#
int quantity = 3;
decimal price = 19.95m;
decimal total = quantity * price;
Console.WriteLine(total); // 59.85

`int` مدل شمارش است و decimal مدل مبلغ ده‌دهی. نمایش خروجی این آزمایش قاعدهٔ تخفیف یا گردکردن tax را تعیین نمی‌کند.

`int` models a count and decimal models a decimal amount. This output does not define discount or tax rounding rules.

۲) چرا مقایسه false شد؟2) Why did the comparison return false?

مقایسهٔ `0.1 + 0.2 == 0.3` را اجرا کن و مقدار round-trip را چاپ کن. در توضیح از «کامپیوتر اشتباه جمع کرد» استفاده نکن؛ مسئله را به نمایش مقدار وصل کن.

Run `0.1 + 0.2 == 0.3` and print a round-trip value. Explain representation rather than saying the computer added incorrectly.

پاسخ و توضیحSolution and explanation

double از نمایش دودویی با دقت محدود استفاده می‌کند؛ بسیاری از کسرهای ده‌دهی دقیقاً بازنمایی نمی‌شوند و جمع نزدیک 0.3 می‌شود. برای اندازه‌گیری tolerance مستند انتخاب کن؛ برای مبلغ decimal را بررسی کن. هیچ‌کدام سیاست دامنه را خودکار تعیین نمی‌کند.

Double uses finite-precision binary representation; many decimal fractions are inexact, so the sum is near 0.3. Choose a documented tolerance for measurements; consider decimal for amounts. Neither decides domain policy automatically.

۳) overflow را بازتولید کن3) Reproduce overflow

`int.MaxValue + 1` را در `checked` و `unchecked` اجرا کن و هر دو نتیجه را گزارش بده. کدام حالت برای شمارندهٔ رکوردی که نباید wrap شود مناسب‌تر است؟

Run `int.MaxValue + 1` in checked and unchecked contexts and report both. Which fits a record counter that must never wrap?

پاسخ و توضیحSolution and reasoning
C#
Console.WriteLine(unchecked(int.MaxValue + 1));
Console.WriteLine(checked(int.MaxValue + 1));

unchecked معمولاً به `int.MinValue` wrap می‌شود؛ checked exception می‌دهد. اگر overflow نقض invariant است، exception/validation قابل‌تشخیص مناسب‌تر است؛ باید recovery و گزارش هم طراحی شود.

Unchecked commonly wraps to `int.MinValue`; checked throws. If overflow violates an invariant, a detectable failure is preferable, with recovery and reporting designed explicitly.

۴) truncation را با گردکردن قاطی نکن4) Do not confuse truncation with rounding

عدد `12.8` را به int cast کن و جداگانه مبلغ `12.825m` را تا دو رقم با midpoint policy مشخص گرد کن. هر دو خروجی را چاپ و تفاوت عملیات را توضیح بده.

Cast `12.8` to int and separately round `12.825m` to two places with a chosen midpoint policy. Print both and explain the difference.

پاسخ و توضیحSolution and reasoning

cast مقدار اعشار را truncate می‌کند و به 12 می‌رسد؛ `Math.Round(..., AwayFromZero)` در این مثال 12.83 می‌دهد. نتیجه به policy انتخاب‌شده وابسته است؛ cast جای قاعدهٔ مالی نیست.

The cast truncates to 12; `Math.Round(..., AwayFromZero)` yields 12.83 here. The result depends on the chosen policy; a cast is not a financial rule.

۵) نوع را از معنی انتخاب کن5) Choose types from meaning

برای تعداد سفارش، موجودی قابل تقسیم، مبلغ پول و دمای سنسور type پیشنهاد بده. یک snippet بنویس که همه compile شود و برای هر انتخاب محدودیت نزدیکش را ذکر کند.

Choose types for order count, fractional inventory, money and sensor temperature. Write a compiling snippet and name a nearby limitation for each choice.

نمونهٔ پاسخSample solution
C#
int orders = 12;
decimal kilograms = 2.75m;
decimal amount = 149.90m;
double temperature = 21.6;

این انتخاب‌ها معنای داده را منعکس می‌کنند، اما ممکن است domain دقیق‌تر بخواهد: موجودی می‌تواند واحد کوچک‌ترین جزء داشته باشد؛ پول ممکن است به currency و policy نیاز داشته باشد؛ sensor ممکن است tolerance داشته باشد. نوع داده همهٔ قرارداد دامنه نیست.

These types reflect likely meanings, but the domain may require more: inventory may use a smallest unit, money may need a currency and policy, and sensors may need a tolerance. A primitive type is not the whole domain contract.
