VM بالا میاد، ولی دوباره وارد نصاب می‌شهThe VM boots—but keeps returning to the installer

ISO رو وصل کردی، Ubuntu نصب شد، ولی هر بار Start می‌زنی دوباره صفحهٔ نصب میاد. قبل از اینکه دیسک مجازی رو پاک کنی، یک سؤال: ماشین از کدوم دستگاه boot می‌کنه؟ VirtualBox ترتیب boot و دستگاه‌های مجازی رو مدیریت می‌کنه؛ دیسک و ISO هر دو می‌تونن هنوز متصل باشن.

You attached an ISO and installed Ubuntu, but every Start opens the installer again. Before deleting the virtual disk, ask: which device is the machine booting from? VirtualBox manages virtual devices and boot order; both the disk and ISO may still be attached.

در فصل قبل گفتیم hypervisor برای guest سخت‌افزار مجازی می‌سازه. حالا با VirtualBox دست‌به‌کار می‌شیم: اول host و ISO رو می‌سنجیم، VM کوچک می‌سازیم، از NAT برای خروجی استفاده می‌کنیم و شواهد رو با GUI و VBoxManage می‌خونیم. چیزی رو روی host پاک یا پارتیشن‌بندی نمی‌کنیم.

The previous chapter introduced a hypervisor presenting virtual hardware to a guest. Now we use VirtualBox: check the host and ISO, create a small VM, use NAT for outbound access, and inspect it through both the GUI and VBoxManage. We will not delete or repartition the host.

قبل از نصب: آیا host می‌تونه این guest رو اجرا کنه؟Before installing: can the host run this guest?

سه چیز رو جدا بررسی کن: host OS و معماری CPU، روشن‌بودن سخت‌افزار virtualization، و فضای آزاد RAM/دیسک. نسخه‌های جدید VirtualBox می‌تونن hostهای x86-64 و برخی hostهای Apple Silicon رو پشتیبانی کنن، ولی فهرست guestهای سازگار یکسان نیست؛ روی ARM فرض نکن ISOهای x86 رو بومی اجرا می‌کنی. جدول رسمی ترکیب host/guest و بستهٔ درست رو همون روز بررسی کن.

Check three things separately: host OS and CPU architecture, enabled hardware virtualisation, and free memory/disk. Recent VirtualBox releases support x86-64 hosts and some Apple Silicon hosts, but their guest combinations differ; on ARM, do not assume x86 ISOs run natively. Check the current official host/guest matrix and select the matching package.

در تاریخ نگارش این صفحه، Oracle برای VirtualBox 7.2.20 بسته‌های host مختلف و Guest Additions ISO همون نسخه رو منتشر کرده. این شماره نسخه تغییر می‌کنه؛ از صفحهٔ رسمی Download نصب‌کننده و ISO هم‌نسخه رو بردار، checksum منتشرشده رو بررسی کن و Extension Pack رو فقط اگه قابلیت مشخصی لازم داری نصب کن. Extension Pack با Guest Additions یکی نیست.

At the time this page was written, Oracle listed VirtualBox 7.2.20 host packages and a matching Guest Additions ISO. This version number changes: use Oracle’s official Downloads page, select a matching installer/ISO, verify its published checksum, and install the Extension Pack only if you need a specific feature. It is not the same thing as Guest Additions.

روی Linux می‌تونی قبل از نصب قابلیت رو با `lscpu` یا flagهای `vmx/svm` بررسی کنی؛ نبودن flag مثل فصل قبل لزوماً به معنی CPU ناسازگار نیست و ممکنه firmware یا cloud اون رو پنهان کرده باشه. روی Windows وضعیت virtualization در Task Manager قابل‌مشاهده هست. خطای نصب kernel module در Linux معمولاً به kernel headers/build tools یا Secure Boot سیاست مربوط می‌شه؛ نصب رو با بستهٔ توزیع و مستند همون نسخه جلو ببر.

On Linux, inspect `lscpu` or the `vmx/svm` flags first; as in Chapter 1, missing flags do not always mean unsupported hardware—firmware or a cloud host may hide them. On Windows, Task Manager reports virtualisation status. Linux host-kernel module build failures commonly involve matching kernel headers/build tools or Secure Boot policy; use your distro’s package method and documentation for that version.

برای نسخه و syntax جاری از صفحهٔ رسمی Download و راهنمای VirtualBox 7.2 استفاده کن. مسیرهای منو بین نسخه‌ها عوض می‌شن؛ مدل دستگاه مجازی پایدارتر از تصویر هست.

For current releases and syntax, use Oracle’s official Downloads page and VirtualBox 7.2 User Guide. Menu locations change across versions; the virtual-device model is more durable than a screenshot.

یک VM کوچک بساز؛ عددها رو با host خودت بسنجCreate a small VM; size it for your host

برای lab، Ubuntu Server LTS رو از منبع رسمی بگیر و نام ISO رو یادداشت کن. New رو در VirtualBox باز کن، نامی مثل `lab-ubuntu` بده، نوع Linux/Ubuntu رو انتخاب کن و ISO رو به optical drive وصل کن. گزینهٔ unattended install می‌تونه حساب و نصب رو خودکار بسازد؛ اگه می‌خوای هر صفحه رو یاد بگیری، اون رو خاموش کن و نصب دستی انجام بده.

For this lab, obtain an Ubuntu Server LTS ISO from its official source and note its filename. In VirtualBox choose New, name it `lab-ubuntu`, select Linux/Ubuntu, and attach the ISO to the virtual optical drive. Unattended installation can automate the account and OS setup; disable it if you want to learn the manual installer path.

برای guest آزمایشی سبک می‌تونی با ۲ vCPU، حدود ۴ GiB RAM و VDI با سقف ۲۵ GiB شروع کنی—فقط اگه host منابع آزاد کافی داره. vCPU رزرو قطعی یک هستهٔ فیزیکی نیست. Dynamic دیسک هم از اول ۲۵ GiB واقعی اشغال نمی‌کنه، ولی می‌تونه تا اون سقف رشد کنه و فضای host رو پر کنه. مقدار RAM رو طوری انتخاب کن که host و برنامه‌های بازشده هنوز نفس بکشند.

For a modest test guest, start around 2 vCPUs, 4 GiB RAM, and a VDI with a 25 GiB maximum—only if the host has enough headroom. A vCPU does not reserve one physical core. A dynamically allocated disk does not consume its full 25 GiB immediately, but it can grow to that limit and fill host storage. Allocate memory while leaving enough for the host and its workloads.

VirtualBox wizard می‌تونه دیسک بسازد؛ بررسی کن دیسک حداقل ظرفیت نصب guest و به‌روزرسانیهای آزمایشی رو داشته باشه. Snapshot هنوز این فصل نیست—در فصل ۶ جدا بررسی می‌شه. قبل از تغییر مهم VM خاموش باشه و تنظیمات رو ثبت کن.

The VirtualBox wizard can create the disk; ensure it has room for the guest and lab updates. Snapshots are deferred to Chapter 6. Shut down the VM before significant hardware changes and record its configuration.

VBoxManage list vms
VBoxManage showvminfo "lab-ubuntu"
VBoxManage --version

این سه دستور VM ثبت‌شده، تنظیمات مجازی و نسخهٔ host رو نشون می‌دن. در `showvminfo` دنبال RAM، CPU، ترتیب بوت، storage و NIC حالت بگرد. این خروجی ثابت نمی‌کنه guest OS درست نصب شده؛ برای اون باید خود guest boot بشه.

These commands show registered VMs, virtual configuration, and host version. In `showvminfo`, inspect memory, CPUs, boot order, storage, and NIC mode. This does not prove the guest OS installed correctly; boot the guest to verify that.

نصب تمام شد؟ ISO رو از مسیر boot خارج کنInstallation finished? Remove the ISO from the boot path

VM رو Start کن و Ubuntu رو روی دیسک مجازی نصب کن؛ دیسک فیزیکی host رو انتخاب نکن—نصاب فقط باید VDI ماشین رو ببینه. بعد از نصب و reboot، اگه نصاب دوباره آمد هنوز ISO به optical drive وصل هست یا DVD در ترتیب boot جلوتر از دیسک قرار داره. این معمولاً data corruption نیست؛ boot source اشتباه هست.

Start the VM and install Ubuntu onto its virtual disk; do not select the host’s physical disk—the installer should see the VM’s VDI. If the installer returns after installation and reboot, the ISO is still attached or DVD precedes disk in boot order. This is usually the wrong boot source, not data corruption.

برای تشخیص، در VirtualBox Manager بخش Storage رو ببین: آیا ISO هنوز داخل مجازی optical drive هست؟ Boot Order رو هم بررسی کن. بعد از جمع‌کردن شاهد، از دستگاه‌ها → Optical Drives، دیسک رو eject کن یا از Storage اون رو detach کن؛ دیسک مجازی رو نگه دار و VM رو دوباره روشن کن. این یک تغییر برگشت‌پذیر هست.

Inspect Storage in VirtualBox Manager: is the ISO still in the virtual optical drive? Check Boot Order too. After recording evidence, eject it through Devices → Optical Drives or detach it under Storage; keep the virtual disk and restart. This change is reversible.

اگه VM می‌گه no bootable medium، این بار optical و دیسک هیچ‌کدوم فایل bootable ندارن یا storage controller درست وصل نیست. `VBoxManage showvminfo "lab-ubuntu"` رو برای attachmentها ببین؛ قبل از نصب دوباره دیسک رو delete نکن.

If the VM reports no bootable medium, neither the optical drive nor disk has a bootable image, or the storage controller is misconfigured. Inspect attachments with `VBoxManage showvminfo "lab-ubuntu"`; do not delete the disk before understanding the state.

Guest Additions چه مشکلی رو حل می‌کنه؟Which problem do Guest Additions solve?

Guest Additions مجموعه‌ای از درایور و سرویسهای داخل guest هست؛ می‌تونه resize گرافیکی، pointer یکپارچه‌سازی، clipboard یا پوشهٔ مشترکs رو فراهم کنه. برای Ubuntu Server بدون GUI، mouse یکپارچه‌سازی و auto-resize به کارت نمیاد و SSH با NAT هم به اون وابسته نیست. قابلیت رو فقط وقتی روشن کن که واقعاً نیازش داری.

Guest Additions are drivers and services installed inside the guest. They can provide graphics resizing, pointer integration, clipboard, or shared folders. On an Ubuntu Server guest without a GUI, mouse integration and auto-resize are irrelevant; SSH over NAT does not depend on them. Enable only what you need.

اگه Linux guest داری و قابلیت لازمه، ابتدا نسخهٔ VirtualBox host رو ببین. از دستگاه‌ها → Insert Guest Additions CD Image، ISO هم‌نسخه رو mount کن. برای ماژول kernel ممکنه build tools و headers دقیقاً مطابق kernel فعلی لازم باشه. بعد داخل guest در CD mount شده اجرا کن:

If a Linux guest needs these features, first check the host VirtualBox version. Choose Devices → Insert Guest Additions CD Image to mount the matching ISO. Kernel modules may require build tools and headers matching the running guest kernel. Then run this inside the guest from the mounted CD:

sudo sh ./VBoxLinuxAdditions.run

خروجی نصب باید درایورهای موردنیاز رو بسازد؛ اگه build خراب شد، kernel headers یا لاگ نصب رو بررسی کن، نه اینکه Guest Additions نسخهٔ نامرتبط رو بارها اجرا کنی. بعد از reboot وضعیت رو با `lsmod | grep vbox` و `VBoxControl --version` ببین؛ خالی بودن `grep` می‌تونه بسته به guest و قابلیت موردنیاز طبیعی باشه، پس همهٔ شواهد رو کنار هم تفسیر کن.

The installer should build needed drivers; if that fails, inspect matching kernel headers and installer logs instead of repeatedly running a mismatched ISO. After reboot, inspect `lsmod | grep vbox` and `VBoxControl --version`. An empty `grep` can be normal depending on guest and required feature, so interpret multiple signals together.

پوشهٔ مشترک یعنی مرز دادهٔ میزبان رو باز کرده‌ای

پوشهٔ مشترک رو فقط به یک پوشهٔ lab خالی وصل کن و در صورت کافی‌بودن فقط‌خواندنی بذار. clipboard و کشیدن و رهاکردن هم راه انتقال داده‌اند؛ برای آزمایش فایل ناشناس خاموششان کن. Guest Additions یکپارچه‌سازی راحتی می‌ده، ولی مرز اعتماد host/guest رو کم می‌کنه. Extension Pack قابلیت‌های اختیاری دیگری می‌ده و license جداگانه داره؛ برای نصب Ubuntu یا SSH لازم نیست.

Share only an empty lab folder, preferably read-only when sufficient. Clipboard and drag-and-drop are data paths too; disable them when testing unknown files. Guest Additions improve integration but weaken the host/guest data boundary. The Extension Pack adds optional features under separate licensing terms; it is not required to install Ubuntu or use SSH.

NAT: guest بیرون رو می‌بینه، host لزوماً guest رو نهNAT: the guest sees out; the host does not automatically see in

Adapter پیش‌فرض NAT به guest اجازه می‌ده اتصال خروجی بسازد؛ مثلاً بسته بگیره. به‌طور معمول host نمی‌تونه دلخواه به سرویس مهمان وصل بشه. برای SSH از host، اول داخل guest `openssh-server` رو نصب کن و `ip -br address`/`ip route` رو ببین؛ این نشون می‌ده guest شبکه داره، نه اینکه host route مستقیم به اون داره.

A NAT adapter lets the guest initiate outbound connections, such as package downloads. The host usually cannot directly initiate arbitrary connections to a guest service. To SSH from the host, install `openssh-server` inside the guest and inspect `ip -br address` and `ip route`; this proves the guest has networking, not that the host has a direct route to it.

راه ساده برای همین ماشین، port forwarding محدود به loopback هست: host `127.0.0.1:2222` رو به پورت مهمان 22 بفرست. در GUI مسیر Network → Adapter 1 → Advanced → Port Forwarding هست. با VBoxManage می‌توان همون قاعده رو دید/ساخت؛ اول مطمئن شو پورت 2222 روی host آزاد هست:

For this host, use a port-forward rule restricted to loopback: host `127.0.0.1:2222` to guest port 22. In the GUI, use Network → Adapter 1 → Advanced → Port Forwarding. VBoxManage can express the same rule; first ensure host port 2222 is free:

VBoxManage modifyvm "lab-ubuntu" --natpf1 "guestssh,tcp,127.0.0.1,2222,,22"
VBoxManage showvminfo "lab-ubuntu"

فیلد خالیِ guest IP یعنی VirtualBox از guest DHCP address استفاده می‌کنه. `showvminfo` باید NAT قانون رو نشان بده. سبعد از host با `ssh -p 2222 youruser@127.0.0.1` وصل شو. اگه قانون قبلاً هست، دوباره اضافه نکن؛ GUI یا VBoxManage اون رو بررسی کن و بعد از lab حذفش کن.

The empty guest-IP field means VirtualBox uses the guest’s DHCP address. `showvminfo` should show the NAT rule. From the host, connect with `ssh -p 2222 youruser@127.0.0.1`. Do not add a duplicate rule if one exists; inspect it first and remove it after the lab.

این پورت فقط روی loopback میزبان هست؛ اون رو به `0.0.0.0` نبند، مگر دلیل و فایروال روشن داشته باشی. Port forwarding همون یک سرویس رو در معرض host قرار می‌ده؛ همهٔ پورت‌های guest رو باز نمی‌کنه. برای چند VM روی یک شبکهٔ خصوصی، host-only/internal رو در فصل شبکه می‌سازیم.

This port binds only to host loopback; do not bind it to `0.0.0.0` without a clear reason and firewall plan. Port forwarding exposes that one service to the host; it does not open every guest port. Chapter 7 will build host-only/internal networks for multiple VMs.

خرابی عمدی: نصاب هر بار برمی‌گردهDeliberate failure: the installer returns on every boot

بعد از نصب، VM رو خاموش کن و ISO رو عمداً وصل نگه دار؛ DVD رو هم در ترتیب بوت اول بذار. دوباره Start کن: نصاب ظاهر می‌شه. پیش‌بینی کن آیا VDI پاک شده؟ حالا قبل از تغییر، Storage attachment، ترتیب بوت و `showvminfo` رو ثبت کن. شواهد نشون می‌دن ماشین از کدوم دستگاه بالا آمده، نه اینکه اطلاعات دیسک رو از دست داده‌ای.

After installation, power off the VM but deliberately leave the ISO attached and DVD first in boot order. Start it again: the installer appears. Predict whether the VDI was erased. Before changing anything, record Storage attachments, boot order, and `showvminfo`. This evidence shows which device booted, not that disk data was lost.

تعمیر رو کوچک نگه دار: ISO رو eject کن، دیسک رو نگه دار، ترتیب بوت رو دیسک-first کن و یک بار reboot بزن. اگه Ubuntu بالا آمد، علت رو درست پیدا کردی. اگه «no bootable medium» دیدی، storage controller و دیسک attachment رو ببین. دیسک رو فقط برای اینکه پیام نصاب رو نمی‌پسندی حذف نکن.

Keep the repair narrow: eject the ISO, keep the disk, set disk first in boot order, and boot once. If Ubuntu starts, the diagnosis was right. If you see “no bootable medium,” inspect the storage controller and disk attachment. Do not delete the disk just because the installer screen was unexpected.

آزمایش: یک Ubuntu VM که دوباره ساخته‌اش می‌تونیLab: an Ubuntu VM you can reproduce

قبل از شروع فضای آزاد host و ISO رو ثبت کن. VM رو با ۲ vCPU، RAM متناسب با host، dynamic VDI با سقف حدود ۲۵ GiB، یک optical drive و یک NAT NIC بساز. در نصاب، کاربر معمولی بساز و SSH سرور رو نصب کن؛ اطلاعات محرمانه واقعی یا فایل شخصی داخل guest نگذار.

Record host free space and ISO before starting. Create a VM with 2 vCPUs, memory appropriate to the host, a dynamically allocated VDI capped around 25 GiB, one optical drive, and one NAT NIC. Create a regular user in the installer and install the SSH server; keep real secrets and personal files out of this guest.

بعد از اولین boot، داخل guest `uname -a`, `ip -br address`, `ip route` و `df -h /` بگیر. این‌ها kernel، IP، پیش‌فرض route و فضای فایل‌سیستم guest رو نشون می‌دن؛ فضای آزاد host رو از host جداگانه بسنج. اگه دیسک کوچک هست، guest اون رو می‌بینه، ولی dynamic دیسک ممکنه هم‌زمان فضای host رو هم مصرف کنه.

After first boot, run `uname -a`, `ip -br address`, `ip route`, and `df -h /` inside the guest. These show kernel, IP, default route, and guest filesystem space; measure host free space separately. The guest may see a large virtual disk while the dynamic image consumes increasing host storage.

از host با port-forward loopback به SSH وصل شو؛ بعد قانون رو حذف کن و دوباره تلاش کن. انتظار داریم اتصال خراب بشه، ولی NAT خروجی مهمان هنوز کار کنه. این تغییر نشون می‌ده خروجی NAT و ورودی port forwarding دو مسیر متفاوت‌اند.

Connect from the host to SSH through a loopback-only forward, then delete the rule and try again. The inbound connection should fail while guest outbound NAT continues to work. This separates outbound NAT from inbound forwarding.

در پایان ISO رو detach کن. اگه Guest Additions رو نصب کردی، نسخه و وضعیت رو ثبت کن، clipboard/پوشهٔ مشترکs رو خاموش نگه دار مگر lab واقعاً به اون‌ها نیاز داشته باشه. Snapshot رو در این فصل لازم نداریم؛ فصل ۶ زمان مناسب بررسی برگشت و محدودیت‌هایش هست.

Finally detach the ISO. If you installed Guest Additions, record their version/status and keep clipboard/shared folders disabled unless the lab needs them. A snapshot is not required here; Chapter 6 will examine rollback and its limits.

۱۸ تمرین؛ قبل از دست‌زدن به دیسک، شواهد رو بخون18 exercises: inspect evidence before touching the disk

۱. ISO در برابر VDI

در wizard هر دو فایل ISO و VDI می‌بینی. کدوم boot نصاب هست و کدوم مقصد نصب سیستم‌عامل؟

The wizard shows an ISO and a VDI. Which boots the installer and which stores the installed OS?

پاسخ

ISO رسانهٔ نوری نصاب هست؛ VDI دیسک مجازی مقصد نصب. اشتباه‌گرفتنشان باعث boot loop یا نصب روی هدف اشتباه می‌شه.

The ISO is installer media; the VDI is the virtual disk target. Confusing them causes a boot loop or installation to the wrong target.

۲. host کم‌حافظه

host دارای ۸ GiB RAM هست و browser/work tools هم بازند. آیا تخصیص ۷ GiB به guest انتخاب بدیهی هست؟

The host has 8 GiB RAM with a browser and work tools open. Is assigning 7 GiB to the guest an obvious good choice?

پاسخ

نه؛ host برای خودش حافظه لازم داره و ممکنه swap/thrashing کند. guest رو کوچک‌تر آغاز کن، مصرف رو مشاهده و بر اساس بار کاری تنظیم کن.

No. The host needs memory too and may start swapping heavily. Begin smaller, observe use, and size for the workload.

۳. dynamic VDI

VDI سقف ۲۵ GiB داره ولی اول کار host فقط ۵ GiB فضا نشون می‌ده. آیا host هیچ‌وقت بیشتر مصرف نمی‌کنه؟

A VDI has a 25 GiB cap but uses 5 GiB on the host initially. Can host usage never grow further?

پاسخ

می‌تونه تا سقف مجازی capacity رشد کنه. فضای host رو هم پایش کن؛ dynamic allocation ظرفیت تضمین‌شده یا فضای آزاد دائمی نیست.

It can grow up to the virtual capacity. Monitor host storage too; dynamic allocation is not guaranteed or permanently free capacity.

۴. نصاب دوباره ظاهر شد

بعد از reboot صفحهٔ نصب آمده. قبل از هر تعمیر دو مورد رو بررسی می‌کنی؟

The installer reappears after reboot. Which two things do you inspect before repairing?

پاسخ

ISO هنوز متصل هست؟ ترتیب بوت DVD رو قبل از دیسک می‌آورد؟ این دو رو از GUI یا `showvminfo` ببین و دیسک رو حذف نکن.

Is the ISO still attached? Does boot order place DVD before disk? Inspect both in the GUI or `showvminfo`; do not delete the disk.

۵. no bootable medium

اکنون ISO رو detach کردی و VM پیام no bootable medium می‌ده. کدوم دو attachment رو می‌سنجی؟

You detached the ISO and now see “no bootable medium.” Which two attachments do you inspect?

پاسخ

آیا مجازی hard دیسک هنوز به storage controller وصل هست و آیا OS واقعاً روی اون نصب شده؟ اگه نصاب نصب رو کامل نکرده، ISO رو دوباره attach کن؛ VDI رو بی‌بررسی پاک نکن.

Is the virtual hard disk still attached to its storage controller, and was the OS installed there? If installation was incomplete, reattach the ISO; do not erase the VDI without inspection.

۶. guest شبکه داره، host SSH نداره

guest IP از NAT گرفته و می‌تونه به‌روزرسانی بگیره؛ host نمی‌تونه به guest SSH کند. تناقضی هست؟

The guest has a NAT address and can download updates; the host cannot SSH into it. Is this contradictory?

پاسخ

نه؛ خروجی NAT اتصال رو از guest آغاز می‌کنه. برای ورودی از host، port forwarding یا شبکهٔ دیگری لازمه.

No. Outbound NAT is initiated by the guest. Host-initiated inbound access needs port forwarding or another network mode.

۷. پورت روی همهٔ host interfaceها

NAT قانون روی پورت میزبان 2222 به guest SSH هست. چرا host IP رو خالی گذاشتن ممکنه نامطلوب باشه؟

A NAT rule maps host port 2222 to guest SSH. Why might leaving the host IP empty be undesirable?

پاسخ

ممکنه روی تمام host interfaceها گوش بده، نه فقط loopback. برای تست شخصی `127.0.0.1` رو تعیین کن و با `showvminfo` قانون رو بررسی کن.

It may listen on all host interfaces rather than loopback. For a personal test, specify `127.0.0.1` and verify the rule with `showvminfo`.

۸. VBoxManage قانون تکراری

VBoxManage می‌گه NAT قانون نام تکراری هست. چه می‌کنی؟

VBoxManage reports a duplicate NAT rule name. What do you do?

پاسخ

اول `showvminfo` یا GUI رو بخون؛ قانون موجود رو ویرایش/حذف کن، نه اینکه با نام تصادفی چند forward بسازی. بعد با یک درخواست SSH آزمایش کن.

Inspect `showvminfo` or the GUI first; edit/remove the existing rule instead of creating multiple forwards with random names. Verify with one SSH test.

۹. guest additions build fail

نصب Guest Additions می‌گه kernel module ساخته نشد. اولین بررسی‌ها چیست؟

Guest Additions reports that a kernel module could not be built. What do you check first?

پاسخ

آیا ISO با VirtualBox host هم‌نسخه هست؟ headers/build tools برای kernel در حال اجرا نصب‌اند؟ لاگ نصاب و Secure Boot سیاست رو ببین؛ یک ISO دیگر رو شانسی نصب نکن.

Does the ISO match the VirtualBox host version? Are headers/build tools installed for the running guest kernel? Inspect installer logs and Secure Boot policy; do not randomly try another ISO.

۱۰. clipboard کار نمی‌کنه

Guest Additions نصب شده ولی clipboard shared نیست. چه شرط دیگری باید درست باشه؟

Guest Additions are installed but the clipboard is not shared. What else must be configured?

پاسخ

تنظیم Shared Clipboard در VM باید فعال و Guest Additions سرویس/درایور سالم باشه؛ GUI guest بدون component مربوطه ممکنه لازم داشته باشه. اگه به قابلیت نیاز نداری، خاموش بمونه.

Shared Clipboard must be enabled in the VM settings and Guest Additions services/drivers must work; a graphical guest may need its relevant component. If unnecessary, leave it disabled.

۱۱. Extension Pack با Guest Additions

برای resize صفحهٔ guest می‌خوای Extension Pack نصب کنی. آیا این قطعهٔ درست هست؟

You want guest display resizing and plan to install the Extension Pack. Is that the right component?

پاسخ

معمولاً نه؛ Guest Additions داخل guest درایور/سرویسهایی مثل auto-resize می‌آورد. Extension Pack امکانات اختیاری host-side دیگری داره و license جداگانه داره.

Usually not. Guest Additions provides guest-side drivers/services such as auto-resize. The Extension Pack adds other optional host-side features under separate licensing.

۱۲. پوشهٔ مشترک با نصاب ناشناس

می‌خوای نصاب ناشناس رو آزمایش کنی. پوشهٔ مشترک خانهٔ host روی read/write هست. قبل از اجرا چه تغییری می‌دی؟

You plan to test an unknown installer. The host home folder is shared read/write. What do you change before running it?

پاسخ

پوشهٔ مشترک رو خاموش یا به پوشهٔ آزمایشی و فقط‌خواندنی محدود کن؛ clipboard و drag/drop رو هم خاموش کن و شبکه رو در صورت نیاز internal کن. VM به‌تنهایی barrier کامل نیست.

Disable the share or limit it to a disposable read-only folder; also disable clipboard/drag-and-drop and isolate networking if needed. A VM alone is not a perfect barrier.

۱۳. memory balloon

guest کند هست و host هم حافظه pressure داره. آیا افزودن vCPU اولین پاسخ هست؟

The guest is slow and the host is under memory pressure. Is adding a vCPU the first answer?

پاسخ

نه لزوماً؛ host/guest حافظه، swap، CPU contention و دیسک I/O رو بسنج. منابع مجازی می‌تونن contention رو بیشتر کنند.

Not necessarily; measure host/guest memory, swap, CPU contention, and disk I/O. More virtual resources can increase contention.

۱۴. NAT یا bridge؟

برای تمرین نصب، guest فقط باید بسته بگیره و از LAN دیده نشه. کدوم حالت رو انتخاب می‌کنی؟

For installation, the guest needs package access but should not appear directly on the LAN. Which mode do you choose?

پاسخ

NAT معمولاً شروع ساده‌تری هست چون guest اتصال خروجی می‌سازه. Port forwarding رو فقط برای سرویس مشخص اضافه کن؛ bridge رو بی‌نیاز انتخاب نکن.

NAT is usually the simpler start because the guest initiates outbound connections. Add forwarding only for a specific service; do not choose bridged mode without a need.

۱۵. guest IP عوض شده

بعد از reboot SSH forwarding خراب شد و قانون یک guest IP ثابت داره. چی رو مقایسه می‌کنی؟

SSH forwarding fails after reboot and the rule contains a fixed guest IP. What do you compare?

پاسخ

IP فعلی `ip -br address` با IP قانون. NAT DHCP ممکنه IP رو عوض کنه؛ guest IP خالی/lease مناسب یا reservation رو در همون شبکهٔ NAT ارزیابی کن.

Compare current `ip -br address` with the rule’s address. NAT DHCP may change it; assess an empty guest-IP field or a suitable reservation for that NAT network.

۱۶. ISO mismatch

host VirtualBox به‌روز شده ولی Additions داخل guest قدیمی هست. کدوم علامت رو می‌بینی و از کجا شروع می‌کنی؟

The host VirtualBox was upgraded but guest Additions are old. What symptom might appear and where do you start?

پاسخ

نسخه/درایور mismatch می‌تونه یکپارچه‌سازی رو ناقص کند. نسخهٔ host و `VBoxControl --version` رو مقایسه کن؛ سپس ISO matching host رو از دستگاه‌ها وارد و نصب/بررسی رو دنبال کن.

A driver/version mismatch may break integration. Compare host version with `VBoxControl --version`, insert the matching ISO through Devices, then install and verify.

۱۷. space guest در برابر host

`df -h /` داخل guest ۱۵ GiB آزاد می‌گه ولی host تقریباً پر هست. چرا هر دو می‌تونن درست باشن؟

`df -h /` inside the guest shows 15 GiB free, but the host is almost full. How can both be true?

پاسخ

`df` ظرفیت فایل‌سیستم مجازی رو می‌بینه؛ dynamic VDI روی host رشد کرده و فایل‌های دیگری هم فضا گرفته‌اند. فضای guest و فضای host رو جدا پایش کن.

`df` sees the virtual filesystem capacity; the dynamic VDI may have grown on the host alongside other files. Monitor guest and host capacity separately.

۱۸. بازبینی VM lab

یک VM برای تمرین SSH تحویل می‌دی. سه مقدار `showvminfo` یا GUI رو که ثبت می‌کنی نام ببر و بگو هرکدام چی رو ثابت نمی‌کنن.

You hand off an SSH lab VM. Name three values from `showvminfo`/GUI you record and what each does not prove.

معیار پاسخ

نسخهٔ VirtualBox و boot/storage/NIC/RAM/CPU رو ثبت کن. تنظیمات ثبت‌شده صحت نصب guest، دسترسی شبکهٔ واقعی یا سالم‌بودن دیسک رو ثابت نمی‌کنه؛ با boot، IP، SSH و خواندن لاگ/health تکمیلش کن.

Record VirtualBox version and boot/storage/NIC/RAM/CPU settings. Configuration does not prove guest installation, actual reachability, or disk health; complement it with boot, IP, SSH, and relevant logs.

یک ماشین، چند مرز قابل‌بررسیOne VM, several boundaries you can inspect

VirtualBox به guest سخت‌افزار مجازی می‌ده؛ ISO نصاب رو boot می‌کنه؛ VDI سیستم نصب‌شده رو نگه می‌داره؛ NAT اتصال خروجی می‌ده؛ پورت forward یک ورودی مشخص اضافه می‌کنه؛ Guest Additions یکپارچه‌سازی رو بهتر می‌کنه و هم‌زمان چند مسیر اعتماد به host باز می‌کنه. هر کدوم رو به‌عنوان قطعه‌ای جدا بررسی کن.

VirtualBox presents virtual hardware; the ISO boots an installer; the VDI stores the installed system; NAT provides outbound access; a port forward adds one inbound path; Guest Additions improve integration while opening additional trust paths to the host. Inspect each as a distinct component.
