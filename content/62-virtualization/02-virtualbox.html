VM بالا می‌آید، ولی دوباره وارد installer می‌شودThe VM boots—but keeps returning to the installer

ISO را وصل کردی، Ubuntu نصب شد، ولی هر بار Start می‌زنی دوباره صفحهٔ نصب می‌آید. قبل از اینکه دیسک مجازی را پاک کنی، یک سؤال: ماشین از کدام device boot می‌کند؟ VirtualBox ترتیب boot و دستگاه‌های مجازی را مدیریت می‌کند؛ دیسک و ISO هر دو می‌توانند هنوز متصل باشند.

You attached an ISO and installed Ubuntu, but every Start opens the installer again. Before deleting the virtual disk, ask: which device is the machine booting from? VirtualBox manages virtual devices and boot order; both the disk and ISO may still be attached.

در فصل قبل گفتیم hypervisor برای guest سخت‌افزار مجازی می‌سازد. حالا با VirtualBox دست‌به‌کار می‌شویم: اول host و ISO را می‌سنجیم، VM کوچک می‌سازیم، از NAT برای خروجی استفاده می‌کنیم و شواهد را با GUI و VBoxManage می‌خوانیم. چیزی را روی host پاک یا پارتیشن‌بندی نمی‌کنیم.

The previous chapter introduced a hypervisor presenting virtual hardware to a guest. Now we use VirtualBox: check the host and ISO, create a small VM, use NAT for outbound access, and inspect it through both the GUI and VBoxManage. We will not delete or repartition the host.

فلش‌های پیوسته مسیر resource و packet خروجی‌اند؛ دسترسی ورودی به SSH بدون port forwarding جداگانه ساخته نمی‌شود.

Solid arrows show the resource and outbound-packet path; inbound SSH needs a separate port-forward rule.

قبل از نصب: آیا host می‌تواند این guest را اجرا کند؟Before installing: can the host run this guest?

سه چیز را جدا بررسی کن: host OS و معماری CPU، روشن‌بودن hardware virtualization، و فضای آزاد RAM/disk. نسخه‌های جدید VirtualBox می‌توانند hostهای x86-64 و برخی hostهای Apple Silicon را پشتیبانی کنند، اما فهرست guestهای سازگار یکسان نیست؛ روی ARM فرض نکن ISOهای x86 را native اجرا می‌کنی. جدول رسمی ترکیب host/guest و بستهٔ درست را همان روز بررسی کن.

Check three things separately: host OS and CPU architecture, enabled hardware virtualisation, and free memory/disk. Recent VirtualBox releases support x86-64 hosts and some Apple Silicon hosts, but their guest combinations differ; on ARM, do not assume x86 ISOs run natively. Check the current official host/guest matrix and select the matching package.

در تاریخ نگارش این صفحه، Oracle برای VirtualBox 7.2.20 بسته‌های host مختلف و Guest Additions ISO همان نسخه را منتشر کرده است. این شماره نسخه تغییر می‌کند؛ از صفحهٔ رسمی Download نصب‌کننده و ISO هم‌نسخه را بردار، checksum منتشرشده را بررسی کن و Extension Pack را فقط اگر feature مشخصی لازم داری نصب کن. Extension Pack با Guest Additions یکی نیست.

At the time this page was written, Oracle listed VirtualBox 7.2.20 host packages and a matching Guest Additions ISO. This version number changes: use Oracle’s official Downloads page, select a matching installer/ISO, verify its published checksum, and install the Extension Pack only if you need a specific feature. It is not the same thing as Guest Additions.

روی Linux می‌توانی پیش از نصب extension را با `lscpu` یا flagهای `vmx/svm` بررسی کنی؛ نبودن flag مثل فصل قبل لزوماً به معنی CPU ناسازگار نیست و ممکن است firmware یا cloud آن را پنهان کرده باشد. روی Windows وضعیت virtualization در Task Manager قابل‌مشاهده است. خطای نصب kernel module در Linux معمولاً به kernel headers/build tools یا Secure Boot policy مربوط می‌شود؛ نصب را با بستهٔ توزیع و مستند همان نسخه جلو ببر.

On Linux, inspect `lscpu` or the `vmx/svm` flags first; as in Chapter 1, missing flags do not always mean unsupported hardware—firmware or a cloud host may hide them. On Windows, Task Manager reports virtualisation status. Linux host-kernel module build failures commonly involve matching kernel headers/build tools or Secure Boot policy; use your distro’s package method and documentation for that version.

برای نسخه و syntax جاری از صفحهٔ رسمی Download و راهنمای VirtualBox 7.2 استفاده کن. مسیرهای منو بین نسخه‌ها عوض می‌شوند؛ مدل دستگاه مجازی پایدارتر از screenshot است.

For current releases and syntax, use Oracle’s official Downloads page and VirtualBox 7.2 User Guide. Menu locations change across versions; the virtual-device model is more durable than a screenshot.

یک VM کوچک بساز؛ عددها را با host خودت بسنجCreate a small VM; size it for your host

برای lab، Ubuntu Server LTS را از منبع رسمی بگیر و نام ISO را یادداشت کن. New را در VirtualBox باز کن، نامی مثل `lab-ubuntu` بده، نوع Linux/Ubuntu را انتخاب کن و ISO را به optical drive وصل کن. گزینهٔ unattended install می‌تواند حساب و نصب را خودکار بسازد؛ اگر می‌خواهی هر صفحه را یاد بگیری، آن را خاموش کن و نصب دستی انجام بده.

For this lab, obtain an Ubuntu Server LTS ISO from its official source and note its filename. In VirtualBox choose New, name it `lab-ubuntu`, select Linux/Ubuntu, and attach the ISO to the virtual optical drive. Unattended installation can automate the account and OS setup; disable it if you want to learn the manual installer path.

برای guest آزمایشی سبک می‌توانی با ۲ vCPU، حدود ۴ GiB RAM و VDI با سقف ۲۵ GiB شروع کنی—فقط اگر host منابع آزاد کافی دارد. vCPU رزرو قطعی یک هستهٔ فیزیکی نیست. Dynamic disk هم از اول ۲۵ GiB واقعی اشغال نمی‌کند، اما می‌تواند تا آن سقف رشد کند و فضای host را پر کند. مقدار RAM را طوری انتخاب کن که host و برنامه‌های بازشده هنوز نفس بکشند.

For a modest test guest, start around 2 vCPUs, 4 GiB RAM, and a VDI with a 25 GiB maximum—only if the host has enough headroom. A vCPU does not reserve one physical core. A dynamically allocated disk does not consume its full 25 GiB immediately, but it can grow to that limit and fill host storage. Allocate memory while leaving enough for the host and its workloads.

VirtualBox wizard می‌تواند disk بسازد؛ بررسی کن disk حداقل ظرفیت نصب guest و updateهای آزمایشی را داشته باشد. Snapshot هنوز این فصل نیست—در فصل ۶ جدا بررسی می‌شود. پیش از تغییر مهم VM خاموش باشد و config را ثبت کن.

The VirtualBox wizard can create the disk; ensure it has room for the guest and lab updates. Snapshots are deferred to Chapter 6. Shut down the VM before significant hardware changes and record its configuration.

VBoxManage list vms
VBoxManage showvminfo "lab-ubuntu"
VBoxManage --version

این سه دستور VM ثبت‌شده، config مجازی و نسخهٔ host را نشان می‌دهند. در `showvminfo` دنبال RAM، CPU، boot order، storage و NIC mode بگرد. این خروجی ثابت نمی‌کند guest OS درست نصب شده؛ برای آن باید خود guest boot شود.

These commands show registered VMs, virtual configuration, and host version. In `showvminfo`, inspect memory, CPUs, boot order, storage, and NIC mode. This does not prove the guest OS installed correctly; boot the guest to verify that.

نصب تمام شد؟ ISO را از مسیر boot خارج کنInstallation finished? Remove the ISO from the boot path

VM را Start کن و Ubuntu را روی virtual disk نصب کن؛ دیسک فیزیکی host را انتخاب نکن—installer فقط باید VDI ماشین را ببیند. پس از نصب و reboot، اگر installer دوباره آمد هنوز ISO به optical drive وصل است یا DVD در ترتیب boot جلوتر از disk قرار دارد. این معمولاً data corruption نیست؛ boot source اشتباه است.

Start the VM and install Ubuntu onto its virtual disk; do not select the host’s physical disk—the installer should see the VM’s VDI. If the installer returns after installation and reboot, the ISO is still attached or DVD precedes disk in boot order. This is usually the wrong boot source, not data corruption.

برای تشخیص، در VirtualBox Manager بخش Storage را ببین: آیا ISO هنوز داخل virtual optical drive است؟ Boot Order را هم بررسی کن. بعد از جمع‌کردن شاهد، از Devices → Optical Drives، دیسک را eject کن یا از Storage آن را detach کن؛ disk مجازی را نگه دار و VM را دوباره روشن کن. این یک تغییر برگشت‌پذیر است.

Inspect Storage in VirtualBox Manager: is the ISO still in the virtual optical drive? Check Boot Order too. After recording evidence, eject it through Devices → Optical Drives or detach it under Storage; keep the virtual disk and restart. This change is reversible.

اگر VM می‌گوید no bootable medium، این بار optical و disk هیچ‌کدام فایل bootable ندارند یا storage controller درست وصل نیست. `VBoxManage showvminfo "lab-ubuntu"` را برای attachmentها ببین؛ قبل از نصب دوباره disk را delete نکن.

If the VM reports no bootable medium, neither the optical drive nor disk has a bootable image, or the storage controller is misconfigured. Inspect attachments with `VBoxManage showvminfo "lab-ubuntu"`; do not delete the disk before understanding the state.

Guest Additions چه مشکلی را حل می‌کند؟Which problem do Guest Additions solve?

Guest Additions مجموعه‌ای از driver و serviceهای داخل guest است؛ می‌تواند resize گرافیکی، pointer integration، clipboard یا shared folders را فراهم کند. برای Ubuntu Server بدون GUI، mouse integration و auto-resize به کارت نمی‌آید و SSH با NAT هم به آن وابسته نیست. feature را فقط وقتی روشن کن که واقعاً نیازش داری.

Guest Additions are drivers and services installed inside the guest. They can provide graphics resizing, pointer integration, clipboard, or shared folders. On an Ubuntu Server guest without a GUI, mouse integration and auto-resize are irrelevant; SSH over NAT does not depend on them. Enable only what you need.

اگر Linux guest داری و feature لازم است، ابتدا نسخهٔ VirtualBox host را ببین. از Devices → Insert Guest Additions CD Image، ISO هم‌نسخه را mount کن. برای ماژول kernel ممکن است build tools و headers دقیقاً مطابق kernel فعلی لازم باشد. بعد داخل guest در CD mount شده اجرا کن:

If a Linux guest needs these features, first check the host VirtualBox version. Choose Devices → Insert Guest Additions CD Image to mount the matching ISO. Kernel modules may require build tools and headers matching the running guest kernel. Then run this inside the guest from the mounted CD:

sudo sh ./VBoxLinuxAdditions.run

خروجی نصب باید driverهای موردنیاز را بسازد؛ اگر build fail شد، kernel headers یا log نصب را بررسی کن، نه اینکه Guest Additions نسخهٔ نامرتبط را بارها اجرا کنی. پس از reboot وضعیت را با `lsmod | grep vbox` و `VBoxControl --version` ببین؛ خالی بودن `grep` می‌تواند بسته به guest و feature موردنیاز طبیعی باشد، پس همهٔ شواهد را کنار هم تفسیر کن.

The installer should build needed drivers; if that fails, inspect matching kernel headers and installer logs instead of repeatedly running a mismatched ISO. After reboot, inspect `lsmod | grep vbox` and `VBoxControl --version`. An empty `grep` can be normal depending on guest and required feature, so interpret multiple signals together.

shared folder یعنی مرز دادهٔ میزبان را باز کرده‌ای

shared folder را فقط به یک پوشهٔ lab خالی وصل کن و در صورت کافی‌بودن read-only بگذار. clipboard و drag-and-drop هم راه انتقال داده‌اند؛ برای آزمایش فایل ناشناس خاموششان کن. Guest Additions integration راحتی می‌دهد، اما مرز اعتماد host/guest را کم می‌کند. Extension Pack قابلیت‌های اختیاری دیگری می‌دهد و license جداگانه دارد؛ برای نصب Ubuntu یا SSH لازم نیست.

Share only an empty lab folder, preferably read-only when sufficient. Clipboard and drag-and-drop are data paths too; disable them when testing unknown files. Guest Additions improve integration but weaken the host/guest data boundary. The Extension Pack adds optional features under separate licensing terms; it is not required to install Ubuntu or use SSH.

NAT: guest بیرون را می‌بیند، host لزوماً guest را نهNAT: the guest sees out; the host does not automatically see in

Adapter پیش‌فرض NAT به guest اجازه می‌دهد اتصال خروجی بسازد؛ مثلاً package بگیرد. به‌طور معمول host نمی‌تواند دلخواه به service مهمان وصل شود. برای SSH از host، اول داخل guest `openssh-server` را نصب کن و `ip -br address`/`ip route` را ببین؛ این نشان می‌دهد guest شبکه دارد، نه اینکه host route مستقیم به آن دارد.

A NAT adapter lets the guest initiate outbound connections, such as package downloads. The host usually cannot directly initiate arbitrary connections to a guest service. To SSH from the host, install `openssh-server` inside the guest and inspect `ip -br address` and `ip route`; this proves the guest has networking, not that the host has a direct route to it.

راه ساده برای همین ماشین، port forwarding محدود به loopback است: host `127.0.0.1:2222` را به guest port 22 بفرست. در GUI مسیر Network → Adapter 1 → Advanced → Port Forwarding است. با VBoxManage می‌توان همان قاعده را دید/ساخت؛ اول مطمئن شو port 2222 روی host آزاد است:

For this host, use a port-forward rule restricted to loopback: host `127.0.0.1:2222` to guest port 22. In the GUI, use Network → Adapter 1 → Advanced → Port Forwarding. VBoxManage can express the same rule; first ensure host port 2222 is free:

VBoxManage modifyvm "lab-ubuntu" --natpf1 "guestssh,tcp,127.0.0.1,2222,,22"
VBoxManage showvminfo "lab-ubuntu"

فیلد خالیِ guest IP یعنی VirtualBox از guest DHCP address استفاده می‌کند. `showvminfo` باید NAT rule را نشان بدهد. سپس از host با `ssh -p 2222 youruser@127.0.0.1` وصل شو. اگر rule قبلاً هست، دوباره اضافه نکن؛ GUI یا VBoxManage آن را بررسی کن و پس از lab حذفش کن.

The empty guest-IP field means VirtualBox uses the guest’s DHCP address. `showvminfo` should show the NAT rule. From the host, connect with `ssh -p 2222 youruser@127.0.0.1`. Do not add a duplicate rule if one exists; inspect it first and remove it after the lab.

این port فقط روی loopback میزبان است؛ آن را به `0.0.0.0` نبند، مگر دلیل و firewall روشن داشته باشی. Port forwarding همان یک service را در معرض host قرار می‌دهد؛ همهٔ پورت‌های guest را باز نمی‌کند. برای چند VM روی یک شبکهٔ خصوصی، host-only/internal را در فصل شبکه می‌سازیم.

This port binds only to host loopback; do not bind it to `0.0.0.0` without a clear reason and firewall plan. Port forwarding exposes that one service to the host; it does not open every guest port. Chapter 7 will build host-only/internal networks for multiple VMs.

خرابی عمدی: installer هر بار برمی‌گرددDeliberate failure: the installer returns on every boot

پس از نصب، VM را خاموش کن و ISO را عمداً وصل نگه دار؛ DVD را هم در boot order اول بگذار. دوباره Start کن: installer ظاهر می‌شود. پیش‌بینی کن آیا VDI پاک شده است؟ حالا پیش از تغییر، Storage attachment، boot order و `showvminfo` را ثبت کن. شواهد نشان می‌دهند machine از کدام device بالا آمده، نه اینکه اطلاعات disk را از دست داده‌ای.

After installation, power off the VM but deliberately leave the ISO attached and DVD first in boot order. Start it again: the installer appears. Predict whether the VDI was erased. Before changing anything, record Storage attachments, boot order, and `showvminfo`. This evidence shows which device booted, not that disk data was lost.

repair را کوچک نگه دار: ISO را eject کن، disk را نگه دار، boot order را disk-first کن و یک بار reboot بزن. اگر Ubuntu بالا آمد، علت را درست پیدا کردی. اگر «no bootable medium» دیدی، storage controller و disk attachment را ببین. disk را فقط برای اینکه پیام installer را نمی‌پسندی حذف نکن.

Keep the repair narrow: eject the ISO, keep the disk, set disk first in boot order, and boot once. If Ubuntu starts, the diagnosis was right. If you see “no bootable medium,” inspect the storage controller and disk attachment. Do not delete the disk just because the installer screen was unexpected.

آزمایش: یک Ubuntu VM که دوباره ساخته‌اش می‌توانیLab: an Ubuntu VM you can reproduce

قبل از شروع فضای آزاد host و ISO را ثبت کن. VM را با ۲ vCPU، RAM متناسب با host، dynamic VDI با سقف حدود ۲۵ GiB، یک optical drive و یک NAT NIC بساز. در installer، user معمولی بساز و SSH server را نصب کن؛ secret واقعی یا فایل شخصی داخل guest نگذار.

Record host free space and ISO before starting. Create a VM with 2 vCPUs, memory appropriate to the host, a dynamically allocated VDI capped around 25 GiB, one optical drive, and one NAT NIC. Create a regular user in the installer and install the SSH server; keep real secrets and personal files out of this guest.

پس از اولین boot، داخل guest `uname -a`, `ip -br address`, `ip route` و `df -h /` بگیر. این‌ها kernel، IP، default route و فضای filesystem guest را نشان می‌دهند؛ فضای آزاد host را از host جداگانه بسنج. اگر disk کوچک است، guest آن را می‌بیند، ولی dynamic disk ممکن است هم‌زمان فضای host را هم مصرف کند.

After first boot, run `uname -a`, `ip -br address`, `ip route`, and `df -h /` inside the guest. These show kernel, IP, default route, and guest filesystem space; measure host free space separately. The guest may see a large virtual disk while the dynamic image consumes increasing host storage.

از host با port-forward loopback به SSH وصل شو؛ بعد rule را حذف کن و دوباره تلاش کن. انتظار داریم اتصال fail شود، ولی NAT خروجی مهمان هنوز کار کند. این تغییر نشان می‌دهد outbound NAT و inbound port forwarding دو مسیر متفاوت‌اند.

Connect from the host to SSH through a loopback-only forward, then delete the rule and try again. The inbound connection should fail while guest outbound NAT continues to work. This separates outbound NAT from inbound forwarding.

در پایان ISO را detach کن. اگر Guest Additions را نصب کردی، نسخه و status را ثبت کن، clipboard/shared folders را خاموش نگه دار مگر lab واقعاً به آن‌ها نیاز داشته باشد. Snapshot را در این فصل لازم نداریم؛ فصل ۶ زمان مناسب بررسی برگشت و محدودیت‌هایش است.

Finally detach the ISO. If you installed Guest Additions, record their version/status and keep clipboard/shared folders disabled unless the lab needs them. A snapshot is not required here; Chapter 6 will examine rollback and its limits.

۱۸ تمرین؛ قبل از دست‌زدن به disk، شواهد را بخوان18 exercises: inspect evidence before touching the disk

۱. ISO در برابر VDI

در wizard هر دو فایل ISO و VDI می‌بینی. کدام boot installer است و کدام مقصد نصب سیستم‌عامل؟

The wizard shows an ISO and a VDI. Which boots the installer and which stores the installed OS?

پاسخ

ISO رسانهٔ نوری installer است؛ VDI دیسک مجازی مقصد نصب. اشتباه‌گرفتنشان باعث boot loop یا نصب روی هدف اشتباه می‌شود.

The ISO is installer media; the VDI is the virtual disk target. Confusing them causes a boot loop or installation to the wrong target.

۲. host کم‌حافظه

host دارای ۸ GiB RAM است و browser/work tools هم بازند. آیا تخصیص ۷ GiB به guest انتخاب بدیهی است؟

The host has 8 GiB RAM with a browser and work tools open. Is assigning 7 GiB to the guest an obvious good choice?

پاسخ

نه؛ host برای خودش memory لازم دارد و ممکن است swap/thrashing کند. guest را کوچک‌تر آغاز کن، مصرف را مشاهده و بر اساس workload تنظیم کن.

No. The host needs memory too and may start swapping heavily. Begin smaller, observe use, and size for the workload.

۳. dynamic VDI

VDI سقف ۲۵ GiB دارد ولی اول کار host فقط ۵ GiB فضا نشان می‌دهد. آیا host هیچ‌وقت بیشتر مصرف نمی‌کند؟

A VDI has a 25 GiB cap but uses 5 GiB on the host initially. Can host usage never grow further?

پاسخ

می‌تواند تا سقف virtual capacity رشد کند. فضای host را هم پایش کن؛ dynamic allocation ظرفیت تضمین‌شده یا free space دائمی نیست.

It can grow up to the virtual capacity. Monitor host storage too; dynamic allocation is not guaranteed or permanently free capacity.

۴. installer دوباره ظاهر شد

پس از reboot صفحهٔ نصب آمده. پیش از هر repair دو مورد را بررسی می‌کنی؟

The installer reappears after reboot. Which two things do you inspect before repairing?

پاسخ

ISO هنوز متصل است؟ boot order DVD را قبل از disk می‌آورد؟ این دو را از GUI یا `showvminfo` ببین و disk را حذف نکن.

Is the ISO still attached? Does boot order place DVD before disk? Inspect both in the GUI or `showvminfo`; do not delete the disk.

۵. no bootable medium

اکنون ISO را detach کردی و VM پیام no bootable medium می‌دهد. کدام دو attachment را می‌سنجی؟

You detached the ISO and now see “no bootable medium.” Which two attachments do you inspect?

پاسخ

آیا virtual hard disk هنوز به storage controller وصل است و آیا OS واقعاً روی آن نصب شده؟ اگر installer نصب را کامل نکرده، ISO را دوباره attach کن؛ VDI را بی‌بررسی پاک نکن.

Is the virtual hard disk still attached to its storage controller, and was the OS installed there? If installation was incomplete, reattach the ISO; do not erase the VDI without inspection.

۶. guest شبکه دارد، host SSH ندارد

guest IP از NAT گرفته و می‌تواند update بگیرد؛ host نمی‌تواند به guest SSH کند. تناقضی است؟

The guest has a NAT address and can download updates; the host cannot SSH into it. Is this contradictory?

پاسخ

نه؛ outbound NAT اتصال را از guest آغاز می‌کند. برای inbound از host، port forwarding یا شبکهٔ دیگری لازم است.

No. Outbound NAT is initiated by the guest. Host-initiated inbound access needs port forwarding or another network mode.

۷. port روی همهٔ host interfaceها

NAT rule روی host port 2222 به guest SSH است. چرا host IP را خالی گذاشتن ممکن است نامطلوب باشد؟

A NAT rule maps host port 2222 to guest SSH. Why might leaving the host IP empty be undesirable?

پاسخ

ممکن است روی تمام host interfaceها گوش بدهد، نه فقط loopback. برای تست شخصی `127.0.0.1` را تعیین کن و با `showvminfo` rule را verify کن.

It may listen on all host interfaces rather than loopback. For a personal test, specify `127.0.0.1` and verify the rule with `showvminfo`.

۸. VBoxManage rule تکراری

VBoxManage می‌گوید NAT rule نام تکراری است. چه می‌کنی؟

VBoxManage reports a duplicate NAT rule name. What do you do?

پاسخ

اول `showvminfo` یا GUI را بخوان؛ rule موجود را ویرایش/حذف کن، نه اینکه با نام تصادفی چند forward بسازی. بعد با یک درخواست SSH آزمایش کن.

Inspect `showvminfo` or the GUI first; edit/remove the existing rule instead of creating multiple forwards with random names. Verify with one SSH test.

۹. guest additions build fail

نصب Guest Additions می‌گوید kernel module ساخته نشد. اولین بررسی‌ها چیست؟

Guest Additions reports that a kernel module could not be built. What do you check first?

پاسخ

آیا ISO با VirtualBox host هم‌نسخه است؟ headers/build tools برای kernel در حال اجرا نصب‌اند؟ log installer و Secure Boot policy را ببین؛ یک ISO دیگر را شانسی نصب نکن.

Does the ISO match the VirtualBox host version? Are headers/build tools installed for the running guest kernel? Inspect installer logs and Secure Boot policy; do not randomly try another ISO.

۱۰. clipboard کار نمی‌کند

Guest Additions نصب شده ولی clipboard shared نیست. چه شرط دیگری باید درست باشد؟

Guest Additions are installed but the clipboard is not shared. What else must be configured?

پاسخ

تنظیم Shared Clipboard در VM باید فعال و Guest Additions service/driver سالم باشد؛ GUI guest بدون component مربوطه ممکن است لازم داشته باشد. اگر به feature نیاز نداری، خاموش بماند.

Shared Clipboard must be enabled in the VM settings and Guest Additions services/drivers must work; a graphical guest may need its relevant component. If unnecessary, leave it disabled.

۱۱. Extension Pack با Guest Additions

برای resize صفحهٔ guest می‌خواهی Extension Pack نصب کنی. آیا این قطعهٔ درست است؟

You want guest display resizing and plan to install the Extension Pack. Is that the right component?

پاسخ

معمولاً نه؛ Guest Additions داخل guest driver/serviceهایی مثل auto-resize می‌آورد. Extension Pack امکانات اختیاری host-side دیگری دارد و license جداگانه دارد.

Usually not. Guest Additions provides guest-side drivers/services such as auto-resize. The Extension Pack adds other optional host-side features under separate licensing.

۱۲. shared folder با installer ناشناس

می‌خواهی installer ناشناس را آزمایش کنی. shared folder خانهٔ host روی read/write است. قبل از اجرا چه تغییری می‌دهی؟

You plan to test an unknown installer. The host home folder is shared read/write. What do you change before running it?

پاسخ

shared folder را خاموش یا به پوشهٔ disposable و read-only محدود کن؛ clipboard و drag/drop را هم خاموش کن و network را در صورت نیاز internal کن. VM به‌تنهایی barrier کامل نیست.

Disable the share or limit it to a disposable read-only folder; also disable clipboard/drag-and-drop and isolate networking if needed. A VM alone is not a perfect barrier.

۱۳. memory balloon

guest کند است و host هم memory pressure دارد. آیا افزودن vCPU اولین پاسخ است؟

The guest is slow and the host is under memory pressure. Is adding a vCPU the first answer?

پاسخ

نه لزوماً؛ host/guest memory، swap، CPU contention و disk I/O را بسنج. منابع مجازی می‌توانند contention را بیشتر کنند.

Not necessarily; measure host/guest memory, swap, CPU contention, and disk I/O. More virtual resources can increase contention.

۱۴. NAT یا bridge؟

برای تمرین نصب، guest فقط باید package بگیرد و از LAN دیده نشود. کدام mode را انتخاب می‌کنی؟

For installation, the guest needs package access but should not appear directly on the LAN. Which mode do you choose?

پاسخ

NAT معمولاً شروع ساده‌تری است چون guest اتصال خروجی می‌سازد. Port forwarding را فقط برای سرویس مشخص اضافه کن؛ bridge را بی‌نیاز انتخاب نکن.

NAT is usually the simpler start because the guest initiates outbound connections. Add forwarding only for a specific service; do not choose bridged mode without a need.

۱۵. guest IP عوض شده

پس از reboot SSH forwarding fail شد و rule یک guest IP ثابت دارد. چه چیزی را مقایسه می‌کنی؟

SSH forwarding fails after reboot and the rule contains a fixed guest IP. What do you compare?

پاسخ

IP فعلی `ip -br address` با IP rule. NAT DHCP ممکن است IP را عوض کند؛ guest IP خالی/lease مناسب یا reservation را در همان شبکهٔ NAT ارزیابی کن.

Compare current `ip -br address` with the rule’s address. NAT DHCP may change it; assess an empty guest-IP field or a suitable reservation for that NAT network.

۱۶. ISO mismatch

host VirtualBox به‌روز شده ولی Additions داخل guest قدیمی است. کدام علامت را می‌بینی و از کجا شروع می‌کنی؟

The host VirtualBox was upgraded but guest Additions are old. What symptom might appear and where do you start?

پاسخ

نسخه/driver mismatch می‌تواند integration را ناقص کند. نسخهٔ host و `VBoxControl --version` را مقایسه کن؛ سپس ISO matching host را از Devices وارد و نصب/verification را دنبال کن.

A driver/version mismatch may break integration. Compare host version with `VBoxControl --version`, insert the matching ISO through Devices, then install and verify.

۱۷. space guest در برابر host

`df -h /` داخل guest ۱۵ GiB آزاد می‌گوید ولی host تقریباً پر است. چرا هر دو می‌توانند درست باشند؟

`df -h /` inside the guest shows 15 GiB free, but the host is almost full. How can both be true?

پاسخ

`df` ظرفیت filesystem مجازی را می‌بیند؛ dynamic VDI روی host رشد کرده و فایل‌های دیگری هم فضا گرفته‌اند. فضای guest و فضای host را جدا پایش کن.

`df` sees the virtual filesystem capacity; the dynamic VDI may have grown on the host alongside other files. Monitor guest and host capacity separately.

۱۸. بازبینی VM lab

یک VM برای تمرین SSH تحویل می‌دهی. سه مقدار `showvminfo` یا GUI را که ثبت می‌کنی نام ببر و بگو هرکدام چه چیزی را ثابت نمی‌کنند.

You hand off an SSH lab VM. Name three values from `showvminfo`/GUI you record and what each does not prove.

معیار پاسخ

نسخهٔ VirtualBox و boot/storage/NIC/RAM/CPU را ثبت کن. config ثبت‌شده صحت نصب guest، دسترسی شبکهٔ واقعی یا سالم‌بودن دیسک را ثابت نمی‌کند؛ با boot، IP، SSH و خواندن log/health تکمیلش کن.

Record VirtualBox version and boot/storage/NIC/RAM/CPU settings. Configuration does not prove guest installation, actual reachability, or disk health; complement it with boot, IP, SSH, and relevant logs.

یک ماشین، چند مرز قابل‌بررسیOne VM, several boundaries you can inspect

VirtualBox به guest سخت‌افزار مجازی می‌دهد؛ ISO installer را boot می‌کند؛ VDI سیستم نصب‌شده را نگه می‌دارد؛ NAT اتصال خروجی می‌دهد؛ port forward یک ورودی مشخص اضافه می‌کند؛ Guest Additions integration را بهتر می‌کند و هم‌زمان چند مسیر اعتماد به host باز می‌کند. هر کدام را به‌عنوان قطعه‌ای جدا بررسی کن.

VirtualBox presents virtual hardware; the ISO boots an installer; the VDI stores the installed system; NAT provides outbound access; a port forward adds one inbound path; Guest Additions improve integration while opening additional trust paths to the host. Inspect each as a distinct component.

اگر installer دوباره ظاهر شد، به‌جای پاک‌کردن دیسک boot device را ببین. اگر SSH از host نمی‌رسد، guest IP، listener و NAT rule را جدا بسنج. فصل بعد سراغ KVM و QEMU می‌رویم تا ببینیم Linux چطور VM را روی ابزارهای بومی خودش می‌سازد.

If the installer reappears, inspect boot devices instead of deleting the disk. If host SSH fails, check guest IP, listener, and NAT rule separately. Next we turn to KVM/QEMU and see how Linux builds VMs with its native tooling.
